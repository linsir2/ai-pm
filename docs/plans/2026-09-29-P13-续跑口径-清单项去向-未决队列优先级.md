## 2. 口径（要作者看的几条）

| # | 口径 | 理由 |
|---|---|---|
| C1 | `retry_hint` 只存**报文类**失败的原因；**网关类（超时/5xx）不存** | 网关错对模型没有信息量，递进去只是把提示词喂脏；报文类才是"你上次交的形状不对" |
| C2 | hint **一次性**（`take_retry_hint()` 取走即清） | 不取走的话，后面每个动作都会把陈年错误当 `validation_error` 递进去——比不递更糟 |
| C3 | 清单项**只在"出草案"那一刻**才转 s11（不是在出问卷时） | 还在问的轮次里就落 s11 会一边问一边记，队列白涨；轮末才落等于"这一轮问完了，剩下这些没人管，记下来" |
| C4 | 落 s11 的清单项**不加** `〔未决·阻塞〕` | 它不堵交付（就绪度里是 WARN）；阻塞与否由 `01` §7 的章节/必填字段规则算，不由来源算 |
| C5 | carried 挑选 = **阻塞优先，其次最老**（稳定排序，不打乱同龄次序） | 只有阻塞项决定 ready 不 ready；老的非阻塞条目不该挤掉它。P10 的量：s11 消化 4 条 / 新增 18 条，配额稀缺必须给堵交付的 |
| C6 | 判重键 = `(去处 label, 归一化标题)`，**只跟当前活跃的 s11 条目比** | 答过就 `remove`（P9），撤下之后同一件事**可以**再落——判据是"现在文档里有没有"，不是"历史上有没有" |
| C7 | 清单项落 s11 要**同时**进 `gaps` 一行（"还有 N 条清单项没被处理，已记进 s11"） | 用户点确认前得知道"这些不是被吃了，是排到后面去了" |

```python
# domain/round/round.py
    def fail(self, reason: str, *, hint: str | None = None) -> None:
        """记失败：**只记第一次**（见原 docstring）。`hint` 是给重试用的报错摘要。"""
        if self._step is Step.DONE:
            raise IllegalStepTransition(current=self._step, target=Step.FAILED)
        if self._step is Step.FAILED:
            return
        self._failure = Failure(at_step=self._step, waiting_on=self._waiting_on, reason=reason)
        if hint:
            self._retry_hint = hint
        self._waiting_on = WaitingOn.NONE
        self._step = Step.FAILED

    @property
    def retry_hint(self) -> str | None:
        """上次失败的**报文类**原因（网关类不记）：重试时递给第一次尝试。"""
        return self._retry_hint

    def take_retry_hint(self) -> str | None:
        """取走重试提示（**一次性**）：不取走，陈年错误会被后面每个动作当成校验错误递进去。"""
        hint, self._retry_hint = self._retry_hint, None
        return hint
```

## 4. 数据流（改完之后）

```
席位轮失败 ──► Round.fail(reason, hint=None)            ← 网关类：不递
整合两次都没有效报文 ──► Round.fail(reason, hint=repair_note)  ← 报文类：留
        │
        └─► 用户点"重试" ──► resume()（step 回到失败前那一步）
                            └─► 动作开头 take_retry_hint()（**取走即清**）
                                 └─► 第一次尝试的 validation_error = 上次的报错
                            └─► 席位：pending_seats 已空 → **零模型调用**

一轮的第二批出草案那一刻：
  Round.list_items（P12 累积）
     ├─ 已被题目/提案覆盖 ──► 不动
     └─ 没人处理 ──► s11 提案（非阻塞 + 〔去处：…〕 + 标准格式）+ gaps 一行
                        └─► 下一轮：carried 按"阻塞优先、其次最老"挑走 → 答完 remove

落 s11 之前：同一 (去处, 归一化标题) 已在 → 跳过（写一行说明）
RoundView：failure_reason（老）+ failure_at_step + retry_from（新，人话）
```

## 5. 不做

- **不做"复用上一次失败报文"**：`model_calls` 留样继续只做诊断。理由：复用一份被判定不可用的报文，
  用户会卡在同一个错误上；真跑没有证据说明它值这个复杂度。
- **不做进程内调用级续跑**（进程崩在单次调用中间）：那要 provider 侧支持，v1 不做。
- **不做 C4 / C6**（跨轮统计与继续深挖入口）：要新查询 / 新端点 + 前端，留 P14。
- **不做语义去重**：T7 的判重是 `(去处, 归一化标题)` 的机械判据，不是相似度算法。
- 不动 `MAX_QUESTIONS_PER_BATCH=5`、不动问卷两批上限、不动写入路径、不动端点白名单。

## 6. 成功之后长什么样（自检）

1. 整合/切分失败后点重试，**第一次尝试就带着上次的报错**（T1/T2 的用例 + 真跑看 `validation_error` 槽）。
2. 重试**不再重跑已交回的席位**，而且这条行为有**走真图**的钉子（T3）。
