> **状态**：待作者拍板。拍板后用 writing-plans 出实施计划。
> **依据**：业界 2026 调研（WCXB 2008 页/7 种页面类型；trafilatura 自带 990 页 benchmark 含中文 20–30%）
> + **本机 10 个真实中文页面**的实测（`backend/scripts/page_set.py`）。
> **前置**：批 6b 已落地的「网页保留标题层级」（`02` §11.0.79）与「fetch 二级判决」。

---

## 0. 一句话

网页材料（上传 `.html` 与抓网页）入库时，**用主内容取代全文**（降噪）；
**抽得不信就退回全文**（比例守门）；老材料靠既有的 `HTML_EXTRACT_REVISION` 机制自动判"该重解析"。

---

## 1. 为什么做（现状与实测）

### 1.1 现状

`extract.py:html_text()`：剥 10 个 `CHROME_TAGS`（script/style/nav/aside/footer/form/…）→ 标题加
markdown 前缀（批 6b）→ 整页拍平。**不做主内容抽取**。

理由写在 `extract.py:71-77`：试过 `readability-lxml`，三个真实页面增益只 1–6%，而它会**静默整块丢掉**
它认为不是正文的节点；结论是"该撤的是工具，不是继续加判据"。

### 1.2 但当年的工具选错了（2026 调研）

| 抽取器 | WCXB F1（2008 页/7 种页面类型） | trafilatura 自带 benchmark F1（990 页，含中文 20–30%） |
|---|---|---|
| **trafilatura** | **0.791**（rs- 变体 0.859） | **0.924** |
| newspaper4k | 0.720 | 0.803 |
| readability-lxml | **0.675（倒数第三）** | 0.853 |

**我们当年测的正是倒数第三那个**，而且只测了 3 个页面、只量了字数（不量"丢没丢要的内容"）。

### 1.3 页面集（先建基准）

`scripts/page_set.py`：走**生产抓取器**（SSRF 钉 IP / 重试 / 5MB / 3 跳 / Content-Type 护栏）
把 **17 个真实中文页面**抓下来存到 `.codex/runs/2026-10-19/pages/`（文档站 8 + 门户/首页 7 + 搜索首页 1 + 列表页 1）。
以后所有实验跑这批**固定的**页面。

### 1.4 决定性实验：抽取对检索到底有多少可测收益

`scripts/web_retrieval_bench.py`：两套切块（现状 / 抽取）各灌进**真库**（真材料仓 + 真 FTS5 + 真向量，
真模型），跑两类查询。

**查询词只从「两边都有」的词里取**——第一版从抽取结果取词，等于循环论证（抽取口径当然占便宜），
量出"样板假命中 28/42 → 1/42"的漂亮假数字。第二版又栽在**没做前缀归一**上
（现状的 `### 标题` 与抽取的 `标题` tokenize 不同 → 本该相同的词被算成"样板词"）。
**归一化必须在 token 化之前**——这是本轮最贵的教训。

**17 个真实页面、公平判据、真 FTS5 + 真混合检索**：

| 口径 | 检索路 | 正文命中 | 目标名次 | 排第 1 名 | 样板查询命中块 |
|---|---|---|---|---|---|
| 现状 | FTS5 | 40/48 | 1.38 | 33 | 3.4 |
| 现状 | **混合（生产）** | 37/48 | 1.32 | 30 | 5.0 |
| **抽取** | FTS5 | 40/48 | **1.32** | **34** | **2.5** |
| **抽取** | **混合（生产）** | 37/48 | **1.11** | **33** | 5.0 |

**读法（这才是用户看见的东西）**：
- **正文召回：两边持平**（37/48 / 40/48）→ 抽取**没有**挤掉我们要的内容；
- **目标名次：1.32 → 1.11（-16%）**、**排第 1 名：30 → 33（+10%）** → 抽取让**对的内容排得更前**；
- **成本**：入库字少 **26–31%** → 少那么多块要推理、要存、要进 FTS。

**机制性解释**：我担心的"样板挤掉正文"，在**词面路上 BM25 的 IDF 已经解决大半**（样板词每页都有 →
文档频率高 → IDF 低 → 样板块本来就在后面）。**向量路才是样板污染的重灾区**（IDF 管不到向量），
而抽取正好治的是这个——所以收益体现在**混合路的排序**上，不在词面路的命中上。

### 1.5 代价：门户/列表页会丢主体

| 页面 | 现状行 | 抽取行 | 丢的内容 |
|---|---|---|---|
| people_news（门户首页） | 525 | 18 | **新闻标题列表**（= 首页主体）|
| infoq_home（门户首页） | 385 | 51 | **文章标题列表**（markdown 列表，被判成样板）|
| cnblogs（博客首页） | 70 | 20 | 导航（✓ 丢对了）|
| runoob（教程文章页） | 359 | 35 | **课程导航**（✓ 丢对了，正文 989 字全留）|

**两类页面行为相反**（这决定了必须有守门）：
- **文章/文档页**：丢的是导航 → 抽取**大赢**（runoob 现状 5207 字里大部分是几百个课程链接）；
- **首页/列表页**：丢的可能是主体 → 抽取**大输**。

## 2. 现有设计：复用什么（不造轮子）

| 已有 | 位置 | 本批怎么用 |
|---|---|---|
| `html_text(data) -> (正文, title)` | `extract.py:146` | **签名不动**（现状口径的拍平路径一字不改） |
| `_from_html(...)` → `ParsedMaterial` | `extract.py:337` | **唯一改动点**：在拍平之外多一条"主内容"的路，由它选 |

| `HTML_EXTRACT_REVISION` | `extract.py:48` | **升 1 → 2**：换算法就换档位 → 既有 HTML/抓取材料自动判"该重解析"（原始字节都在，点一次即可）。机制**已存在**，不用新造 |
| `ParsedMaterial.warnings` | `dto.py` | 装"抽取不可信已退回全文"这类**照实说** |

| `lxml 6.1.3` | 已装（传递依赖） | trafilatura 的 `lxml>=6.1.3` **不用动** |

**不造的东西**：不自己写密度启发式（trafilatura 是已知库、Apache-2.0、榜单第一、自带中文评测）；
不引 readability（它当年被撤是因为会静默丢内容）；不并存两份材料。

## 3. 设计

### 3.1 四个决定（作者已拍板 + 数据定的最后一条）

1. **做主内容抽取**（trafilatura `>=2.3`，Apache-2.0）：实测收益见 §1.4（混合路名次 -16%、top1 +10%、入库字少 26–31%），
   远超 readability 那次的门槛（1–6% 且会丢内容）。
2. **比例守门 → 改成标题守门**（作者拍板的是"比例守门"，但实测证明**长度比这个代理判据分不开**：
   people_news 抽 3% **全对**、infoq_home 抽 13% **丢主体**；runoob 抽 10% **全对**却会被长度比判成"不可信"）。
   → 改用**页面标题是否出现在抽取结果里**：它**直接判"抽到主体没有"**，不依赖魔法百分比。
   实测 16 个页面：**该用却判保守 3 个、不该用却判激进 1 个**（长度比是 3/1，链接密度是 4/3）。
3. **`fast=True`**：只跑 trafilatura 自己的规则，**不让 readability 复活**（它的 fallback 链里有）。
   实测这 17 个页面 standard / recall / fast **结果完全一样** → 关掉它零损失。
4. **默认保守**：守门不过就退回**现状口径**（`html_text`：剥了 10 个语义噪音标签的全文），
   不是退回"完全没清洗的原始 HTML"——现状口径已经是"bs4 剥噪音版"，与 PostHog 的
   `_bs4_fallback` 同形。

### 3.2 新增契约（只有一个）

```python
# backend/src/pmstudio/infrastructure/tools/maincontent.py
def extract_main_content(data: bytes) -> tuple[str | None, str | None]:
    """HTML 字节 →（主内容, 说明）。

    **唯一作用**：把网页的**主内容**抽出来（降噪）。
    返回 (None, 说明) 表示"抽不出/不可用"——调用方据此走全文。

    为什么独立成文件：主内容抽取与"拍平"是**两件事**（前者选内容、后者排版），
    混在一个函数里就分不清"没抽到"与"抽到的是空"。
    """
```

- **不引入任何新端口/协议**：`MaterialParser` 的形状不变，上传与抓网页**共用同一条**。
- **不可用即降级**：trafilatura 没装 / 抛错 / 返回空 → `(None, "主内容抽取不可用")` → 用现状口径，**不炸**。

### 3.3 每个文件怎么改（每一步）

**① `backend/pyproject.toml`**
- 依赖加 `trafilatura>=2.3`（Apache-2.0），附理由（榜单第一 + 自带中文评测 + 我们当年测错了工具）。
- `lxml` 约束**不动**（实测已装 6.1.3，满足 trafilatura 的要求；trafilatura 自己的约束会兜住）。

**② `backend/src/pmstudio/infrastructure/tools/maincontent.py`（新增）**

```python
def extract_main_content(data: bytes) -> tuple[str | None, str | None]:
    try:
        import trafilatura
    except ImportError:
        return None, "主内容抽取不可用（trafilatura 未安装）"
    try:
        text = trafilatura.extract(
            data,                      # 原始字节：让它自己按 <meta>/HTTP 头解码
            output_format="markdown",  # **必须 markdown**：txt 会丢标题层级
            fast=True,                 # 不让 readability 复活
            include_comments=False,    # 评论不是正文
            include_tables=True,       # 表格是内容（文档站常见）
        )
    except Exception as error:
        return None, f"主内容抽取失败（{type(error).__name__}）"
    if not text or not text.strip():
        return None, "主内容抽取结果为空"
    return text, None
```

**③ `backend/src/pmstudio/infrastructure/tools/extract.py`**
- `HTML_EXTRACT_REVISION`：1 → **2**（换算法换档位 → 老材料自动判"该重解析"，机制**已存在**）。
- `html_parser_version()`：把 trafilatura 版本也写进身份——否则换了 trafilatura 版本，材料身份不变、抽取结果却变了。
- `_from_html()`：**唯一的行为改动点**
  ```python
  text, title = html_text(data)                    # 现状口径（不动）
  main, note = extract_main_content(data)          # 新口径
  if main is None:
      body, warnings = text, [note]
  elif not _has_title(main, title):
      body, warnings = text, [f"主内容抽取结果里没有页面标题，判为没抽到主体，已退回全文"]
  else:
      body, warnings = main, []
  # 之后与今天完全一样：chunk_text(body, parser_id=HTML_PARSER_ID) → ParsedMaterial
  ```
  `_has_title(main, title)`：把 `<title>` 去掉站名后缀（`-`/`_`/`|` 之后）取前几个字，
  看它**是否出现在抽取结果里**。它就是"抽到主体没有"的最强信号（实测 16 页只错判 1 个）。

  **`html_text` 本身一字不改**（拍平路径、标题前缀、裸 div 噪音全留）。

**④ `backend/src/pmstudio/infrastructure/tools/limits.py`**
- **不加比例常量了**（长度比已证明不可靠）。若将来要加别的上限，仍放这里
  （"上限常量与保证它的那个函数必须在同一个地方"）。

**⑤ 界面/协议/前端**：**零改动**（`MaterialSummaryView` 不变，只是 parser 身份变了）。

**⑥ `backend/scripts/page_set.py` + `web_retrieval_bench.py`**：页面集与量化判据（已入库）。

### 3.4 数据流影响

```
上传 .html ─┐
            ├─→ _from_html ─→ html_text()      （全文拍平，现状口径，不动）
按网址抓网页 ─┘        │
                     └─→ extract_main_content()（新：trafilatura markdown）
                              │
                     比值 < 30%？ ─是→ 用全文 + warnings
                              │否
                              ↓
                     chunk_text(≤500/400) → material_chunks
                                              ├─ FTS5 影子表（分词串）
                                              └─ material_chunks_vec（自然语言向量）
                                              ↓
                                     检索：词面不再被导航词稀释
```

**影响面**：只有 HTML 材料（上传 .html + 抓网页）的**块内容**变干净；
上传的其它格式（md/pdf/docx/xlsx）与**联网检索**（Tavily）**一字不动**（Tavily 的 content
本来就是它自己抽好的文本，没有样板）。

### 3.5 改完的效果（实测预期）

| | 现状 | 改后 |
|---|---|---|
| 文档/文章页块内容 | 含导航/页脚/推荐位 | 降噪 7–53%，代码块与标题层级**更全**（实测 react 多出完整代码示例） |
| 首页/列表页 | 全是噪音 + 主体 | **守门触发 → 退回全文**（不丢主体，也不降噪） |
| FTS 词面匹配 | 导航词稀释（"登录"之类在每个页面都命中） | 文档页上稀释减少 |
| 向量 | 样板文本带偏 | 同上 |
| 老 HTML 材料 | —— | 判"该重解析"，点一次即重算 |

| # | R 需求句 | I 输入 | P 过程 | R 绿标准 |

| 1 | **主内容取代全文**（降噪） | 真实页面 HTML（`pages/react_zh.html`） | `_from_html` → 看块正文 | 块正文里**没有**页面导航/页脚；且**保留**了正文里的完整代码示例 |

## 6. 风险与如实声明

1. **引 trafilatura 就等于引了 charset-normalizer**（传递依赖）。我们**刻意不用**猜编码的
   解码器（`extract.py:103-114`：猜错的表现与静默乱码一样）。但**主内容抽取这条路上
   是 trafilatura 在解码**（它优先用 HTTP 头与 `<meta charset>`）。文本路径仍走我们的
   `decode_text`（UTF-8/GB18030，不猜）→ **两条路的解码策略不同，这是事实，要写进文档**。
2. **30% 这个阈值是在 10 个页面上定的**。它只区分了"列表页"与"其它"，
   别的形态（论坛、商品页）我们还没样本 → **要留作可调**（放 `limits.py`，改一个数）。
3. **首页/列表页不降噪**（守门退回全文）。这是有意的取舍：宁可噪音，也不可丢主体。
4. **老 HTML 材料不会自动重算**——判"该重解析"、原始字节还在、**要用户点一次**。
   仓库里本来就是这样（`extract.py:136-140` 写明"点一次即可"）。
5. **我们的页面集只有 10 页**，且没覆盖论坛/商品页/搜索结果页（那几类当时抓不到）。
   基准要能扩（`scripts/page_set.py` 加 `PAGES` 即可）。
6. **trafilatura 的 markdown 输出与我们的拍平格式不同**（列表有 `- ` 前缀、代码块是围栏）。
   这对 FTS 无影响（分词后一样），对**展示**有影响（用户会看到 `- ` 和 ``` 围栏）。
   要不要在展示层处理，量了再说。

## 7. 最终形态推演（做完之后是什么样）

1. 用户上传一份 FastAPI 中文文档页 → 库里 3 块，内容是教程正文 + 完整代码示例，
   `heading_path` 是 `("# 快速入门", "## 创建与嵌套组件")`；**没有**站点导航与"上一页/下一页"。
2. 用户按网址抓一个技术门户首页 → trafilatura 抽出来只剩 23% → **守门触发** → 用全文
   （文章标题列表一条不少），`warnings` 写明"主内容抽取只得到 23%，已退回全文"。
3. 用户在 F6 搜文档站里的那句话 → 命中**正文块**，不再被全站都有的"登录/导航"挤掉。
4. 界面上的材料卡：老 HTML 材料标"该重解析"，点一下 → 用新口径重算 → 卡片更新。
5. 抓回来的网页 anchor 仍是"第 N 行"（拍平后行号）——**本批不动**（已知边界，另议）。

## 8. 明确不做

| 不做 | 理由 |
|---|---|
| **重排（cross-encoder）** | 收益最大（MRR 0.873→0.941）但要新模型 + 推理延迟 + Recall 会掉一条；**已存档**在 `docs/plans/`，另起一轮 |
| **换嵌入模型**（gte-zh / m3e / bge-m3） | 中文榜单上 gte-zh 在法律文书上比 bge-zh 高 6.2pp；但换模型 = 全量重算向量 + 口径版本变更；**已存档**，另起一轮 |
