- [ ] **Step 1: 写语料生成器（真模型，一次调用出 JSON）**

在 `backend/scripts/vector_recall_bench.py` 里加：

```python
SYNTH_SCHEMA = {
    "type": "object",
    "properties": {
        "items": {
            "type": "array",
            "items": {
                "type": "object",
                "properties": {
                    "title": {"type": "string"},
                    "text": {"type": "string"},
                    "paraphrase": {"type": "string"},
                },
                "required": ["title", "text", "paraphrase"],
            },
        }
    },
    "required": ["items"],
}
```

调真模型要 100 条（`title` 8–14 字、`text` 40–120 字、`paraphrase` 15–30 字），**领域要散**（客服/仓储/财务/排班/权限/物流/质检/客服话术…），每条 `paraphrase` 是**同义改述**（不得与 `text` 有任何 2-gram 重合，否则它就不叫"同义改述"了）。
提示词要写清：`paraphrase` 用**日常说法**问同一件事，不要照抄原文词。

- [ ] **Step 2: 造语料库（真材料仓建索引）**

把 46 条真 observations（`SELECT title, detail FROM observations`）当材料块（`text` = title + detail），加上 100 条合成块，**全部经 `SqliteMaterialStore.put()`** 灌进临时库——索引（FTS5 影子表）由生产代码建，**不手写 SQL 建索引**（`scripts/retrieval_acceptance.py` 同一体例）。
每块的 `chunk_id` 记下来，查询的 ground truth 就是它。

- [ ] **Step 3: 造三类查询（每类 40 条）**

照抄 `scripts/retrieval_acceptance.py:_queries()` 的两类造法（**同一把尺子**，否则跟 134/169 口径不可比）：

- ①逐字子串：从 `text` 里切一段 8–14 字的连续中文（正则切标点 + 去 ASCII），原样当查询。
- ②同词换序：那段 `query_tokens()` 后**倒序**拼回。
- ③同义改述：合成语料自带的 `paraphrase`。

**配平**：逐字与换序两类从前 40 条语料各取一条（保证与语料同分布）；同义改述取 100 条合成里的前 40 条（真观察没有人工改述，硬造会失真）。
**有效性检查**：③的每条查询与目标块的 2-gram 重合数**必须为 0**，否则**弃用该条并换下一条**（记弃用数）；重合不为 0 的它就不是"同义改述"，混进来会把基线抬高。

- [ ] **Step 4: 跑三个检索器出表**

同一份语料、同一批查询，分别跑：
- `SqliteFtsRetriever`（v2 词法基线）
- `SqliteHybridRetriever` + `FastEmbedEmbedder`（v3 真模型）
- `SqliteHybridRetriever` + `FakeEmbedder(dimensions=512)`（v3 假模型——**只为对照"向量路到底有没有起作用"**，不作为验收对象）

每个查询算 `top1`（第一条是不是目标块）与 `recall@5`（前 5 条里有没有目标块）。
输出 Markdown 表：行=查询类型，列=三个检索器的 top1 / recall@5，末尾"合计"行。

- [ ] **Step 5: 断言（预注册判据，阈值写死在脚本里）**

```
①逐字子串：v3(真模型) 的 top1 与 recall@5 **逐档 >= v2**
②同词换序：v3(真模型) 的 top1 与 recall@5 **逐档 >= v2**
③同义改述：v3(真模型) 的 recall@5 >= 60%
   且 v2 在同一批③上的 recall@5 <= 10%（基线必须≈0，否则说明造词失真）
```

任一条不过 → **退出码 1**，把实测数字原样打进 stderr，**不许调阈值**。

- [ ] **Step 6: 附带跑一次"老口径不回归"**

调 `scripts/retrieval_acceptance.py`（它已实现 46×4 类 + 134/169 口径），确认 **v2 仍是 top1 134 / recall@5 169**——证明批 5 的改动没动 v2 行为。这条数字进证据文档。
