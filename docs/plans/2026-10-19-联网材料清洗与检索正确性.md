## 0. 为什么有这批活

两条调研（业界 2026 现状 + 本仓现状逐条核实）交叉后，落出**一个病根 + 三个确定性错误**。

### 病根：入库层与使用层职责混淆

上传材料早就是分开的：**整份入库**（截 20 万字）→ `select_chunks` 按预算挑进提示词。
**联网这条链没分开**，于是：

- 入库时截 **300 字**——而 Tavily 实测给 **568–2302 字**（basic / advanced 两档都量过），
  **扔掉 50–78% 的内容**；
- 同时**联网材料不写向量索引**（`use_cases.py:905-918` 只调 `materials.put`）——
  搜来的材料，事后搜不到；
- `web_block_cost`（`context.py:1124`）与 `render_web_results`（`context.py:1230`）
  都按"一结果一块"写死，整段入库会连带打破这两把尺子。

### 三个确定性错误（与设计无关，先修）

| # | 位置 | 错误 |
|---|---|---|
| 1 | `materials.py:554` | `score=1.0/(total-position)` → **第一名拿最小分**，与上一行注释「越大越好」相反 |
| 2 | `use_cases.py:905-918` | 联网材料**不写向量** |
| 3 | `tokenize.py:47` vs `materials.py:624` | **嵌入口径不对称**：索引侧 embed 的是 jieba 分词串，查询侧 embed 的是原文 |

## 1. 调研依据（都是实测，不是引文）

### 1.1 业界做法（2026）

| 做法 | 结论 | 对我们的意义 |
|---|---|---|
| 切块 | 简单结构化切块在库内检索上稳定优于 LLM 引导切块；**重叠无可测收益、只涨成本**；块长 150–300 token 最佳 | 我们 500 字、**无重叠** —— **已经是对的，不改** |
| 上下文补全 | Anthropic「contextual retrieval」前置 50–100 token LLM 上下文 → top-20 失败降 35%（+contextual BM25 49%，+重排 67%） | 便宜的基线是"标题+章节路径前置"，**我们已有**（`index_source`）。LLM 逐块调用属检索增强，本批不做 |
| 网页正文抽取 | trafilatura 在 WCXB（2008 页 / 7 种页面类型）F1 **0.84**，readability 仅 **0.67**；但**所有启发式在文档站会误删代码块与 API 表格** | 我们当年测的是 readability（最差的那个）——**值得重测，但本批不做**（另起一轮） |
| 搜索结果去重 | 分三层：字节级 / 近重复 / 语义级；**时机比方法重要**（语料级入库时最划算） | 见 §2.3 |
| 重排 | 单项收益最大：**+17.2pp MRR@3 / +12.1pp Recall@5** | 要 cross-encoder，本批不做 |

### 1.2 Tavily 实测（真跑，2026-10-19）

### 1.3 三层去重的对比台（`scripts/nd_compare.py` / `nd_threshold.py` / `nd_semantic.py`）

真跑 Tavily 拿 50 条结果 → 990–1225 对 → 弱标签（同一份法规的正文 = 正例）。

**构造集（标签确切，35 个已知变体）**

| 方法 | precision | recall | f1 | 耗时 |
|---|---|---|---|---|
| sha256（字节级） | 0.000 | 0.000 | **0.000** | 0.2ms |
| 精确 Jaccard(5-gram) | 1.000 | 1.000 | **1.000** | 1.6ms |
| MinHash 估计(perm=128) | 1.000 | 1.000 | 1.000 | **248ms** |

**真集（弱标签）**

| 方法 | 阈值 | precision | recall | 耗时 |
|---|---|---|---|---|
| sha256 | — | 1.000 | 0.061 | 54ms |
| 精确 Jaccard | 0.2 | **1.000** | 0.159 | 2255ms |
| 精确 Jaccard | 0.55 | 1.000 | 0.084 | — |
| MinHash(128) | 0.2 等价 | 1.000 | 0.093 | **92418ms** |
| 语义余弦（真模型） | 0.90 | 1.000 | 0.185 | — |
| 语义余弦（真模型） | 0.80 | 0.772 | 0.422 | — |

**三层命中集合的互补性**

```
字节级命中 19、n-gram 命中 68
余弦≥0.90：命中 58，**余弦独有 0**，n-gram 独有 10
余弦≥0.80：命中 132，余弦独有 65，但 39 个误杀
```

### 1.4 三条被数据推翻的假设

1. **MinHash 不划算** —— recall 与精确 Jaccard 打平（差 1–2 条是弱标签噪声），
   **慢 57 倍**（真规模 192s vs 3.4s），且 `datasketch` 强制依赖 **scipy（~50MB）**。
   精确 Jaccard 零依赖，而它**就是** MinHash 要近似的那个东西。
2. **语义层当去重判据不成立** —— 在保精度阈值（0.90）上对 n-gram **零增量**；
   放松到 0.80 就开始误杀不同内容（它是"同主题"检测器，不是"重复"检测器：
   39 个误报是词汇相近的**不同法规**）。而语义层要的 embedding 我们本来就要算
   （补联网材料的向量），不额外花钱——但它该用在**检索**上，不是去重上。
3. **块级去重没有优势** —— 同阈值下块级 recall 按比例**更低**（0.3 阈值：文档级
   11.9% vs 块级 10.6%），precision 更差（0.892 vs 1.000）→ **留在文档级**。

## 2. 设计

### 2.1 三个确定性错误

| # | 修法 | 影响面 |
|---|---|---|
| 1 | `score` 改 `1.0/(position+1)`（`materials.py:554`） | 纯数值修正。消费方（`dto.py:780`）不重排，只影响展示的分值 |
| 2 | `SubmitOpening` 加 `vectors: MaterialVectorIndex = NO_VECTORS` 端口；`_keep()` 入库成功后 `vectors.write(material_id)`；**命中已存在（URL 重复）则跳过**（避免白花 ONNX 推理） | `use_cases.py:753-781` + `container.py` 接线 |
| 3 | **先用 bench 量两种口径再定**：索引侧改 embed 自然语言（`title + heading_path + text`，不分词）还是查询侧也分词 | 若改索引侧：**必须加"向量口径版本"标记**——口径变了旧向量就是脏的，而现在 `migrate` 只补 NULL，脏向量会静默留着（潜在 bug） |

### 2.2 联网清洗：入库保全 + 使用裁剪

```
Tavily content（568–2302 字）
  → 清洗归一（§2.3）
  → 整段入库 + 按 500 字切块（复用 tools/extract.py:chunk_text，与上传同一条路径）
  → 写 FTS 索引 + 写向量索引
  → 预算层（WEB_BUDGET=2000）挑块进提示词
```

**切块带来的白捡**：Tavily content 里的 `## 标题` 会被 `_HEADING` 认出 →
**联网材料的 `heading_path` 不再恒空**（现在恒为 `()`），而 `heading_path` 是索引源
（`index_source` = 标题 + 章节链 + 正文）的一部分 → 检索质量顺带提升。

**两个连带修改（必须一起做，否则账本被污染）**：

- `render_web_results` 现在取 `parsed.chunks[0]`（`context.py:1230`）——假设"一结果一块"。
  一结果多块时**同一段文字会挂在两个编号下重复渲染** → 改成按块渲染。
- `web_block_cost` 用 `chunk.text[:WEB_SNIPPET_CHARS]` 算成本（`context.py:1124`）——
  渲染与成本必须同源（那把尺子的原话）→ 同步改成按块算。

**决策（作者拍板）**：联网块**整块进提示词**（不再截 300 字），由 `WEB_BUDGET` 决定能带几条。
可见后果：每轮进的联网结果**从 ~3 条降到 ~1–2 条**，但每条信息量从 300 字变成 ≤500 字。

### 2.3 清洗与归一（新增 `infrastructure/tools/webclean.py`，纯函数）

| 做什么 | 为什么 |
|---|---|
| 去掉 `[...]` | Tavily 自己的省略标记，不是内容 |
| 全角空格 `　` → 半角 | 法条原文排版空格，会干扰 2-gram 与分词两侧的一致性 |
| 空白归一（连续空白折叠、行尾去空） | 现在只有 `.strip()`，行内空白不动 |
| 剥 Markdown 表格分隔行（`\| --- \|`） | 表格骨架不是内容；表格**内容行保留**（那是有信息的） |
| Markdown 标题符（`## `）**保留** | 是内容的一部分，且给检索更多 token；同时被 `_HEADING` 用来生成 heading_path |

**不做**：主内容抽取（readability/trafilatura）——那是"抓网页"那条路的活，本批不含。

### 2.4 两层去重（新增 `infrastructure/tools/webdedup.py`，纯函数）

| 层 | 判据 | 阈值 | 数据依据 |
|---|---|---|---|
| 字节级 | 清洗后正文的 sha256 | 精确 | 抓"逐字相同"（真集 recall 0.061、precision 1.000） |
| 近重复 | 精确 5-gram Jaccard | **≥ 0.2** | 精度 1.000、recall 0.159（0.55 只有 0.084） |

- **不引 datasketch/scipy**（§1.4 第 1 条）。
- **粒度：文档级**（§1.4 第 3 条）——比的是材料的全部块拼成的文本。
- **作用域：批内**（这一批联网候选之间）。不与项目里已有材料比：
  那需要给 `MaterialStore` 加一个读块文本的端口（`MaterialStore` 现有协议
  `put/get/raw_bytes/list_for_project/count_for_project/find_by_sha/chunk_count/delete/replace_chunks`
  都没有），且实测真实近重复率低（recall 0.16）——收益撑不起扩端口的成本。
  入口设计成纯函数、日后要扩到跨语料只加一个"已有文本"参数即可。

### 2.5 Tavily 深度：basic 与 advanced 都跑，用数据定

同一批判据（入库保留率 / 去重前后条数 / 块数 / 检索命中）跑两档，用数字决定。
**不做二选一的先验判断**——去年我们就是这么栽的（当年用 readability 测，测的是最差的那个）。

## 6. 已知风险与诚实声明

1. **嵌入口径（#3）尚未定** —— 用 bench 量两种口径再定。若改索引侧，**已有向量全部作废**
   （需要口径版本 + 全量重算），这一步有真实成本。
2. **量化判据用的仍是合成/弱标签语料** —— 真库 0 份材料，没有真实用户查询分布。
   这条与批 5 的诚实声明同源。
3. **联网结果进提示词的条数会变**（~3 → ~1–2），这是**可见的行为变化**，
   靠预算而不是靠截断控制。收益（每条信息量翻倍）与代价（条数减少）都要认。
4. **去重的真实收益有限**（真集 recall 0.16）——它抓的是"抽到了同一段"的重复，
   不是"同一主题"。但 precision 1.000，误杀风险低。
