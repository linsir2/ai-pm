## 0. 影响分析与执行范围

### 0.1 一句话说清病根

**入库层与使用层的职责被混在一处**（上传材料早就是分开的：整份入库 → 预算层挑）。
联网这条链没分开，于是：入库时截 300 字（实测 Tavily 给 568–2302 字，**扔掉 50–78%**）、
**联网材料不写向量**（搜来的材料搜不到）、成本与渲染都按"一结果一块"写死。

外加**三个确定性错误**（与病根无关，先修）与**一个模型侧硬约束**（512-token 静默截断）。

### 0.2 影响面（改哪些、影响谁）

| 层 | 受影响的 | 后果 |
|---|---|---|
| 材料检索 | `SqliteHybridRetriever` 的 `score` 数值 | 第一名现在拿最小分，与注释相反。**次序不变**（消费方 `dto.py:780` 不重排） |
| 向量索引 | 所有已存向量 | 口径从"分词串"改成"自然语言" → **旧向量全部作废**，需版本标记 + 一次性重算 |
| 联网入库 | Tavily 结果 → 材料 | 不再截 300；改按 ≤400 字切块；**heading_path 不再恒空**（Tavily content 里的 `## 标题` 被 `_HEADING` 认出） |
| 联网去重 | Tavily 结果批内 | 字节级 + 5-gram Jaccard ≥0.2 |
| 提示词 | 联网结果那一段 | **每轮进的联网结果从 ~3–5 条降到 ~1–2 条**（每条从 300 字变 ≤400 字，标题+URL 只算一次） |
| 账本 | 联网结果的 `external` 出处 | 一个结果一个 E 号（今天也是一个，但那时只有一块，恰好相同） |
| **不动** | 上传材料、抓网页（fetch）、轮内选块、文档/记忆层、模型侧 | 全部一字不改 |

### 2.2 联网结果的数据流（改前 → 改后）

```
改前：Tavily content（568–2302 字）
        └─ .strip() → 截 300 字 → 1 块（heading_path=()、anchor="网页摘要"）
             └─ 入库（不写向量）→ 选块（按块）→ 渲染 chunks[0]（截 300）
             ⇒ 库里只有前 300 字；向量里没有它；F6 搜不到尾部

改后：Tavily content
        └─ normalize（去 [...]、全角→半角、空白归一、剥表格分隔行）
             └─ chunk_text(≤400 字) → 1..N 块（heading_path 有值、anchor="第 N 段"）
                  └─ 入库 + 写 FTS + 写向量（自然语言口径）
                       └─ 选块（整条结果为单位）→ 每条结果一个 E 号
                            └─ 渲染：标题+URL+全部块正文
             ⇒ 库里是全文；向量覆盖全文（每块 ≤512 token）；F6 能搜到尾部
```

**为什么联网块宽是 400 而不是 500**（实测依据）：
bge-small-zh-v1.5 的 `model_max_length = 512`，中文 **1 字 ≈ 1 token**（实测 500 字 = 502 token）。
`index_source` = 标题 + 章节链 + 正文 → 500 字正文 + 标题/路径 ≈ 520–560 token **超 512**，
而**超出的尾部对向量完全不可见**（实测 `embed(700字)` 与 `embed(前510字)` 余弦 **1.000000**，
尾部加独特标记词向量**完全不变**）。取 400 字留出标题/路径/特殊 token 的预算。

**为什么不是「整段一块」**：那样 1400 字只有前 512 字进向量（**丢 37%**），2302 字丢 **78%**——
而联网材料恰恰是"换个说法"价值最大的（用户不知道它长什么样）。

### 2.3 embed 口径（改前 → 改后）

```
改前：索引侧 embed( index_source(...) )   ← jieba 分词后的空格串
      查询侧 embed( 原始 query )
      ⇒ 两侧形态不同；分词串把自然语言退化成词袋，bge 的语义优势被抹掉一半

改后：索引侧 embed( 标题 + 章节链 + 正文 )  ← 自然语言，不分词
      查询侧 embed( 原始 query )
      ⇒ 两侧同形态（业界一致做法）
      实测：改述类 recall@5 34/40（85%）→ 38/40（95%）
            同期"假 embedder"对照组几乎不变（1/2）⇒ 证明是口径削弱了真模型
```

**代价与对策**：口径变了旧向量就是脏的。`migrate()` 加**口径版本**：
版本不符 → **清空 vec 表 + 全量重算**（ONNX ~20ms/块，单用户几百块 = 几秒，一次性）。

### 5.1 方案自洽性检查

| 检查项 | 结论 |
|---|---|
| 有没有引入新契约/新端口？ | **没有**。只加了一个 `select_chunks` 的可选参数和一个 `webclean`/`webdedup` 纯函数模块 |
| 有没有造轮子？ | **没有**。切块复用 `chunk_text`；向量复用 `SqliteVectorIndex.write`；去重用标准库集合运算 |
| 有没有和既有决定冲突？ | 查过：① 轮内选块仍用 2-gram 粗排（`context.py:1096` 的"语义被证据否决"不在这批推翻）② 块宽不变式守住（联网另用 400）③ 账本语义守住（E 号的正文 == 提示词里那段） |
| "一个结果一个编号"和"多块"矛盾吗？ | 不矛盾：ref 只加一个（指第一块，供跳转与"被引用过"判定），**渲染从 packet 的全部块拼**——不依赖 ref 还原正文 |
| 512-token 截断处理了吗？ | **处理了**：联网块宽 400（正文+标题 ≈ 460 token < 512）；上传材料的 500 字块**本批不动**（那是既有状态，且 FTS 路看全文） |
| 每个 Task 都能独立验收吗？ | 能：Task 1/2/3/4/5/6/7 各有独立红→绿；Task 8/9 是端到端判据 |

### 5.2 最终形态推演（按计划做完，末态是什么样）

```
库里：46 条真观察 + 用户上传的材料（多块，heading_path 完整）
    + 联网材料（多块、清洗过、heading_path 有值、有向量）

F6 搜索：搜「背板槽位」→ 命中（词法）
         搜「网线要接到哪里」→ 命中（语义，联网材料也在内）

起一轮：分析者提名联网检索词 → 勾选 → 真 Tavily → 5 条结果
        → 清洗 → 切块 → 去重（URL 级 + 批内字节/近重复）→ 入库 + 写向量
        → 按 Tavily 原序整条进预算（WEB_BUDGET=2000）→ 1~2 条结果带编号进提示词
        → 提示词里：[E12] 标题\nURL\n<该结果的正文>（标题URL只一次）

账本：联网结果一条 E 号，text == 提示词里那段；点编号跳到该结果第一块
向量：口径 natural-v1；口径变了自动清表重算
```

**推演中发现的三个必须处理点**（已落进 Task）：
1. 一个结果多块 → 渲染不能只取 `chunks[0]`（Task 7 的第 3 条红测试）
2. 成本要按结果算，不能按块（否则标题URL重复计，预算只够一条）（Task 7 第 1 条）
3. 账本 E 号的正文必须等于提示词里那段（否则"发号却没进提示词"）（Task 7 第 4 条）

### 5.3 已知风险与诚实声明

1. **embed 口径改动会让已有向量作废**（一次性重算，几十秒）。这是本批最大的**不可逆**动作。
2. **量化判据仍用合成/弱标签语料**（真库 0 份材料）——与批 5 同一限制。
3. **联网结果进提示词的条数会变**（~3–5 → ~1–2），**用户可见**。
4. **去重的真实收益有限**（真集 recall 0.16）——它抓"抽到了同一段"，不抓"同主题"。
5. **抓网页的 HTML 正文抽取仍未做**（当年测的是 readability，业界榜单最差的那个）——**另起一轮**，
   建议先建我们自己的页面集基准再动。
