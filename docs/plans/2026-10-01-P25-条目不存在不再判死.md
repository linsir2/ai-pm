# P25 方案 · 「要改的条目不存在」不再判死整轮

> **给执行的 agent**：按任务顺序做，一个任务一次提交；先写红测试 → 跑到红 → 再实现 → 再跑绿。
> **除非测试本身写错（要说明错在哪），不许改测试迁就实现。** 产品代码里不许有假实现。

**Goal**：`replace` / `remove` 指到不存在的条目时，**丢那一条 + 留痕**（与"去处写错"同一件），
不再让整包两次过不了校验、整轮降级；并堵住由此暴露的 409 洞。

**Architecture**：两处改动，都在既有分层里，不新增端口/端点/字段：
① `application/assembly.py` 的提案循环里加一个谓词分支（丢那一条 + 留痕）；
② `application/use_cases.py` 的第一段循环里加一个守卫（装配后全空 → 报文错 → 重装/降级），
替掉今天会漏出去的 `ShapeError` → HTTP 409。

**Tech Stack**：Python 3.13 · FastAPI · Pydantic v2 · LangGraph · pytest

**Spec**：`.codex/docs/设计/02-编排与数据.md` §11.0.2（去处写错只丢那一条，本次照抄它的口径）
· §11.0.35（整合 lenient）· §11.0.37（归因补交代）· `.codex/runs/2026-10-01/P24验证.md`（现场）

## Global Constraints

- **不新增端点**（`EXPECTED_PATHS` 仍 25 条）、**不改文档 schema**、**不动 domain**；
- **写入路径唯一**：这两处都不碰写入（只影响"哪些提案进草案卡"）；
- **一条都不许默默丢**：丢掉的那条必须进 `Round.dropped`；
- 测试跑法：`cd backend && PYTHONDONTWRITEBYTECODE=1 python3 -m pytest -p no:cacheprovider -o addopts=""`；
  lint：`python3 -m ruff check --no-cache .`。

## 2. 任务

### Task 1 · 条目不存在 → 丢那一条 + 留痕（assembly）

**Files**：`backend/src/pmstudio/application/assembly.py` · `backend/tests/application/test_assembly.py`

- 新增纯谓词 `_entry_target_missing(draft, *, document) -> bool`
  （`op ∈ {replace, remove}` 且 `entry_id` 非空 且 `not _entry_exists(...)`）；
- `assemble()` 的提案循环：命中 → `dropped.append(DroppedItem(handle=f"提案 #{index}",
  reason=f"要改的条目不存在：{draft.entry_id}", source=ASSEMBLY, pass_index=...))` → `continue`；
- `_proposal` 那处 `raise` 保留（同一谓词驱动，规则只有一份实现），注释写清它在 `assemble` 路上不可达；
- **不给 `gaps` 加行**（与"去处写错"一致）。

**用例**：`test_a_replace_with_a_missing_entry_is_dropped_with_a_trace` ·
`test_a_remove_with_a_missing_entry_is_dropped_too` ·
`test_replacing_an_existing_entry_still_works`（不误伤）·
`test_a_replace_without_an_entry_id_is_still_a_packet_error`（不放松）

### Task 2 · 装配后全空 → 报文错（use_cases）

**Files**：`backend/src/pmstudio/application/use_cases.py` · `backend/tests/application/test_integrate_answers.py`

- 第一段循环里，`_assemble_and_gaps(...)` 之后：
  `if not assembled.questions and not assembled.proposals and not assembled.list_items:` →
  抛 `PacketParseError("装配完什么都不剩：题、提案、清单项都没有（等于这一趟没给东西）")`；
- 这样它走既有的"重装 → 仍不行就降级/判死"出口，**同时堵掉空包 409 的老洞**；
- 判据用**装配后**的产物（`_proposal`/`_target_or_drop` 丢掉的都算）——那才是用户真能拿到的东西。

**用例**：`test_a_missing_entry_no_longer_degrades_the_round`（1 次整包调用、到草案、无"两次都过不了校验"）·
`test_a_packet_whose_proposals_all_miss_their_entries_degrades`（降级，不是 409）·
`test_an_empty_packet_still_takes_the_graceful_exit`（空包也不再 409）

## 3. 明确不做

1. 不放松 `replace`/`remove` **缺** `entry_id`（字段缺失不是笔误，它在 `_WRITE_SEMANTICS_FIELDS` 黑名单里）；
2. 不新增端点/字段/事件，不动 domain，不动 P24 的小调用机制；
3. 不引入相似度、不猜"它本来想改哪一条"。
