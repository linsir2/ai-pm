## 3. 顺带修的两处（算核验的一部分，不算加戏）

### 3.1 网关：回包"不是 JSON / 是空的"原来没有留痕

T0 的第一次基线没跑完就崩了：`ModelCallFailed: 模型没有按约定返回 JSON`。
想查为什么时发现——这两条路（回包不是 JSON / 空回包）一行都不落库，`model_calls` 里
连"模型回了什么"都没有（留样开着也白搭）。

改（`litellm_gateway.py`，两条路各加一次 `_record`）：回包原文（取头部）、`usage`、
`finish_reason` 一并记下；错误写成 `NonJsonReply: …（finish_reason=length，开头：…）`、
空回包写成 `EmptyReply: …`。行为一个字没改（照旧抛 `ModelCallFailed`、照旧按失败处理）。

### 3.2 eval 驱动：失败也要能"接着跑"

产品本来就支持续跑（`Round.resume()` + `POST /retry`，用户在界面上就是点一下继续），
但驱动只会把异常往外冒 → 整条用例记成"崩溃"，连 `failure_reason` 都看不到。

改（`backend/scripts/eval.py`）：① 动作失败时接住，用 `get_round` 把这一轮读回来
（`start` 那次用 `list_rounds` 找最新一轮）；② 看到 `step=failed` 就点一次继续，
最多 2 次，每一次都在日志里打 `[重试] …`（不静默）。断言照旧跑在最终视图上。
——与 P33 那条同一个道理：能力在，缺的是驱动那一环。

### 3.3 由 3.1 查出来的 F34：输出被截断在 8192

留痕一开，真相立刻可见：整合那一步的回包是从头像 JSON、在 21.7K 字符处断在半句上的。
一次干净的实验（`.codex/runs/2026-10-03/M3调研/probe_max_tokens.py`，同一句提示词发两次）：

| params | `finish_reason` | `completion_tokens` | 结果 |
|---|---|---|---|
| `.env` 原样（`extra_body.enable_thinking=false`） | `length` | 8192 | 截断 → 不是合法 JSON |
| 加 `"max_tokens": 16384` | `length` | 16384 | 上限确实抬上去了（这次是故意要 3 万字） |

→ 默认输出上限就是 8192；`edge-external-facts` 这种长输入的整合回包（21.7K 字符）撞死在这里，
而 `edge-contradiction` 那种小输入不会撞。杠杆是一行配置（`PMSTUDIO_MODEL_PARAMS` 里加
`max_tokens`），不动代码。本条记 `04` G10 的 F34。
