## 1. Goal

右栏第二页签从「过目台」升级为「灵感箱」：讨论聊出来的卡与调研带回来的候选在同一处过目，
**收下为下一轮输入（种子）/ 收下为材料 / 忽略 / 就这条聊聊**；标签带未处理数徽标。

成功判据（都可验）：

1. 统一箱视图：两个投影（`ThreadView.cards` + `ExplorationView.candidates`）合并渲染，
   未处理数 = 可动作条目数，收下/忽略后条目消失、数字减一；
2. 双处同动作：同一张卡在讨论 tab 与箱里都能收种/收料/忽略，同端点同状态；
3. 真模型端到端：收卡为种 → 起轮 → `Round.seeds` 落 `SeedRef(origin=discussion)` 回链；
4. 老链路不回归：调研候选 keep/seed/material/dismiss、讨论 say/总结/关线程照旧；
5. 全量绿：后端 pytest+ruff、前端 vitest+tsc、parity、openapi 冻结 40 条路径。

## 2. Architecture

```
讨论线程（M9）                       调研趟（M8）
 ThreadView.cards[]                  ExplorationView.candidates[]
  state ∈ new|kept|dismissed           state ∈ new|kept|dismissed（已有）
        │                                     │
        └──── 前端 state/inbox.ts 合并 ───────┘
                       │
                灵感箱（LoopColumn 第二页签）
                 收下为下一轮输入 / 收下为材料 / 忽略 / 聊聊
                       │
   ┌───────────────────┼───────────────────────────┐
   ▼                   ▼                           ▼
POST …/cards/{id}/keep POST …/cards/{id}/dismiss   聊聊 = 锚点 + 切讨论 tab
 {as: seed|material}   （终态幂等）                 （不写库）
   │ seed：不落材料，只盖 kept_as=seed
   │ material：合成材料（origin=discussion，SIMULATED）
   ▼
前端成功才预填输入框（seed）+ 记 pendingSeeds=["discussion:线程#卡"]
   ▼
起轮 POST /rounds {seed_ids:["discussion:d-1#C1"]}
   → _resolve_seeds 验「同项目 + state=KEPT + kept_as=seed」
   → Round.seeds=[SeedRef(origin="discussion", ref_id, item_id)]（回链）
```

**设计要点**：箱是**视图不是存储**——不加表、不加 GET、不加事件（keep/dismiss 与 M8/M9
同口径：响应体即真身）；卡片状态挂在 `Thread` 聚合的 `Card` 上（与候选同构，破 T5 走 409）；
种子 id 统一成 `来源:id#条目id`（与材料 `external_ref` 的既用前缀同构）。

## 3. Spec

### 3.1 领域（T5）

- `Card` + `CardState{new,kept,dismissed}` + `kept_as ∈ seed|material`（`kept_ref` 保留）；
- `keep_card(card_id, *, as_, material_id=None)`：幂等同去向、**不许改去向**、忽略过的不能再收、
  `material` 必须带 id；**不判 open**（T1：收下是回流不是聊天）；
- `dismiss_card(card_id)`：已收不许忽略；幂等；
- `SeedRef{origin, ref_id, item_id}`（origin ∈ exploration|discussion）；
- 不变式 `T5`；错误 `CardNotReviewable`（`invariant:T5` → 自动 409）。

### 3.2 应用

- `KeepDiscussionCard(as_)`：`seed` 不合成材料只盖章；`material` 走原链；
  同去向早返（不再合成/写信）；不发事件（响应即真身）；
- 新 `DismissDiscussionCard`：uow 内 dismiss + save；
- `StartRound` + `discussions: DiscussionReader`；`_resolve_seeds` 解析统一格式，
  discussion 分支验「线程存在（404）/ 同项目 / 卡存在 / state=KEPT + kept_as=seed」。

### 3.3 序列化（不加 USER_VERSION）

- 讨论 payload：卡片状态用稀疏映射 `states` / `kept_as` / `kept_ref`（照探索口径，
  只存非默认）；老 `kept` map **只在读侧**兼容（有 ref = kept/material）；
- 轮次 seeds：写 `{origin,ref_id,item_id}`；老两键行读回 = exploration 来源。

### 3.4 API（端点 39 → 40）

- `POST /discussions/{id}/cards/{card_id}/keep` 改收 `{as}`（`KeepRequest`，与候选端点共用；
  原 `KeepCandidateRequest` 改名）；
- 新 `POST /discussions/{id}/cards/{card_id}/dismiss`；
- `CardView` + `state` / `kept_as`；`StartRoundRequest.seed_ids` 注释改统一格式。

### 3.5 前端

- 纯函数：`state/inbox.ts`（`inboxCards` / `inboxCount`）；`discussions.ts` 的
  `cardActions` / `cardStatusText` / `cardSeedText`（`cardKeepable` 退休）；
  `explorations.ts` 的 `tray*` 更名 `review*`；`api/payload.ts` 加
  `explorationSeedId` / `discussionSeedId`（种子 id 唯一构造点）；
- 组件：`ExplorationTray` → `InboxTray`（新增「讨论里聊出来的」卡组 + 聊聊）；
  `DiscussionTray` 卡区三动作 + 状态文案；`LoopColumn` 标签更名 + 徽标 + 聊聊切 tab；
  动作词统一 `labels.ts` 的 `REVIEW_ACTION_TEXT`（候选的「删掉」并入「忽略」）；
- 数据流：`useWorkspaceData.keepDiscussionCard(id, cardId, as)`（成功才预填）、
  `dismissDiscussionCard`、`addSeed(seedId, text)` 泛化；事件不动。

## 7. 执行中发现（先于本批的 bug）

**`.prop` 网格的单一子元素误用**：`.prop` 是 `52px 1fr` 两列网格（为"侧栏 + 内容"设计），
而 M6b 的记忆行、M8 的候选卡、M9 的卡都是**单子元素**用法——子元素落进 52px 列、
正文被压成一字一行；这些面从未被截图清点，一路带到 M12 灵感箱截图才暴露。
修法一条根源规则：`.prop > :only-child { grid-column: 1 / -1 }`（已随手修，入 `learnings.md` L23）。
`MemoryDrawer` 的"内容 + 删除按钮"两子元素用法按同一机制推定同样错位（内容进 52px 列）——
副本库没有记忆条目、这轮没能截图实证；**未在本批处理**（不属 M12 面），已记在这里留待另排。
