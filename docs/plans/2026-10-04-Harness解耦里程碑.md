# Harness 解耦里程碑

> **执行准则**（作者 2026-10-04 定）：每个里程碑先分析影响面与数据流，再 TDD 实现；
> **除测试本身写错外不许改测试断言**（只允许改 import 路径）；不写假实现；
> 每步跑全量 `pytest` + `ruff` 验证，最后逐文件回写说明。

**目标**：把"模型能力"从应用层里解耦出来，落成独立的 `harness/` 运行时控制平面，
让分层可被守卫强制，而不是靠约定。

**判据（贯穿全篇）**：

1. **模型能力 = 只因为"模型会胡说八道"而存在的代码**；周边设计 = 只因为"产品经理要写产品文档"而存在。
   物证：`tests/support/doubles.py` 的 `ScriptedModelGateway` 只依赖 `ModelRequest` / `ModelReply` /
   `ModelCallFailed` 三个符号就能跑通全流程（1103 条测试）。
2. **零业务词 ≠ 属于 harness**。判据是「运行时控制平面需不需要它」。
   因此 `infrastructure/tools/{extract,office,fetch,tavily}.py`（950 行）、`bootstrap/settings.py`、
   `api/sse.py`、`infrastructure/sqlite/unit_of_work.py` **不搬**——它们是应用工具实现 /
   应用配置 / 传输层 / SQLite 细节，搬进去就是为通用而通用。
3. **只搬不抄，不留兼容层**：旧路径 `git rm`，全仓唯一真相源。允许改测试的 import 路径，不许改断言。
4. **按扇出从小到大**：零依赖模块先搬；`domain/shared/{ids,errors,target,writing}.py`
   是全仓最热节点（41/25/13/15 处 src 引用），一律不从它们下手。

**依赖图**：`M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7`。
M0 必须最先：否则新层会落在三条守卫的盲区里（见下）。

## M4b · 重试判据按类型判 + 测试打桩去腐化（2026-10-04 执行）

### 根因（不是"忘了接线"，是"两套权威做同一个决定"）

`TRANSIENT_HINTS` 里有一项叫 `"internalservererror"`（**无空格**）——这说明旧口径早就在
匹配异常**类名**了，因为网关传进去的是 `f"{type(error).__name__} {error}"`。
**类型名本来就在被匹配的字符串里，只是被当成匿名子串匹配。** 而子串匹配双向都不可靠：

| 方向 | 实例 | 旧口径的错 |
|---|---|---|
| 假阴性 | `ServiceUnavailableError: upstream overloaded` | 真的 503，**不重试，直接判死** |
| 假阳性 | `JSONSchemaValidationError: schema mismatch, expected 500 items` | 裸 `500` 命中，**白重试 3 次** |
| 假阳性 | `BadRequestError: InvalidParameter: maxItems 500 exceeds limit` | 同上，约 4 秒 + 3 行无用留样 |

而 litellm **早就是把 HTTP 状态码归一化成了异常类型**（从 `.venv/.../litellm/exceptions.py`
逐类抄出 30 个）。所以根修是：把"已经在被匹配的类名"提成显式类型表。

### 改了什么

1. **`failure.py` 加五张类型表**（`_TIMEOUT_TYPES` / `_TRANSIENT_TYPES` / `_QUOTA_TYPES` /
   `_POLICY_TYPES` / `_VALIDATION_TYPES`）+ `classify_type(names)`：认**类名集合**，沿 MRO 判。
   - **按类名而不 `isinstance`**：让 `failure.py` 不绑定 litellm 这家 SDK（openai/httpx 的
     同名类也认）。代价是表会漂移 → 由对齐守卫盯着。
   - **顺序有讲究**：配额先于抖动（额度用完常被当 429 限流发下来，退避解决不了）；
     **校验先于抖动**（`BadRequestError` 沿 MRO 带着 `APIError`，而它在抖动表里）；
     策略先于校验（"被拒绝"比"请求有问题"更具体）；结构化拒收提示**在类型表之前**
     （qwen 两分钟抖动是真跑证据）。
   - `is_transient` **降为私有** `_message_says_transient`。公开它就会有人拿它当第二个判据，
     根因就又长回来了。
2. **网关**改调 `failure.classify(error).retryable`；删掉 `is_transient` 转发。
3. **`LiteLLMGateway.__init__` 加 `sleeper` 注入口**（默认 `asyncio.sleep`，生产路径不变）。
4. **测试打桩去腐化**：25 处 `monkeypatch.setattr("点分字符串", ...)` → 21 处改模块对象
   `monkeypatch.setattr(provider_module, "acompletion", ...)`；4 处全局 `asyncio.sleep`
   打桩 → 改注入 `sleeper`。

### 行为变化（回归 0，修正 3）

用真实 litellm 类型 + 13 条真实消息形态实测：**回归 0，修正 3**（假阴性 1、假阳性 2）。
未变：结构化拒收要重试、参数写错立刻失败、认证失败不重试、上下文超限不重试、配额不重试、
无类型异常（`RuntimeError("503")`）仍走消息兜底。

### TDD 与验证

`CROSS_CORPUS` 那 5 条在接线瞬间转红——**它本来就是为这一刻设的警戒线**，
断言从"两套口径相反"翻转为"不再相反"，防回退。

绿灯：**1401 passed**（+26）、`ruff` 零告警。新增守卫

### M4b 补 · 类型表绑定 litellm（2026-10-04，作者拍板）

先前按"类名 + 沿 MRO 匹配"是为了让 `failure.py` 不绑定 SDK。**作者拍板改为绑定**，
理由成立：按类名那张表是**手抄**的——litellm 改个类名它就静默失效，退回消息兜底，
于是本轮要修的"确定性失败被当成抖动"换个马甲再来一次。绑上之后：

- **改名变成导入期就报错**，漂移无处可藏（这是绑定的核心价值，不是"更精确"）。
- `isinstance` **天然覆盖子类**，表里不必列 `MidStreamFallbackError`、
  `ImageFetchError`、`LiteLLMUnknownProvider`、`VectorStoreSearchError`——
  它们自动跟着基类走（实测已核）。
- 实测 30 个 litellm 异常类：transient 7 / validation 12 / policy 6 / quota 1 /
  timeout 1 / 未分类 3。阶梯顺序仍关键：`ContentPolicyViolationError` 是
  `BadRequestError` 子类，靠"策略先于校验"拿到 POLICY 而不是 VALIDATION
  （行为等价但归类正确）；`BadRequestError` 沿 MRO 带着 `APIError`（在抖动表里），
  靠"校验先于抖动"不被当成抖动。
- **未分类 3 个，各有理由**（守卫会盯）：`MockException`（litellm 自测替身）、
  `ModifyResponseException`（没挂 response hooks，走不到）、`OpenAIError`
  （openai 根基类，也是认证类祖先，收进任何表都会一锅端）。

**测试从替身改成真实类型**：原先用同名本地替身类（因为按类名匹配时代替身能命中）。
改成 `isinstance` 后替身不再命中——这正是要的：**测试必须跑在真 SDK 类型上**，
否则"表和 SDK 脱节"只有生产才会暴露。代价是这些异常要 2~4 个关键字参数
（`message`/`model`/`llm_provider`），另有两个签名特殊：
`BudgetExceededError` 要 `current_cost`、`PermissionDeniedError` 的 openai 基类会去读
`response.request`（不能给 `None`，得造真的 `httpx.Response`）。

**顺带修掉一个隐患**：`LITELLM_LOCAL_MODEL_COST_MAP` 原先只在 `providers/litellm.py` 里
设，而 M4b 之后 `failure.py` 也 import litellm——谁先被导入是不确定的，落到
`failure.py` 那条路就会去**网上拉价目表**（实测 9.3 秒且依赖网络，设了 3.4 秒）。
已提到 `harness/model/__init__.py`：Python 保证子模块导入前先跑包 `__init__`，
放哪个具体模块里都不够。

## M6b · CancellationToken —— **取消**（2026-10-04，作者拍板）

原计划：把 `graph.py` 的"整轮 `task.cancel()` + 5s wait"换成 token 向下传播。

**取消理由**：
1. **撞既有守卫**——`test_graph_state.py:5` 硬断言
   `RoundState.__annotations__ == {"command", "round_id", "view"}`。把 token 放进图状态
   就违反"state 只放引用、不放业务状态"这条（`05 §7`：真相源永远是 Round 聚合）。
   要下传只能走闭包 / contextvar / 每节点自查——三条都比现在复杂，且都不在状态里。
2. **零功能收益**——`cancel()` 现在 6 行，注释还专门解释了为什么用 `asyncio.wait`
   而不是 `wait_for`（后者超时会**再取消一次**，那不是帮忙）。
3. **碰真跑验证过的路径**——`abandon` 那条"先写 abandoned、再取消"的口径是真跑踩出来的，
   为一个零收益的重构去动它，风险不对等。

**保留现状**：取消只在 `RoundCanceller.cancel()` 一处，写法（`task.cancel()` +
`asyncio.wait(timeout=5)`）已有注释说明取舍。若将来出现"要取消其中一步、而不是整轮"的
真实需求，再按那个需求设计——**不要为 imagined 需求预留抽象**。
