# 检索重构 · 子任务评审方案

> 配套：`docs/plans/2026-10-24-检索重构-实施计划.md`（v2）
> 用途：每个 Task 交付后、每个 Phase 收口前，按本方案评审。**评审不过不进下一个 Task。**

---

## 0. 评审分层

| 层 | 谁评 | 频率 | 产出 |
|---|---|---|---|
| L1 机器门 | CI/本地命令 | 每个 Task | 命令输出（贴进交付报告） |
| L2 契约评审 | 独立子智能体（只读 diff） | 每个 Task | Critical/Nit/Optional + file:line |
| L3 红线评审 | 独立子智能体（只读全链） | 每个 Phase | 四条红线逐条结论 |
| L4 作者验收 | 作者 | 每个 Phase | 拍板/打回 |

**L2 与 L3 必须由不同子智能体做**：同一个 agent 先写后审会自洽。

## 2. L2 契约评审（每个 Task 固定 10 问）

评审子智能体提示词：

```text
只读审查 <git diff 范围>。按 Critical / Nit / Optional 输出，每条带 file:line。
逐条回答：
1. 这个 Task 的 R（契约）测试是否覆盖了新字段/新端点/新状态机的**形状**与**默认值**？
2. I（行为）测试是否有**反例**：预算超限、幂等、失败降级、边界状态？
3. P（生产）测试是否真的用了真 SQLite/真检索器/真账本？有没有"假实现绿"？
4. R2（回归）是否覆盖了老 payload、老轮、旧调用方？
5. 有没有新增第二真相源（同一事实存两处）？
6. 有没有静默降级（失败只 warning、不经 Round.dropped/可见状态）？
7. 新字段/新常量是否进了 `02 §11.0.90`、DTO、序列化、前端类型？
8. 新文件是否进了 `05-DDD架构.md` §8 目录图？
9. 是否有"说不清作用"的新函数/新参数/新枚举值？有就指出并建议删。
10. 改动是否只碰了本 Task 的文件？有没有顺手重构/格式化噪音？
不要改代码；只报问题。
```

**判定**：出现任一 Critical → 本 Task 打回；只有 Nit → 修完再进下一 Task；Optional → 记录，不阻塞。

## 3. L3 红线评审（每个 Phase 一次）

四个子智能体可并行，各查一条，互不复用上下文：

| 红线 | 查什么 | 反例 |
|---|---|---|
| R1 AI 不写文档 | 新用例有没有 `DocumentWriter`；写入路径白名单是否仍只有 `ProposalCommitter` | `test_write_path.py` 白名单变了 |
| R2 编号只由账本发 | 有没有手拼 `E{n}`、有没有绕 `ledger.record` | trace/DTO 里出现 eid；`evidence_id()` 在用例层被直接调 |
| R3 编号 == 进过提示词的块 | `Round.materials` 的每个 chunk 是否至少进过一次 `PreparedContext.text`；web 是否仍一条一个号 | 入池即发号；web 块被 `render_materials` 渲染 |
| R4 模型/外部调用在事务外 | `prepare`/检索/联网/研究是否在 `with uow` 外；落库是否一次 UoW | 在 UoW 里调 `retriever.search`/Tavily |

**判定**：任一条不通过 → 整个 Phase 回滚，不进入下一 Phase。

## 4. 按 Task 类型的专项检查

### Domain（0.1/0.2/3.1）
- 不 import 任何外部包（`test_domain_imports.py`）。
- 值对象 `frozen=True, slots=True`；`__post_init__` 只校验不变量，不做 IO。
- 新增字段默认空；`round_to_payload`/`round_from_payload` 往返；老 payload 无键可读。
- 方法名不与既有撞（评审时 grep 全仓）。

### Application（2.1/2.2/2.3/2.5/2.6/3.2/3.3/4.2）
- 依赖方向：`application` 不 import `infrastructure`；工具用协议。
- 纯函数（`build_stage_query`/`select_projection`）不碰 IO、不读时钟。
- 事务：读与模型/检索在 UoW 外；写一次 UoW；trace 与材料同事务。
- 失败：检索/联网/研究失败不判死整轮，但必须进 `Round.dropped` 或 `WebRequest.state=failed`。
- 幂等：同 `(stage, pass_index)` 不重查、不重发号；重入测试必须有。

### Infrastructure（1.1/2.0/4.1）
- 实现协议签名与协议逐字一致；换实现只改 `container.py` 一行。
- 不 import `api`；不把 SDK 泄漏进 `harness`。
- 真子进程/真 SQLite 至少一条。

### API（1.3/3.3/4.2）
- 端点必须带 `CurrentUser`（`test_route_identity.py`）。
- 新端点进 `EXPECTED_PATHS`；错误码进 `CODE_STATUS`。
- 轮内动作走 `RoundRunner`（同一把轮锁）；外部调用在 UoW 外。
- 老请求体兼容（`web_queries` 字符串数组）。

### Frontend（1.4/2.8/3.4/4.3）
- 组件不做业务判断：可见/可用/文案/默认勾选全在 `payload.ts`/`progress.ts` 纯函数。
- 纯函数单测覆盖：disabled 的每一种 reason。
- `round.updated` 只推进度 + 置 `roundStale`；不新增 seq。
- 键盘/ARIA：主按钮是 option，次按钮普通焦点；Esc/Enter 不吞。

### Prompt（2.7/3.2/4.2）
- 静态槽在前、动态槽在后（`test_prompt_slot_order.py`）。
- 新槽位必须同时进模板与 `definitions.py` 的槽清单。
- 文案不许出现"像编号的非编号"；web 申请必须写"只提名、不执行"。

## 6. 评审失败的处置

1. **Critical（红线/数据不一致/编不过）**：当场修；修完重跑 L1+L2；不许"下一 Task 一起修"。
2. **同一 Phase 出现 ≥2 个 Critical**：暂停实现，回写计划（说明哪条假设错了），作者拍板后再继续。
3. **Nit**：本 Task 内修；修不完记进 `04-未决.md`，不许静默带走。
4. **Optional**：记进 `04-未决.md` 的 §0.5（工程欠账），不阻塞。
5. **评审与实现冲突**：以"四条红线 + 现有设计文档"为准；评审子智能体不拍板，作者拍板。
