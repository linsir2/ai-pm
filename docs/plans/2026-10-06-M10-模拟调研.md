# M10 模拟调研（待验证假设）设计（2026-10-06）

> 状态：设计已过三节（§1 落点数据流 / §2 产物机械筛 / §3 入口上限测试，用户逐节拍板）。
> 下一步：用户审阅本文档 → writing-plans 拆 TDD 任务 → 实现。
> 先前材料：`.codex/runs/2026-10-06-生态目标设计归档/`（D1 报告/自举实验/拍板原话）。

## Goal

给 PM Studio 加"模拟调研"：AI 扮演潜在用户做一次性推演，产出**待验证假设**
（处境切片 → 走向分叉 → 假设 → 盲区），勾选后走材料通道回流。解决"写文档前
没想到"的风险，不解决"想错了"的风险（模拟降"没想到"，不降"想错了"）。

非目标：不提供真实用户数据；不做人口学画像；不出数字/排序/报告；不自动写文档。

## Architecture

- **落点**：轮内动作（与 `dig` 同级），不是新聚合、不是 Exploration 容器。
  `RunSimInquiry` / `KeepSimInquiry` 两个用例，**不注入 DocumentWriter**，
  不改 `Step` / `LEGAL_ADVANCES`，只借 `RoundRunner` 动作锁与 `abandon` 取消。
- **数据流**：`POST /rounds/{id}/inquiries` → 一次结构化调用（`purpose="sim_inquiry"`——
  M8 的 inquirer 已占 `inquiry`，留样里真调研与模拟推演必须分得开；
  新提示词 `sim_inquiry.md`，重装一圈同 claims）→ 机械筛 → artifact 落 `Round.payload.inquiry`
  （`inquiry_runs` 计数、`inquiry_chosen` 勾选；老行缺键回落空）。
  勾选 → `KeepSimInquiry` 合成**一份** `origin=simulation` 材料
 （`source_ref=simulation:inquiry:<round_id>`，chunks=勾中假设经 `material_synthesis` 公共信封渲染；
 `_material_kind` 加 `simulation→SIMULATED` 分支；`ORIGIN_TITLES` 加 `simulation` 显示标签）。
  下一轮显式带材料 → 发号 `SIMULATED` → 引用它的提案装配层自动降级
  `proposed`（默认不勾；`TERMINAL_KINDS` 不动；`RoundView` 先加 `inquiry` 投影，eval 断言才有落点）。
- **与 exploration 的关系**：只复用"单调用＋重装＋机械筛"的机械，
  不复用 `Exploration` 聚合与过目台容器（真取证 external 与推演 simulated
  住同一容器是分类错误）。
- **上限**：1 调用/点击；`MAX_INQUIRIES_PER_ROUND=2`；
  artifact 3 切片 / 6 假设 / 3 盲区；上限进 `tests/contracts/test_limits.py`。

## Spec

### 产物（`SimInquiryPacket`，与既有包同族，走 `parse_packet_lenient`）

- `SliceDraft{S1..}`：situation（不许身份属性）/ job / trigger / workaround /
  `anchors≥1`（文档/材料 E 编号）。
- `HypothesisDraft{H1..}`：statement（可证伪）/ kind∈{need,workaround,failure,
  opportunity,alternative} / branch / subject∈{end_user_behavior,user_intent,
  market_fact} / grounding∈{document,material,invented} / based_on /
  touches / falsification / evidence_needed。
- `UnknownDraft{U1..}`：statement / why_it_matters / how_to_find_out。
- schema **无 demographic / numeric 字段**（结构性测试钉黑名单）。

### 机械筛（解析后、落 Round 前）

1. anchors/based_on 落不回账本 → 丢条＋留痕（§11.0.2 口径，不判死）；
2. grounding 一致性（document/material 必须有 based_on；invented 必须为空）；
3. 归一化去重（命中文档条目/s11 活跃 → 丢＋计数）；
4. 数字话术（`\d+%|成|倍|占比|比例|多数人|调查显示|数据显示`）或人口学窄词表命中
   → 带指引重装一次，再犯丢条＋留痕；
5. `basis` 缺失，或无假设无盲区 → 整动作失败（502 人话＋`generation.failed`，
   不返回空 artifact，轮次状态不动）。

### 口径红线（5 条，违反即设计错误）

1. 不称真实用户数据/外部事实；2. 只称"待验证假设"；
3. 不自动写/覆盖正式文档；4. 不隐去推演标签（账本 kind=`simulated`、材料 origin=`simulation`），不混同 external；
5. 不称代表性/统计效力（N 个 agent ≠ N 个用户）。
命名保留「模拟调研」，副标题固定「生成待验证的假设，不是用户数据」；
禁用词：受访者/样本/画像/发现/洞察/结论/数据/满意度/占比。

### 入口与测试

- v1 只挂草案卡（按钮「去模拟调研」→ 抽屉渲染 artifact，勾选默认全空；
  keep 后提示"已进材料库，下一轮可在『＋带材料』带上"）。
  选中段落/讨论发起卡/灵感卡是后续，不在 v1。
- 测试：机械筛单测（锚点/去重/数字/人口学/空结果）＋ kind 分支
  ＋上限钉＋OpenAPI 冻结（现 36 条，＋2 → 38）＋写路径守卫
  ＋真模型 eval 5 断言（`grounded/needs_verification/no_quantities` 进默认集；
  `never_terminal/no_demographic_fields` 离线）＋ UI 眼睛一屏。
- 文档同步：`01`（F 清单＋三篇证据落地理由）、`02`（§4.4 加 packet kind、
  §11.0 新节、上限表）、`04`（新拍板条目）、`05`（模块边界）、`06`（入口与文案）。

### v1 明确不做

跨轮语义去重、自动转问卷题/检索词、单假设单材料、N persona 并发、
访谈实录逐字稿、导出独立章节、"足够真实"的任何声明。
盲区只活在 artifact，不经机械通道落文档；不自动写记忆。
