# 右列轻量化（Trae 式：去链子 / 状态行素化 / 答案进流 / 入口去重）实施计划

> 拍板（2026-10-14 问卷）：Q1 改动范围=右列整体轻量化；Q2 链子=删；Q3 问卷答案=变时间线节点；
> Q4 灵感箱=删顶栏入口；Q5 失败态重试=只留状态行。
> 依据：用户四张截图点名 + Trae Work 参考图（一行可折叠 / 发丝线 / 灰字 meta / 单一焦点色）。
> 后端零碰。测试规则：旧用例一字不改（错了才改）；新测先红后绿；被测试消费不算真跑通，关键链真屏验。

**Goal:** 右列从"三层 chrome + 七格链子 + 按钮墙"收成 Trae 式：头部两条薄字 + 无编号时间线 +
答案直接可读 + 一处入口一件事。

**Architecture:** 纯前端呈现层重构。删 `ProgressSteps`/`roundProgress`（唯一消费者）；
新增 `statusText` 纯函数（waiting 优先于 step）；`RoundStatus` 素化并接管 resume 可见性；
`LoopPane` 加「你 · 答过 N 批」节点、整合按钮改条件渲染；`RoundHistory` 挪进头部插槽；
`TopBar` 删灵感箱；`LoopComposer` 删与状态行重复的失败/停滞分支。

**Tech Stack:** React 18 + TS strict + vitest(jsdom) + 现有 tokens。

**Spec:** `.codex/docs/设计/06-前端.md` §2/§4（同步更新） + 本计划。

## Global Constraints

- 后端 45 端点 / DTO / SSE / 纯函数 / parity 45/45 全不动。
- 前端业务判断只在 `state/progress.ts`（`statusText`）/ `labels.ts`（`stepText` 回落）等纯函数，
  组件不新增判断。
- `RESUME_ROUTES`（`backend/.../graph/graph.py:46`）：claims_ready/awaiting_*/done/abandoned 全 → END，
  这些 step 上的「接着跑」是死动作 → 不渲染。
- `answer_sets[].answers` 已是后端 `answer_text()` 渲染的「题目 → 选项；备注」整串 → 直接展示。
- 不提交（仓规）；文档同步进 `06-前端.md`（标日期）。
