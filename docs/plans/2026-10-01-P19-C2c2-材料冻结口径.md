## 1. 现在要实现什么

**Goal：** 让"材料库"这件事**有始有终**——上传进来的材料能删掉、解析器升级后能重读一遍；
而**已经发过编号的材料一律冻结**（编号指向的内容不许变、不许消失），界面在动手之前
就把"能不能动、为什么不能动"写在按钮旁边。

**为什么现在做**：材料是 P17/P17b/P18 一路堆起来的最大的数据面，但到现在**只能加、不能减**
（`MaterialStore.delete()` 写了却没人调用、没有端点）；而"换解析器"这件事作者已经明说要走
（docling），`needs_reparse` 谓词、`stale` 标记、原始字节**三样都准备好了**，就差那一步动作。

**边界**：不做"按主张取块"（C-2c-3）、不做 `web_fetch`/docling 适配（C-2c-4）、
不做"材料重命名/改标题"、不做批量删除。

## 3. 三条口径（必须作者拍板）

### 口径 1 · "冻结"的判据 = **有没有被任何一轮引用过**（不是"有没有被用过一次"）

真相源是轮次 payload 的 `materials[].material_id`。被引用 = 这份材料里**至少有一块**发过
`external` 编号（进了某一轮的提示词）。

**为什么不能按账本反查**：`external_ref` 是 `attachment:<标题>#cNN`（P17 定的），两份同名文件
会撞；标题还可能被改。轮次 payload 里是 `material_id`，唯一、稳定。

**新只读能力**（放 `WorkspaceIndex`——它本来就是"只读查询投影"的家）：

```python
def material_references(self, project_id: ProjectId) -> Mapping[str, tuple[str, ...]]:
    """这份材料被哪些编号引用过：{material_id: (E7, E12, …)}。空 = 没被引用过 = 可以删/可以就地重解析。"""
```

实现：`SELECT payload FROM rounds WHERE project_id = ?` → 逐行 `json.loads` → 收
`payload["materials"][]` 的 `(material_id, eid)`。坏行跳过（与索引层既有口径一致），不抛。

### 口径 2 · 删除：没被引用就能删；被引用就 **409**，并说清是哪些编号

- 没被引用 → 删材料行 + 它的块（`ON DELETE CASCADE` 已有）+ 原始字节。**不可恢复**
  （单用户本地工具，不做回收站；界面二次确认）。
- 被引用 → `MaterialFrozen`（新错误，**409**，与 `round_busy` 同一档"状态不允许"），
  消息写成："这份材料已经发过编号 E7、E12——编号不能回收（那些编号指向它里面的块）。
  留着它，或者用「重解析」再读一份。"
- id 不存在 / 不属于这个项目 → `UnknownMaterial`（**404**，与 `unknown_round` 同档）。

### 口径 3 · 重解析：没被引用就**就地**重读；被引用就**另出一份**（旧的冻结留着）

先定三条分叉：

**(a) 只有"上传的"材料能重解析。** 联网检索回来的材料（`origin="web_search"`）**不给重解析**：
它的"原始字节"就是当时的网页摘要快照，重解析没有意义（要新的就重新搜）。
→ 422（复用 `unsupported_material` 的档位，消息写清"联网来的材料不重解析"）。

**(b) 没被引用 → 就地重解析**：同一个 `material_id`、同一个去重键、原始字节不动，
只把块重建 + `parser_id/parser_version/schema_version/truncated/warnings` 更新。
**id 不变**很要紧：前端"这一轮选了哪几份"是按 id 记的，id 一变那份选择就失效。
落库用新的仓储方法 `MaterialStore.replace_chunks(material_id, parsed)`。

**(c) 被引用 → 不就地改，另出一份"当前解析器读的"**：

```python
key = sha256(f"reparse:{material_id}|{parsed.parser_id}@{parsed.parser_version}")   # 变体键
store.put(project_id=…, parsed=parsed, sha256=key, content=raw, now=…)
```

- 旧的**留着**（它的块还挂着 E7、E12 —— 证据不可变）；新的那份可以用在下一轮。
- 变体键让**重复点两次不会生出第三份**（幂等，有测试）；也不会撞 `(project_id, sha256)` 唯一索引。
- 为什么必须有 (c)：否则"**已被引用 + 解析器升级**"是**死锁**——就地改会改指编号，
  删又不许删，而"重新上传同一份文件"会被去重键挡回旧那份（`find_by_sha(sha256(原始字节))` 命中旧行）。

> **备选 a（更小）**：被引用就一律拒绝（不另出那份）→ 端点变回 23 → 24，
> 代价是上面那条死锁留着（界面只能说"没办法，重新传一份"——而重新传会被去重挡回来）。
> **备选 b（少一条端点）**：把重解析做成 `POST /attachments`（multipart）加一个
> `reparse_of=<material_id>` 表单字段，复用上传端点。**不建议**：一个端点两种动作，
> 读代码的人要绕一圈才知道它到底干了什么；端点白名单本来就是"显式改一条"的冻结表。

## 4. 数据流（做完之后）

```mermaid
flowchart TD
    UI[材料库面板] -->|看列表| GET[GET /projects/id/attachments]
    GET --> LIST[ListMaterials 用例]
    LIST --> REF1[WorkspaceIndex.material_references<br/>只读：rounds.payload.materials[]]
    LIST --> SUM[MaterialSummaryView + eids<br/>（空 = 可删可重解析）]

    UI -->|删| DEL[DELETE /projects/id/attachments/material_id]
    DEL --> DC[DeleteMaterial 用例]
    DC --> REF2[引用判据（同上，只读）]
    REF2 -->|空| W1[事务：store.delete（块 + 字节一起走）]
    REF2 -->|非空| E409[409 material_frozen<br/>消息里列出 E7、E12]

    UI -->|重解析| RE[POST /projects/id/attachments/material_id/reparse]
    RE --> RP[ReparseMaterial 用例]
    RP --> RAW[store.raw_bytes → parser.parse（事务外）]
    RAW -->|抽不出字| E422[422 unsupported_material]
    RP --> REF3[引用判据]
    REF3 -->|空| W2[事务：replace_chunks（同一个 id）]
    REF3 -->|非空| W3[事务：put（变体键 → 新的一份，旧的冻结留着）]
    W1 --> BACK[返回刷新后的材料列表]
    W2 --> BACK
    W3 --> BACK
    E409 --> UI
    E422 --> UI
    BACK --> UI
```

写路径只有两处，且都在**事务内**；模型调用没有（解析是本地 CPU），所以没有"事务外模型调用"的
那套事务纪律问题，但**解析仍然放在事务外**（它可能很慢，别占着写事务）。

## 7. 成功之后长什么样（自检）

1. 底部多一个 `材料库（4）`；打开能看到**项目里全部材料**（含以前上传的、联网搜回来的），
   每行写着来源、块数、解析器，以及**被哪些编号引用过**。
2. 没被用过的那份 → `删掉` 可用（二次确认后消失，材料列表与库同步刷新）。
3. 被引用过的那份 → `删掉` **是灰的**，旁边写着"已经发过编号 E7、E12"；点不动就不会有 409 惊吓。
4. 一份 stale 的材料：没被引用 → 点`重解析` → **同一行**变成当前解析器读的（块数可能变，`stale` 消失）；
   被引用 → 点`重解析` → **多出一份**，旧的那份标着"冻结（E7、E12）"，两份都在列表里。
5. 联网搜回来的那份：有来源标记、有块数、**没有重解析按钮**（它不是文件，是当时的网页快照）。
6. 把已有材料**带进这一轮** → 底部输入条那份清单里出现它，起轮时 `material_ids` 带上它。
7. 后端：端点 **25**、两张表没动结构、`materials` 的 `content`（原始字节）仍然永不进任何投影。
8. 证据链不变：被引用过的块，编号与正文一个字节都没变（测试钉住）。
