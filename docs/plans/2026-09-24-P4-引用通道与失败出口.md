# P4 · 引用通道 + 整合失败的出口

> 起因：作者真跑一轮（`p-edc2b350` / `r-405b6840`）时整轮失败，界面报
> 「整合两次都过不了校验：题目的依据编号不存在：O1」；席位交了 9 条疑问却无处可答。
> 诊断见 `.codex/docs/设计/04-未决.md` C9。作者 2026-09-24 拍板：三条都做。
> 执行方式照旧：TDD，先红后绿，一步一提交，每步给命令与输出。

## 1. 改之前的事实（诊断结论）

| 事实 | 位置 | 后果 |
|---|---|---|
| 席位意见渲染成 `[判断] [O1] …`，而整合器提示词说"编号就是这条判断的出处" | `application/context.py::render_reviews`、`infrastructure/llm/prompts/integrator.md` | 同一份提示词另一处又要求"evidence_refs 只能引用清单里的编号"，模型没有合法写法可引 → 自造（重放抓到 `seat.business_rules:O1`） |
| **疑问不进账本**（`if form is QUESTION: continue`），所以席位疑问没有 E 编号 | `domain/services/assigner.py::assign_opinions` | 想引用"这道题来自哪条意见"时无编号可用；界面也看不出谁提的 |
| `QuestionDraft.asked_by` 由模型自己填 | `application/agents/schemas.py`、`application/assembly.py` | 模型会瞎认（真数据里两个空手席位被写成提问者） |
| 整合 2 次仍失败 → 整轮 failed；点到失败点重跑还是同一句提示词 | `application/use_cases.py::_integrate_with_repair` | 死循环：3 次重试 = 6 次模型调用，永远出不来（已用 stub 复现） |
| `Rounding.fail()` 用"当前 step"当 `at_step`，无并发保护 | `domain/round/round.py::fail`、`infrastructure/graph/graph.py` | 双击重试会把 `at_step` 写成 `failed` → `resume()` 恢复成非法状态 → `RESUME_ROUTES` KeyError → 该轮永久锁死（作者库里就是这个状态） |
| 席位"疑问"只经整合器转手；被丢弃时没有留痕（C5 未做） | `application/assembly.py` | 界面上的疑问看起来"只是展示思考" |

## 2. 目标（三件，作者拍板）

1. **词表分离**：`E 编号`只表示出处；席位意见的身份写成 `seat.xxx:O1` 这种"席位条目"，
   两套写法在提示词里都显式命名，不再互相冒充。判断自己的 E 编号要显示出来（原来没有）。
2. **归因通道**：题目新增 `from_opinions`（**非证据**字段，只做归因）→ 装配层据此生成
   `asked_by`；解析不到的条目丢弃并**留痕**在问卷上。账本不动（疑问不是证据）。
3. **失败出口**：整合 2 次仍失败 → **显式降级**（本轮席位疑问原样落成 s11 开放问题 + 出草案卡，
   卡上写明失败原因与未归并条数），不再抛 502；并修 `fail/resume/RESUME_ROUTES` 三处 +
   给一轮加"同时只允许一个动作"的保护。

## 4. 任务

### Task 1 渲染：两套写法各归各位

- `render_reviews(reviews, *, titles, ledger=None)`：
  - 判断 → `- [判断] 〔席位条目 seat.x:O2〕 出处编号 E7`（没有 E 编号则写"没有出处编号"）
  - 疑问 → `- [疑问] 〔席位条目 seat.x:O1〕（这个身份不是出处编号）`
- 先红：`tests/application/test_context.py` ① 判断的 E 编号出现在意见行里；
  ② 疑问行里不出现"编号 E"这种字样；③ `ledger=None` 时不崩、不显示编号。
- 提示词：`integrator.md` 小标题改成"席位条目（**不是**出处编号）"，
  `LIMITS_TEXT` 写明 `evidence_refs` 只收 E 编号、座位条目不许写进去。
  `seat_review.md` 同理（席位读历史意见时也会看到这套写法）。
- 验收：`uv run pytest tests/application/test_context.py -q`

### Task 2 归因通道：`from_opinions` → `asked_by`，丢了要留痕

- `schemas.QuestionDraft`：去掉 `asked_by`，加 `from_opinions: list[str]`
  （形状 `seat.xxx:O1`，说明"这是席位条目身份，不是出处编号"）。
- `assembly._question(draft, known=…, reviews=…)`：
  - `asked_by` = 依据里那些 E 编号所属席位 ∪ `from_opinions` 解析出的席位；
  - `from_opinions` 里解析不到的（席位或条目不存在）→ 丢进 `dropped`（留痕），不判死整轮。
- `Questionnaire.dropped: tuple[str, ...] = ()` + 序列化往返（老行兼容）+ DTO 投影。
- 先红：`tests/application/test_assembly.py` ① `from_opinions` 决定 `asked_by`；
  ② 依据编号也能推出 `asked_by`；③ 不存在的条目进 `dropped` 且整轮不失败；
  `tests/infrastructure/test_sqlite_repositories.py` ④ `dropped` 往返；⑤ 老 payload 读成空元组。
- 验收：`uv run pytest tests/application/test_assembly.py tests/infrastructure -q`

### Task 3 整合失败 → 降级出草案（不再 502）

- `_integrate_with_repair` 第 2 次仍失败时：把本轮 `current_reviews` 里的**疑问**按
  `open_question_proposals` 的形状落成 s11 开放问题（每条配一条 `system_default` 出处，
  rationale 写"整合失败降级"），并在 gaps 里加一行"整合未成功：<原因>"；出草案卡。
  一条疑问都没有时仍然按失败处理（没有可降级的内容）。
- 先红：`tests/application/test_integrate_answers.py`
  ① `test_integrate_round_bad_two_failures_fail_the_round` 改成"降级出草案"（这条断言钉的
  正是要推翻的行为，说明理由）；② 新测试：降级草案里疑问原样在 s11、来源是 system_default、
  gaps 里有原因；③ 席位没交疑问时仍然是整轮失败。
- 验收：`uv run pytest tests/application/test_integrate_answers.py -q`

### Task 4 失败语义与并发：一轮同时只许一个动作

- `Round.fail()`：已经 FAILED 时保留**原来那条**失败（不再把 `at_step` 覆盖成 `failed`）。
- `Round.resume()`：`at_step` 是 `FAILED`（老库里的坏行）→ 抛明确错误，别让路由表 KeyError。
- `RESUME_ROUTES` 补 `failed → END`（兜底：坏行至少返回 200 + 失败原因，不再 500）。
- `RoundRunner.run()`：按 `round_id` 串行化，重入的直接报"这一轮正在处理中"，不并发跑两遍。
- 先红：`tests/domain/round/test_round.py`（①②）、`tests/infrastructure/test_graph.py`（③④）。
- 验收：`uv run pytest tests/domain/round tests/infrastructure/test_graph.py -q`

### Task 5 前端：问卷卡显示"没解析上的归因" + 类型跟上

- `QuestionnaireDrawer.tsx`：`dropped` 非空时一行灰字"有 N 条席位条目没能解析成归因：…"。
- 验收：`npx tsc --noEmit && npx vitest run`
