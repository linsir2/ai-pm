# 轻量 PRD 导出 Implementation Plan

> **For agentic workers:** Use `executing-plans` 在当前会话逐项实施，检查点留在本计划。

**Goal:** 导出一份正文分层、缺口就地提示、出处索引紧凑的 Markdown；真实样本附录字符数至少减半。

**Architecture:** 保持 `ExportMarkdown → render_markdown` 的只读纯函数路径，改动集中在交付渲染器。
共享出处遍历、摘要查询与领域判据继续作为真相源；导出格式不写回聚合。

**Tech Stack:** Python 3.13、pytest、PostgreSQL 测试夹具；开发依赖 `markdown-it-py` 验证 Markdown 解析语义，Playwright 检查真实导出。

**Spec:** `.codex/docs/设计/01-规格.md` §7.3。

## Global Constraints

- 标准、轻量、自定义模板都按 `TemplateAdapter` 的章序和角色渲染。
- 已确认文字与数字保留；只调整换行、列表标记与辅助元信息的位置。
- 出处索引准入继续调用 `cited_evidence_ids`，排除只被未决清单引用的编号。
- 模拟来源保留既有标签与 `SIMULATION_DISCLAIMER`。
- 不修改共享 `summarize_line` / `SUMMARY_LIMIT=60`（出处查询也在使用）。
- 最近版本展示 5 版，唯一配置 `application/deliverable.py::EXPORTED_VERSION_LIMIT`。
- 临时导出、HTML、截图与浏览器证据只存 `/tmp/opencode`。

## 设计评审检查点

- 确认空章与非空章的全部阻塞是否仍有落点；不凭格式删掉未决正文。
- 检查编号区间的断号、类型与来源隔离；URL query / fragment 不被合并。
- 检查多行字段、数字、代码围栏和表格；引用不能追加到围栏闭合行或表格最后一个单元格。
- 检查共享摘要函数与 API 投影不受影响。
- 检查默认下载所连的运行时与源码版本一致；浏览器证据必须来自新代码。

### 评审结果（2026-10-31，实施前）

已按上述五轴核对实际 `deliverable.py`、`ReadinessChecker`、`material_refs.external_ref` 与现有用例。

1. **P1，已纳入方案**：删附录 C 会丢掉非空章节的剩余条数 / 槽缺口。`section_min_entries`
   必须在非空章就地展示标题和 detail；空章复用已有说明，不能只留文首计数。
2. **P1，已纳入方案**：编号区间不可跨断号；URL fragment 不能当材料块后缀剥掉。
   仅非 URL 的既有 `#cNN` 后缀可归并，仍保留每个编号，类型也不混组。
3. **P2，已纳入方案**：引用追加到代码闭合围栏会破坏后续全文结构，追加到表格末行会改列数。
   两者都在块后独立标引用；版本摘要的管道和换行转义。用真实 Markdown 解析器检查 token / HTML，而非仅比字符串。
4. **P2，已修正计划**：数据流文档的导出章节实际是 `02` §10；共享 `SUMMARY_LIMIT=60` 也供出处查询使用，保留。
5. **验证环境**：测试用已有 scratch-schema 机制隔离；真实服务基线与新版必须核对相同项目 ID / 文档版本。

**结论：可实施。** 当前已有功能分支上原位执行；正文重写、证据裁库及新的导出模式均不在这份实现中。
