# 批 17 · RAG 流程重设计：补 stage 2「收敛」+ 修好预算尺子

> 2026-10-23 · 作者拍板：先评审再动手、最小化、TDD+RIPR
> 状态：**已实现 + 已真机验证 + 已量化实验**（实验两条预注册判据**不中**，结论与下一步见 §5）

## 0. 问题（v4 消融发现的根因）

业界两阶段是「宽召回 → **重排收敛**（3–10）→ 预算打包」。我们只有前后两段，
**中间那段不存在**，而且 `_select_ranked` 的**第一步**恰好是反收敛的
（"每份材料至少露一名" → 候选一宽就变成**摊薄器**）。

**v4 实测**（120 问，C 臂走真 FTS5+向量）：

| 臂 | 正确率 | 材料份数 | gold 材料占到的块数 |
|---|---|---|---|
| A 无材料 | 0.120 | 0 | — |
| **B1 手勾·对** | **0.737** | 1 | **13.45** |
| **C 库级检索（无收敛）** | **0.485** | **17.82** | **1.54** |

检索本身没问题（gold 进候选 120/120、top-1 命中 88.3%）——**问题就是预算被摊薄**。

**顺带挖出一个更大的既有 bug**：`material_block_cost` 只在 `chunk.ordinal == 0` 时计入
抬头行 + 截断说明，而 `render_materials` 对**每份有选中块的材料**都渲染抬头
→ 粗排路里"第一名"常不是 `ordinal 0` → **全额漏算**。
实测 C 臂渲染 **5578 字**、成本合计 **4000**（差额 ≈ 抬头 1312 + 截断说明 269 + 收尾 96）。
**这就是 `render_materials` 注释里那句"预算是假的"。**

## 2. TDD + RIPR 用例

**R（契约形状）**：`select_chunks` 返回 `(picked, used)`；两个成本函数都收 `first_of_material`。
**I（行为）**：分数压过 2-gram、非命中块不参赛、**无保底**（根因）、手勾不被挤掉、
两段共用一个预算、auto 材料进 `packets`/`order`、去重 + 过滤 `None`、
手勾材料缺失仍抛 `ShapeError`、`missed` 只数手勾、检索失败回退、**提示词不说反话**、
联网材料不进材料段、跨项目材料被跳过、记忆摘要不把 auto 说成"被丢掉"。
**P（生产·真跑）**：`tests/e2e/test_round_material_convergence_e2e.py`（真 SQLite + 真检索器 + 真建轮）。
**R（回归）**：`retriever=None` 只受 F0 影响；`missed` 文案逐字不变。

## 4. v5 量化实验（`experiment-v5.md`，1080 次调用）

**臂**：B1（手勾·对）/ C（库级检索·有保底）/ C'（库级检索 + **收敛**）。
**检索路：纯 FTS5**（沙箱连不上 HuggingFace，如实降级）。

| 臂 | 正确率 | 引用命中 | 引用精度 | gold块数 | 材料份数 | tokens |
|---|---|---|---|---|---|---|
| **B1** | **0.723** | 0.642 | 0.843 | 1.38 | 1.00 | 269 819 |
| **C** | 0.581 | 0.530 | 0.609 | 0.97 | 6.03 | 282 557 |
| **C'** | 0.661 | 0.652 | 0.767 | 1.16 | 5.63 | **251 282** |

### 4.1 两条预注册判据**都不中**

- **H2′** `C' ≥ B1 − ε`（ε=0.05）：`C'−B1 = −0.062` ❌
- **H3′** `C' − C ≥ 0.10` 且配对改善 > 倒退：`+0.080`，配对 **18 好 / 28 坏** ❌

→ **不能宣称"收敛让库级检索追平手勾"。**

### 4.2 但机制上收敛修好了该修的那一半

**gold 材料缺席的题：23 → 5**（B1 是 3）。**残余差距来自"深度"不是"存在"**：
C' 给 gold 材料 1–2 块（`_MATERIAL_SLOTS=2` 上限），B1 给 1–6 块 + 整份材料的上下文；
**控制变量后**（只看 C' 拿 1 块 gold 的 87 题）C' = 0.681 vs B1 = 0.726。

**成本归一化后 C' ≈ B1**（每千 token 正确率 0.0026 vs 0.0027），且 C' 比 C 少花 11% token。

**最大的环境降级**：纯 FTS5 的候选池只有 **7.12 份**（v4 有向量时 **17.82 份**）
——**v4 那个"摊薄"场景本轮根本没复现**，收敛的收益空间本来就小。
（B1 新旧两次只差 0.014 → 模型稳定。）

## 5. 结论与下一步

> **收敛的方向和机制都对**（gold 缺席 23→5 题、成本更低、每 token 产出追平手勾），
> **但它没能让库级检索追平"用户恰好勾对"**（差 0.062，刚过 ε=0.05）——
> **瓶颈已经不在"材料在不在"，而在"最好的那份材料读得够不够深"**。

1. **别再调检索宽度**（`limit`）：本轮池子只有 7 份材料，宽度不是瓶颈。
2. **该测"单份材料的槽位"**：`_MATERIAL_SLOTS=2` 让最好的材料只读 1–2 块。
   抬到 3–4（或按分数给槽）才是对症的旋钮。
3. **补一个能跑向量的环境复测**：v4 的摊薄场景（17.8 份材料）才是收敛该发挥的地方。
4. **口径要改**：生产里自动段是"**加料**"不是"**替代**"（手勾的永远先选、永远在）。
   所以 H2′ 那个"替代"口径与生产场景不对应——**真正该测的是 `B1 + 自动`**（`experiment-v6`）。

## 7. 同批修掉的 CI 三处红（`new-branch` 上三次 CI 全失败）

| 现象 | 根因 | 修法 |
|---|---|---|
| `E: Unable to locate package libxslt1` | Debian trixie 的源里**没有** `libxslt1`（实测 `Package: libxslt1` 命中 0 条），只有 `libxslt1.1` | `backend/Dockerfile` 改包名 |
| `env file .../backend/.env not found` | backend 的 CI job **没造占位 `.env`**（只有 build job 造了），而那条用例**故意**把 env_file 缺失当红灯 | `ci.yml` 的 backend job 补 `cp backend/.env.example backend/.env` |
| `unshare: write failed /proc/self/uid_map: Operation not permitted` ×5 | GH Actions runner **不允许用户命名空间**；而 `test_disk_full.py` 的跳过条件写成 `not in (0, 1)`，于是 `unshare` 的退出码 1 **漏过去**，接着断言"探针没吐 JSON"→ 红 | 改成 `!= 0`（探针的契约就是"非 0 = 基础设施没起来 → 跳过"） |

> 三处都是**既有问题**（run#1 就有 disk_full 那 5 条），不是本次改动引入的。
> 修完本地实测：伪造 `unshare` 失败 → 5 条按预期 **skip 并打印理由**。
