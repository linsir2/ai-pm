## 0. 一句话

## 1. 逐件的证据与取舍

### 1.1 B1：块宽 500 → 向量尾部完全不可见（cos=1.000000）

**已实测**（批 6c 核验）：块宽 500 → `index_text` 464 字符/≈token，长标题 + 3 级章节链
→ 尾部加独特标记词，向量 **cos=1.000000**（尾部对向量完全不可见）；450 → 0.991、400 → 0.996。
**无报错、无告警。**

**调研结论**（2026-10-21）：
- bge 的 **512 是模型契约**（BAAI 官方工程师：超 512 直接截），**不是配置项**；
  强行拉长的质量代价很大（LongEmbed：BGE-Base(512) 33.9 vs 原生 8192 模型 58.9）。
- 业界正确做法是**按 token 配比**，不是按字符：「正文预算 = 模型上限 − 标题/章节链 − 余量」，
  且**闸门必须做在自家层**（fastembed 的截断是静默的）。
- 我们已有 `WEB_CHUNK_CHARS=400` 正是这个理由（limits.py 注释写得很清楚）——**上传路漏了**。

**取舍**：

| 方案 | 结论 |
|---|---|
| **降块宽 400 + token 闸门** | **采纳**。零重算、零模型变更、延迟不变 |
| 只降块宽 | 半修：超长标题/深章节链仍会顶出 512，且仍静默 |
| 块宽降到 250 | 块数 +100~150%、上下文碎、论述类召回可能退化 |
| 换长上下文模型 | 见 §1.3（CPU 上不可行） |
| 只改口径不修 | 等于不修 |

### 1.2 B3：语义单路候选无下限

**已实测**：查一个整页里**根本没有**的词（"logo"），库里含此词=False，**混合路仍返回该材料**
（成因=向量余弦）；纯 FTS 路正确返空。

**调研结论**：
- 业界几乎**不在融合公式里**给语义腿设下限；闸门在**融合之后**（ES `min_score` /
  LangChain `EmbeddingsFilter`）或**只挂语义腿**（Qdrant `score_threshold`）。
- **闸要建在语义腿的绝对余弦上**，不能建在融合分上（TOIS 2023：归一化方式 rank-equivalent
  → 换归一化会让融合分刻度漂移；我们最后还把 `score` 改写成 `1/(position+1)`，融合分无绝对含义）。
- BGE 官方：相似度分布约 **[0.6, 1]**，**>0.5 不代表相似**，建议阈值 0.8/0.85/0.9，
  且强调**按自己数据上的分布选**。
- **"OOV 判空"这个免费做法不能用**：改述查询的词**也不在语料里**（OOV），
  判空等于把向量路径的意义全废了 → 改述召回会从 11/14 掉到 0。

**因此：先量再定。** 判据（先注册再实现）：
1. 现有 bench **没有负样本** → 先补「库里根本没有的词」这一类（否则无法验收任何改动）；
2. 量「真改述对的余弦」与「负样本的余弦」两条分布；
3. **能分开** → 加语义腿绝对余弦下限（只作用于「只有 KNN 命中、词面零命中」的候选，
   融合公式一字不改）；**不能分开** → **诚实记录「在本语料上不可分」**，不硬加阀
   （宁可假阳性也不误杀改述——那是已验收的正指标）。

### 1.3 换嵌入模型：**先实测 CPU 延迟再定**

**收益**：MTEB(cmn) 检索 61.77 → **71.03**（+9.3）；32K 上下文 → **彻底解决 B1**；
Apache-2.0；fastembed 已支持（ORT 1.26 ✓）。

**代价（推算）**：0.6B 参数 = bge-small 的 **18 倍** → 单块 49ms → **~0.9s** →
联网路每轮 120 块 → **~108 秒/轮**。就算靠 32K 把块放大到 4000 字（块数降到 10/轮），
也要 ~9s，且块级精度崩。连带：维度 512→1024、**全量重算**、查询侧要加 `Instruct:` 前缀
（文档侧不加 → **两侧不在同一空间，检索静默变差**，这是最易漏的重算项）、
`EMBED_PROFILE` 变更、**融合 α 必须重量**、联网材料向量预算 N 要重选。

**先实测**：下载 Qwen3-Embedding-0.6B ONNX（int8 1.12GB），测 20 块的真实 ms/块。
**判据**：单块 ≤ 150ms（每轮 120 块 ≤ 18s）才继续谈；否则正式归档，理由带实测数字。

### 1.4 B5：`ConnectTimeout` 不在抓取重试集合

**已核实 httpx 异常层次**：`ConnectTimeout` → `TimeoutException` → `TransportError`
（**不是** `NetworkError`）；`ConnectError` → `NetworkError` → `TransportError`。
我们只重试 `ReadTimeout` + `RemoteProtocolError` → **`ConnectTimeout` 直接失败**。
实测：同一公网地址十次里约四五次 `ConnectTimeout`。

**取舍**：加进重试集合（`ConnectTimeout` = "连得太慢"，可重试；证书错仍是 `ConnectError`，不受影响）。
**边界**：连接类错误（`ConnectError`：DNS 失败/连接被拒/证书错）**仍然不重试**——那是"连不上"。

### 1.5 老材料：启动时自动重切重算（作者拍板）

- 降块宽 → **已入库的上传/抓网页材料**的块结构过时（原始字节在库 ✓，**不需网络**）。
- 联网材料块宽本来就是 400 → **不受影响** ✓。
- **已被编号引用的材料不能就地重切**（编号指着旧块，改块=改指编号，P19 冻结）→ **跳过**。
- 幂等：重切后解析器档位对上 → 不再需要重切 ✓。

## 2. 范围

### 做
1. `CHUNK_CHARS` 500 → **400**；**删掉 `WEB_CHUNK_CHARS`**（同值 → 两个真相源），
   联网路改用 `CHUNK_CHARS`。
2. **token 闸门**：喂模型前按 token 上限裁（从尾部），**换模型自动跟随**；裁了有告警。
3. **B3 的负样本 bench + 分布测量** → 按测量结果决定加不加语义腿下限。
4. `httpx.ConnectTimeout` 进重试集合。
5. **启动时自动重切重算**（未被引用的上传/抓网页材料）。
6. 换模型：**实测 CPU 延迟**，按判据决定做/归档。

### 不做（明确排除）
重排（CPU 20 候选 × 300–500 token = 1.7–4.2s，搜索框不可用）；
稀疏检索（SPLADE/BGE-M3 稀疏头：要新建倒排表，一个量级的复杂度差）；
语义切块/重叠窗口/上下文增强检索（实验一致反对 / 与 5-gram 去重冲突 / 需 LLM 批处理）；
bge 强行拉长（无官方权重，LongEmbed 证据显示远远不够）。

### 4.2 `sqlite/embedding.py`：token 闸门（换模型自动跟随）

```python
#: 嵌入模型的 **token 上限**（模型契约，不是配置项）。
#: `bge-small-zh-v1.5` = 512；换模型时**连同 `MODEL_NAME` 一起改**（同处一个真相源）。
MODEL_MAX_TOKENS = 512

#: 留给特殊 token（`[CLS]`/`[SEP]`）与未知的余量。
EMBED_TOKEN_MARGIN = 32
```

```python
    def embed_many(self, texts):
        model = self._ensure()
        return [
            tuple(float(x) for x in vector)
            for vector in model.embed([self._fit_to_window(text) for text in texts])
        ]

    def _fit_to_window(self, text: str) -> str:
        """把输入裁到模型窗口内（**从尾部裁**）。

        为什么在**这里**裁：这是唯一真正把文本送进模型的地方——模型换了自动跟随
        （上限是模型契约）。为什么从尾部裁：`index_text` 的拼装顺序是
        `标题 + 章节链 + 正文` → 尾部先被牺牲的是**正文的尾部**，
        留下"这段是关于什么的"（定位信号）——细节还能靠词面检索兜底
        （与 "The Power of Noise" 的结论同向：语义侧保主题，词面兜细节）。

        **不静默**：裁了要留 warning（"静默降级比失败更贵"）。
        """
        limit = MODEL_MAX_TOKENS - EMBED_TOKEN_MARGIN
        if self._token_count(text) <= limit:
            return text
        # 按 token 边界裁：快查 token 数 → 二分找切点 → 解码回字符串
        ...
        logger.warning("向量输入超出模型窗口，已裁掉尾部 %d 字", ...)
        return trimmed
```

**裁剪要按 token 边界**（不能按字符硬切，否则会切出半个字/半个词）。
实现：`model.token_count(prefix)` 二分 → 再用 tokenizer 的 decode 取前缀。
fastembed 的 `TextEmbedding.token_count(texts) -> int` ✓ 已核实存在。

**流程**（`MaterialMaintenance._run`）：

```
for (material_id, owner_id) in store.list_needing_reparse():   # 维护专用查询（不带 owner 过滤）
    set_owner_scope(owner_id)
    try:
        raw = store.raw_bytes(material_id)
        parsed = parser.parse(filename=material.title, media_type=material.media_type, data=raw)
        store.replace_chunks(material_id, parsed)     # 档位更新 → 幂等

    except Exception:
        logger.warning(...)                             # 失败不阻断
    finally:
        clear_owner_scope()
```

**三条纪律**：
- **不阻塞启动**（后台任务）；
- **已被编号引用的材料跳过**（编号指着旧块，改块=改指编号，P19 冻结）；
- **幂等**（档位对上 → 不再需要重切）。

**新的仓储方法**：`SqliteMaterialStore.list_needing_reparse() -> tuple[tuple[str,str],...]`
（material_id, owner_id）——**维护专用**：跨 owner 扫描，**只读**，与 `optional_owner`
的"查询本身就要包含全局行"同一性质（templates 的先例）。

## 5. 数据流影响

```
上传/抓网页（块宽 500→400）
  → chunk_text(max_chars=400) → 块变多 25% → FTS 索引变大
  → index_text(标题+章节链+正文) → embed_many → **闸门按 token 裁**
                                     └─ 裁了 → warning（不再静默）
  → 老材料：启动后台任务重切重算（未被引用的）→ 档位更新 → 幂等

联网检索（块宽不变 400）
  → 闸门同样生效（标题/章节链超长时）
  → 向量预算 N=24 不变（块数没变）

抓取（重试集合）
  → ConnectTimeout 走重试（最多 3 次，full jitter 退避）→ 连接类错误仍不重试
```

**不变式**：写入路径唯一 / AI 不写文档 / 入库量与提示词量是两层 / 事件只通知。

## 7. 风险与兜底

| 风险 | 兜底 |
|---|---|
| 块宽 400 让块数 +25%（上传/抓网页） | 向量成本 +25%（这些材料量小）；联网路**不变** |
| 老材料重切在启动时占 CPU | 后台任务、不阻塞；材料量小（本地单用户） |
| 已被引用的材料重切不了 | 保持旧结构（编号不能改指）→ 界面 stale 徽标 + 「重解析」会另出一份（P19 既有路径） |
| token 闸门用 fastembed 内部 API | `token_count` 是 fastembed 的公开方法；换模型时随模型变 |
| B3 加阈值误杀改述 | **先量**；改述召回 11/14 是不退的红线 |
| 换模型实测要下 1.12GB | 一次性；不可行就归档，带实测数字 |

## 8. 最终形态推演

**用户上传一份 40 页的 PDF/HTML**：
- 切块从 500 宽变成 400 宽（块数 +25%）；
- 每块的向量输入（标题+章节链+正文）经闸门检查，**超 480 token 的从尾部裁掉并留 warning**；
- 上一轮入库的同类材料，启动后被后台重切重算（未被引用的），界面上的 stale 徽标消失；
- 已被编号引用过的那几份保持原样（编号不能改指），用户点「重解析」会得到一份新的。

**用户搜一个库里根本没有的概念**（"kubernetes 部署"）：
- 词面零命中；
- 语义路可能捞回一些弱相关材料 → **B3 的测量会告诉我们该不该加闸**；
- 若分布不可分 → 保持现状（假阳性可见，用户能忽略）+ 在 `04-未决.md` 记着。
