## §1 为什么是适配器（上一版直读 vs 本版，评审用）

| 维度 | 上一版（消费者直读 template） | 本版（adapter 单接缝） |
|---|---|---|
| `template.py` | 涨 6 个引擎方法（blocking/coverage/check…），引擎概念泄漏进独立库 | 只加声明字段 + validate，零引擎概念 |
| 解读逻辑 | 散在 readiness/assembly/deliverable/context 各写一遍"锚点/序号/缺省" | 全关进一个文件一套测试；消费者只做符号替换 |
| view | 带 template（DTO/前端类型多一处投影，虽不序列化） | 只加 `role: str`，DTO 加一字段 |
| 旧常量 | 部分保留（双轨风险） | 解读层全删，误读全局表编译期即爆 |
| 新增文件 | 无（逻辑散） | `template_adapter.py`（~200 行）+ 测试（~250 行） |
| 以后换判据 | 改 N 个消费者 | 新写一个 adapter，模板库不动 |

## §2 边界规则（四条，评审时拿着 grep）

1. **模板库操作**（`anchor` / `slot` / `section_ids` / `validate` / 快照 / 建骨架）由 `Document` / factory / loader / repo / API 直接用，不经 adapter。
2. **引擎解读**（阻塞 / 覆盖 / 序号 / 标题 / 落点校验 / 归位表数据）只经 `TemplateAdapter`，不读全局表，不读 `template.sections` 内部。
3. **接缝动作**只有 `adapt(document.template)`（或已有 adapter 透传）；`adapt(` 的 grep 结果 = 本次迁移的全部接缝点（约 20 处，§5 清单）。
4. **文案组装**（placement/limits 字符串）住 `context.py`，只读 adapter 的数据方法；adapter 不返回格式化字符串（数据与文案分离）。

## §5 adapter exact 契约

```python
# domain/shared/template_adapter.py
@dataclass(frozen=True, slots=True)
class TemplateAdapter:
    template: DocumentTemplate  # 唯一字段：无预计算，无缓存（模板≤13章，derive一次μs级；快照不可变，无失效问题）

def adapt(template: DocumentTemplate) -> TemplateAdapter: ...

# 方法（全纯 derive；standard 复刻断言见测试）：
feature_home / open_home / version_home  -> SectionId   # anchor 三件套
section_ids      -> tuple[SectionId, ...]               # 模板顺序 = 文档顺序
has(sid)         -> bool
number_of(sid)   -> int                                 # index+1（导出章号/功能号/附录"第N章"全走它；standard下恒等于s数字）
title_of / purpose_of / role_of(sid)                    # role_of -> TemplateRole | None
slots_of(sid)    -> tuple[SlotSpec, ...]
slot(sid, name)  -> SlotSpec | None
min_entries_for(sid) -> MinEntries | None               # 声明值；未知BACKBONE回退 (1,None)；FEATURE/OPEN/VERSION无声明恒None
coverage_minimum(sid) -> int                            # 声明 > 有槽len(slots) > FEATURE/STEPS/DECISION/OPEN=2 > BACKBONE=min数(无声明1) > PLAIN=1；VERSION调了validate已炸
steps_section() / decision_section() -> SectionId | None
required_kind_for(sid) -> BlockKind | None              # min声明的kind过滤（backbone"本轮已写"判定用）
blocking_sections() -> frozenset[str]                   # FEATURE锚点 ∪ 有min声明 ∪ 有槽（standard复刻s1,2,3,4,5,8,10,12）
backbone() -> tuple[(sid, title, purpose, MinEntries)]   # role==BACKBONE且有min声明（gap lines用）
only_kind_for(sid) -> BlockKind | None                  # role==STEPS -> STEPS，否则None（调用方回落draft kind/TEXT）
check_target(sid, slug, field) -> None                  # 成员三闸，消息见§6
```

`ROLE_PRESENCE_LABEL = {STEPS: "主流程", DECISION: "技术决策"}`（domain 常量，kind-presence warn 用）。

## §6 exact 消息 / TOML / 文案

- `check_target` 未知章：`f"未知章节：{sid}（模板「{title}」里没有这一章）"`（`UnknownSection` + `template_title` details）。
- 功能错位：`f"功能子树只能长在 {anchor}，{sid} 不行（模板「{title}」）"`（`FeatureNotAllowedHere(..., feature_home=anchor, template_title=title)`；错误类加可选 `template_title=""`）。
- 槽错：`f"{sid} 没有名为 {field} 的章节槽（模板「{title}」）"`（`TargetShapeError`）。
- `Target` 新增形状错：`"正文 target 的 section_id 不能为空"`。
- `feature_field` 的 `home` 改为**必填关键字**（无 silent 缺省；调用方全传 `adapter.feature_home`；`FEATURE_HOME` 常量随之删除）。
- TOML（同上一版 §3，不重复贴；standard 声明 6 处 min，coverage 全缺省；light 声明 s1/s2/s4）。
- 缺省复刻表（adapter 测试手写字面量断言）：coverage s1:1 s2:2 s3:1 s4:2 s5:2 s6:2 s7:2 s8:6 s9:2 s10:1 s11:2 s12:1；blocking = {s1,s2,s3,s4,s5,s8,s10,s12}；number(s5)=5，number(s13)=13。
- backbone hints 新文案（exact）：`f"⚠ 文档里这几章还是空的（这一轮也没往那儿写）：{names}。随手补一条也算——{hints}；不补的话导出永远是「未通过」。"`（names=`、`join `f"{sid} {title}"`，hints=`；`join purpose；standard 六处文案变化，测试同步改）。
- descriptions 新文案（exact，static）：`section_id`："章节 id（如 s5；写功能字段时必须是功能锚点章——本轮章节表里标了 feature 的那章）"；其余含 s5/s8 字样处（Probe 列全，约 schemas.py 4 处）同口径改写。
- `placement_text` 格式（exact，任务内定，standard 下 analyzer 行为由 fake 整轮验证，不钉字节）。
