> 除非测试本身写错（要说明错在哪），**不许改测试来迁就实现**。
> 上游方案：`docs/plans/2026-09-24-P5-方案-把项目补扎实.md`（六条已拍板）。

**Goal：** 让系统能回答"这份文档够不够交出去"，并把它导成一份可以直接递给工程师的 Markdown。

**Architecture：** 判据是纯代码服务（`ReadinessChecker`），只读 `DocumentView`；
渲染是纯函数（`deliverable.render_markdown`）；两者都不持有写入能力。
为了让 s8 的"六项表态"可判据，引入**章节槽（section slot）**——s8 下的六个固定空块，
用 `Target.body("s8", field="performance")` 寻址，于是 AI 与人写的 NFR 内容能落进对应的槽。

**Tech Stack：** Python 3.13 + FastAPI + SQLite + LiteLLM；React 18 + Vite + TS strict。

**Spec：** `.codex/docs/设计/01-规格.md` §4/§7、`02-编排与数据.md` §4.6–§4.8/§10、
`06-前端.md` §2.2、`04-未决.md` G（六条拍板）。

```python
# domain/shared/sections.py（追加；BlockKind 在 shared.writing，同层，不违反分层）
@dataclass(frozen=True, slots=True)
class SlotSpec:
    name: str
    title: str
    kind: BlockKind


SECTION_SLOTS: dict[SectionId, tuple[SlotSpec, ...]] = {
    SectionId("s8"): tuple(
        SlotSpec(name, title, BlockKind.NFR)
        for name, title in (
            ("performance", "性能"), ("availability", "可用性"), ("security", "安全"),
            ("compatibility", "兼容"), ("observability", "可观测"), ("cost", "成本"),
        )
    ),
}


def section_slot(section_id: SectionId | str, name: str) -> SlotSpec | None:
    for slot in SECTION_SLOTS.get(SectionId(section_id), ()):
        if slot.name == name:
            return slot
    return None


def slot_block_id(section_id: SectionId | str, name: str) -> BlockId:
    return BlockId(f"{section_id}.{name}")
```

`Document.new()` 在 13 个 section 根之后追加六个空槽（骨架，不是内容）：

```python
blocks = tuple(Block.section(spec.section_id) for spec in SECTIONS) + tuple(
    Block(
        block_id=slot_block_id(section_id, slot.name),
        parent_id=BlockId(str(section_id)),
        kind=slot.kind,
        field=slot.name,
    )
    for section_id, slots in SECTION_SLOTS.items()
    for slot in slots
)
```

⚠️ `field=slot.name` 会让 `Document._validate` 走进"字段块必须挂在功能根下"那条分支，
所以那条校验要一并放开成两个合法分支：父块是 `FEATURE`（功能字段，`field_spec(field)` 必须认识）
**或** 父块是 `SECTION` 且 `section_slot(parent.block_id, block.field)` 非空（章节槽）。

```python
# domain/authoring/readiness.py 的关键常量
BLOCKING_SECTIONS = frozenset({"s1", "s2", "s3", "s4", "s5", "s8", "s10", "s12"})
MIN_ENTRIES = {"s1": 1, "s2": 2, "s3": 1, "s4": 2, "s8": 1, "s10": 1, "s12": 1}
BLOCKING_MARK = "〔未决·阻塞〕"


class ReadinessChecker:
    def check(self, view: DocumentView) -> tuple[ReadinessItem, ...]:
        items: list[ReadinessItem] = []
        items += self._section_entries(view)      # section_min_entries
        items += self._feature_gaps(view)         # feature_field_empty
        items += self._kind_presence(view)        # section_kind_present（warn）
        items += self._cross_links(view)          # cross_section_link（warn）
        items += self._open_questions(view)       # open_blocking_question
        return tuple(items)
```

细则（写进 docstring）：

1. `_section_entries`：`_entries_of(section)`（递归取该章所有非空条目）少于 `MIN_ENTRIES` → blocker；
   s8 的 `detail` = 六个槽里还没有条目的那些的标题（`性能、可用性…`），`title` 形如
   `"非功能需求还缺 4 项表态"`。
2. `_feature_gaps`：`view.feature_gaps` 为空且 `_features(view)` 为空 → 一条
   `detail="还没有任何功能"`；有功能 → 一条，`detail` 按功能分组列缺失字段的中文名。
3. `_kind_presence`（warn）：有功能但 s6 没有非空 `steps`；s12 没有 `acceptance`。
4. `_cross_links`（warn）：有功能的 `dependencies` 非空但 s7 没有 `interface`/`entity` 条目。
5. `_open_questions`：s11 的条目里，文本以 `BLOCKING_MARK` 开头的 → blocker（`detail` 列前 3 条），
   其余 s11 条目 → 一条 warn。
6. s13 不参与。

```python
READINESS_HARD_RULE = "补缺口不等于填满——拿不准就出题，不许为凑判据编内容。"


def render_readiness(items: Sequence[ReadinessItem]) -> str:
    if not items:
        return ""
    lines = ["## 本章还差什么（系统按 01-规格 §4 的合格标准算的）", READINESS_HARD_RULE]
    lines += [
        f"- {item.section_id} {item.title}：{item.detail}"
        f"〔{'阻塞' if item.severity is Severity.BLOCKER else '提示'}〕"
        for item in items
    ]
    return "\n".join(lines)


def render_document_state(view: DocumentView, *, readiness: Sequence[ReadinessItem] = ()) -> str:
    gaps = render_readiness(readiness)
    return render_document(view) if not gaps else f"{render_document(view)}\n\n{gaps}"
```
