## 二、缺口与既有事实（再调研核实，2026-10-18）

### 1 · L2 排序 bug（真，实证）
`observations_repo.recent()`：`ORDER BY id DESC` 是**字典序**（`obs-9` > `obs-10`），去重"留 id 最大"再按 id 排。**真库同时存在 `obs-10-5cf824` 与 `obs-9-792a3a`**。

> **2026-10-18 更正（实现者回报 + 我复核）**：那两行**同属一轮**（`r-7ac1912a`），所以它们的先后
> **从来不是跨轮时间错**，只是同刻的 `id DESC` 破平。真正的 bug 是**跨轮**：`id` 里没有时间
> （`_SimpleIdGen` 每轮从 1 重数 + 随机后缀；L3/L4 更是随机 hex），跨轮"最新"是任意的。
> 本批修的正是跨轮；同轮内的破平键（`id DESC` vs `rowid`）是另一处判断，本批**不动**。

### 2 · L2 时间源 = 重建 `created_at` 列（作者裁决）
- `DROPPED_COLUMNS["observations"]` 现在**含** `created_at`（上一轮死字段清理删的）→ **必须把它移出**，否则 migrate 会重新删掉。
- `ADDED_COLUMNS["observations"]` 现只有 `owner_id` → 加 `created_at`（老库 ALTER 补）；`schema.sql` 的 `observations` 加 `created_at TEXT NOT NULL DEFAULT ''`（新库）。
- **时间在哪盖章（再调研核实，2026-10-18）**：`extract_observations_from_reviews`（`application/context.py:1395-1427`）**就地构造** `RoundObservation(...)` 且现在**不传任何时间**。`Round` 聚合自带 `created_at`（`Round.created_at` property），且提取拿到的是**内存轮次**（`self._rounds.get(round_id)`），不需回读 DB。
  → **实体自带时间**（照 `MemoryEntry`/`MaterialEntry` 都自带 `created_at` 的既有形状）：
  `RoundObservation` 加 `created_at: str`；`extract_observations_from_reviews` 增 `created_at: str` 形参，在 `RoundObservation(...)` 里盖章；
  `_extract_and_store_observations` 传 `round_.created_at.isoformat()`。
  → **仓储只负责落库**（`save`/`save_batch` **不加** `now` 形参——实体已带时间，这是更小的改动面）。
  → 用**轮次时刻**而非提取时刻：同一轮重试产出的两条观察时间相同且稳定，不因重试时刻漂移导致排序抖动。
- **老行 `created_at=''`（没时间）**：`recent()` 排序必须把空的排**最后**（`ORDER BY (created_at='') ASC, created_at DESC, id DESC`），不许炸、不许让空值挤掉有时间的。

### 3 · L3/L4 读点预截断（范围扩大，如实记）
`use_cases.py:2278` digest `recent(..., limit=DIGEST_LIMIT)`、`:2283` inspiration `recent(..., limit=5)` —— 渲染器**看不到总数**，报不出"共 N"。要让 L3/L4 真有水位，必须**去预截断**（与 C2 对 L2 做的同一件事），让渲染层截断+报数。`DIGEST_LIMIT` 常量保留（渲染器 `limit=` 形参仍用它算"只带最近 N 轮"）。

### 4 · "共 N 条"尾注已在 C2 生效
`render_observations_index:1463-1465` 已有"（共 N 条，只带了前 M 条）"，且调用点不传 limit → 已真生效。批 3 在其上**补水位分句**。

## 四、数据流（前 → 后）

```
L2 读（前）: recent(ORDER BY id DESC 字典序) → 去重留 id 最大 → 渲染截5+报"共 N"
L2 读（改）: recent(ORDER BY 空排最后, created_at DESC, id DESC) → 去重留时间较新 → 渲染截5 + 超水位"更早的待复核"
L3/L4 读（前）: recent(limit=5/3) → 渲染看不到总数 → 报不出数
L3/L4 读（改）: recent(全量) → 渲染截 + 报"共 N" + 超水位"更早的待复核"
写入（L2）: extractor → save_batch(now=轮次时间) → 同库 created_at 列
迁移: 老库 ALTER 补 created_at('' ) → 空值排最后 → migrate 幂等
```

## 五、架构图

```
写入（不变，一行不删）:
  席位轮 → extract_observations_from_reviews → save_batch(now=…) → observations(created_at)
读:
  observations.recent()  [按 created_at，空排最后]  ─► render_observations_index(limit=5) ─┐
  inspirations.recent()   [去 limit，全量]           ─► render_inspirations_index       ─┼─ 超 L*_CAPACITY?
  digests.recent()        [去 limit，全量]           ─► render_digests                   ─┘   └─► "…；更早的 N−M 条待复核"
常量：L2/L3_CAPACITY=200, L4_CAPACITY=50
遥测：telemetry.memory_watermarks（只读，零写库）
```

## 六、终态想象

一个项目 L2 攒到 250 条观察（同轮序号有 ≥10）时：席位提示词里观察索引**按真实时间排序**（最新轮在前，`obs-10` 不被 `obs-9` 压过去），尾注写「共 250 条，只带了最近 5 条；更早的 245 条待复核」。L3/L4 同形。库里的数据**一行没少**。

## 七、自检

- **最小**：3 源文件 + 1 脚本 + 迁移；不加新表；不删数据。
- **只改根源**：排序用真实时间戳（作者裁决自建列，非 JOIN）；水位=读侧可见性+观测，非裁剪。
- **范围变更如实记**：L3/L4 必须去预截断才能报数（原计划漏了，本方案补上）；重建列比 JOIN 侵入（撤销上轮删列拍板），已由作者拍板承担。
- **不假实现**：RIPR #1 用真库同款 `obs-9`/`obs-10` 数据形态；排序守卫靠时间不同的两轮，不靠同时间破平。
