## 3. 三条口径（先定，免得做一半返工）

### 口径 1 · 命中粒度是**块**，不是"一份材料"

理由：材料卡、编号、锚点全是块级的（`m-x#c03` / "第 3 页 §2.1"）。
命中"一份材料"只能跳到材料标题，说不清"是哪一句"；命中块才能滚到那一块并显示片段。
所以 `MaterialRetriever.search()` 返回 `tuple[MaterialHit, ...]`——**`MaterialHit` 这个已存在的 DTO 就是它的形状**。

### 口径 2 · v1 用 `LIKE`（中文子串可靠），明确不做的与升级位

- 用 `text LIKE '%<q>%' ESCAPE '\'`：中文整段子串可靠、零索引、零迁移；查询里的 `%` / `_` **必须转义**；
  空查询 / 纯空白**回空**（与 F6 同一条规矩：绝不"不填就是全量"）。
- **不做**：分词、模糊匹配、拼音、向量、重排。`FTS5(trigram)` 的升级位留在同一个端口后面——
  **什么时候升**：等真跑量出"按整句搜命中率不够"（本包的 `MaterialHit.score` 与 `excerpt` 就是量它的抓手）。
- 排序（**必须有消费者**）：命中次数降序 → 命中位置靠前 → 块更短（并列时按 `chunk_id` 稳定）。
  `score` 的消费者就是 **F6 结果的展示顺序**——`search_hits` 拿到材料命中后**不再重排**。

### 口径 3 · 材料在 F6 里排**最后**，且"点得动"要说实话

- 顺序：条目 → 功能 → 编号 → 席位发言 → **材料**。理由：人最常找的是"文档里哪句写了"；
  材料是外部事实（不算权威），排在最后；上限仍是 `SEARCH_LIMIT = 50`，到顶 `truncated=True`。
- 点击：命中块的 `chunk_id` **在本轮材料里**（`RoundView.materials`）→ 滚到材料卡那一块并闪一下；
  **不在**任何一轮里 → 就地说明"这一块还没带进任何一轮（所以没有编号）；它在材料列表里，
  等它进某一轮才会有 E 编号"，**不假装能跳**（与仓库其它地方"找不到就说实话"同一口径）。

## 5. 契约（字段：谁赋值 → 谁消费）

| 字段 | 谁赋值 | 谁消费 |
|---|---|---|
| `MaterialHit.material_id` / `.chunk_id` | `MaterialRetriever` 实现（v1 `SqliteLikeRetriever`） | `search_hits` 造 `SearchHitView.ref` |
| `MaterialHit.score` | 同上（命中次数 → 位置 → 块长） | **F6 的展示顺序**（`search_hits` 不重排） |
| `MaterialHit.excerpt` | 同上（命中词前后各约 40 字的窗口） | `SearchHitView.label`（一行摘要） |
| `MaterialHit.anchor` / `.source_ref` | 同上 | `SearchHitView.where`（"材料 · 诊断报告.pdf · 第 3 页 §2.1"） |
| `SearchHitView.kind = "material"` | `search_hits` | 前端 `KIND_TEXT`（中文名）与 `App.pickSearchHit`（跳转分支） |
| `SearchHitView.ref`（材料）= `chunk_id` | `search_hits` | `jumpToChunk(chunkId)` / 找不到时的人话 |
| `MaterialSummaryView.origin`（**已存在**） | 材料仓储（盖章时写在行上） | `MaterialPicker` 的"来源"标签（本包新消费） |

**一条不变量（写测试钉住）**：**材料命中只能来自"这个项目的材料"**——
跨项目串味（A 项目的查询命中 B 项目的块）会让用户看到别家的数据，测试里造两个项目各一份材料，
断言只回本项目的。
