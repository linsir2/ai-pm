## 三、修复方案（待拍板）

### F1 · 幽灵 CSS 变量（根因修复，TDD）

**现象**：`var(--muted)`（8 处）、`var(--accent)`（4 处，其中 1 处在死类 `.versionbar__link`）在 `tokens.css` 从未定义 → 该属性失效、颜色继承父元素。

**根因**：`tokens.css` 从未定义这两个变量（原设计也没有），`app.css` 却引用它们。

**方案（第一性原理，不造别名）**：
- 不新增 `--muted`/`--accent` 别名 token（那会制造冗余）。
- `var(--muted)` × 8 → `var(--open)`（次要文字语义，与既有 `.muted { color: var(--open) }` 一致）。
- `var(--accent)` × 3（`.version__pick--on` ×2、`.diff__line--add` ×1）→ `var(--primary)`（强调语义）。
- 第 4 处（`.versionbar__link`）随死类删除（F3）。

**TDD（先红后绿）**：新增守卫测试 `frontend/src/styles/tokens.test.ts`：
1. 读 `tokens.css` 收集所有已定义的 `--x`；读 `app.css` 收集所有 `var(--x)`（无 fallback 形式）。
2. **断言：`app.css` 里每个被引用的 `var(--x)` 都在 `tokens.css` 有定义**。
3. 先跑 → 红（`--muted`/`--accent` 不在集合）→ 改 → 绿。

**影响**：纯 CSS 值变化，**无数据流影响**。8+3 处颜色从"继承"变为确定值。

**效果**：亮/暗色下这些文字/边框颜色确定，不再依赖父元素偶然继承。

---

### F2 · 暗色主题对比度

**现象**：`.step--done .step__dot`、`.prop__verdict--on`、`.topbar__badge` 用 `color: #ffffff` 配 `var(--primary)` 背景；暗色下 `--primary` 是亮色 → 对比度 < 3:1（WCAG AA 不达标）。

**方案**：新增 `[data-theme="dark"]` 覆盖，文字改深色 `#17161a`——与既有 `[data-theme="dark"] .btn--primary { color:#17161a }` 同一模式，**复用既有约定**。

**测试**：颜色对比度无单元测试（jsdom 不计算层叠色）。**诚实说明**：靠暗色截图核验，不加假测试。

**影响**：纯 CSS，**无数据流影响**。

**效果**：暗色下三个位置文字可读（达标）。
