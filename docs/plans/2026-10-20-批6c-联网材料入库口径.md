# 批 6c：联网材料入库口径改造

> **本文件重写自 `2026-10-19-批6c-网页主内容抽取.md`。原方案的病找错了**（见 §1）。
> 证据脚本：`backend/scripts/tavily_raw_bench.py`、`vector_budget_bench.py`、`paraphrase_bench.py`。
> 冻结语料与查询：`.codex/runs/2026-10-19/tavily_raw/`（gitignored，可复跑重建）。

## 0. 一句话

**库里存的根本不是网页正文，是 Tavily 按 query 挑的 3 段片段。** 改成入库整页 markdown，
检索命中 **29% → 71%**，而每轮的向量成本**不升反降**（43 块 → 40 块）。

## 1. 证据：原方案为什么被推翻

### 1.1 现状存的是什么

Tavily 官方文档（`/search` 端点）：

> `chunks_per_source`（默认 3）：*"Chunks are short content snippets (about **500 characters**
> each … pulled directly from the source"*
> `content` 字段：*"The most query-related content from the scraped URL. Tavily uses proprietary AI
> to extract the most relevant content based on context quality and size."*

我们**实测**（`tavily_raw_bench.py`，3 个真实 query × 5 条结果 = 15 份材料）：

| 口径 | 总字数 | 块数 | 平均每份 |
|---|---|---|---|
| `content`（现状） | 18705 | 130 | 1247 字 |

1247 字 ≈ 3 × 420 字 —— 与官方口径吻合。**同一 URL 换 query 会存进不同文本，页面主体永远不在库里。**

### 1.2 后果（真 Tavily + 真生产路径 + 真 FTS5 + 真混合检索 + 真模型）

查询词取自**页面真实内容**（中段），45 条：

| 口径 | **目标词在本路语料里存在** | FTS 命中 | 混合命中 | 名次均 | 排第 1 名 |
|---|---|---|---|---|---|
| **A `content`（现状）** | **19/45** | 13/13 | 13/13 | 2.08 | 6 |
| **B `raw_content`** | **45/45** | 30/30 | 31/31 | 1.77 | **20** |
| **C `raw_content` 剔导航行** | 45/45 | 30/30 | **32/32** | **1.75** | 20 |

读法：
- 现状下 **26/45 = 58% 的查询，目标词压根不在语料里** —— 不是排序差，是**内容不存在**。
- 以全部 45 条为分母：混合命中 **13/45 = 29%** → **32/45 = 71%**。
- **C 优于 B**：剔掉导航行后命中更高（32 vs 31）、名次更好（1.75 vs 1.77）、块数少 17%。
  → 剔导航**是净正**，不是妥协。

### 1.3 `raw_content` 是什么（实测）

| 事实 | 证据 |
|---|---|
| 请求参数 `include_raw_content="markdown"` | 实测返回 markdown，标题层级完整（`#` / `##` / `###`） |
| `include_raw_content=true` 与 `"markdown"` **返回同一个东西** | 实测同一 query，两者都返回 32006 字 markdown → **"拿 HTML 自己抽"这条路不存在** |
| **credits 不加** | 实测 `usage: {credits: 1}`（开了 raw_content 仍是 1） |
| 可能为 `null` | LangChain 为此专门打过补丁（`langchain-ai/langchain#30021`）→ **必须回退** |
| 含导航噪音 | 18.7% 的行是「整行只有一个 markdown 链接/图片」；剔掉后**总字数降 32%** |

markdown 标题层级完整 → `chunk_text` 直接生成 `heading_path` → **向量/词面索引源都变强**
（`index_source` / `index_text` 都把 `heading_path` 拼进去了）。

### 1.4 为什么**不做**主内容抽取（原方案的核心）

DAnIEL 中文子集 400 页，ROUGE-L（SIGIR'25 / `doi.org/10.1145/3726302.3730234`）：

| 抽取器 | 中文 Precision | 中文 Recall | 中文 F1 | 宏平均 F1 |
|---|---|---|---|---|
| `html_text`（**我们现状口径**） | 0.300 | **0.970** | 0.414 | 0.412 |
| Readability | 0.688 | 0.702 | **0.672** | **0.838** |
| Boilerpipe | 0.664 | 0.622 | 0.611 | 0.805 |
| **trafilatura** | **0.501** | 0.836 | 0.555 | 0.770 |

四条理由，逐条对上我们的处境：

1. **抽取器只降噪，不补内容** → 治不了"内容不存在"。我们自己的实测也印证：
   17 个真实页面上，抽取后**正文召回持平**（37/48），只有名次动了（1.32 → 1.11）。
2. **中文 Precision 三个里最低**（0.501）→ 噪音照样多，Recall 高只是因为它把什么都留下了。
3. **会丢内容**：`readability-lxml` 我们 2024 年已经因为同类问题撤掉了
   （`extract.py:63-77` 记着"增益 1–6%，会静默整块丢掉"）。中文最优的 Readability 恰恰是
   Precision 靠"敢丢"换来的（Recall 0.702 < 我们现状的 0.970）。
4. **+41 个依赖**，而收益只是名次 -16%，且只作用于「抓网页」一条路。

补充核验：**HTML5 语义标签也不够** —— 17 个真实页面里**只有 8 页**有 `<article>` / `<main>`，
一半页面拿不到内容。所以「有语义标签就用、没有就整页」也只能当加分项，不能当主方案。

### 1.5 字级兜底补的是什么

实测 `jieba.cut_for_search` 的输出：

| 输入 | 输出 |
|---|---|
| 召回率提升 | `召回` `率` `提升` |
| 新能源汽车 | `能源` `新能源` `汽车` |
| 光合作用 | `光合` `合作` `作用` `光合作用` |

→ **单字不在索引里**（`index_tokens("召")` → `召`，但 `index_tokens("召回率提升")` 里没有 `召`）。
→ 缺口 = **词面路零命中**的场景：跨词子串（`新能`）、英文子串（`AI` vs `AIGC`）、
单字查询、近拼写。**所以它是「兜底」（只在零命中时触发），不是并行索引。**

### 1.6 已排除的方案（附排除理由）

| 方案 | 排除理由 |
|---|---|
| 引 trafilatura 做主内容抽取 | §1.4：只降噪不补内容；中文 Precision 最低；丢内容；+41 依赖 |
| 换 Readability | 同上；且**我们 2024 年刚撤过它**，理由至今成立 |
| 语义切块 | NAACL'25：fixed-size 在 5 数据集 3 个最好；Chroma：语义切块 recall 83.6% < 固定窗口 89.5% |
| 重叠窗口 | 与我们的 **5-gram Jaccard ≥0.2 去重**直接冲突（重叠块必被判重复）；文献也指向 O=0 |
| 命题化检索 | 要 LLM 批处理 + 换索引单元（检索/去重/引用全改），远超本批 |
| late chunking | 需要长上下文嵌入模型；bge-small 上限 512，做不了 |
| 上下文增强检索（Anthropic） | 每块一次 LLM 调用；且 400 字块已 412 token，加前缀必截断（官方警告的场景） |
| 换嵌入模型（Qwen3-0.6B 等） | MTEB 中文检索 61.77 → 71.03（+9.3），**值得做，但要另起一批**：换模型要全量重算、维度 512→1024、查询侧要拆 instruction、**融合权重 α 必须重量**。本批不并入（§1.2 修好之后召回天花板更高，先修地基） |
| 稀疏检索（SPLADE / BGE-M3 稀疏头） | 要新建倒排表（复杂度差一个量级）；中文 SPLADE 无 C-MTEB 成绩；我们 FTS5+jieba 已占稀疏位 |
| 上下文选择改语义排序 | 「The Power of Noise」：语义相关但无用的块**比完全无关的块更伤**；我们现状是纯 2-gram 粗排，**维持** |

## 2. 范围

### 做（本批）
1. **联网检索入库整页 markdown**（`include_raw_content="markdown"`），`raw_content` 为 null 时回退 `content`。
2. **清洗加一条规则**：整行只有一个 markdown 链接/图片 → 视为导航行剔除（实测省 32% 字、命中更高）。
3. **向量预算**：联网材料只向量化每份的**前 N 块**（N 由实测定，§4.3），FTS 覆盖全部块。
4. **字级兜底**：词面路零命中时，用字级子串匹配捞回（**先量后做**，量不出收益就砍，§4.4）。
5. **老材料自动重搜**：把已入库的"片段版"联网材料按原查询重新搜一遍换成整页版。

### 不做（明确排除，理由见 §1.6）
主内容抽取器、换嵌入模型、重排、稀疏检索、语义切块、重叠窗口、上下文选择改语义排序。

### 不碰
「抓网页」路（`web_fetch`）与上传材料的清洗口径、块宽、融合算法、界面。

## 4. 逐文件、每一步

### 4.1 `infrastructure/tools/tavily.py`（核心）

| 步 | 改什么 | 为什么 |
|---|---|---|
| 1 | `PARSER_VERSION = "tavily-rest-v1"` → `"tavily-rest-v2-raw"` | 换档位 → 老的"片段版"材料自动被 `needs_reparse` 判为 stale（**复用现成机制**，不新造） |
| 2 | `search()` 的 payload 加 `"include_raw_content": "markdown"` | 实测：markdown 格式、标题层级完整、**credits 不加** |
| 3 | `_packet()`：`body = str(item.get("raw_content") or item.get("content") or "")` | raw_content 可能为 null（LangChain 打过补丁）→ **回退 content**，不能为空 |
| 4 | `_packet()` 里调 `cap_text(body)`（**从 `extract.py` 复用**），截了就置 `truncated=True` 并加 `TRUNCATED_WARNING` | **联网路径现在完全没有字数上限**（`cap_text` 只在上传路径调用）→ raw_content 下单页可达 27943 字，个别站点能到几十万 → 必须补。复用 `MAX_MATERIAL_CHARS=200_000`（**不新增魔法数**） |
| 5 | `_packet()` 的 docstring 补一段：写明 `content` 是 query 相关片段、`raw_content` 是整页 | 下一个读代码的人不会再以为 `content` 是正文 |

**不改**：`media_type`（仍是 `text/html`，描述的是来源）、`origin`、`source_ref`、锚点、warnings 结构。

### 4.2 `infrastructure/tools/webclean.py`（清洗加一条）

在 `normalize_web_text()` 里加一步：**整行只有一个 markdown 链接或图片 → 剔除**。

```
_LINK_ONLY = re.compile(r"^!?\[[^\]]*\]\([^)]*\)$")
```

- 命中的是 `![](url)`、`[产品中心 >>](url "产品中心")`、`[· NF5270G7](url "NF5270G7")` 这类**导航/装饰行**。
- **不命中** `- [参考资料标题](url)`（有列表符号）→ **参考资料列表会保留**。
- **不命中** `[文档](url)[反馈](url)`（一行多个链接）→ 正文里的行内链接会保留。
- 位置：放在**最前**（先剔导航，再做其余归一）。

实测依据：剔掉后总字数 251174 → 200377（**-20%**），块数 1293 → 1075（-17%），
**检索命中 31/31 → 32/32、名次 1.77 → 1.75**（净正）。

### 4.3 `infrastructure/sqlite/vector_index.py` + `sqlite/database.py`（向量预算）

**规则**：**只有 `origin == "web_search"` 的材料**限制向量块数（每份前 N 块），其余材料不动。

- 为什么不一刀切：上传材料是**用户精挑、要精读**的（通常 < 12 块），抓网页材料是用户点名要读的。
  一刀切会改掉批 5/6a 已交付的语义召回能力 → 越界。
- 为什么联网材料要限：raw_content 让单份材料从 4 块涨到 21–167 块，全量向量化一要 **263 秒**。

**N 的取值（实测，两个独立判据都在 8 饱和）**：

| N（块/份） | 每轮向量块 | 耗时 | 词面查询命中 | 改述查询命中 | 名次均 |
|---|---|---|---|---|---|
| 0（无向量） | 0 | 0s | 30/30 | 8/14 | 2.38 |
| **8** | 40 | **2.0s** | **32/32** | **9/14** | **1.75** |
| 12 | 60 | 2.9s | 32/32 | 9/14 | 1.75 |
| 24 / 48 / 全量 | ↑ | ↑ | 32/32 | 9/14 | 1.75 |

- **取 N = 8**：两个判据在 8 就饱和，加到全量（167 块/份）**一分钱收益没有**。
- 现状对照：现状每轮 43 块向量（2.1s）→ 新口径每轮 **40 块（2.0s）**，**成本降 7%、质量翻 2.4 倍**。
- **登记的重扫触发条件**：语料规模超过 50 份材料，或改述召回从 9/14 掉下来 → 重跑
  `scripts/vector_budget_bench.py` + `scripts/paraphrase_bench.py` 重新定 N。

**实现**：
- `SqliteVectorIndex.write(material_id, *, max_blocks: int | None = None)` —— 传 `None` 表示不限。
- **规则收在一处**：`vector_index.py` 里一个纯函数 `vector_block_budget(origin) -> int | None`
  （`limits.py` 放常量），`write` 与 `database._backfill_chunk_vectors` **都调它**
  —— 否则启动回填会把预算外的块补上，预算形同虚设。

### 4.4 字级兜底（**先量后做**）

**为什么不是"加单字进 FTS 索引"**：那会改每份文档的 term 统计（doclen 涨 ~字符数），
**改变主路径的 BM25 长度归一** → 批 5/6a 调好的融合平衡要重量，副作用外溢。

**为什么不是"建独立 trigram 表"**：要双写 + 迁移 + 存储翻倍，而我们**已经有正文**
（`material_chunks.text`），兜底只在**零命中**时触发（罕见路径）。

**方案**：在混合检索**零命中**时，用 `material_chunks.text` 做**子串 LIKE 匹配**兜底
（覆盖跨词子串、英文子串、单字）。

**判据（实现第一步就量，量不出就砍）**：手写 10 条"字面零命中"的查询
（跨词子串 / 英文子串 / 单字 / 近拼写），量字级兜底能捞回几条。
**捞回 0 条 → 砍掉这个功能**，并在计划里记一笔"为什么砍"。

### 4.5 老材料自动重搜

**为什么需要**：老材料存的是片段，`content` blob 只是块文本拼接（`_keep` 写的），
**拿不回 `raw_content`** → 只能重新搜。

**怎么找到原查询**：`ParsedMaterial.warnings` 里有 `"来自检索：{query}"`，
`materials.warnings` 以 JSON 存库 → **原查询读得回来**。

**流程**（照抄 `FetchMaterial` 的分支模式，`use_cases.py:3503-3534`）：

```
lifespan 启动 → 后台任务：
  for 项目 in 所有项目:
    for 材料 in list_for_project(项目, current=identities()):
      if not material.stale: continue
      if material.origin != "web_search": continue
      if 已被 E 编号引用: 跳过（历史证据不能改）
      查询 = 从 warnings 里解析 "来自检索：xxx"
      结果 = Tavily.search(查询)
      for 每条结果:
        按 URL 去重键 upsert：
          同 URL 且未被引用 → materials.refresh(...)
          同 URL 且已被引用 → 另出一份（变体键）
          新 URL → materials.put(...)
      写向量（受预算）
```

- **幂等**：刷新后 `parser_version` 对上 → 不再 stale → 下次启动不再刷。
- **失败**：网络失败 → 材料保持 stale → 下次启动再试。**不抛、不阻断启动。**
- **不自动花额度**：只在有 stale 材料时才有搜索发生；stale 材料是一次性的（刷完就没了）。
- **已被引用的老材料**：保持原样（历史证据不该被改写），界面上仍是 stale 徽标。

### 4.6 不改的文件（明确列出，避免误伤）

`api/routes.py`、`api/schemas.py`、前端全部、`application/context.py`、
`application/dto.py`、`infrastructure/sqlite/materials.py`（除必要的刷新调用）、
`bootstrap/settings.py`、`schema.sql`、`pyproject.toml`（**零新依赖**）。

## 5. 数据流影响

### 改后

```
用户勾选"联网检索"
   │
   ▼
SubmitOpening._search ──► Tavily /search  {include_raw_content:"markdown"}
   │                            │
   │                            ├─ content     (query 相关 3 段)  ─┐  ← 现在被丢弃
   │                            └─ raw_content (整页 markdown)  ───┤
   │                                                           ▼
   │                                    TavilySearchGateway._packet
   │                                       ├─ body = raw_content or content   (null 回退)
   │                                       ├─ normalize_web_text  (剔导航行 → 剔省略标记 → …)
   │                                       ├─ chunk_text(max_chars=400)  → heading_path
   │                                       └─ warnings("来自检索：{query}")
   │                                                           ▼
   │                              SubmitOpening._keep   (去重键 = sha256("web:"+url))
   │                                   ├─ materials.put  → 块 + FTS 索引（**全量块**）
   │                                   └─ vectors.write(max_blocks=8) → **前 8 块**
   │                                                           ▼
   │                              select_chunks(budget=2000) → E 编号 → 提示词
   ▼
检索时：SqliteHybridRetriever
   ├─ FTS5 候选（前 20）—— 覆盖**全部**块
   ├─ KNN 候选（扫 200）—— 只有**前 8 块**有向量
   └─ 凸组合 0.5·真余弦 + 0.5·饱和归一 BM25
```

### 关键不变式
- **写入路径唯一**：只有材料用例写库，编排层拿不到写库能力（不变）。
- **AI 不写文档**：不变。
- **进提示词的量不变**：入库变大，但进提示词仍由 `WEB_BUDGET=2000` 与 `select_chunks` 管
  —— **入库量与提示词量是两层**（这正是批 6a 撤销"入库截 300 字"时定下的原则）。
- **事件只通知**：不变。

## 6. RIPR 判据（缺一不可）

| # | R（需求句） | I（输入） | P（过程） | R（绿标准） |
|---|---|---|---|---|
| 1 | 联网检索入库的必须是**整页正文**，不是 query 相关片段 | 真 Tavily 响应（含 `raw_content`） | `_packet` 读 `raw_content` | 冻结语料上：**目标词存在率 45/45**（现状 19/45） |
| 2 | `raw_content` 为 null 时不能空包 | Tavily 响应 `raw_content: null` | 回退 `content` | 仍产出可入库的材料，且 warnings 说明 |
| 3 | 导航行不该进库 | 整页 markdown（含 18.7% 纯链接行） | `normalize_web_text` 剔导航行 | 剔后总字数 **-20%**；**混合命中 32/32 ≥ 剔前 31/31** |
| 4 | 向量推理成本不能随入库量线性爆炸 | 每份 21–167 块的材料 | 联网材料只向量化前 8 块 | 每轮向量块 **≤ 40**、耗时 **≤ 2.5s**；改述命中 **9/14**（无向量 8/14） |
| 5 | 老的片段版材料要能换成整页版 | 项目里 stale 的 `web_search` 材料 | 启动后台按原查询重搜并刷新 | 刷完后 `stale` 变 False；**再刷一次不产生新的搜索**（幂等） |
| 6 | 已被 E 编号引用的材料不能被改写 | 已被引用的 stale 材料 | 重搜流程跳过 | 该材料的 `content` 与 `chunks` **逐字节不变** |
| 7 | 词面路零命中时，字级子串能捞回一些 | 10 条字面零命中的查询 | 零命中时 LIKE 兜底 | 捞回 **≥ 3 条**；**捞回 0 条 → 砍掉该功能**（并在计划记原因） |
| 8 | 换档位要触发老材料重解析 | 老 `web_search` 材料 | `PARSER_VERSION` 升档 | `needs_reparse` 判 True，界面出现 stale 徽标 |
| 9 | 全部既有行为不回退 | 全量测试 | — | `pytest` 全绿、`ruff` 无告警、架构守卫全过、前端 `tsc`/`vitest` 不动 |

## 7. 风险与兜底

| 风险 | 触发条件 | 兜底 |
|---|---|---|
| Tavily 改了 `raw_content` 语义 | 返回空/非 markdown | `raw_content or content` 回退；`raw_content` 为空串也算回退 |
| 某些站点 `raw_content` 极大 | 单份 > 200k 字 | **本批新增** `cap_text`（复用 `MAX_MATERIAL_CHARS=200_000`）：先截再切块，截断记 `truncated` + `TRUNCATED_WARNING`。实测语料 4968–27943 字，很少触发 |
| 重搜时网络失败 | Tavily 超时/限流 | 材料保持 stale，下次启动再试；**不抛、不阻断启动** |
| 重搜结果与当初不同 | Tavily 每次排序不同 | 按 URL 去重：同 URL 就地刷新，新 URL 新建；老 URL 保留不动 |
| 向量预算让某份材料语义覆盖不足 | 材料特别长（167 块） | 已实测：改述命中在 N=8 与全量**完全一致**；若语料变大 → 重扫（§4.3 触发条件） |
| 字级兜底过匹配 | 兜底路径 | 兜底**只在零命中时**触发，且**排在词面结果之后**；同时跑判据 7，捞回 0 条就砍 |

## 8. 最终形态推演

**一轮真实对话**（用户问"NF5270G7 这台服务器支不支持 RAG"）：

1. 联网检索命中一篇浪潮的产品页。
2. 旧口径：库里只有 Tavily 挑的 3 段（约 1200 字），**"NF5270G7" 大概率不在里面** → 搜不到。
3. 新口径：整页 markdown 入库（剔掉导航后约 12k 字）→ **"NF5270G7" 在正文里** → FTS 命中 ✓
4. 该份材料 33 块，**只有前 8 块写了向量**（约 3200 字）→ 语义路也能召回它（标题+导言含"浪潮/RAG"）。
5. 混合融合后，这份材料排在前列 → 进 2000 字提示词预算 → AI 引用它（带 E 编号 + URL）。
6. 用户在项目搜索框搜"服务器"→ 同样能搜到（词面路覆盖全部块）。

**实施后仓库的样子**：
- `backend/scripts/` 多三个可复跑的量化脚本（冻结语料 + 真检索）。
- `tavily.py` 多一个请求参数 + 一行回退。
- `webclean.py` 多一条纯函数规则。
- `vector_index.py` 多一个 `max_blocks` 参数 + 一个预算规则函数。
- 多一个后台刷新用例（照抄 `FetchMaterial` 的分支）。
- **零新依赖、零 schema 变更、零新端口、零界面改动。**
