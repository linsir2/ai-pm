# M11 模拟评测（模拟使用者走查）设计（2026-10-07）

> 来源：归档 `B1-模拟使用反馈回流.md`（2026-10-05 子任务设计报告）。与 M10 `sim_inquiry` 对称施工。
> 本文已逐条与现有代码核对：与现状冲突的以本仓口径为准；说不清 / 无消费者的直接砍（见 §9）。
> 拍板记录（2026-10-07，用户："都按照推荐的来"）：每份草案限 1 次；R2 保留"≥1 cannot_start"；
> 失败写 `Draft.gaps` 且可重跑（runs 不增）；提案追加进 `Draft.proposals`；功能 ≤2；代码名 `sim_review`。

## 1. Goal

草案卡上新增"减"动作：选 3 个模拟使用者（persona）× ≤2 个**已存在**的功能 → 按行为规则走查文档
→ 摩擦点 + 三档结论 → 机械规则产生 ≤3 条**删条目 / 降级优先级**提案（追加进草案，"它提议的"组，
默认不勾）→ 随确认写入（唯一写路径）→ 文档多一版。

成功判据（三条都可验）：

1. 真跑一条链：草案卡 → 评测（真模型）→ ≥1 条有依据的减提案 → 勾选确认 → 文档多一版；
2. 任何界面 / 导出都不出现可误读为"用户数据 / 评分"的形状（结构测试钉死）；
3. 与 M10 共用 `simulated` 编号、`proposed` 默认不勾、写路径不变——零新表、零新写路径、零新事件类型。

## 2. Architecture

```
草案卡「模拟评测」→ 抽屉选择器（persona ≤3 / 功能 ≤2）
   │ POST /api/rounds/{id}/sim-review
   ▼
RoundRunner（每轮动作锁）── node_sim_review ──▶ RunSimReview（用例）
   │ 门控：AWAITING_CONFIRM + DRAFT + runs<1；persona / 功能参数校验
   │ 渲染四源：document_state / claims / external_material / project_memory
   │ 并行 3 个 persona（asyncio.gather）
   │   每人：调用 → 校验（结构 + 文档引用 + 窄表）→ 有过失 → 重装 1 次（带指引）
   │          → 再犯 = 整趟失败（gap 一行 + 502，runs 不增，可重跑）
   ▼ 全部干净
纯函数 evaluate_rules（R1/R2/R3）→ ≤3 条减提案 + advisories + cited 条目
   │ 一个事务：assign_sim_review（按需发 simulated 编号）
   │          + Round.record_sim_review（artifact）
   │          + Round.augment_draft（提案追加进草案）
   │          + round.updated 事件
   ▼
草案卡：提案带「模拟评测依据」tag、默认不勾 ──勾选──▶ /confirm（唯一写路径）──▶ 文档多一版
```

### 与 M10 的对称 / 差异（一眼看清）

| 环节 | M10 模拟调研 | M11 模拟评测 | 差异理由 |
|---|---|---|---|
| 产物去向 | 勾选 → 材料 → 下一轮 | 提案 → **本轮草案** | 评测服务"减"，要改的就是这一版的草案；走材料会多绕一轮 |
| 待确认态 | `keep` 端点 | 无 keep，随草案确认 | 提案走既有写路径，零新入口 |
| 引用落空 | 重装一次 → 丢条 + 留痕 | 重装一次 → **整趟失败** | 调研是候选清单（丢一条不伤整体）；评测是一份走查报告，烂一处即半份，不出 |
| 账 | 第五本（1+1=2 次/趟） | **第六本**（3×2=6 次/趟） | 3 persona 并行，各带 1 次重装 |
| 每轮次数 | ≤2 趟 | ≤1 趟（**随草案**，dig 出草案时重置） | 防审批疲劳；提案直接进草案，重跑会叠 |
| 材料 origin | `simulation` | 不产材料 | 无回流载体 |
| 编号来源 | 材料块进轮时发号 | 提案引用时**当趟发号** | 同上 |

## 3. Spec

### 3.1 触发与门控

- 端点：`POST /api/rounds/{round_id}/sim-review`，body `{persona_ids: [str], feature_slugs: [str]}`；
- 门控（违规错误 → 已有映射）：`step=AWAITING_CONFIRM` + `waiting_on=DRAFT`（否则 409）；
  `sim_review_runs < MAX_SIM_REVIEWS_PER_DRAFT`（否则 `TooManySimReviews` → 409，R9）；
  persona 1..3 且全在目录、功能 1..2 且全在文档（否则 `ShapeError` → 422，人话点名）；
- 不碰 step、不进 `LEGAL_ADVANCES`；借动作锁（`RoundBusy` 409）；界面读回最新投影。

### 3.2 报文 `SimReviewPacket`（每 persona 一次调用，覆盖被选功能列表）

| 模型 | 字段 | 约束（schema / 筛） | 消费者 |
|---|---|---|---|
| Packet | `basis` | 非空（读了什么才走查出这些） | 展示 + 防"空报告" |
| Packet | `features[]` | ≥1；`feature_slug ∈ 被点名列表` | 挂载 / R2/R3 |
| FeatureReview | `started` | bool | R2/R3 |
| FeatureReview | `walkthrough[]` | ≤12；`started=true ⇒ ≥1` | 展示（第几步卡住） |
| WalkStep | `step_index, step_text, from_doc, action, outcome(ok\|stuck\|guessed), need` | `outcome≠ok ⇒ need 非空`；`from_doc` 自由文本**不机械验**（溯源展示用） | 展示 |
| FeatureReview | `frictions[]` | ≤6；见下 | R1/R2 + 展示 |
| Friction | `local_id`（F1…）、`kind`（8 种：missing_entry / missing_feedback / ambiguous_rule / dead_end / extra_work / trust_gap / edge_break / cannot_start） | `kind` 只是展示分类，机械只消费 `dead_end` 与 `cannot_start` | 展示 + 规则 |
| Friction | `where{entry_id?, field?, feature_slug}` | 至少一个锚点且**指向文档真实存在**（screen）；优先 entry_id | R1 + 展示 |
| Friction | `quote` / `not_documented` | 二选一（机械判） | 展示 |
| Friction | `blocks_flow`、`note` | note 非空 | R2 代表摩擦选取 |
| FeatureReview | `acceptance_checks[]` | 覆盖该功能**全部** acceptance 条目（机械判） | 展示 + 摘要 |
| AcceptanceCheck | `local_id`（A1…）、`entry_id`、`status(verified\|unverified\|contradicted)`、`note` | entry 必须属于该功能且真实存在 | R1 贡献（contradicted） |
| FeatureReview | `verdict(smooth\|friction\|blocked)`、`verdict_because[]` | `verdict_because ⊆ 本功能 friction_id`；`friction/blocked ⇒ 非空`；`smooth ⇒ 空` | 展示 + R2/R3 |
| FeatureReview | `cannot_start` 的表现 | `started=false ⇒ ≥1 kind=cannot_start` friction | R2/R3 |

**砍掉 B1 的**：`would_use_again`（无机械消费者；"还会用吗"是态度预测，与"不预测个体态度"的学术前提冲突，
verdict 已表达）、`abandon_trigger`（与 `blocks_flow` / verdict_because 重复）、每功能 `evaluated_version`
（改放 run 级元信息——一趟评测 = 一个文档版本）。

上限常量（`application/agents/schemas.py`，与模型同处）：
`MAX_SIM_REVIEW_WALKTHROUGH_STEPS = 12`、`MAX_SIM_REVIEW_FRICTIONS = 6`。

### 3.3 机械规则（`application/sim_review.py` 纯函数，不靠模型发挥）

| 规则 | 触发（全在报文里） | 产出 | 文本从哪来 |
|---|---|---|---|
| **R1 删条目** | 同 `entry_id` 被 **≥2 个不同 persona** 标：`dead_end` friction（where 指向它）**或** `contradicted` acceptance check | `remove` | 抄该条目现行正文 |
| **R2 降级** | 同功能 **≥2 persona `blocked`**，或 **≥1 persona `started=false`** | `replace` 该功能优先级条目 | 模板「待复核（模拟评测：N/M 个模拟使用者未能走通）」——不编新级别 |
| **R3 建议复核** | 全 persona 都 `blocked` / `started=false` | 不出提案，只进 `advisories` | 「建议人工复核（v1 不支持删除整棵功能）」 |

硬约束：
- 每次运行 ≤3 条提案（R1 按文档条目序、R2 按文档功能序），超出 → `advisories` 列一行摘要（不静默丢）；
- R2 找不到该功能的优先级条目 → 跳过 + advisory；触发 persona 一条 friction 都没有 → 它贡献不了引用，跳过；
  refs 汇总为空 → 跳过该条 + advisory；
- 提案 `origin = Origin(PROPOSED, refs=..., rationale="模拟评测：…")`；refs 指向**当趟发的 simulated 编号**；
- 同一 friction 被 R1/R2 同时引用 → **先去重汇总再统一发号**，提案引用同一个编号。

### 3.4 机械筛：唯一处置 = 重装一次，再犯整趟失败

对每个 persona（并行）执行：

1. `call_structured` 的结构校验（必填 / 上限 / 枚举 / 数组形状）——不过 → 重装；
2. 文档引用校验（`document_anchors`）：`feature_slug` 在名单、`where` 锚点存在、acceptance 全覆盖、
   `started` 一致性、`verdict_because` 闭包——不过 → 重装（指引逐条点名，不复制错串，P5d 纪律）；
3. 窄表：`friction.note` / `step.action` / `step.need`（**模型自撰字段**，文档引文 `quote`/`step_text` 豁免）
   命中身份词（复用 `sim_demographic_hits`）或数量断言（复用 `SIM_NUMERIC`）——不过 → 重装；
4. 第 2 次仍有任何过失 → **整趟失败**：`Draft.gaps` 写一行（点名哪个 persona、什么过失）→ 抛
   `PacketParseError`（→502）→ runs 不增 → 可重跑。

**为什么与 M10 的"丢条"不同**：调研产物是候选清单，丢一条不伤整体；评测是一份走查报告，丢一条 friction
会牵连 `verdict_because` / R1 计数（悬空连环），得不偿失。**没有条目级丢弃通道、没有 notes 通道**——
比 M10 少一整套复杂度。理由写进 `02` §11.0.48。

网关级失败（超时 / 拒收）：同样走"gap 一行 + 502 + 可重跑"。三人并行用 `asyncio.gather` 收齐再判
（不让半路取消吞掉已发生的调用账）。

### 3.5 发号（按需）

- 只给**被提案引用**的 friction / contradicted check 发编号：`EvidenceAssigner.assign_sim_review(items, ledger, round_id, now)`；
- `external_ref = simulation:review:{round_id}#{persona_id}@{feature_slug}#{local_id}`（人可读、可审计；
  与 M10 的 `simulation:inquiry:…` 前缀区分）；
- `kind = SIMULATED`（不进 `TERMINAL_KINDS`，结构测试已钉）；事务内发号，失败整趟回滚。

### 3.6 Round / 序列化（`domain/round/round.py`、`infrastructure/sqlite/serialization.py`）

- 新字段：`_sim_review: dict | None = None`、`_sim_review_runs: int = 0`；artifact 全 plain dict
  （`round` 不许 import 其他 domain 模块，同 M10）；
- `record_sim_review(review: Mapping) -> None`：覆盖写 + runs+1；
- `augment_draft(*, proposals=(), gaps=()) -> None`：`dataclasses.replace` 新 Draft（复用
  `Draft.__post_init__` 的查重与 ShapeError，不自写校验）；无草案 → `ShapeError`；
- `dig()`：清草案时**一并清 `_sim_review` 并重置 runs**——"每份草案限 1 次"的语义精确化
  （dig 出的是新草案，旧评测的提案已随旧草案消失）；
- 序列化：写 `sim_review`（可 null）+ `sim_review_runs`；老行回落 `None` / `0`。

### 3.7 DTO / 前端合同（`application/dto.py`、`frontend/src`）

- `RoundView.sim_review: SimReviewView | None`（没跑过是 None）；子视图：
  `SimPersonaReviewView`（persona_id/title/features）、`SimFeatureReviewView`（slug/started/verdict/
  verdict_because/walkthrough/frictions/acceptance_checks）、`SimWalkStepView`、`SimFrictionView`、
  `SimAcceptanceCheckView`；摘要 `summary`（按 persona×功能对的 smooth/friction/blocked 计数，
  不给百分比）+ `advisories` + `runs`/`max_runs`/`evaluated_version`；
- `ProposalView.simulation_based: bool`：`round_view(…, ledger=…)` 已有 ledger，向下传给 `_draft_view`
  → `_proposal_view`，按"refs 是否命中账本里的 SIMULATED 编号"计算；`ledger=None` 时 False
  （AbandonRound 那一条视图不带 tag，可接受，测试钉两态）；
- `/schema`：`personas`（persona_id/title/situation，给选择器）+ `LimitsView` 加
  `max_sim_review_personas` / `max_sim_review_features`（真相源 = `application/sim_review.py` 常量）；
- 前端：`DraftDrawer` 加按钮「模拟评测」→ `SimReviewDrawer`（三段：选择 → 运行中 → 报告/失败重跑）；
  纯函数 `state/simReview.ts`：`defaultPersonaIds`（前 3）、`defaultFeatureSlugs`（本轮提案触及的功能
  去重保序取 ≤2；没有则文档功能序 ≤2）、`canStartReview`（1≤persona≤3、1≤功能≤2）；
  提案卡 `simulation_based` → tag「模拟评测依据」；`PendingAction` 加 `"sim_review"`。

### 3.8 导出（顺手补 M10 欠账）

- `deliverable.py`：`KIND_LABELS[SIMULATED] = "模拟推演（未验证）"`（D1 设计要求的标签，M10 漏了）；
- `_appendix_a` 渲染到任何 SIMULATED 编号时，附录尾追加固定声明：
  「本附录含模型推演内容（模拟调研/模拟评测）：由 AI 生成，不是真实用户数据，不能替代用户调研。」
- 离线字节级单测（`render_markdown` 是纯函数，比真模型 eval 更准）。

### 3.9 口径红线（违反即设计错误）

1. 不称真实用户数据 / 外部事实；2. 只称"模拟使用者 / 走查 / 建议"；3. 不自动写文档（提案默认不勾，
   写只走确认）；4. 不隐去标签（编号 kind=`simulated`、提案 tag、导出声明）；
5. 不称代表性 / 统计效力、不给分数 / 百分比 / 满意度。禁用词：受访者 / 样本 / 画像 / 发现 / 洞察 /
   结论 / 数据 / 满意度 / 占比。

### 3.10 v1 明确不做

文档区入口（评测已确认版本）、删整棵功能树、persona 自定义、跨轮评测历史、评测报告留存为材料 /
附页、A/B 对比、逐 persona 流式进度（一次 POST 同步返回）、任何分数 / 百分比。

## 4. Global Constraints

- 后端 `PYTHONDONTWRITEBYTECODE=1 python3 -m pytest -p no:cacheprovider` 全绿 + `ruff` 干净；

| 端点 | `POST /api/rounds/{id}/sim-review`（+1；无 keep） |
| 请求 | `{persona_ids: [1..3], feature_slugs: [1..2]}` |
| Round 键 | `sim_review`（dict\|null：evaluated_version / personas / advisories）、`sim_review_runs`（int） |
| 账本 | `kind=SIMULATED`、`external_ref=simulation:review:{round_id}#{persona}@{slug}#{local_id}` |
| 提案 | `sim#1..3`、`origin=PROPOSED`、refs=当趟编号、追加进 `Draft.proposals` |
| 上限 | persona 3 / 功能 2 / 每草案 1 次 / 每 persona 重装 1 次（**第六本账 ≤6 次调用**） |
| 错误 | 门控 409（`TooManySimReviews`=R9）、参数 422（`ShapeError`）、失败 502（`PacketParseError`）+ gap |
| 事件 | 只发既有 `round.updated`（零新事件） |

## 7. 前端交互（终态）

按钮「模拟评测」→ 抽屉「模拟使用者走查（合成，不是用户数据）」
→ 选择区：persona 三勾（默认前 3，最多 3）、功能（默认本轮提案触及的 ≤2，最多 2）→「开始评测」
→ 运行中（一次 POST，转圈）→ 报告区：三档计数 + 常驻声明 + advisories + 逐 persona 展开
（功能 → verdict 标 → 走查步骤表（ok/stuck/guessed）→ 摩擦点（kind / 锚点 / note / 堵住标）→ 验收核对表）
→ 失败：一行人话 +「重跑」；提案区：草案卡"它提议的"组里带 tag「模拟评测依据」，默认不勾。

## 8. 自检（翻车点与规避）

1. `simulation_based` 需要 ledger：GetRound 已传；AbandonRound 的视图不传 → 默认 False，测试钉两态，
   不为一个 tag 给 AbandonRound 加依赖。
2. dig 重置 runs：不重置会让"每份草案一次"卡死新草案；重置写测试。
3. R1/R2 同引一条摩擦 → 先汇总去重再统一发号（重复编号会让证据链脏）。
4. `augment_draft` 复用 `Draft.__post_init__` 查重，不新写校验（零新轮子）。
5. 整合已有同 entry 的 remove + 评测 remove → 既有 `merge_duplicate_removes` 在装配/写入两处合并，
   加一条测试钉住"评测提案不破坏该机制"。
6. 3 persona 并行 + 脚本网关会乱序 → `ScriptedModelGateway` 加 `persona_replies`（按
   `metadata.persona_id` 取，agent 调用时带上），否则 e2e 闪断。
7. acceptance 全覆盖筛可能让真模型重装率偏高 → 属"诚实优先"的代价，真跑观察；若过高，
   改法（放宽为警告）记录在案再议，不先砍。
8. 提示词槽位四处同步（md 的 `$` / `PROMPT_SLOTS` / `test_prompt_library` / `test_llm`）——
   测试会强制看见，不靠记性。
9. 并发写：三人 gather 全部在事务外调用，只有一个事务落库（同 RunSeatRound 先例）。

## 9. 砍掉清单（B1 → 本版）

| B1 | 处置 | 理由 |
|---|---|---|
| `would_use_again` | 砍 | 无机械消费者；态度预测与学术前提冲突 |
| `abandon_trigger` | 砍 | 与 blocks_flow / verdict_because 重复 |
| 条目级丢条 + notes 通道 | 砍 | 报告整体性（§3.4）；少一整套丢弃语义 |

| 文档区入口 / persona 自定义 / 删功能树 / 评测历史 | 不做 | v1 范围（B1 同） |

## 10. 最终模样（实施后）

草案卡底部按钮从一枚变两枚：「去模拟调研」（加）与「模拟评测」（减）。点后者，抽屉里先勾人和功能，
开始后等半分钟，报告出来：`顺 2 / 有摩擦 1 / 走不通 0`，逐人展开能看到"第 3 步：点导出——
文档没写新手引导，只能猜"，"AC-2 '及时'没有量级"。若有 ≥2 人说同一条走不通，草案"它提议的"组里
多一条「删一条」，标着「模拟评测依据」，默认不勾；你勾了它、确认，文档少一条、版本 +1——
回退随时可用。导出里那条编号标注「模拟推演（未验证）」，页脚常驻"不是真实用户数据"。
