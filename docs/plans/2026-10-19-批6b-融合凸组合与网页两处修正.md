## 病根（一句话）

**离散门控 + 纯名次 = 丢掉了分数幅度**。我们的融合是「覆盖率分档（1.0 / 0.5 / else）+ 档内按语义名次排」：
BM25 说"这块多强"被一个阈值拍成两档，档内再按语义重排 → 强度信息彻底没了。
症状：查询多一个字（覆盖率 1.0→0.8）就整档掉，**BM25 挣到的第 1 位被语义掀翻**。

## Global Constraints

- 判据**先注册再跑**：`逐字/换序` 的 top1 与 recall@5 **不低于纯 FTS5**；`同义改述` 的 recall@5 **高于纯 FTS5**。
- **不改协议**：`MaterialRetriever` / `MaterialHit` / `MaterialVectorIndex` 签名一律不动。
- **零新依赖**（本批明确不引库）。
- 真模型口径：两个 embedder 都**已归一**（范数 1.0，实测）→ `cos = 1 - d²/2`（L2 距离换算）。
- 向量侧的 KNN 要**距离值**：`SELECT chunk_id, distance FROM material_chunks_vec WHERE embedding MATCH ? ORDER BY distance LIMIT ?`（实测可用）。

## 明确不做

| 不做 | 理由 |
|---|---|
| **主内容抽取（trafilatura 等）** | 本轮只做零依赖的两件；主内容抽取**另起一轮**，先建我们自己的页面集基准（现在 `.codex/runs/` 零真实网页 HTML，也没有任何"正文 vs 样板"标注集）。没基准就动库 = 重跑已判死的实验（readability 那次） |
| **重排（cross-encoder）** | 收益最大（MRR 0.873→0.941）但要新模型 + 推理延迟 + Recall 会掉一条；另起一轮 |
| **换嵌入模型（gte-zh / m3e / bge-m3）** | 中文榜单上 gte-zh 略胜 bge-zh，但**换模型 = 全量重算向量 + 口径版本变更**；且我们连基线都还没建全，不急在这一轮 |

## 如实声明

1. **我们没有任何真实网页 HTML 样本**（`.codex/runs/` 零 HTML），也**没有"正文 vs 样板"标注集**——
   这正是主内容抽取要"另起一轮"的原因。
2. **α 与归一化方式是在我们自己的语料上量的**（批 5 合成语料 + 真 Tavily 冻结语料），
   样本量不大（每类 40 条），**换语料可能要重调**。
3. 中文 FTS 的 OR 匹配 + 不过滤停用词，让"改述类基线"天然不低——判据只能是**增量**。
