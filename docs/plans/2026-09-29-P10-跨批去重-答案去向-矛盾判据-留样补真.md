### 0.1 六处同根：题号不是身份

**证据编号（`E1…En`）本身没问题**——账本按项目单调分配，唯一、不复用、可跨轮引用。
错的是**指针**：题号在一轮里每批从 `q1` 重排，于是所有"按题号回查"的地方都可能指到别的批（甚至别的轮）。

| # | 位置 | 症状 | 谁受害 |
|---|---|---|---|
| 1 | `application/context.py:235-274` `render_answers` | 答案行挂**别的批**的题面 | 席位 + 整合者（模型分不清哪条答案答的哪道题） |
| 2 | `application/context.py:289-295` `_answer_eid`、`:277-287` `answer_eids` | 编号只按裸题号找（`setdefault` 取第一条）→ **第二轮引到第一轮的答案** | 归因污染（写进文档的 `evidence_refs` 指错人） |

### 0.2 这次新查出来的证据（三段探针，先看这个）

**证据 1（探针 1）· 第二批的答案挂错了题面、还挂着第一批的编号**（`/tmp/probe_answers2.py`）：

构造：第一批 `f1/q1`「第一批量级是多少？」答"10万"（真编号 **E1**）；
第二批 `f2/q1`「对端不可用时怎么降级？」答"重试三次"（真编号 **E2**）。模型实际看到的：

```
- q1 对端不可用时怎么降级？ → 10万〔E1〕
- q1 对端不可用时怎么降级？ → 重试三次〔E1〕
（引用用户的回答请用它的 E 编号，题号 q1 不是出处编号）
```

**两行都挂第二批的题面，两行都写 E1**——E2 在提示词里**根本没出现**。
后果有两层：① 模型根本分不清哪条答案对应哪道题（这就是 F6"反复问同一件事"的机理：它以为那件事没答）；
② 提示词明确要求"引用用户的回答请用它的 E 编号"，于是席位/整合者会**把第一批的答案当第二批答案的出处**——
在一个以"每条内容可回溯"为核心承诺的产品里，这是**归因污染**，不是文案瑕疵。

**证据 2（探针 2）· 写范围也指错**（`/tmp/probe_scope.py`）：`Round.write_scope` 同样是按裸题号去**当前**问卷里反查已答题的去处：

```
本轮去处（write_scope）: ['s2', 's8']
  期望：s2（主张）+ s5（第一批答过的那道题的去处）
  实际：s8 混进来了，s5 丢了 —— 因为按 q1 去当前问卷（f2）里反查
```

**证据 3（离线复现）· `outside_scope_items_are_labeled` 与 P8 置顶告警互斥**：

```
advisories: 2
  - ⚠ 这一轮一条功能内容都没有：你点到了「order-export」1 个功能，但草案里 s5 没有任何提案。…
  - s1：这条落在 s1，不在本轮去处里（席位替你判断的，确认前请看一眼）
labeled: ['p01']
ASSERT: 跑出本轮去处的条目与顶部提示的标注对不上：卡片上标了 1 条、顶部有 2 条
```

判据拿"顶部提示总行数"和"带标注的提案数"比相等（`evals/assertions.py::outside_scope_items_are_labeled`），
而置顶告警**不挂在任何提案上**。只要两者同时出现，真模型 eval 就会红——现在没炸只是用例没同时命中。

## 2. 口径（要作者拍板）

### D1 · 写范围按**功能级**匹配（这就是"a"）

**现在是什么样：** `Round.write_scope`（`domain/round/round.py:274`）收的是**主张的精确 target**。
主张点了 `s5/order-export.one_liner`，写范围就**只有**这一个字段；`ScopeGuard` 用
`Target.is_within`（`domain/services/scope_guard.py:36`）判"这条内容在不在范围里"，
`is_within` 的语义是"scope 给了 field 就必须相等"。于是：

| 主张点了 | 整合者写了 | 今天的结果 |
|---|---|---|
| `s5/order-export.one_liner` | `s5/order-export.goal` | ❌ 报"跑出本轮去处" |
| `s5/order-export.one_liner` | `s5/order-export.acceptance` | ❌ 报 |
| `s5/order-export.one_liner` | `s5/another-feature.name` | ❌ 报（对） |
| `s8.compatibility` | `s8.security` | ❌ 报（对） |

而 P8 的提示词（`02` §11.0.9 口径三）**明确要求**"主张点名过的功能已授权，内容要落到功能字段，拿不准也别降级成章节级"。
提示词推它写全字段、写范围只认一个字段——**自己跟自己打架**，真跑里一轮刷出 20 条 advisory。

**A 是什么：** 写范围**折叠到功能级**——只要主张点过这个功能的**任意字段**，这个功能的**全部字段**都算在范围内。
实现落在 `Round.write_scope`（把带 `feature_slug` 的 scope 换成 `Target.body(section_id, feature_slug=slug)`），
**不改 `Target.is_within`**（它仍是"子树包含"这个纯原语，策略只在一个地方）。

| 主张点了 | 整合者写了 | A 之后 |
|---|---|---|
| `s5/order-export.one_liner` | `s5/order-export.goal` / `.acceptance` / … | ✅ 不报 |
| `s5/order-export.one_liner` | `s5/another-feature.name` | ❌ 仍然报 |
| `s8.compatibility` | `s8.security` | ❌ 仍然报（**只对功能字段放宽**，章节槽不放宽） |

**A 不动什么：** 它只是**提示**通道的口径（`02` §3①：跑出本轮去处只标注、不拒绝）。
不得新增未授权功能子树这条硬约束在别处（`assembly.assemble` 的 `pending_features` → `new_feature_yes` 决策题 + `Document.apply`），
一个字都不动。

**为什么不选 B（advisories 折叠计数）：** B 只让它"看起来短"，语义仍然错——同一功能的其它字段本来就不该算跑出去处。
B 还会把"每条内容一条标注"的诚实性换成一行计数（`evals/assertions.py` 就是靠"两处一致"抓漂移的）。
真要 B，也应该在 A 之后当**补充**（A 之后残留的越界条目通常已经是个位数）。

**A 的残留风险：** 主张点了功能的一个字段，模型可能去写这个功能的 `dependencies`（其实用户没提依赖）。
它会被标成……什么都不会标。接受：这个功能是用户点名要的，写它的其它字段属于"在这个功能的范围内把话说完"，
而且内容本身仍要带出处（`evidence_refs` 少一条就整轮不合格），不是凭空编。

### D2 · "问过"包括"已跳过"

去重的身份仍是 `question_key = (去处, 归一问法)`（`assembly.py::question_key`）。
种子里同时放**已答**与**已跳过**的题：

- 已答 → 结论由 `T7` 保证有去向（被引用或机械落地），不留缺口；
- 已跳过 → 出草案那一刻已经按题面后果落成 s11 未决条（`open_question_proposals`），
  同一轮再问一遍等于当着用户的面反悔（用户刚说"跳过"）。

### D3 · 答案去向：**引用或机械落地**

跨轮去重的真相源只有**文档**（作者定过：`P9` 明写"不新建表、不搞第二真相源"；`PROJECT.md`/记忆层 v1 不做）。
一条答案要是不落进文档，下一轮**必然**再问一遍——这就是 F6 跨轮那一半的根。

口径：**出草案那一刻，装配层核查每条答案的出处编号有没有被这一趟的提案/题目引用；没有引用的，机械落一条提案**：

- 「去处」= 那道题的 `target`；
- 「文本」= `用户已定：<选项文案 或 自由文本>`（**用选项文案，不用 `new_feature_no` 这种机器 id**）；
- 「出处」= 这条答案自己的 E 编号；`origin=user`（用户自己说的话，卡片上默认勾选）。

**不落地**的三种情况（都写进执行结果，不许含糊）：

1. 题的 `target` 是**未授权的新功能 slug**（`new_feature_*` 决策题）——机械落地等于凭空建一棵功能子树，
   直接撞硬约束；这一条的用户决策已经被 `authorize_new_feature` / "不新建"这两条结构动作消费掉了。
2. 这道题**来自 s11 未决条目**（`carried_sources` 里有它）——答完已经有机械 `remove`（P9）把它撤下，
   再 ADD 一条 s11 会当场对冲。
3. 答案已经被引用（那就是整合者干完了活）。

### D4 · 题号在**轮内单调**（不再每批从 q1 重排）

"统一编号"这件事要对**题目**也做一遍：证据编号是按**项目**单调发的（所以 `E` 号天生唯一），
题目编号现在只按**批次**发（每批 `q1…q5`），于是同一个轮次里 `q1` 有两个意思。改成**按轮次单调发**：
第一批 `q1–q5`，第二批从 `q6` 起，第三批接下去。轮内唯一 + 证据自带 `round_id`
⇒ **答案的身份 = `(轮次 id, 题号)`，不需要给证据加字段**。

连带效果（都是变好）：
- 提示词里可以一直用 `qN` 指题，不再需要 `f1#q1` 这种两段键；
- `carried_sources`（P9 为了绕开重排而引入的 `form#qid` 键）**保留但不必要**，界面与代码都不用动；
- 后面若要"一条答案一行"地引用，指针不会重。

**代价（要作者点头）**：几处既有测试里"第二批的题号是 `q1`"这个假设要改成 `q6` 之类——
**这是编号口径变更，不是为了让实现变绿**（`tests/application/test_integrate_answers.py` 里最多 2–3 处，
`test_assembly.py` 若有断言批内编号的地方一并说明）。改测试时必须在提交信息里写清"为什么口径变了"。

### D5 · 老库兼容与回退（宁可不显示，也不显示错的）

- `rounds.payload.questionnaire_history`：老行没有这个键 → 读侧回落到 `(questionnaire,) if questionnaire else ()`，
  也就是"老行只有当前这一批"，**不编历史**。
- 老库里已经每批重排过的题（同一轮里两个 `q1`）：按 `(轮次 id, 题号)` 查会**撞上两条**——
  撞上时**不显示 E 编号**、题面找不到就只写题号；绝不给一个可能错的编号。
- `model_calls` 加三列：`connect()` 里做**幂等** `ALTER TABLE`（先 `PRAGMA table_info` 看有没有），
  `USER_VERSION` 1 → 2。留样表本身就是可丢的（`02` §5.3：要清就 `DELETE`），但**不主动删数据**。

### D6 · 为什么**不能**照搬"把所有证据堆成一个数组灌进上下文"

作者的直觉（"统一编号 → 给模型 → 它就能引用"）**已经实现了，而且这套机制是对的**：
出处账本按项目单调发号（`E1…En`），`known_eids` 全量进校验（写不存在的编号整轮不合格），
编号在主张/席位意见/答案上就地渲染。**这次错的不是编号，是"这条答案的编号是哪一条"这个反查**（§0.2 六处）。

但"全部证据原文堆成一个数组"这条不能照做，两个原因：

1. **它会掩盖而不是修好**：清单只救第 1 处（模型看得见"E1 的原文是 10 万"）。
   另外五处是**系统自己按题号动手**（落 s11 的题面、撤下未决项引的编号、写范围），
   模型看不到、也帮不上——错照样发生。
2. **体积无界**：一项目跑到第 10 轮，出处条数轻松几百条（主张片段 + 每席位判断 + 每道答案 + 每次降级），
   全量原文每轮重灌 = 提示词线性膨胀（现在 integration 提示词就已经 17k–20k 字符，报告 §四）。
   现在的渲染是**有界**的：文档现状 + 本轮主张 + 本轮席位意见 + 本轮问答——证据原文只出现在相关的地方。

要给"全量出处清单"的话，它得配一个**索引/摘要层**（按需取、折叠、只给编号+一行摘要）——
那是 v1 明确不做的部分（`P6` 留位）。所以本轮**不新增全量清单**，只把指针修准。
