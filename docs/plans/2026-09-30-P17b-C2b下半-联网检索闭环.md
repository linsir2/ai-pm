## 2. 四条必须先定的口径（不定就会返工）

### 2.1 「编号 == 带进提示词的块」在联网这条路上也必须成立（**P17 没说清，必须补**）

**问题**：两把尺子量同一件事，必然对不上号。

- `context.select_chunks` 的成本是 `len(chunk.text) + CHUNK_OVERHEAD`（24）；
- `context.render_web_results` 的成本是整块 `[编号] 标题\nURL\n摘要`——
  标题 + URL 通常再加 60–120 字符。

拿默认成本把 6 条检索结果选进 `Round.materials`（发 6 个号），渲染时第 6 条可能因为
**标题 + URL** 超预算而没被写进提示词 → **账本里多出一个模型永远看不到的编号**，
正好踩穿 §8 那条不变量（也是作者反复强调的"证据不能凭空"）。

**建议**：选块仍然只有一个决策点，但**成本函数可注入**：

```python
# application/context.py
WEB_EID_RESERVE = 12  # "[E123456] " 的上界；选块的成本 ≥ 渲染的成本，渲染就不会再截

def select_chunks(
    packets: Sequence[MaterialPacket],
    *,
    budget: int = MATERIAL_BUDGET,
    cost: Callable[[MaterialPacket, MaterialChunk], int] | None = None,  # 新增，默认原口径
) -> tuple[tuple[str, MaterialChunk], ...]: ...

def web_block_cost(packet: MaterialPacket, chunk: MaterialChunk) -> int:
    """与 `render_web_results` 的排版**同源**的成本：标题 + URL + 摘要 + 编号位。"""
```

联网那条路调 `select_chunks(web_packets, budget=WEB_BUDGET, cost=web_block_cost)`。
`render_web_results` 的 `budget` 参数**保留**（当安全网），但要有一条测试钉住：
**选出来的块，渲染时一条都不会再被截掉**（`truncated is False` 且
`used_chunk_ids == 选中的 chunk_id`）。

### 2.2 「没勾 = 一次网络调用都没有」，而且这个判断**只在一处**

- **默认不勾**（联网是花钱 + 花时间的事，要用户显式授权；与席位的"默认全勾"不同——
  席位是本地模型调用，不花钱）。备选：跟席位一样默认全勾（作者可改）。
- 判断只发生在 `SubmitOpening`：没有勾中的检索词 → 网关**一次都不被调用**（测试用记录替身钉死）。
- **后端也要拦**：勾了检索词、但服务端没配网关 → `ShapeError`（422），
  与"席位 id 不在注册表里"同一个口径（"你给的东西现在办不了"，不是领域不变量被破坏）。

### 2.3 模型给多了 / 给歪了的检索词：**丢那一条 + 留痕，不重跑整轮**

P17 原稿写的是 `Field(max_length=3)` → 模型给 4 条就 `too_long` → 整包重装一次
（真跑一次几十秒）；给 5 条还是too_long → **整轮判死**。这与仓库已经定下的口径冲突：
席位提名越界、互斥对子序号越界，都是**丢那一条 + 留痕**（`analyzer.py:196/300`）。

**建议**：schema 里**不设 `max_length`**，把上限写进字段描述（"最多 3 条"）与提示词，
在解析层丢超出 / 丢没有 `why` 的，各留一条痕。**备选**：照 P17 原稿严格判死
（代价是每个越界都要一次重装，最坏整轮失败）。

### 2.4 检索到了、但预算带不进去的那几条，要不要告诉用户？

P17 §9·3 写了"界面说'还有 N 条没带进去'"，但**上传材料靠材料卡的"只带了 N 块 / 共 M 块"**，
检索结果没有对应的显示口：没被发号的包不在 `RoundView.materials` 里（那个投影只含**带进去的块**），
所以用户看不见"搜到 15 条、带进去 6 条"。

**建议**：走**已有的留痕通道**——`Round.dropped(source=TOOL)`，
`handle="联网检索结果 15 条"`、`reason="预算只带得下 6 条，其余没进提示词（材料表里都留着，搜得到）"`。
这样闭环区末尾那一行就是用户看得见的"工具这一趟拿了什么、用了什么"，
和"检索失败"共用同一个显示口（T10 要给 `tool` 单列一句）。
**备选**：只在提示词里对模型说（用户看不见）。

**事务边界（这一步最容易写错，按顺序来）**

```text
0. 只读：round_ = rounds.get(round_id)（不开事务）
1. 校验（都在写之前）：席位在注册表里 / 勾中的检索词 ≤ tool.max_queries / 勾了但没配网关 → 422
2. **事务外**：对每条勾中的 query 调 WebSearchGateway.search(query, limit=max_results)
3. **事务外**：每条结果 → ParsedMaterial → MaterialStore.put 盖章（URL 去重）
4. **事务外**：select_chunks(web_packets, budget=WEB_BUDGET, cost=web_block_cost) → 这一轮真正带进去的块
5. **一个事务**（写入只有这一处）：
   a. 应用复述卡（席位 / claim_edits，原有逻辑）
   b. round.submit_opening(seats=..., web_queries_chosen=勾中的)
   c. 失败 → round.note_dropped([DroppedItem(source=TOOL, reason="检索失败：<人话>")])，**继续跑**
   d. 成功 → 逐块记 external 出处（external_ref = URL）→ round.add_materials(...)
   e. 检索到但没带进去的 → note_dropped(source=TOOL)（§2.4）
   f. 保存 round / evidence
6. 事务外：_publish(...)（与现在一样）
7. 图接着走 seat_round → integrate（席位与整合者读到的 external_material 里已经有检索结果）
```

**为什么"先查、后写"而不是反过来**（这是与 P17 §5·T10 的顺序差别，理由要留在代码注释里）：
如果先提交复述卡（把轮次推到 `seats_running`）再去查，进程在查的中间挂掉，
重试会按 `RESUME_ROUTES` 直接进 `seat_round`——**用户授权的检索被静默跳过**。
先查后写的话，最坏情况是"材料库里多了一份没人引用的包"，用户重进还停在复述卡，能重来一次。

## 10. 与 P17 v3 的偏差（6 条，都写了理由）

| # | P17 v3 怎么写 | 这份怎么定 | 为什么 |
|---|---|---|---|
| 1 | T9 就把"没勾不联网"钉住 | 这条测试挪到 **T10** | 那一刻 `SubmitOpening` 才拿到网关；T9 里写等于先造一个没人用的注入口 |
| 2 | `ClaimsPacket.web_queries` 用 `max_length=3` 严格判死 | 上限只写在描述 + 提示词，解析层**丢+留痕** | 与席位提名 / 互斥对子同一个口径；判死要整包重装，最坏整轮失败 |
| 3 | 检索结果"用 select_chunks 选中后发号" | **成本函数可注入**，联网用 `web_block_cost` | 否则标题 + URL 会把渲染挤到预算外，编号与提示词对不上（§2.1） |
| 4 | 契约清单里没有"工具能不能用" | `RoundView.web_search_available` | 没密钥时复述卡不能出现那一栏；前端不该自己猜 |
| 5 | 没写 `external_material_text` 怎么合两段 | 按 `origin` 分流：上传走 `render_materials`，检索走 `render_web_results` | 两段的排版/预算/截断话术都不一样 |
| 6 | 检索"先落库再查"（T10 的 1→5 步） | **先查后写**，写入只在一个事务里 | 崩在中间的话，"先写"会静默跳过用户授权的检索（§6 说明） |
