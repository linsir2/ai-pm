## 2. 口径（要作者看的几条）

| # | 口径 | 理由 |
|---|---|---|
| C1 | 题序只调**顺序**、不改配额：`carried` → **引了用户主张的题** → 其余按模型给的顺序 | 用户明确说过的先问，是 F12 的最小修法；不动"一批 5 题"这个产品口径 |
| C2 | "同去处收口"**只在 carried 与新题之间**生效，且被丢的那条**必须留痕** | P6 定过"同一去处上的两件事照问"，所以这条不能推广到普通新题；留痕让用户查得到"你那句话为什么没再问" |
| C3 | 每批 carried 从 2 提到 3；**不设"必须清零"的目标** | 产生（一轮暴露 ~15 条缺口）本来就可能大于消化（一轮最多 6 题）；把"阻塞未决"当成**随交付物一起给的清单**，比假装能清零诚实（这条请作者点头） |
| C4 | 补齐度是**纯投影**，进 `gaps` 不进 `advisories` | advisories 是"要你看一眼的提醒"，gaps 是"还差什么"——进度属于后者；前端已经在渲染 gaps |
| C5 | `list_items` 的真相源是**轮次**（累积），不再是当轮问卷 | 与 `deferred`/`questionnaire_history` 同一个范式：老行 `.get` 回落 |
| C6 | 互斥对子由 analyzer 报、装配层盖章；整合者**不许重报**、只负责出题 | 判断做一次、做在读原话的地方；系统盖章保证 label 不会因为模型省略而消失 |

```python
def _asks_user_something(refs: Sequence[EvidenceId], *, ledger: EvidenceLedger) -> bool:
    """这条题的依据里有没有**用户自己说过的话**（主张 / 问卷答案）——F12 的排序用它。"""

    return any(
        ledger.get(ref).kind in {EvidenceKind.USER_INPUT, EvidenceKind.CARD_ANSWER}
        for ref in refs
    )
```

`assemble` 里把 `for index, item in enumerate(packet.questions, ...)` 收集成列表后**稳定排序**：
`sorted(new_questions, key=lambda pair: 0 if _asks_user_something(pair[1].evidence_refs, ledger=ledger) else 1)`
（Python 的 `sorted` 稳定，同组内保持模型给的顺序。）

```python
def _feature_progress(probe: Document) -> str | None:
    """草案卡上的补齐度：必填功能字段填了几个（F10）。纯投影，不改任何东西。"""

    features = [block for block in probe.features()]
    if not features:
        return None
    total = len(features) * len(REQUIRED_FEATURE_FIELDS)
    missing = len(probe.gaps())
    return f"s5 已填 {total - missing}/{total} 个必填字段（还有 {missing} 个空着）"
```

## 4. 数据流（改完之后）

```
analyzer：读用户原话 → 主张 + 席位 + **互斥对子**（c1 ↔ c2）
   ↓（Round.contradictions 持久化）
assemble：carried 先排 → 引用户主张的题排前 → 同去处近义新题让位（留痕）
          → 题目的 refs 覆盖互斥两侧 ⇒ **盖章 kind=conflict**
          → 超 5 题的进轮内队列
   ↓
整合 → 出草案：gaps[0] = 「s5 已填 x/y 个必填字段」；清单项带进轮次
   ↓
草案卡（前端不变：advisories + 分组 + gaps）
   ↓
确认 → 唯一写路径写文档 → 版本 +1
   ↓
下一轮：carried（每批 3 条）回到原章节 + **上一轮的清单项**进提示词
```

## 5. 不做

- 不做"阻塞未决清零"的机制（产生大于消化是算术事实；C3 请作者点头：把未决清单当成随交付物一起给的东西）。
- 不做前端改动（补齐度走 `gaps`、清单项走现有 `list_items` 字段）。
- 不做模糊语义去重（T2 的收口是**限定情形**，不是相似度算法）。
- 不动 `MAX_QUESTIONS_PER_BATCH=5`、不动问卷两批上限、不动写入路径。

## 6. 成功之后长什么样（自检）

1. 用户明确提出的需求不会因为配额被模型自己的题挤掉（T1 的用例 + 真跑看题序）。
2. 同一去处上不再出现"carried 那道 + 新出的近义那道"（T2 的用例 + P11 那个真跑场景复现不了）。
3. 一轮最多消化 6 条未决项；卡片上能看到"还差多少"（T3/T4）。
4. 上一轮记下的清单项在下一轮的提示词里（T5 的用例），不再凭空消失。
5. 用户的"我这条意见为什么没进文档"能查到它说了什么（T6）。
6. `conflict` 由系统盖章：只要 analyzer 标了互斥对子，题目就带 `conflict`（T7/T8 的用例）。
