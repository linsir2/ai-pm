# 修复 · 不配 Redis 时后端起不来（工具/总线生命周期形状错配）

> 状态：设计已拍板（2026-10-18，作者选 **B 方案** + 顺带补 `dev.py` 一行提示）。实现按 TDD。
> 根因由批 2 终审证出并逐行核过；本方案只修形状，**不碰任何事件语义**。
>
> **已实施**：`85238d8`（`app.py` / `container.py` / `dev.py` + 生命周期真启停的 e2e）
> 与 `3f0c31f`（补 `GetWorkspace` 路径的覆盖）。真跑：不配 Redis 起得来，
> `/api/health` → 200，启动横幅打「事件：进程内总线（单 worker，不跨进程扇出）」。

## 0. 根因（一句话）

`container` 把**没有生命周期**的 `InProcessEventBus` 当成 `BackgroundResource` 交给 `create_app`，
而 lifespan 无条件 `await background.start()`——进程内总线**没有 `start`**。

## 1. 现有设计（逐处核过，引用真代码）

```
harness/events/bus.py:19   class InProcessEventBus        ← 只有 publish/subscribe/subscriber_count
                                                             **没有 start、没有 stop**（实测 hasattr → False/False）

api/app.py:90              class BackgroundResource(Protocol)  ← 有 start/stop；**没有 @runtime_checkable**
api/app.py:151             create_app(services, *, background: BackgroundResource | None = None)
api/app.py:160-170         lifespan: if background is not None: await background.start()
                                    finally:               if background is not None: await background.stop()
api/app.py:~171            app.state.services = services    ← 测试可经此拿到真 services（测试设计要用的形状）

container.py:196-205       _build_event_bus(settings): redis_url 为空 → InProcessEventBus()
                                                       否则 → RedisFanoutEventBus(...)（有 start/stop，redis_bus.py:180/191）
container.py:771           app = create_app(services, background=bus)   ← **无条件**传
container.py:776           return Container(settings=settings, app=app)  ← **不暴露 bus**

scripts/dev.py:173-175     redis_url = os.environ.get("PMSTUDIO_REDIS_URL","").strip()
                           if redis_url: print("登录限流：Redis 共享计数（…）")   ← 为空时**什么都不说**
```

**为什么测试没抓到（结构性盲区，两条都核过）**：
1. `tests/` 全仓**零处** `redis_url` → `build_app`（`tests/e2e/conftest.py:62`）的 `Settings(...)` 走默认 `""`；
2. `tests/` 全仓**零处** `with TestClient(...)` → **lifespan 从不运行**。
   → e2e 全绿，`uvicorn` 一跑就炸。

## 2. 修法（B 方案，作者已拍）

| # | 文件 | 动作 | 作用 |
|---|---|---|---|
| 1 | `api/app.py` | `BackgroundResource` 加 `@runtime_checkable` | 让"这东西有没有生命周期"可判；**必须加**——非 runtime 的 Protocol 直接 `isinstance` 会 `TypeError` |
| 2 | `bootstrap/container.py` | `app = create_app(services, background=bus if isinstance(bus, BackgroundResource) else None)`；顶部 import `BackgroundResource` | 只有**真有生命周期**的总线才交给 lifespan；进程内总线不传 |
| 3 | `scripts/dev.py` | `redis_url` 为空时多打一行：`事件：进程内总线（单 worker，不跨进程扇出）` | 运维可见性；与既有"登录限流：Redis 共享计数"那句成对 |

**语义**：`BackgroundResource` 的 docstring 已经写着它表达的是"**谁创建谁负责关**"——
进程内总线没有可关的东西，它**本来就不是** `BackgroundResource`。修的是形状，不是总线。

**砍掉**：方案 A（给 `InProcessEventBus` 加两个空 `start/stop`——那是"建空壳"，与本仓"不建桩不建空壳"相悖）；方案 D（`_build_event_bus` 返回元组——改私有签名、多解一层，表达力不如守卫）；`getattr(background,"start",None)` 式容忍（把类型错配藏起来）；给既有 9 个 `create_app(services)` 调用点加 `background`。

## 3. 数据流（前 → 后）

```
前：uvicorn → lifespan → background=InProcessEventBus() → await .start() → AttributeError → 进程退出
后：uvicorn → lifespan → 该总线的 isinstance(...BackgroundResource) 为假 → background=None → 跳过 → 服务正常起
     Redis 路径：RedisFanoutEventBus 满足协议 → 照旧 start()/stop()（共享订阅 + drainer），**一字不变**
     事件语义：publish 同步投本地订阅者、SSE 订阅、队列满丢最旧 ——**全部一字不变**
```

## 4. RIPR（先红后绿；R/I/P/R 缺一不可）

| # | R 需求句 | I 输入 | P 过程 | R 绿标准 |
|---|---|---|---|---|
| 1 | **不配 Redis 时 app 能起来**（主需求） | `build_app(tmp_path, replies={})`（`Settings` 不带 `redis_url` → `""`） | `with TestClient(app) as client`（**这会真跑 lifespan**）+ `client.get("/api/projects")`（带 autologin cookie） | 不抛 `AttributeError`；起得来、请求不是 5xx |
| 2 | 进程内总线**不是** BackgroundResource（钉住 B 的选择） | `InProcessEventBus()` | `isinstance(bus, BackgroundResource)` | `is False`（若将来有人给它加空 start/stop，这条会红——提醒那是方案 A） |
| 3 | Redis 总线**是** BackgroundResource（防守卫把它也挡掉 = 防"把 Redis 生命周期一起关掉"） | `RedisFanoutEventBus(url=…)`（不 start） | `isinstance(bus, BackgroundResource)` | `is True` |
| 4 | 真传了 background 时，start/stop **都被调**（lifespan 回归锚） | 记录调用的假 `BackgroundResource` | `create_app(container.app.state.services, background=fake)` + `with TestClient(app)` | 进 `with` 后 `fake.started is True`；出 `with` 后 `fake.stopped is True` |
| 5 | 不带 Redis 起服务时**照实说** | `PMSTUDIO_REDIS_URL` 未设 | `python scripts/dev.py --help` 不适用；改为断言 `dev.py` 里那句在 `redis_url` 为空分支（纯文本/单元级） | 输出含「进程内总线」且**不含**「Redis 共享计数」 |
| 6 | **装配点真把"有生命周期"的那个传下去**（防倒退核心，2026-10-18 补） | `Settings(redis_url="redis://…")` 与 `Settings()`（无） | spy 住 `pmstudio.bootstrap.container.create_app`：记录 `background` 后**委托真实现**（不建测试专用生产钩子） | 有 redis → `is not None` 且 `isinstance(..., BackgroundResource)`；无 → `is None`。**变异证据**：守卫改 `None` → redis 极红 |

**#2/#3/#6 才是这一批的防倒退核心**（2026-10-18 更正：原写「#2/#3 是核心」**是错的**，
评审当场证伪——#2/#3 只 `isinstance` 本地造的总线、**不碰装配点**；#4 绕过守卫；#1 在「正确守卫」
与「恒传 `None`」下**都绿**。补上的 **#6** 才是那条：spy 记录真 `build_container` 传给
`create_app` 的 `background`，两极为「redis_url 有 → 非 None 且 isinstance」/「无 → None」，
并附**变异证据**（守卫改 `None` → redis 极红）。）
没有它们，把 container 改成恒传 `None` 就能让 #1 照样绿——
而那就把 Redis 的多 worker 扇出生命周期（共享订阅 + drainer）一起关掉了。

## 5. 测试落点

新建 `backend/tests/e2e/test_app_lifespan.py`（用 `tests/e2e/conftest.py` 既有的 `make_app` 夹具，
它内部就是 `build_app`）。#2/#3/#4 可放在同文件（#4 需要真 `services`，从
`build_app(...)[0].state.services` 取——**这是 `create_app` 里既有的装配**，不是新接口）。

**为什么必须放在 `tests/e2e/`**：本批的 #1/#4 必须真跑 lifespan（`with TestClient`），
而 `make_app` 夹具只在该目录下可用。**不**给既有 9 个 `create_app(services)` 调用点加 `with`（超范围、拖慢套件）。

## 6. 架构图

```
                       ┌─ redis_url 非空 ─→ RedisFanoutEventBus ──┐ (有 start/stop：共享订阅 + drainer)
_build_event_bus ──────┤                                          ├─→ create_app(background=…)
                       └─ redis_url 为空 ─→ InProcessEventBus ────┘     lifespan: start() / stop()
                                                   │                       ▲
                              不再是 BackgroundResource ────────────────────┘
                              → container 传 None（**本修复**：第 2 步那行守卫）
```

## 7. 自检

- **最小**：2 个源文件各 1~2 行（decorator + 守卫 + import）+ `dev.py` 1 行；测试 1 个新文件。
- **只改根源**：修"形状错配"，不碰事件语义、不碰 Redis 实现、不碰 SSE。
- **不假实现**：#1/#4 用**真跑 lifespan** 的姿势（这正是测试一直缺的那一步），不是断言"函数存在"。
- **真实业务跑通**（收口必做，写入 `.codex/runs/2026-10-18/Redis修复-证据.md`）：
  ① `uv run python scripts/dev.py`（**不带** `PMSTUDIO_REDIS_URL`）真起服务 → 打出一行进程内总线提示
  → 一次真 HTTP 请求 200；
  ② 带上 `PMSTUDIO_REDIS_URL=<测试 Redis>` 再起一次 → 打出"Redis 共享计数"那行 → 起得来（回归锚）。
  只有 ① 不算完成：② 是"没把 Redis 那条路一起关掉"的证据。
- **终态**：不配 Redis 一条命令起服务、界面连上、SSE 收得到事件（进程内扇出）；配了 Redis 多 worker 扇出照旧。
