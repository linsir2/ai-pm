# 批 10 方案：切点规则（标点优先）+ 父子分块 + 预算硬上限

> 实现依据：`docs/plans/2026-10-20-批6c-联网材料入库口径.md`（批 6c 口径）、
> `.codex/docs/设计/02-编排与数据.md` §11.0.80–§11.0.83（批 6c/7/8/9 的口径与实验）、
> `04-未决.md` E6。
> 实验脚本：`backend/scripts/{chunking_experiment,chunking_variants,retrieval_bench,
> context_layer_bench,rerank_experiment}.py`（真语料 + 真模型，可复跑）。
> **作者的三条决定**（2026-10-21）：① 切点要在**预算周围**找**句末标点**，
> 块大小**有区间**、不分断；② **父子分块 = 子块检索、父块返回**；
> ③ **先修预算硬上限**。

---

## 0. 一句话

**切点规则**从"行优先"改成"标点优先、贴近预算"（块数 −14%、不分断）；
**父子分块**（子块检索、父块返回给用户）把跨块证据完整率 **0.357 → 0.714**；
**预算硬上限**先修（现在保底机制会突破 4000 字，实测喂到 6477–16609）。

## 1. 三个问题的实测依据

### 1.1 切点规则：标点优先 vs 行优先（现状）

| 变体 | 块级 r5 | 材料 r5 | MRR | 跨块(检索) | **块数** | 上下文(块/份/字) |
|---|---|---|---|---|---|---|
| 行优先 200 | 0.800 | 0.800 | 0.736 | 0.267 | 1446 | 25/25/3608 |
| 行优先 300 | 0.750 | 0.750 | 0.777 | 0.400 | 1116 | 17/17/3513 |
| 行优先 400（现状） | 0.750 | 0.800 | 0.744 | 0.357 | 945 | 14/14/3906 |
| 标点优先 200 | 0.750 | 0.800 | 0.666 | 0.467 | 1197 | 23/23/3513 |
| 标点优先 300 | 0.700 | 0.750 | 0.753 | 0.571 | 929 | 19/19/3812 |
| **标点优先 400** | 0.750 | 0.750 | 0.723 | 0.429 | **815** | 13/13/3906 |

**显著结论**（n=20/14，5 点 = 1 条查询，其余都在噪声内）：
- **块数 945 → 815（−14%）**：块贴近预算 → 同样的内容用更少的块 → **向量成本降**；
- 定位/排序**在噪声内**（块级 r5 0.750 持平，MRR −2.1）。

### 1.2 父子分块：子块检索、父块返回

| 变体 | 跨块(检索) | 跨块(上下文同框) | 上下文(块/份/字) |
|---|---|---|---|
| 行优先 400（现状） | 0.357（5/14） | 0.000 | 14/14/3906 |
| 标点优先 400 | 0.429（6/14） | 0.000 | 13/13/3906 |
| **标点优先 父子 300→1200** | **0.714（10/14）** | 0.000 | 19/18/**14734** |

- **跨块(检索) 0.357 → 0.714**：差 5 条 → **超出噪声** ✓
- **上下文同框率仍为 0**：我的跨块查询两处证据**相距 4 个子块**，父块 ≤1200 字
  刚好**跨过父块边界** → 提示词层拿不到 → **父块只对展示层有效**（作者说的
  "子块检索、父块返回"正是这个形态 ✓）
- **上下文字数暴涨**（14734 vs 3906）→ 必须先修预算硬上限（作者已决定先修 ✓）

### 1.3 预算硬上限：现在不是硬上限

`select_chunks` 的"每份材料至少露出它自己的第一名"（保底）会**突破** `MATERIAL_BUDGET`：
实测喂到 **6477–16609 字**（预算 4000）。**父块方案会把超支放大 3 倍** → 先修。

## 2. 范围

### 做
1. **切点规则**：块内按**句末标点**切句、贪心装到上限；**标题行仍然起新块**（保住 `heading_path`）。
2. **预算硬上限**：`select_chunks` 的保底不得突破预算（保底块装不下就**不给**它保底）。
3. **父子分块**：**子块检索**（现状不变）、**父块返回**（展示层：命中子块 → 返回它所在的父块）。
4. **父键不新增数据库列**：父键 = `(material_id, heading_path, ordinal // N)` → **可推导** ✓

### 不做（明确）
- **cross-encoder 重排**：实测延迟 33.8–58.3 秒/查询、词面块级精度倒退 0.950→0.700
  → 要重排得有 GPU（`02 §11.0.83`）。
- **换嵌入模型**：CPU 上每轮 ~108 秒（`04-未决` E6 已归档）。
- **提示词层用父块**：同框率 0 + 字数暴涨 → 只在展示层用。

## 4. 逐文件、每一步

### 4.1 `tools/limits.py`：切点规则（标点优先、贴近预算）

- 新增 `SENTENCE_SPLIT` 用的正则（保留标点）。
- `parts_of` 的下刀优先序：**句末标点 → 换行 → 硬切**（原：换行 → 句末 → 硬切）。
- 关键：切点必须是**完整句**（标点跟着前一句走），**不丢内容**
  （第一版实验用 `re.findall` 丢了行尾 → r5 假跌，已修，见 `scripts/chunking_variants.py`）。

### 4.2 `tools/extract.py`：`chunk_text` 仍是"标题起新块 + 块内按标点装"

- 标题行起新块**不变**（`heading_path` 靠它）。
- 块内累积：从"逐行累积"改成"逐句累积"（句 = 标点分隔），超上限就切。

### 4.3 `application/context.py`：
- **预算硬上限**：`select_chunks` 的保底（每份材料至少 1 块）改成**装不下就不保底**
  （并在渲染里说清"有 N 份材料因预算装不下没带进来"）。
- **父块回喂**：渲染时把子块替换成父块（**子块 id 与编号不变**，父块文本是渲染内容）。

### 4.4 `application/dto.py`：`MaterialHit` / 渲染视图
- 命中仍按**子块**（编号、锚点、`ref` 都不变）→ **引用链不变** ✓
- 渲染时用父块文本（`render_web_results` / `render_materials`）。

### 4.5 父子参数的**推导规则**（写进代码注释）
- 父块 = **相邻 N 个子块**（N = 父块上限 / 子块上限）。
- 父键 = `(material_id, heading_path, ordinal // N)` → 同一 `heading_path` 内的连续 N 块。
- 父块文本 = 那 N 个子块文本按序拼接（子块是原文的连续片段 → 拼起来仍是原文的一段 ✓）。

## 5. 数据流影响

```
切块：标题行起新块 → 块内按句末标点装句到上限 → 块贴近上限、块数 −14%
  ↓
入库：material_chunks（子块）+ FTS（子块）+ 向量（子块，受 WEB_VECTOR_BLOCKS 预算）
  ↓
检索：粗排 → 融合 → top5（子块）           ← 检索侧完全不变
  ↓
展示：命中子块 → 渲染时回喂父块（相邻 N 个子块拼接）→ 用户看到完整段落
  ↓
提示词：select_chunks（预算**硬上限**）→ 子块 → 渲染（这里不喂父块）
```

**不变式**：写入路径唯一 / AI 不写文档 / 入库量与提示词量是两层 / 编号与引用链不变。

## 6. RIPR 判据

| # | R | I | P | 绿标准 |
|---|---|---|---|---|
| 1 | 切点落在句末标点，块不分断 | 含多句的行 | 块内按标点切句 | 块的**每一行**都以标点结尾或以标题开头；**内容零丢失**（拼回原文与清洗后逐字相同） |
| 2 | 块贴近预算 | 上限 400 的长文 | 贪心装句 | 块的字数中位数 ≥ 上限的 **90%**（现状行优先时远低于此） |
| 3 | 块数不增 | 同一份材料 | 标点优先 | 块数 ≤ 现状的 **90%**（实测 −14%） |
| 4 | 预算变硬上限 | 12 份材料 + 小预算 | 保底不突破 | 渲染出的总字数 **≤ 预算**（现在实测 6477 > 4000） |
| 5 | 父子：子块检索、父块返回 | 跨块查询 | 渲染回喂父块 | 跨块证据完整率 **≥ 0.60**（现状 0.357，目标 0.714） |
| 6 | 引用链不变 | 父块回喂 | 编号/锚点/ref 仍指子块 | 编号、锚点、`ref` 与改造前**逐字相同** |
| 7 | 不丢内容 | 任意材料 | 切块 + 拼接 | 子块拼回 == 清洗后原文（忽略换行差异） |
| 8 | 既有行为不回退 | 全量 | — | pytest 全绿、ruff 净、架构守卫过 |

## 7. 风险与兜底

| 风险 | 兜底 |
|---|---|
| 标点优先让某些块超过上限（长句无标点） | 保留硬切兜底（`parts_of` 的第三级） |
| 预算硬上限会让"用户勾了材料却没带进来" | 渲染里写明"有 N 份因预算装不下没带进来"（`render_materials` 已有类似话术） |
| 父块拼接后锚点与内容不符 | 编号/锚点仍指**子块**（`ref` 不变）→ 用户点开滚到子块位置，看到父块文本 → **需在渲染里说清"这是第 N 段所在的完整段落"** |
| 块数变化 → 已有材料的块结构过时 | 解析器档位升 → 启动维护任务重切（批 7 已建）✓ |
| 上传材料的块也变细 → 向量成本 | 上传材料量小；联网材料块数 −14% → 成本降 ✓ |
