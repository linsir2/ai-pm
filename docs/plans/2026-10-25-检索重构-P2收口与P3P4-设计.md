## 1. 决策

### D1：60/40 改成“有自动候选时的硬保底”

保留原方案的核心：**自动段有 40% 的机会**；但不再让“每份手勾至少一块”无限突破 60%。

规则：

1. `PINNED_BUDGET_SHARE = 0.6` 不变；40% 由 `1 - PINNED_BUDGET_SHARE` 派生，不新增可调常量。
2. 先判断 `auto_feasible`：池里/检索结果里存在**非手勾**块，且它作为该材料第一块的成本 ≤ `usable - int(usable × PINNED_BUDGET_SHARE)`。
3. `auto_feasible = True`：
   - `pinned_cap = int(usable × 0.6)`（2277；严格 ≤60%）；
   - `auto_reserve = usable - pinned_cap`（1519；40.02%）；
   - 手勾/manual 的**总量**不得超过 `pinned_cap`；
   - 地板也只能在 `pinned_cap` 内；某份手勾材料连最便宜的一块都放不进 → **当步不选**，**不写 per-step `Round.dropped`**（`MATERIAL` 的语义是“整轮没进”，per-step 写会让提示词说反话）；由 `material_header` 的“没带进来的仍在池里”说明；
   - 自动段装不满 40% 时**不回填手勾**（auto 是保底机会，不是必须用满）。
4. `auto_feasible = False`（没有自动候选，或自动候选全部放不进 40%）：
   - `auto_reserve = 0`，`pinned_cap = usable`；
   - 手勾可以用满预算；自动候选仍可在剩余预算里尝试；
   - 不新增 `AUTO_UNDERFILLED` drop/日志；不谎称“自动段已保底”。
5. 只对 **SEED / SEAT / INTEGRATE** 三个主路径强制 60/40；`external_material_text` 的 Analyzer/sim 旁路只保证**渲染后 ≤4000**，不强行套 60/40（sim 没有完整的 pool/pinned 语义，强套会制造第二套规则）。

**算法落点（一个纯函数，两处共用）**

```python
@dataclass(frozen=True, slots=True)
class BudgetSplit:
    usable: int
    pinned_cap: int
    auto_feasible: bool

def split_material_budget(
    *,
    usable: int,
    pinned_share: float,
    auto_costs: Sequence[int],  # 非手勾候选块“作为第一块”的成本
) -> BudgetSplit:
    pinned_cap = int(usable * pinned_share)
    reserve = usable - pinned_cap
    feasible = bool(auto_costs) and any(cost <= reserve for cost in auto_costs)
    if not feasible:
        return BudgetSplit(usable, usable, False)
    return BudgetSplit(usable, pinned_cap, True)
```

- `use_cases._pick_materials`：先检索自动段（只读、事务外），拿到 `auto_costs`；用 `split_material_budget` 决定 `pinned_cap`；手勾先选，自动再选。
- `context_pool.select_projection`：池里已有自动候选，直接算 `auto_costs`；同样用 `split_material_budget`。
- `context_pool` 的地板 `take(..., respect_pinned_cap=True)`，不再用总预算绕过 `pinned_cap`。
- 新增 `test_auto_gets_room_when_a_single_pinned_block_exceeds_the_cap`、`test_no_auto_candidates_lets_pinned_use_full_budget`、`test_pinned_materials_never_exceed_the_share_when_auto_candidates_exist`、`test_manual_over_the_cap_is_skipped_when_auto_candidates_exist`。

**代价（作者已知情）**：单块超过 60% 的手勾材料可能当步进不来；这是“自动段保底”换来的。不写 per-step drop；整轮从未进过的材料仍由 SEED 聚合 `MATERIAL` drop 说明。

## 3. Batch B：P3a 统一联网申请

**目标**：Analyzer / 席位 / 整合都能“申请”；用户逐条批准；`allow_web` 可自动批准后续申请；非阻塞；执行一次、结果一条一个 E 号、不进材料投影。

### B1. 数据模型

```python
class WebRequestState(StrEnum):
    PROPOSED = "proposed"
    APPROVED = "approved"
    REJECTED = "rejected"
    DONE = "done"
    FAILED = "failed"

@dataclass(frozen=True, slots=True)
class WebRequest:
    request_id: str          # 用例层生成 w1...
    query: str
    why: str
    origin: Literal["analyzer", "seat", "integrator"]
    seat_id: str | None
    pass_index: int | None
    state: WebRequestState
    result_note: str | None = None
    created_at: datetime | None = None
```

- `Round` 加 `web_requests`、`allow_web`；方法 `attach_web_requests` / `decide_web_request` / `mark_web_request`。
- 去重：同 `origin + seat_id + normalized query`；上限 `MAX_WEB_QUERIES=3`/轮；超出丢条 + `Round.dropped(TOOL)`。
- 旧 payload：`web_queries` + `web_queries_chosen` → analyzer `WebRequest`；有 web 材料才 `done`，否则 `proposed`。
- `RoundView.web_requests`、`allow_web`；`web_queries` 保留为派生字段，前端迁移后再删。

### B2. 三方穿透

- `Analysis.web_requests`、`SeatPacket.web_requests`、`IntegrationPacket.web_requests`（复用 `WebQueryDraft`）。
- `Analysis`/`SeatOutcome`/`IntegrationOutcome` 全链带到 `Round.attach_web_requests`；只加 schema 会静默丢，测试逐站断言。
- 提示词：`analyzer.md` 保留；`seat_review.md` / `integrator.md` 加“何时申请、最多几条、只提名不执行”。

### B3. 执行

- 新增 `application/web_research.py`：把 `SubmitOpening._search/_search_one/_keep/_checked_queries/_record_tool_call` 搬过去；`SubmitOpening` 只调用服务。
- 执行点：
  - `SubmitOpening`：执行 analyzer 的 `approved` 请求（旧 `web_queries` 选中项映射成 approved）。
  - `RunSeatRound` / `IntegrateRound`：进入模型步之前执行所有 `approved`；`allow_web=True` 时先把 seat/integrator 的 `proposed` 自动置 approved；整合者本轮刚提的请求不执行，下一模型步生效。
- 网络/解析在 UoW 外；结果材料、E 号、请求状态、drop 在一个 UoW。
- 失败：`state=failed` + `result_note` + `Round.dropped(TOOL)`；不判死整轮；无半 E 号。
- 一条结果一个 E 号；`origin=web_search`；`render_web_results`；不进材料投影。

### B4. API / 命令 / UI

- `POST /rounds/{id}/web-requests/{rid}/decision`，body `{decision: "approve"|"reject"}`；走 `RoundRunner` 新命令 `decide_web_request`；跑动中 409；不改 `waiting_on`。
- `OpeningRequest` 加 `allow_web`、`approved_request_ids`；`RoundCommand`/`node_opening`/`submit_opening` 全链。
- 前端：
  - `OpeningCard` 逐条勾 = approved；`allow_web` 开关默认关。
  - `WebRequestCard`：query / why / origin / 第三方披露 / 批准 / 拒绝；非阻塞。
  - `progress.ts` 加“有 N 条联网申请”徽标；`round.updated` 仍只置 stale。
  - 纯函数 `webRequestAction`；组件不判业务。

### B5. 验收

- 未授权不执行；approved 执行一次；失败留痕；≤3；一条结果一个 E 号；下一步能看到结果；整合者本轮请求不立即执行；旧 opening 联网测试全绿。
- 真 SQLite + 替身 Tavily 的 e2e；真模型 + 真 Tavily 冒烟（key 已配）作为证据，不放进快测试。

## 4. Batch C：P3b 有界研究

**目标**：闭环区“研究这个” → 有界 agentic（search/fetch）→ 来源入库 → 结构化 findings 带 E 号 → 结果视图；不是模拟调研。

### C1. 工具层

- `infrastructure/tools/research.py`：`ResearchToolbox(search, fetcher, parser)` 实现 `ToolInvoker`。
- 工具：`web_search(query, max_results)`、`fetch_url(url)`。
- 每次研究**新建** toolbox；`sources` 只记成功、URL 去重、≤5；第 6 个在 `invoke` 层直接 `ToolCallFailed("来源已达上限")`。
- `fetch_url` 解析正文，按 `MAX_MATERIAL_CHARS` 截断并写明；`ResearchToolbox` 不碰 DB。
- 应用层定义 `ResearchInvoker` 协议；container 注入，application 不 import infrastructure。

### C2. 用例

- `StartWebResearch`：`run_tool_loop`（`purpose="web_research"`，不带 `response_format`）→ 读 sources → 内存账本 `ledger.record` 拿 E 号 → `ResearchPacket{findings:[{text, refs}], open_questions}` → refs 机械过滤到本次来源 E 集合 → 一个 UoW 保存 materials + ledger + `Exploration(kind=web_research, findings, sources)`。
- 失败：丢弃内存账本；来源材料可留库但无 E 号；exploration `failed`。
- 当前轮若开放（`started/claims_ready/seats_running/awaiting_answers`），把来源挂进当前轮（web 材料，一条一个 E 号）；否则只进材料库。
- 上限：≤6 轮 / ≤12 调用 / ≤5 来源；空 findings 合法。
- `POST /rounds/{id}/research` 走 `RoundRunner` 新命令 `start_research`；网络在 UoW 外；跑动中 409。

### C3. 数据与 UI

- `ExplorationKind.WEB_RESEARCH`、`Exploration.findings/sources`、序列化/DTO/`ResearchView`。
- `harness/prompts/research_synthesis.md`。
- 前端：研究入口（topic）→ 运行态 → `ResearchResult`（findings + E 号 + 来源）；不复用 `KeepCandidate`。
- 不做新抽屉/新中断；沿用现有探索生命周期。

### C4. 验收

- 工具名/schema/未知工具失败/per-run 生命周期；
- URL 去重、≤5、超限报错、正文截断；
- findings refs 只能来自来源；空 findings 合法；失败无半 E 号；
- 当前轮挂载/不挂载两种状态；
- 真模型 + 真 Tavily 冒烟并记录 model/prompt sha。
