# B 组批 5 · 检索向量召回（sqlite-vec + fastembed + RRF）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development（推荐）或
> superpowers:executing-plans 逐任务执行。

**Goal:** 给材料检索补上**语义召回**（换个说法也能命中），用同库向量 + 手写 RRF 融合，
**协议零改**（`MaterialRetriever` 签名与 `MaterialHit` 不动）；模型/扩展不可用时**降级回纯 FTS5**。

**Architecture:**
- **向量不进写事务**（本批唯一的架构抉择，作者已拍 (c′)）：ONNX 推理 ~20ms/块，
  10 块 = 200ms 持写锁，是基线写操作的百倍，与 P5 系列刚拿下的写锁纪律正面冲突。
  所以向量由**独立的 `MaterialVectorIndex`** 在主事务**提交后**写（自己的小事务），
  崩溃窗口由 `migrate` 的**幂等回填**兜底。
- 融合在检索器内部：FTS5 topK + `vec0` KNN topK → `Σ 1/(60+rank)`。

**Tech Stack:** `sqlite-vec`（0.1.9，MIT/Apache-2.0，需 `enable_load_extension`）、
`fastembed` + `BAAI/bge-small-zh-v1.5`（dim 512 / MIT / 0.09GB / ONNX 无 torch）、SQLite 3.51

**Spec:** `docs/plans/2026-10-18-B组-设计.md` §6

## Global Constraints

- **协议零改**：`MaterialRetriever.search(*, project_id, query, limit=5, owner)` 与 `MaterialHit` 一字不动。
- **降级不判死**：扩展载不了 / 模型下载失败 / 推理抛 → 一行 warning，检索走纯 FTS5，上传与检索都成功。
- **锁版本**：`sqlite-vec` 是 pre-v1（有 breaking）——`uv.lock` 锁住；抽象只在 `Embedder` /
  `SqliteHybridRetriever` 两处，换实现只改 `container.py` 一行。
- **真库只读**：全部真跑在副本或 `/tmp`。

```python
"""向量适配（检索阶段 2）：**模型只在这一处**，换模型/换库只改这里 + `container.py` 一行。

`fastembed` 用 ONNX（无 torch），`BAAI/bge-small-zh-v1.5` = 512 维 / MIT / ~90MB，
**懒加载**：不碰检索的进程（绝大多数测试与 CLI）永远不下载模型、不载 onnxruntime。
"""

from typing import Protocol

MODEL_NAME = "BAAI/bge-small-zh-v1.5"
DIMENSIONS = 512


class Embedder(Protocol):
    dimensions: int

    def embed_many(self, texts: Sequence[str]) -> list[tuple[float, ...]]: ...


class FastEmbedEmbedder:
    def __init__(self, model_name: str = MODEL_NAME, *, lazy_load: bool = True) -> None:
        self.dimensions = DIMENSIONS
        self._model = None
        self._model_name, self._lazy = model_name, lazy_load
        if not lazy_load:
            self._ensure()

    def _ensure(self) -> None:
        if self._model is None:
            from fastembed import TextEmbedding  # 延迟 import：不碰检索就不付 onnxruntime 的启动成本
            self._model = TextEmbedding(model_name=self._model_name)
        return self._model

    def embed_many(self, texts):
        model = self._ensure()
        return [tuple(float(x) for x in vector) for vector in model.embed(list(texts))]
```

`database.py`：

```python
def load_sqlite_vec(connection: sqlite3.Connection) -> bool:
    """把 `sqlite-vec` 载进这条连接。**载不了就返回 False**——调用方据此降级，
    绝不因此炸 `connect()`（"缺配置说缺，不是假装有"）。"""

    try:
        import sqlite_vec
        connection.enable_load_extension(True)
        sqlite_vec.load(connection)
        connection.enable_load_extension(False)
        return True
    except Exception as error:  # noqa: BLE001 —— 扩展/平台问题一律降级
        logger.warning("sqlite-vec 载入失败，检索退回纯 FTS5：%s", error)
        return False
```

`connect()` 里在 `migrate(connection)` **之前**调 `load_sqlite_vec(connection)`（`vec0` 表

`_backfill_chunk_index`：在补完 FTS 之后，对"有块无向量"的行补向量——
**扩展不可用就整段跳过**（返回前先 `if not load_sqlite_vec(connection): return`），
逐条 `embed_many([index_source(...)])` 然后 `INSERT OR REPLACE INTO material_chunks_vec`。

```python
#: 材料块规模是十几个，任何 k 在几十的量级都不改变次序；调它属于没有数据支撑的调优。
RRF_K = 60


def reciprocal_rank_fusion(ranked: Sequence[Sequence[str]], *, k: int = RRF_K) -> tuple[str, ...]:
    """把若干"已按相关性排好的 id 列表"融成一个次序。

    手写 10 行：没有值得引的 RRF 库，而 FTS5 已给 BM25、vec0 已给距离，
    这里只需要把两列名次加起来（`07`-style：不引库能说清就不引）。
    """

    scores: dict[str, float] = {}
    for column in ranked:
        for rank, item in enumerate(column, start=1):
            scores[item] = scores.get(item, 0.0) + 1.0 / (k + rank)
    # 同分按**首列出现序**稳定（`sorted` 稳定；先用首列建一次序）
    first_seen = {item: i for column in ranked for i, item in enumerate(column)}
    return tuple(sorted(scores, key=lambda item: (-scores[item], first_seen[item])))
```
