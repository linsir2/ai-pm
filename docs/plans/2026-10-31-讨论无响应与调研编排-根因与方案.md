# 讨论区无响应、调研只复述：根因与修复方案（2026-10-31）

状态：**待拍板**。已完成代码级根因调查与公开资料调研；尚未改代码。

## 0. 三句话结论

1. **讨论区"点了没反应"不是后端慢，是前端静默吞掉了点击**：全局动作闸在别的动作在途时
   `return`，而讨论按钮只按自己那一个 pending 禁用 → 无请求、无 loading、无提示。
2. **研究"联网成功但只复述问题"是设计问题**：工具循环抓到的正文被丢弃，综合只拿到 800 字来源卡；
   schema 里根本没有"回答"字段，prompt 还允许把不确定全部转成开放问题；5 条来源上限被一次搜索占满后
   `fetch_url` 直接拒绝执行，所以真实数据里出现"1 次 search、5 条来源、0 次抓取"。
3. **模拟调研失败是判据过宽 + 一票否决**：`\d+\s*(成|倍)` 会吃掉"成功/成本"，裸词"比例/大多数"
   也命中；整包任意一条命中即整轮失败，重试提示又不告诉模型是哪条哪个字段。

## 2. 公开资料给的设计结论

- Anthropic《How we built our multi-agent research system》：research 属于开放问题，一次性流水线做不了；
  orchestrator-worker + 并行子代理在内部评测上比单代理高 90.2%，但**多代理约 15× token**；
  关键实践是"规划→并行检索→综合→判断是否继续"、子任务要带目标/格式/工具/边界、
  先宽后窄、检索词短、来源质量启发式、以及**把子代理产物落成文件/引用而不是全部挤回主上下文**。
- LangChain Open Deep Research：把"摘要/检索/压缩/最终报告"拆成不同角色的模型调用，
  检索结果先摘要再压缩，最后才写报告；支持 MCP 与多搜索后端。
- 我们当前规模（单项目、5 条来源、单人使用）不需要多代理；**先把单代理循环补成
  "计划→检索→抓正文→综合→缺口复查"的闭环**，把多代理留成后续可插拔的一层。

## 3. 方案（按问题分三块，均最小改动）

### A. 讨论区无响应（纯前端，先修）

1. `run()` 不再静默 return：在途时抛出明确的"当前正在<动作>，完成后再试"，由调用方 toast；
   或返回 `{ok:false, reason}`。二选一，倾向后者（不改既有抛错语义）。
2. 所有"开跑"按钮统一按 `pending !== null` 禁用，并在按钮旁显示"正在<动作>…"，
   不只按自己那一类 pending。
3. 讨论列表加载失败要显示错误与重试，不再伪造成"还没有讨论"。
4. 勾选"先跑一轮调研"时：客户端超时用长档（900s），提交后立刻显示"正在跑调研（最长 10 分钟）"，
   调研完成后自动继续开讨论；调研失败要同时说明"讨论未开始"而不是静默。
5. 每轮 panel 用 `RUN_TIMEOUT_MS`（长档），不再吃 300s 默认。

TDD：`pending="research"` 时点开跑必须出现提示且不发 POST；列表失败显示错误；
`startPanel` 在调研分支使用长超时（用假 client 断言参数）。

### B. 研究：从"来源摘要"变成"读正文再回答"

分四步，全部复用现有 `run_tool_loop` / `ToolInvoker` / Tavily / HttpxWebFetcher / UoW：

1. **计划一步**（新增一次小调用）：把 topic 拆成 1 个主问题 + 2–4 个子问题，各给 1 条短检索词
   （≤6 字为主，先宽后窄）。落进 `Round`/`Exploration` 的 payload，供复查与 UI 展示。
2. **检索与过滤**：搜索结果先做相关性门（域名黑名单 + 必须与子问题共享至少一个关键词 + 每条带
   `score`），只把通过的候选送进"待抓取"；**搜索结果本身不再直接算来源**。
3. **抓正文**：至少抓 `min(3, 候选)` 篇，来源上限从"搜索结果 5 条"改为"**已读正文 3–5 篇**"；
   抓取失败换下一篇（不再因上限直接拒绝）；每篇压缩到 ~1200 字进综合。
4. **综合要有答案**：`ResearchPacket` 增加
   `answer: str`（必须直接回答主问题，禁止复述）、
   `subanswers: list[{question, answer, source_refs}]`（逐子问题覆盖）、
   `unresolved: list[{question, why}]`（只放真正查不到的）。
   保留 `findings` 作为"带出处的证据点"，`open_questions` 改为 `unresolved` 的别名或直接复用。
   prompt 明确：answer 必须是结论句，不得重复 topic；给一个"差例子=复述问题、好例子=给出取舍"的对照。
5. **缺口复查（最多 1 轮）**：综合后若 `unresolved` 非空且预算允许，按 unresolved 生成最多 2 条补搜，
   再综合一次（总模型调用上限写死，例如 计划1 + 循环≤6 + 综合≤2 + 复查1）。

明确不做：多子代理并行（当前规模不值 15× token）；把抓到的全文整段塞进提示词。

TDD/验收：3 个固定主题（含"分页策略怎么选"这个真实失败例），断言
①answer 不含 topic 原句的高重合；②`subanswers` 覆盖 ≥2 个子问题；③每条 answer 至少引用 1 个
**已抓取**来源；④来源里不再出现 Indeed/CURSOR Software 这类词面噪声；⑤总模型调用数在预算内。

### C. 模拟调研校验（三处小改）

1. 收紧正则：`成/倍` 只在数字后且不是"成功/成本/成员"时命中（用 `(?![功本员])` 这类负向断言）；
   裸词"比例/大多数"保留但**只扫 statement**，不扫 falsification/next_step。
2. 由"整包一票否决"改为**丢这一条 + 留痕**（复用 M10 在 `use_cases.py:7042-7131` 的条目级处理），
   剩下合法假设照常出卡；只有全部被丢才判失败。
3. 重试提示定位到 `local_id` + 字段 + 原句片段，让模型能改具体那一条；
   同时给模拟调研的失败样本留痕（`PMSTUDIO_TRACE_MODEL=1` 时进 `model_calls`，
   或落一个只含失败条目的 JSON），否则下次仍无法复核。

## 5. 风险

- 研究多了一次计划调用与正文抓取，**总耗时与 token 会上升**（预计每趟 +2 次模型、+3–5 次抓取）；
  需要给出预算上限与"超时可见"的兜底。
- 收紧正则仍可能漏报（模型真写百分比而表述绕开正则）；因此条目级留痕与可复核比判据本身更重要。
- 讨论区修好只是"能开跑"；panel 质量（3 轮讨论是否产出可收卡）不在本方案范围。

   不是 P3b-1 `project_research.py`；M8 **没有 600s 总闸**。P3b-1 是「研究」页签

3. `loop.text` 的确没被使用；准确说法是"综合阶段只拿到来源卡"，循环内模型是读过工具正文的。

### 6.3 预算闭合（必须一起改，否则 S3/S4 不可上线）

- 现在 `RESEARCH_TIMEOUT_SECONDS=600` 套了两次（循环 `project_research.py:258`、综合 `:293`），
  最坏 1200s，而前端默认 300s。改成**一个总 deadline 包住全部阶段**（外层 `asyncio.timeout(600)` 或统一 deadline），
  综合重试与外层共用；`tests/contracts/test_limits.py` 的 600 断言保持不变。
- 前端三处超时改为长档，但**必须 ≤ 后端总闸**（600s），不能填 900 却让后端 1200。
- "1200 字进综合"只用于综合正文，**不动** `RESEARCH_SOURCE_CARD_CHARS=800` 与来源卡预算。

### 6.4 多代理：现在不做

Anthropic 的 90.2% 增益来自"广撒网、多来源、并行子代理"，其代价约 15× token；我们是单用户单项目、
Tavily、≤5 来源，瓶颈是"没读正文 / 没有答案"，不是覆盖广度。升级触发条件（任一满足再评估）：
常见主题需要 >8–10 个互不重叠来源；单代理 p95 >8 分钟或 `hit_turn_limit` 率 >20–30%；
来源上限提到 >10 且综合开始截断丢料；已有持久化子代理产物与独立预算。

### 6.5 评审指出的最可能失败点

S3/S4 的总时限与调用预算：现有单次 150s、综合还带重试，塞进 600s 会出现间歇性"研究超时"。
因此 S3 的第一条验收就是"总 deadline 生效且失败可见"，不是先看答案质量。
