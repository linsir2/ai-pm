# 工具韧性 P1：检索重试与按 query 隔离

> 状态：设计待拍板（2026-10-17 调研）。实现按 TDD，测试先红后绿。

## 缺口记录（本次调研新确认的 4 条）

- **G1 Tavily 零重试**：同包 `fetch.py` 有 3 次＋jitter＋Retry-After（15 条用例钉着），
  `tavily.py` 一次即炸。同一包两套标准。
- **G2 `_search` 首错 `break` 丢弃后续 query**：`use_cases.py:866`。一条 query 撞限流，
  后面本来能成的也不打了。过于保守（失败路径，不是正确性必需）。
- **G3 query 长度无上限**：Tavily 超 400 字必 400（`Query is too long`，永不自愈）。
  chosen queries 是模型提名＋用户勾原话，长度无界——必炸的请求现在照发。
- **G4（记录，不碰）**：注入 client 时 `timeout` 参数没用上（只在自建 client 分支用）。
  与本次无关，不顺手修。

## 非缺口（已验证，无需动）

- `search_depth: "basic"` 已显式（防 auto 升 advanced 扣 2 credits）。
- `timeout=30.0` 在 10–30s 区间内。
- 失败分层（`ToolCallFailed` 502 vs `FetchRefused` 422）与留痕通道（`_tool_drop`）已达标。
- `max_queries=3/max_results=5` 由 TOML 声明。

## 设计（待拍板，详见会话内分析①）

- 重试集：超时/连接错/`429`（遵 `Retry-After`）/`500/502/503/504`；`400/401/403/432/433`
  永不重试（432/433 是账单，400 是客户端错，含超长）。
- 退避复用 `fetch._backoff`（加可选 `sleep` 形参，默认不变；LiteLLMGateway 同先例），
  `MAX_ATTEMPTS=3`（fetch 同形）。
- 网关入口截断 query 到 400 字（漏斗原则；warnings 用截后串，所见即所发）。
- `_search` 的 `break` 改 `continue`（每 query 独立留痕，`_tool_drop` 现货）。
- 网关构造器加可选 `sleeper`（LiteLLMGateway 同先例；旧失败测试跟进传参，断言不动）。
- `02 §11.0.29` 补重试/隔离小节。

## 真跑实测（2026-10-17，对真实 Tavily）

- **query 长度墙 = 1500 字**（不是文档旧版的 400）：2040 字 → HTTP 400
  `Query is too long. Max query length is 1500 characters.`；1501 字 → 200。
  故 `MAX_QUERY_CHARS = 1500`（测试另钉"常量 ≤ 实测墙"）。
- 重构后真路径（**不注入 client** 那条分支）：正常短 query → 2 个信息包；
  2040 字 query 过网关 → 200（截断生效，1 个信息包）。
- 重试/429 封顶：`MockTransport` 钉（真 key 无法制造可控的 429/500）。

## 复审对设计的 delta（对照真实代码）

- 重试 status 集含 **500**（Tavily 官网明说 500 可重试）；fetch 不含 500 是因为它
  防用户粘的任意网址，场景不同——delta 有意，注释写明。
- 异常集 = `TimeoutException`（全套超时）+ `ConnectError` + `RemoteProtocolError`
  （固定可靠端点，网络抖动该重试；fetch 只重试 ReadTimeout/RemoteProtocolError）。
- 耗尽时 message 带"试了 3 次都没成"（照 fetch 先例，排查有用；现有测试只断 code/tool_id）。
