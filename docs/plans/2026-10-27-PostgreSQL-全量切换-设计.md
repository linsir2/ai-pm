## 1. 目标拓扑

```text
Caddy ─> backend × N ──(PMSTUDIO_DATABASE_URL, 6432)──> PgBouncer ─> PostgreSQL 18 + pgvector
             │                                                   ▲
             ├─ Redis（SSE/限流）                                │
             └─ 每 worker 1 条 psycopg 连接                       │
init / maintenance / backup ──(PMSTUDIO_DIRECT_DATABASE_URL, 5432)┘
```

- backend 连接数 = N（4/16/64）；PgBouncer 默认池 10–24，PG `max_connections=100`；init/maintenance/backup 各 1–2 条直连。
- PgBouncer 1.26（`edoburu/pgbouncer:v1.26.1-p0`，pin digest）与 PG（`pgvector/pgvector:0.8.7-pg18-trixie`，pin digest）；PgBouncer 无官方镜像，使用维护中的社区镜像，不自研网关。
- PgBouncer `pool_mode=transaction`、`max_prepared_statements=0`；backend `prepare_threshold=None`、`autocommit=True`、`row_factory=dict_row`、`options` **合并 DSN 自带值** + `-c timezone=UTC`（不覆盖 search_path）、`application_name=pmstudio-<host>-<pid>`。
- 不使用 session `SET`/search_path/advisory lock/LISTEN/临时表；需要时只用事务内 `SET LOCAL`（HNSW）。
- `/api/health` 只 liveness；`/api/ready` 经 PgBouncer `SELECT 1`（短超时）。DB 掉线不能仍 healthy。

## 3. Schema 与原生类型

**列类型**：`timestamptz`（普通 created/updated/expires/approved/last_seen/revoked 等）、`jsonb`（所有结构化 JSON）、`text[]`（warnings/heading_path/changed_block_ids/sections/features/outcomes）、`boolean`（materials.truncated/templates.builtin/model_calls.ok/tool_calls.ok）、`bytea`（materials.content）、`bigint identity`（model_calls.id/tool_calls.id/seq）、`vector(512)`（material_chunks.embedding）、`text`（tokens）。

**例外（明确、不是兼容层）**：
- JSON 负载内部的时间仍 ISO 字符串；`serialization.py` 的 `_when/_unwhen` 保留（否则旧 JSON/API 一起变）。
- `observations.created_at`、`round_digests.created_at`、`inspirations.created_at` 保留 TEXT + `''` 哨兵；领域/排序语义不变。
- `lease_expires_at`/`round_skips.requested_at` 保留 epoch ms **BIGINT**；领域单位，不换 timestamptz。
- `duration_ms`/计数保留 INTEGER；ID 主键保持 TEXT（`p-`/`r-` 前缀）。

**FTS**：`material_chunks.tokens TEXT NOT NULL` 保存 `index_source(title, heading_path, text)`；`search_tsv tsvector GENERATED ALWAYS AS (to_tsvector('simple', tokens)) STORED` + GIN；查询 `to_tsquery('simple', %s)` 逐 token 引号/转义；排序 `ts_rank_cd`（正分），删除 bm25 负号；pivot/α 用冻结语料重标。`LIKE` 子串兜底改 `ILIKE`，测试 `% _ \`/中文。
**向量**：`embedding vector(512)`；`<=>` cosine，分数 `1-distance`（不是 `1-d²/2`）；HNSW `vector_cosine_ops`；过滤后候选不足用 over-fetch/`hnsw.iterative_scan`（事务内 `SET LOCAL`）；profile 变更清空 embedding 后重建。

**迁移/锁**：`schema_migrations(version int primary key, applied_at timestamptz)`；init job 直连执行，`pg_advisory_lock`（session）；`explorations(project_id) WHERE status='running'` 唯一索引在 0001 建；ETL 插入前把重复 running 标 abandoned（保行）；`rounds` 的读改写（claim/SkipSeat/review/auto-approve）必须 `SELECT ... FOR UPDATE`，或 SERIALIZABLE+40001 重试；`round_skips` 与 review 锁同一 round 行；lease DB 时间。

## 4. PgBouncer 边界

- 只对 backend 使用 transaction mode；`prepare_threshold=None` + `max_prepared_statements=0`；不使用 session 级 `SET`/advisory/LISTEN/临时表；`SET LOCAL` 只放在显式事务内。
- `PMSTUDIO_DATABASE_URL`（app, 6432）与 `PMSTUDIO_DIRECT_DATABASE_URL`（init/maintenance/backup, 5432）必须分开；缺失各自失败，不能相互推导/回落。
- 连接预算：4 workers = 4 client + 直连 2–3；PgBouncer `max_client_conn=64`、`default_pool_size=10`、`reserve_pool_size=4`、`query_wait_timeout=30`。16/64 workers 按 100/16、200/24 调整；PG `max_connections=100` 单机足够。
- `statement_timeout=15s`、`lock_timeout=3s`、`idle_in_transaction_session_timeout=15s`；`55P03`→503+Retry-After，`40001/40P01`→回滚/有限重试，`08006`→503+重连，`25P02`→rollback，`23505`→ON CONFLICT/savepoint。
- PgBouncer 不是延展单 worker 内并发的方案；sync DB 仍阻塞事件循环。用 N workers + 负载门；不达标再单独立项 async。

## 5. 数据迁移与切换

- 停后端 → `.backup` 旧 SQLite → 空 PG + migrations + init → ETL（`sqlite3` 只读）→ 校验 → 切 app URL → smoke → 旧库保留 30 天。
- ETL 从 `sqlite_master` 枚举普通表 + 显式 skip map（sessions、FTS/vec 影子）；`tool_calls`/`round_skips`/`vector_index_meta` feature-detect；未知表报错。
- 类型迁移：text→timestamptz（UTC，naive 按 UTC；空值按允许语义）、text→jsonb（解析后校验，不哈希原文）、数组→text[]（`''`→`[]`）、0/1→boolean、BLOB→bytea、rowid→seq/id（保留旧序 + setval）、tokens 回填、向量重嵌入（当前 0）。
- 0001 已建唯一 running 索引；ETL 在插入前把重复 running 除最新一条外改成 `abandoned`（保留全部行）；`sessions` 不迁；`model_calls` 迁；`tool_calls` 有则迁；`vector_index_meta` 有则迁。
- 校验：行数/主键哈希/JSON 解析相等/文档-轮次 roundtrip/recall@5（冻结语料）/备份恢复；回滚=旧镜像+旧 SQLite，明确切后写丢失 RPO。不双写/不回写。
- 停机切换/回滚步骤见 `2026-10-27-PostgreSQL-全量切换-runbook.md`（备份、ETL、finalize、smoke、观察期、RPO 与回滚边界）。

## 7. 分阶段

1. **P0**：冻结 P3b-1；备份 SQLite；建分支。
2. **P1**：PG 运行时骨架（settings 两 URL、连接、UoW、init/PgBouncer/compose、test fixture）。
3. **P2**：schema/migrations/native types/seq/索引/FTS/vector。
4. **P3**：简单仓储 + 核心仓储 + UoW 锁/事务。
5. **P4**：FTS/vector/materials。
6. **P5**：P3b lease/claim/SkipSeat/多进程迁 PG。
7. **P6**：init/maintenance/bootstrap/scripts/Docker/CI/tests。
8. **P7**：ETL/停机切换/回滚演练/4 workers 负载/文档/删除 SQLite。
- 先单 worker 全绿 → 再 N workers → 再多机；P3b-1 在切换后。

## 8. 风险/回滚/不做

- 风险：原生类型改动面大（JSONB/时区/布尔/数组/`Jsonb`）；PgBouncer transaction 限制；单连接 sync 阻塞；UoW 丢更新；ETL v15/坏 JSON；测试 schema 泄漏；pg_dump 版本；FTS/向量排名。
- 回滚：旧镜像+旧 SQLite；切换前备份；切后回滚丢 PG 写；不保留双运行时。
- 不做：双后端/双写/影子读；自研 pool；SQLAlchemy/asyncpg（除非负载门失败另立项）；session PgBouncer/主从/读副本/外部向量库；ETL 代码进生产镜像；把一次性 bench 全部重写。
