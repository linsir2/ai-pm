# 里程碑与真相源

> **给执行者**：本文件是路线与纪律；每个里程碑开工时，再按 `writing-plans` 的格式
> 产出该里程碑的 tasks 级计划（每步一个动作、带代码与测试命令）。
> **Spec**：`.codex/docs/设计/01-规格.md`（要做什么）、`02-编排与数据.md`（怎么跑）、
> `05-DDD架构.md`（怎么实现）。执行时这三份与本文一起读。

## 全局约束（每个任务都隐含遵守）

- 技术栈：Python 3.13 + FastAPI + pydantic v2 + **LiteLLM** + **SQLite** + pytest + ruff；
  前端 **React + Vite**。
- `domain/` **不 import 任何外部包**（fastapi / langgraph / litellm / sqlite3 都不行）。
- **写入路径唯一**：只有 `ConfirmDraft` 能改文档。
- **假模型只许活在测试里**：生产路径不提供"用假模型"的开关，不写无密钥降级分支。
  汇报"跑通"必须给真实模型证据。
- LangGraph 的 state 只放引用（`round_id`、`step`），不放业务状态。
- 事件只做通知与投影：摘掉全部订阅者，流程照样能跑完。
- 每次提交粒度：一个任务一次提交，消息用 `feat:` / `fix:` / `test:` / `docs:` 前缀。

## 真相源注册表（漂移防线）

| 信息 | 唯一真相源 | 谁不能写 | 漂移怎么被发现 |
|------|-----------|---------|---------------|
| 文档内容与结构 | `Document` 聚合（blocks + versions） | 编排层 / 席位 / 整合者 / 界面 | 只有 `ConfirmDraft` 有写路径；代码扫描测试断言没有第二条 |
| 出处与编号 | `EvidenceLedger` 聚合 | 同上；席位只能用局部 id | 回溯校验 + DB 唯一约束 |
| 一轮推进 | `Round` 聚合（`step` / `waiting_on`） | LangGraph state | 测试断言图 state 只含白名单字段 |
| 席位与工具定义 | `infrastructure/seats/definitions/*.yaml` | 业务代码里不硬编码席位 | 目录测试：catalog 只从 yaml 读 |
| 设计意图 | `.codex/docs/设计/`（5 份） | 别处不复述设计 | 评审；AGENTS.md 是唯一入口 |
| 当前状态与下一步 | `.codex/docs/上下文/checkpoint.md` | — | 每次交接前必须更新 |
| 视觉规范 | `DESIGN.md` | — | 界面评审 |
| 项目级铁律 | `AGENTS.md` | — | — |

三道防线，缺一不可：**结构性**（拿不到写能力）、**测试性**（扫 import / 白名单 / 唯一约束）、
**文档性**（一份设计只在一个地方维护）。

## 里程碑

### P0 · 地基与防线

范围：目录与依赖方向、`domain/` 空骨架、SQLite `schema.sql`、`UnitOfWork`、
三个仓储端口、`ModelGateway` 端口、pytest + ruff 配置、**扫 import 与写入路径的守卫测试**。

退出条件（可测）：`pytest` 全绿（含守卫测试）；`ruff check` 无告警；
生产路径里搜不到假模型实现。

### P1 · 领域层（不碰模型）

范围：`Document` 聚合（D1–D6 + 版本快照 + 墓碑）、`EvidenceLedger`（E1–E3）、
`Round` 聚合（R1–R6）、领域服务 `TraceabilityChecker` / `ScopeGuard` /
`EvidenceAssigner` / `ProposalCommitter`。

退出条件：**每条不变量至少一个正例 + 一个反例测试**；
`ProposalCommitter` 的"写入 + 版本"是同一事务（测试里用假仓储断言行数）。

### P2 · 单轮闭环（真实模型 + 最小界面）

范围：`StartRound` → Analyzer → 开场卡 → 席位轮（并行，真 LiteLLM）→ `IntegrateRound`
→（有题则问卷 → 答案 → 回到席位轮；无题则直接草案）→ `ConfirmDraft` → 版本。
API + SSE；前端最小集：文档区 + 闭环区 + 弹出抽屉。

退出条件：在浏览器里用**真实模型**跑通一次完整迭代，文档多一版；
并且**信息明确的那条路径（不出问卷）也能跑通**。

### P3 · 循环与恢复

范围：答案回灌后缩编席位轮、席位轮上限 3、失败从 `step` 续跑、
运行中断（关页面）后恢复、`generation.failed` 的界面呈现。

退出条件：模拟中途关页面再回来能接着跑；席位返回不可解析 → 整轮失败且**文档无写入**。

### P4 · 界面完整度

范围：闭环区的 `packet.emitted` 讨论流、依据角标跳转、版本历史与差异、章节缺口标记、
手动输入框。

退出条件：`01-规格.md` §5 与 `03-案例与验收.md` 的验收清单全部通过。

### P5 · 席位扩展

范围：席位定义外置到 yaml、提名器（按输入匹配）、用户在开场卡增删席位、
席位来源标记（提名 / 用户添加）。

退出条件：新增一个席位**不需要改业务代码**，只加一份 yaml + 一条测试。

### P6 · 留位（不在 v1）

手动编辑文档、陌生人读者、范围守卫常驻、门禁、导出、讨论区、工具层、记忆维护。

## Lane 与里程碑的关系

| Lane | 覆盖 | 依赖 |
|------|------|------|
| A 领域层 | P1 | P0 |
| B 编排层（含图与 LiteLLM 网关） | P2、P3 | P1 的接口签名 |
| C API + 前端 | P2 的最小集、P4 | B 的动作入口与事件形状 |

P0 完成后，先定 A 与 B 之间的函数签名，再让 A、B、C 并行。
