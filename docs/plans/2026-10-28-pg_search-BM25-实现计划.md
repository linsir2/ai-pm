# pg_search + Robertson 重排实现计划

> 依据：2026-10-28 会话方案；用户已批准：官方 ParadeDB 0.26.3-pg18、空库重建、raw `search_text` + pg_search jieba、候选 200、统一 `pmstudio_tokens` 做 Robertson 重排、跨块先复现旧 646/400、删除 SQLite ETL。

## Global Constraints

- 不做 SQLite 兼容/降级；不迁现有 PG 数据（空库）。
- `MaterialRetriever.search` / `MaterialHit` / API / DTO / 前端零改。
- 写路径唯一；检索只读；owner/project 隔离不变。
- 词法索引源是 `material_chunks.search_text`（title + heading + text），pg_search jieba；token 统一由 `pmstudio_tokens`（`paradedb.tokenize` jieba）产生。
- pg_search 候选 200；Robertson BM25（k1=1.2, b=0.75, IDF `ln((N-df+.5)/(df+.5))`），返回前平移为正分；`α=.4`、每材料 2 槽不变。
- **验收基线（Task 5 校正，2026-10-28）**：791/300 当前实测词面 r5 **.844**、改述 r5 **.857**、top1 **.467 / .214**、MRR **.605 / .425**、跨块 **4/15 = .267**；旧 646/400 只作对照，跨块 **7/15 = .467**。
- **Ruling（宽度标签 / 目标出处）**：旧 `.867 / .786`（以及 `.689 / .515`）来自 646/400 的 `retrieval_baseline.json`，**不是 300 门**；`.596 / .482` 只出现在未入库的 300 参考里，也不作门。`top1/MRR` 相对旧参考的下降记 `04` R15 **未收**，不改阈值、不写通过。
- 删除 `migrate_sqlite_to_pg.py` 与 `test_etl_cutover.py`；删除 `tokens`/`search_tsv`/GIN；删除 app 侧 jieba/tokenize 词法函数。
- 官方镜像 `paradedb/paradedb:0.26.3-pg18`（digest 钉死），shared_preload=pg_search；空 PGDATA。
- 每个任务 TDD/RIPR，真 PG；任务后独立评审；最后整批评审；未评审不得合并。
- 不启动 P3b-1。
