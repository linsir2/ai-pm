## 2. 缺口分级（P0/P1/P2）

### 🔴 P0：不做就是硬伤

#### 缺口 P0-1：没有 README
- **核验**：`Glob **/README*` → 无文件。
- **简历后果**：HR/面试官 7 秒扫描 GitHub，看不到 README 就等于项目不存在。**这是唯一一件"投入产出比最高、且当前完全为零"的事。**
- **为什么是 P0**：它不是"少一个功能"，而是"整个项目不可见"。

#### 缺口 P0-2：没有 Docker / docker-compose
- **核验**：无 `Dockerfile`、无 `docker-compose*`。
- **简历后果**：面试官 clone 下来要自己配 Python 3.13 + Redis + 下 ONNX 模型，5 分钟跑不起来就放弃。**"可运行 Demo"是强信号。**
- **为什么是 P0**：JD 高频词 Docker/K8s；且这是"可验证产出"的直接体现。

#### 缺口 P0-3：没有 MCP
- **核验**：全仓 `grep -i mcp` 零命中。
- **简历后果**：技能栏少一个 2025-2026 最热关键词；海外 JD 甚至要求"亲手写过 MCP server"。
- **为什么是 P0**：**你的工具层（`infrastructure/tools/`）已经是现成的工具目录，包成 MCP 是低成本高回报**——不需要重写业务，只需要加一层协议适配。

### 🟠 P1：补上就是"王者段位"

#### 缺口 P1-1：Eval 未产品化
- **核验**：`backend/evals/` 有 11 用例 + `assertions.py`（12 条断言、纯函数）；`03-案例与验收.md` 有检索验收清单。
- **差距**：**有评测，但没有"可复现的 benchmark + 指标看板"**——而 JD 要的是"自动化评测流水线"。
- **简历后果**：面试官问"你怎么衡量 Agent 效果"时，你现在只能说"有测试"；补完后能说"有 11 条真模型用例 + 结构断言 + 检索配对增量 + 符号检验"。
- **为什么是 P1**：你已有 80% 的料，只差最后一公里，是**性价比极高的差异化**。

#### 缺口 P1-2：缺 Reranker
- **核验**：`grep rerank/重排` 仅命中"题号重排"（与 RAG 无关）。
- **差距**：RAG 全链路"解析→分块→向量化→检索→**重排**→生成"缺最后一环。
- **为什么是 P1**：补全链条，关键词对齐；且 `04-未决.md` R11 已记录过 cross-encoder 重排的延迟实测（33.8–58.3s，需 GPU），有据可依。

#### 缺口 P1-3：没有 CI
- **核验**：无 `.github/`、无 `*.yml`。
- **简历后果**：仓库专业度；"684 次提交 + 257 个测试"却没有 CI，会让人疑惑这些测试谁在跑。
- **为什么是 P1**：实现成本极低（一个 workflow 文件）。

#### 缺口 P1-4：默认分支名 `new-branch`
- **核验**：`git branch -a` 确认 `origin/HEAD -> origin/new-branch`。
- **简历后果**：细节观感——面试官会注意到默认分支名不正式。
- **为什么是 P1**：一行改名的事，但影响专业度印象。

### 🟡 P2：锦上添花

| 缺口 | 核验 | 简历后果 |
|---|---|---|
| P2-1 无可观测性 | 无 OTel/LangSmith/Langfuse | JD 的 Observability 分区完全空白 |
| P2-2 无技术博客 | 设计文档未对外 | 缺面试谈资与对外影响力 |
| P2-3 无 ReAct/Planner | 编排是确定性状态机 | 缺一个 JD 高频词（但确定性状态机本身是优点，可作为对照） |
| P2-4 设计文档漂移 | 模板 UI 已实现但文档标"未实现" | 违反"双真相源明令禁止"的规矩 |

## 3. 已经很强、别妄自菲薄的部分

对照完缺口，也要看清**你本来就有的**（这些是很多候选人没有的）：

| 能力 | 为什么稀缺 |
|---|---|
| 熔断/隔离舱/重试预算 + 抖动退避 | 多数候选人没听过，更别说实现并写测试 |
| 结构化输出归一化引擎（三档口径） | 真跑踩坑攒出来的工程能力 |
| 失败分类单点权威表（`isinstance` 绑真实异常） | 对"两套权威做同一决定"的清醒认知 |
| 混合检索融合算法选型（RRF→凸组合） | 有量化依据的算法选型能力 |
| 跨轮记忆治理（出处强制 + 用户确认唯一写入口） | 对"记忆污染"的系统性防御 |
| 架构守卫（含"守卫自己有没有效"那一层） | 把架构从"约定"变成"机器可验证" |
| 混沌矩阵（真注入 5xx/断 Redis/写锁/磁盘满） | 真正的故障注入，不是 mock |

> **一句话**：你不是"技术含量低"，你是"**技术含量藏在代码里，没被翻译成简历语言**"。
