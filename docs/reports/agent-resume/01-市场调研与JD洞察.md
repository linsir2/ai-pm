# 01 · 市场调研与 JD 洞察

> 本分册回答"别人要什么"：Agent 开发工程师的 JD 在写什么、优秀简历长什么样、面试考什么、市场给多少钱。
> 结论来自多来源 web 调研（国内 5 份在招 JD + 海外 4 份 + 4 份真实简历/作品集 + 2 份面试记录统计 + 4 份行业报告），关键结论均标注出处。

## 0. 调研方法与样本

- **国内 JD**：美团（Agent 开发工程师·全栈）、小鹏（AI Agents 开发工程师）、上海 AI 实验室（Agent 开发工程师）、猎聘、智联。
- **海外 JD**：Built In、SmartRecruiters（Applaudo Senior AI Engineer）、Weekday、TopCoding。
- **真实简历/作品集**：akshaykalapgar.com 等 4 份。
- **面试记录**：牛客 2828 条面经统计。
- **行业/薪酬**：尚硅谷就业报告、证券时报、亨德森猎头、脉脉。

## 1. 最本质的变化：从"做 Agent 应用"到"把模型能力工程化为可靠系统"

这是每份 JD 都在强调的事——**不是"会用框架"，而是"生产可用、确定性、可落地"**。

- 美团把该岗位定位为**"不是传统后端，也不是纯算法研究，而是将大模型能力工程化为可靠 B 端策略与流程执行 Agent 系统的全栈工程师"**，并明确要解决"**模型输出不确定性 vs 业务流程确定性**"的矛盾（[美团 Agent 开发工程师（全栈）JD](https://zhaopin.meituan.com/m/position/detail?highlightType=social&jobUnionId=4647373928)）。
- 猎聘某 JD 直接写明：**"具备完整的 LLM/AI Agent 产品开发与线上落地经验，拥有正式投产运行的智能体系统项目，无纯 Demo、纯 Prompt 调试实验类从业经历"**（[猎聘 Agent JD](https://www.liepin.com/a/79249041.shtml)）。

> **可引用结论**：2026 年 Agent 岗的核心筛选标准，是候选人的项目**是否真正投产运行**，而非跑通 Demo。

## 2. JD 高频技能关键词（按出现频次排序）

| 类别 | 高频关键词 |
|---|---|
| 编程 | **Python（几乎必备）**、Go/Java/Rust、SQL/Hive/Spark |
| Agent 框架 | **LangChain / LangGraph（出现率最高）**、LlamaIndex、CrewAI、AutoGen、OpenAI Agents SDK、Google ADK、Semantic Kernel |
| 协议 | **MCP（极高优先）**、A2A、ANP |
| 核心技术 | Tool/Function Calling、**RAG**、Memory/Context Engineering、多智能体编排、任务规划（ReAct / Plan-and-Execute） |
| 工程化 | Docker/K8s、FastAPI、**Eval Pipeline / 可观测性（trace）**、CI/CD、微服务 |
| 加分 | 微调（LoRA/SFT/DPO/RLHF/RLVR）、vLLM、向量库（Milvus/FAISS/pgvector） |

来源：[小鹏 AI Agents 开发工程师](https://xiaopeng.jobs.feishu.cn/index/position/detail/7578769398917695763)、[上海 AI 实验室 Agent 开发工程师](https://www.shlab.org.cn/joinus/detail/7686149294239467814)、[智联 AI Agent 开发工程师](https://m.zhaopin.com/jobs/CC246890110J40875528210.htm)、[TopCoding AI Agent Engineer](https://topcoding.io/resources/ai-agent-engineer)。

> **可引用结论**：2026 年 Agent JD 中，**LangGraph 与 MCP 已成为事实上的标配组合**，RAG 与 Agent 评测（evals）是几乎所有岗位的必答项。

### 2.1 特别强调 MCP 的地位

- 海外 JD 明确要求候选人**"必须亲手写过 MCP server，而不是仅仅集成或调用过"**（[Applaudo Senior AI Engineer](https://jobs.smartrecruiters.com/applaudostudios/744000144456619-senior-ai-engineer-llms-agentic-ai-)）。
- 上海 AI 实验室把 MCP 列为"理解者优先"。
- 智联 JD 把 **MCP、A2A、ANP** 并列。
- 生态数据支撑其权重：2026 年 3 月 MCP 月 SDK 下载量约 **9700 万次**，2025 年 12 月已移交 Linux 基金会 AAIF 中立治理（[AgentMarketCap](http://agentmarketcap.ai/blog/2026/07/13/mcp-meets-a2a-two-protocol-stack)、[BotSailor](https://dev.to/botsailorofficial/7-agentic-ai-shifts-worth-tracking-in-2026-3en2)）。

## 3. 最被低估、也最能拉开差距的能力：Evals + Guardrails + 可观测性

- TopCoding 明确把 **Evals + guardrails** 称为"agentic system 中投入最少的两块，却决定系统能否在生产环境可靠工作"（[TopCoding](https://topcoding.io/resources/ai-agent-engineer)）。
- 上海 AI 实验室 JD 用整段职责描述"建设 Agent 评测体系和自动化评测流水线……工具链成功率、流程质量、稳定性、任务完成度"。
- 海外 JD 反复出现 **trajectory evaluation、eval framework、regression suite、guardrail tests**（[Weekday/Interactly](https://jobs.weekday.works/agentic-ai-engineer-senior-at-startx-med-wkdyyfbq8e)）。

> **可引用结论**：只会搭 Agent 的人很多，**能为 Agent 建立评测体系与护栏的人很少**——这正是资深岗位的溢价来源。

## 4. 优秀简历的 6 大特征

### 特征 1：用"问题 → 方案 → 个人贡献 → 量化结果"四段式

- 反例（流水账）：*"基于 LangChain 搭建多智能体协作系统，集成 RAG，使用 ChromaDB，实现 Prompt 优化。"*
- 正例：*"独立负责 Agent 工具调用链路稳定性优化，针对工具超时导致的会话中断，引入重试+降级双保险，将调用成功率从 80%+ 提到 99% 以上。"*（[牛客秋招改简历复盘](https://m.nowcoder.com/discuss/1678990)）
- 该候选人按此重写后，**简历通过率从 10% 提升到 60%**（[牛客](https://www.nowcoder.com/feed/main/detail/cb028558dc0946218070e8057ca1799e)）。

### 特征 2：五类项目的"可验证表达模板"（[职坐标](https://m.zhizuobiao.com/blog/interview/interview-26101000003/)）

| 类目 | 必含要素 | 正例片段 |
|---|---|---|
| Agent 应用 | 业务场景 + 规模 + 自动化率 + 延迟 | "覆盖 200+ SKU，日均 5000+ 咨询，自动应答率 78%，人工介入率 65%→22%，响应 1.2s" |
| 工具调用 | 工具数 + 成功率 + 调用链长度 + 异常处理 | "集成 12 个工具，成功率 94%，平均链长 3.2 步，异常场景完成率 71%→89%" |
| 多 Agent | Agent 数 + 角色 + 协作模式 + 效率 | "4 Agent（Supervisor 模式），日均 800+ 报告，单报告 4h→12min，调度成功率 96%" |
| RAG/知识库 | 文档规模 + 检索准确率 + 采纳率 | "2.3 万份文档，BGE + Milvus，问答准确率 72%→93%，幻觉率 38%→8%" |
| 工程化 | trace + 成本 + 稳定性 | "接口耗时 800ms→180ms，支撑单轮 100+ 并发" |

### 特征 3：量化一切，拒绝"提升了效率"这类空话

- 真实案例："引入混合检索 + BGE 重排，**准确率 72%→93%，幻觉率 38%→8%；缓存+异步检索把耗时 800ms→180ms**"（[牛客](https://www.nowcoder.com/feed/main/detail/cb028558dc0946218070e8057ca1799e)）。
- 海外作品集范例：简历顶部直接放 **"100K+ users · MCP servers · 99.9% uptime · −50% cold-start latency · 1,180+ OSS commits"**（[akshaykalapgar.com](https://akshaykalapgar.com/)）。

### 特征 4：必须写清"你亲手做了什么"，且经得起追问

- 明确区分"**你亲手构建的 / 你参与的 / 你只观察到的**"（[Applaudo](https://jobs.smartrecruiters.com/applaudostudios/744000144456619-senior-ai-engineer-llms-agentic-ai-)）。
- 反例：*"参与 XX Agent 平台开发，负责核心模块设计与实现"*。
- 正例：*"独立负责多智能体客服系统的工具调用模块与决策逻辑优化，基于 ReAct 设计工具选择与参数校验流程，自定义开发 8 个工具"*。
- 关键提醒：**"简历上写了但讲不清，比不写更扣分——不写只是不知道，写了讲不清是诚信问题"**。

### 特征 5：必须体现"工程化闭环"，而非单点调用（[HI简历](https://hicv.cn/blog/ai-agent-resume-function-calling-multi-agent)）

1. **只写框架名不写架构** → 应写清"意图识别 → 工具选择 → 参数构造 → 结果解析 → 异常回退"全链路。
2. **忽略异常处理** → 不提超时/幻觉/兜底，说明项目只是 Demo。
3. **回避效果度量** → 必须给准确率、召回率、端到端耗时、用户反馈。
4. 同时提醒：**"不要把所有项目硬写成 Agent"**——单轮问答就老实写"对话系统"。

### 特征 6：技能栏分区，用词与 JD 对齐（ATS 7 秒扫描）

| 分区 | 内容 |
|---|---|
| Languages | Python、TypeScript、SQL |
| Agent Frameworks | LangGraph、LangChain、CrewAI、AutoGen |
| MCP & Protocols | MCP Server、A2A |
| RAG & VectorDB | FTS5、sqlite-vec、fastembed、jieba、混合检索、重排 |
| Eval & Observability | Eval Pipeline、回归测试、Trace |
| Infra | Docker、Redis、SQLite/WAL、FastAPI |

## 5. 面试考点频次（牛客 2828 条真实面经统计）

来源：[八股精·2025-2026 AI 应用与 Agent 面试洞察](https://www.nowcoder.com/discuss/927907662107246592)

| 主题 | 出现频次 | 说明 |
|---|---|---|
| **RAG（含检索增强、向量库）** | **175 次** | 断层第一考点，必考全链路 + 评测 + 边界处理 |
| 提示词工程 + 大模型基础 | 60 次 | 幻觉治理是重点，排斥"只调 Prompt"的答案 |
| 多智能体系统 | 13 次 | 概念辨析 + 编排设计 |
| 大模型幻觉 | 13 次 | 要系统性方案（检索校验/置信度过滤/人工审核） |
| ReAct | 11 次 | 必考范式对比 + 死循环处理 |
| Agent 记忆/上下文压缩 | 13 次 | 长对话场景必问 |

> **可引用结论**：简历里每一个 Agent 关键词，都必须能在面试中展开到"边界情况 + 量化评估 + 权衡取舍"，否则就是给自己挖坑。

## 7. 行业趋势（2026 主叙事）

1. **协议层收敛**：MCP 管 agent↔tool，A2A 管 agent↔agent，二者于 2026 年 8 月 17 日共同并入 Linux 基金会 AAIF（247 家成员、8 家白金赞助），**"双协议栈"成为企业默认架构**（[PracticalLogix](https://www.practicallogix.com/the-2026-agent-interoperability-reset-a2a-mcp-under-aaif)）。
2. **多智能体成为默认架构**：orchestrator + specialist 模式取代单 Agent。
3. **"Guardian Agents（守护智能体）"成为独立品类**：Gartner 2026 年 2 月发布首个 Market Guide，将治理层拆为 reviewer / monitor / protector。
4. **治理滞后于采用**：Gartner 预测 2026 年底 **40% 企业应用将含任务型 Agent**（2025 年不足 5%）；CSA 报告显示仅约 16% 的企业能真正治理其 Agent 权限。
