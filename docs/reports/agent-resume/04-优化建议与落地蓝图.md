## P0-2 · Docker / docker-compose 一键启动

### 为什么
无 `Dockerfile`。面试官 clone 下来要自己配 Python 3.13 + Redis + 下 ONNX 模型，5 分钟跑不起来就放弃。

### 落地方案

**新建文件**：
- `backend/Dockerfile`
- `frontend/Dockerfile`
- `docker-compose.yml`（仓库根）

**后端 Dockerfile 要点**（复用现有约定）：
```dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY pyproject.toml uv.lock ./
RUN pip install uv && uv sync --frozen
COPY src ./src
COPY scripts ./scripts
COPY .env.example ./.env.example
EXPOSE 8000
CMD ["uv", "run", "python", "scripts/dev.py", "--no-reload"]
```
- 依据：现有入口是 [scripts/dev.py](file:///workspace/ai-pm/backend/scripts/dev.py)，它读 `backend/.env`（没有就用 shell 环境变量）、把 `backend/src` 放进模块路径、起 uvicorn。
- 模型依赖：`fastembed` 首次跑会下 ONNX 模型（`Qdrant/bge-small-zh-v1.5`，约 90MB）——Dockerfile 里预拉或首启懒加载（懒加载更安全，避免构建期网络问题）。

**前端 Dockerfile 要点**：
```dockerfile
FROM node:22-alpine AS build
WORKDIR /app
COPY package.json package-lock.json* ./
RUN npm ci
COPY . .
RUN npm run build
FROM caddy:2-alpine
COPY --from=build /app/dist /srv
COPY Caddyfile /etc/caddy/Caddyfile
```
- 依据：前端 `build` 脚本已含 `tsc --noEmit && vite build`（见 [package.json](file:///workspace/ai-pm/frontend/package.json)）；现有 [Caddyfile](file:///workspace/ai-pm/Caddyfile) 可直接复用。

**docker-compose.yml 要点**：
- services：`backend`（8000）、`frontend`（80，反代 `/api` 到 backend）、`redis`（可选，用于多 worker 限流/SSE 扇出）。
- 环境变量：全部来自 `.env`（复用 [backend/.env.example](file:///workspace/ai-pm/backend/.env.example) 的键名）。
- 卷：`pmstudio-data`（挂 `~/.pmstudio`，避免容器重建丢库）。

### 验收
```bash
docker compose up -d
curl -s localhost:8000/api/health   # 期望 200
curl -s localhost:80/ | head         # 期望前端首页
```

## P0-3 · 工具层包成 MCP Server

### 为什么
全仓 `grep -i mcp` 零命中。MCP 是 2025-2026 最热关键词，海外 JD 要求"亲手写过 MCP server"。**你的工具层已经是现成目录，包成 MCP 是低成本高回报。**

### 落地方案

**新增依赖**：`backend/pyproject.toml` 的 `[project].dependencies` 增加 `"mcp>=1.0"`（官方 Python SDK）。

**新建包**：`backend/src/pmstudio/infrastructure/mcp/`
- `__init__.py`
- `server.py` —— MCP server 入口（`FastMCP` 实例 + 注册 tools + stdio/SSE transport）
- `adapters.py` —— 把现有工具适配成 MCP tool handler

**复用现有结构**：
- 工具声明：[harness/tools/registry.py](file:///workspace/ai-pm/backend/src/pmstudio/harness/tools/registry.py) 的 `ToolDefinition` + [harness/tools/definitions/](file:///workspace/ai-pm/backend/src/pmstudio/harness/tools/definitions) 的 `web_search.toml`、`attachment.toml`
- 工具实现：[infrastructure/tools/](file:///workspace/ai-pm/backend/src/pmstudio/infrastructure/tools) 的 `tavily.py`（联网检索）、`fetch.py`（抓网页）、`office.py`（Office 解析）、`webclean.py`、`webdedup.py`、`extract.py`
- 配置门控：`requires` 字段（没配密钥就不出现）——MCP tool 列表同样按 `available(has=...)` 过滤

**适配层设计**：
```python
# infrastructure/mcp/adapters.py（示意）
async def to_mcp_tool(defn: ToolDefinition, settings: Settings) -> McpTool:
    """把 ToolDefinition + 其实现适配成 MCP tool；缺 requires 配置就不注册。"""
```
- 每个 MCP tool 的 inputSchema 从 `ToolDefinition` 派生（`max_queries`/`max_results` 等已有字段可直接映射）。

**入口**：`backend/scripts/mcp_server.py`（新），供 `claude_desktop_config.json` / IDE 挂载。

### 验收
```bash
cd backend && uv run python scripts/mcp_server.py --list
# 期望列出：web_search / fetch / parse_office 等（按已配密钥）
```
- 守卫：MCP 层不许反向依赖 `domain`/`application`（保持 `infrastructure` 在内侧），或明确它是一次性出口。

## P1-2 · 加 Reranker（补全 RAG 链路）

### 为什么
RAG 全链路"解析→分块→向量化→检索→**重排**→生成"缺最后一环。

### 重要修正（核验后）
仓库**已有** [scripts/rerank_experiment.py](file:///workspace/ai-pm/backend/scripts/rerank_experiment.py)——一份**二阶段检索（粗排 → 精排）cross-encoder 实验**，含六个指标（材料级 r5、块级 r5、MRR、跨块证据完整率、无关块数、延迟）。**缺的不是"实验"，是"把重排接进生产检索路径"。**

### 落地方案
- 在 [infrastructure/sqlite/materials.py](file:///workspace/ai-pm/backend/src/pmstudio/infrastructure/sqlite/materials.py) 的检索后阶段加一个**可选**精排步骤（cross-encoder），由配置开关控制。
- **必须降级**：重排不可用（模型下载失败/超时）时回退到现有凸组合结果——沿用现有"扩展/模型失败退回纯 FTS5"的降级纪律。
- 延迟约束：`04-未决.md` R11 已实测 cross-encoder 延迟 33.8–58.3s（需 GPU）——**生产默认关，或只在离线/异步场景开**。

### 验收
- 有开关时 A/B 指标可复跑（对照 `rerank_experiment.py` 的六个指标）；
- 开关关闭时行为与现状逐字一致（回归测试）。

### 为什么

### 落地方案
- 在 `application/agents/` 下加一个**探索型 ReAct agent**（工具选择 → 执行 → 观察 → 再决策），与现有确定性编排并存。
- 简历里可以写："**两种范式都实现过：确定性状态机用于主闭环（可控、可恢复），ReAct 用于探索性调研（灵活）**"——这比只写"用了 ReAct"更能体现判断力。

### 验收
