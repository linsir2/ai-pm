## 〇 · 新增：三项 P0 落地后的简历增量

这三项落地后，你的简历从"一个 PM 工具"变成"**一个能被别人 clone 下来跑、并且接了 2026 最热协议的 Agent 系统**"。

**A. MCP（新增，最值钱的一条）**

> - 基于 **MCP（Model Context Protocol）** 为工具层实现**只读侧接入**：将外部 MCP server 的工具投影为模型可调用的函数声明（`mcp__<server>__<tool>` 前缀保证多 server 同名工具不冲突），并自研 **agentic 循环**（`Tool Spec → 模型自主决策 → 工具执行 → 结果回灌 → 再决策），支持 stdio 与 HTTP 两种标准传输。
> - 设计**模型侧输出契约的向后兼容扩展**：`ModelRequest.tools` / `ModelReply.tool_calls` 均为**默认空**的可选字段，使 5 个既有 Agent（Analyzer / 席位 / 整合者 / 讨论 / 记忆）**零改动**继续走单发单 JSON 路径。
> - 工具失败**不判死整轮但绝不伪装成功**：失败以显式文本回灌给模型由其自行决策；模型请求未注册工具同样回灌告知；循环轮数达上限**显式标注**而非静默截断。
> - **实测**：真模型自主选中 MCP 工具并据此作答（3¹⁷ = 129140163），全链路留样可查。

**B. Docker + CI（新增，工程化）**

> - 容器化交付：后端（Python 3.13 slim）/ 前端（Node 构建 → Caddy 伺服）/ Redis 三服务编排，并抽取**原生等价验证脚本**，在没有 Docker 的环境复现同一套环境变量与启动序列（由契约测试保证两者键名不漂移）。
> - 补齐 15 条**防静默失败**的架构守卫：容器必须 `--host 0.0.0.0`、必须整树 COPY 源码（漏 COPY 资源目录会导致提示词静默为空）、基础镜像禁用 alpine（onnxruntime 需 glibc）、跨容器反代必须配置 `FORWARDED_ALLOW_IPS`（否则登录限流退化为全站限流）。
> - 建立 CI（后端 pytest + ruff、前端 tsc + vitest、接口零差校验），并修复了仓库中**预先存在**的前端构建失败（缺失 `@types/node`）。

## 三、项目经历（问题 → 方案 → 个人贡献 → 量化结果）

> 以下每条都是"可核验"的。建议按目标岗位裁剪 5–7 条。

### 3.1 项目一句话

**PM Studio · 多 Agent 产品文档生成系统**（个人独立项目，2025.09–2026.10）
> 面向产品经理的本地工作台：把零散想法整理成结构化产品文档。**AI 只出草案，人确认才写入**，每次改动产生版本。

### 3.2 核心 bullet

**A. 多智能体编排（对应 JD：LangGraph / Multi-Agent / 任务规划）**
> - 基于 **LangGraph** 设计轮次状态图：state **只放引用**（command/round_id/view）、**不挂 checkpointer**（避免图与聚合成两个真相源），命令路由 + step 恢复路由双表，同轮串行化 + 可取消。
> - 实现 **10 个领域化 Agent**（Analyzer / SeatReviewer / Integrator / Inquirer / Discusser / MemoryCurator / SimInquiry / SimReview）的声明式基类 + 注册表，统一"构造调用 → 解析信封"路径；明确"**席位出意见、整合者出形状**"的职责边界。
> - 席位并行 **fan-out/fan-in + 分级失败处置**：网关类失败整轮重试、内容错记名跳过 + 留痕，整轮继续；重试环最多 3 次，最后一次 lenient（摘幻觉编号不判死）。
> - **量化**：一轮的模型调用次数与句数无关，只与席位数 × 席位轮数有关（最多 3 轮）；席位编制由 Analyzer 判断（非关键词匹配）。

**B. RAG 检索（对应 JD：RAG / 混合检索 / 向量库 / Rerank）**
> - 自研**混合检索**：jieba 预分词 + SQLite FTS5 + sqlite-vec + fastembed(bge-small-zh)，**零第二存储**（同库同表族）。
> - **融合算法选型**：从 RRF 改为**凸组合**（α·余弦 + (1−α)·饱和归一 BM25），语义侧用**真余弦**而非名次归一化（保住分数幅度）。
> - **量化驱动调优**（真语料 + 真模型 A/B）：查询改 OR（recall@5 45/45 vs AND 39/45）；向量预算从"块数"改"字数"（覆盖 41%→66%）；联网材料整页入库（混合命中 **29%→71%**）；FTS5 替换 LIKE（top1 **34→134**、recall@5 **39→169**）。
> - 治理 512-token 模型契约的**静默截断**（按 token 边界二分裁剪 + 告警）。

**C. 记忆与上下文（对应 JD：Memory / Context Engineering）**
> - 实现**多层记忆系统**（L1 项目上下文 / L2 轮次观察 / L3 灵感 / L4 轮次摘要 / M6 跨轮记忆），M6 带**出处强制**（必须携带账本编号）、**用户确认唯一写入口**、机械去重、命中现算、容量 60 条 / 命中窗口 10 轮。
> - **上下文预算治理**：消费遥测（注入 vs 引用）、位置感知组装（Lost in the Middle）、按编排层裁剪。
> - **量化**：席位意见折叠成"覆盖清单"后 `opinions_so_far` **42,803 → 22,259 字（−48%）**，再改指针式 **−78%**；schema 瘦身 **19,242 → 16,844（−12.5%）**。

**D. 运行时控制与韧性（对应 JD：生产级 / 高可用 / 降级）**
> - 实现**熔断 + 隔离舱 + 重试预算**三件套 + 抖动退避；熔断**只计"依赖不健康"的失败**（用户输错不会熔断上游）。
> - 建立**失败分类单点权威表**（`isinstance` 绑真实 SDK 异常，改名即导入期报错），消除"两套权威做同一决定"。
> - **量化**：`max_tokens` 按真实调用 **P99=7048 × 1.2 = 8457** 设定，消除"事后截断、用户拿不到条目"；登录链路 argon2 移出事件循环 + 并发隔离舱，**200 并发下事件循环不再被占死**（改前 50 并发登录 p50 2354ms）。

**E. 架构治理（对应 JD：DDD / 工程化 / 架构能力）**
> - 用 **AST 依赖守卫**强制 DDD 分层（`harness` 零业务词、只依赖 pydantic/litellm/pybreaker），替代"靠约定"；含"**守卫自己有没有效**"那一层（`guard_coverage.py` 用合成违规测守卫判据）。
> - 14 个架构守卫 + 18 个混沌/容错 e2e（磁盘满真 ENOSPC、Redis 强断、SQLite 写锁、上游 5xx、并发冒烟）。
> - **量化**：后端 257 个测试文件、ruff 零告警；前端 75 个组件 + `tsc --noEmit` 零输出。

**F. 评测（对应 JD：Eval Pipeline）**
> - 建立**真模型 eval**：11 条用例（含矛盾/模糊/外部事实/端到端边界）+ 12 条**纯函数结构断言**（不看文案只看形状）。
> - 检索质量验收清单：**配对增量测量 + 符号检验**（词面 Δ+7、9 赢 2 输；改述 Δ+5、5 赢 0 输）。
> - 纪律：**不把"模型行为率"当默认必过判据**（量不出下降的红灯会训练人忽略红灯）。

**G. 安全（对应 JD：安全 / 权限）**
> - argon2（RFC 9106 LOW_MEMORY）+ 异步隔离舱；会话 token 明文永不入库（只有 `token_hash`）。
> - **三维登录限流**（失败锁回 401 不可枚举 / per-IP / per-username 回 429 + Retry-After）；跨租户**越权一律 404**；SSE 按 owner 裁剪。

## 四、面试追问弹药（高频考点 + 答题要点）

> 按牛客 2828 条面经的频次排序。每题给出"考点 + 你的答法 + 代码依据"。

### 4.1 RAG（175 次，断层第一）

**Q：讲讲你的 RAG 全链路，以及你怎么衡量效果？**
- **答**：解析（docx/xlsx/pdf/网页）→ 分块（标点优先、贴近预算）→ 混合检索（jieba 预分词 + FTS5 + sqlite-vec）→ 凸组合融合 → 上下文预算治理 → 生成。**衡量**：材料级 r5、块级 r5、MRR、跨块证据完整率、无关块数、延迟；用**配对增量 + 符号检验**做验收。
- **依据**：[materials.py](file:///workspace/ai-pm/backend/src/pmstudio/infrastructure/sqlite/materials.py)、[vector_index.py](file:///workspace/ai-pm/backend/src/pmstudio/infrastructure/sqlite/vector_index.py)、`03-案例与验收.md` E9。

**Q：为什么用 OR 不用 FTS5 默认的 AND？**
- **答**：实测（15 篇 × 3 类 = 45 查询）OR recall@5 45/45、AND 39/45、LIKE 15/45。中文查询词稀疏，AND 会漏。
- **依据**：`docs/plans/2026-10-17-检索升级-方案.md`。

**Q：为什么不用 Milvus/Qdrant？**
- **答**：单用户本地应用，引入外部向量库是净负担（部署、运维、网络）。sqlite-vec 与 FTS 同库同表族，**零第二存储**，检索器协议零改。**代价**：不适合海量向量；如果场景是百万级文档，我会选 Qdrant/Milvus。
- **依据**：[vector_index.py](file:///workspace/ai-pm/backend/src/pmstudio/infrastructure/sqlite/vector_index.py)。

**Q：RRF 和凸组合的区别？你为什么换？**
- **答**：RRF 是纯名次函数、丢掉分数幅度，实测逐字子串 top1 30→25（倒退）。凸组合 `α·余弦 + (1−α)·饱和归一 BM25`，语义侧用真余弦保住"差多远"。调研依据：TOIS 2023（9 数据集，in/out-of-domain 都赢 RRF）。
- **依据**：[materials.py](file:///workspace/ai-pm/backend/src/pmstudio/infrastructure/sqlite/materials.py)。

### 4.2 多智能体（13 次）

**Q：为什么用确定性状态机，而不是让 LLM 自己规划（ReAct）？**
- **答**：主闭环要**可控、可恢复、可审计**——LLM 规划会引入不确定性，而文档写入是不可逆动作。所以主闭环用 LangGraph 状态机（state 只放引用、真相源是 Round 聚合）；**探索性调研**才用更灵活的 agent。两种范式我都在项目里实现过，取舍依据是"动作是否可逆"。
- **依据**：[graph.py](file:///workspace/ai-pm/backend/src/pmstudio/infrastructure/graph/graph.py)。

**Q：席位并行怎么处理失败？**
- **答**：分级——网关类失败（超时/5xx）→ 整轮失败可重试；内容错（两次交不出）→ **记名跳过该席位 + 留痕**，整轮继续（不让一个席位拖死整轮）。汇合点幂等编号；跳过席位的迟交不 attest、不谎报。
- **依据**：`application/use_cases.py`。

### 4.3 幻觉（13 次）

**Q：你怎么治理幻觉？**
- **答**：三层——① **出处账本**（每条内容带编号，`refs → derived_from` 必须回溯到用户输入或问卷答案）；② **AI 不写文档**（编排层只产出待写入清单，唯一写入口是确认端点）；③ **lenient 兜底**（最后一次重试摘掉引用不存在编号的条目 + 留痕，不判死整轮）。
- **依据**：`domain/provenance/ledger.py`、`AGENTS.md` 四条不变式。

### 4.4 ReAct（11 次）

**Q：ReAct 和 Plan-and-Execute 的区别？死循环怎么处理？**
- **答**：ReAct 是"思考→行动→观察"的**逐步**循环，灵活但难控；Plan-and-Execute 先规划再执行，可控但规划可能过时。**死循环处理**：① 轮次上限（一轮内最多 3 次席位轮，到上限仍有缺口就全部显式化为开放问题）；② 动作幂等；③ 有界重试 + 熔断。
- **依据**：`02-编排与数据.md` §2、`graph.py` 的 `RESUME_ROUTES`。

### 4.5 记忆 / 上下文压缩（13 次）

**Q：你的记忆系统怎么设计？怎么防止记忆污染？**
- **答**：五层（L1 现算不落库 / L2 观察 / L3 灵感 / L4 摘要 / M6 跨轮）。**M6 两条硬约束**：① 一条记忆必须带账本里存在的出处编号；② **只有人的确认能改它**（Curator 只能出提议）。容量 60 条、命中窗口 10 轮（现算，不落库）。
- **依据**：`domain/memory/memory.py`。

**Q：上下文太长怎么办？**
- **答**：不是"截断"而是**治理**——① 消费遥测（追踪"注入 vs 引用"，实测 materials 注入但 0 引用）；② 位置感知组装（承重块贴头，Lost in the Middle）；③ 席位意见折叠成覆盖清单（−48%）再改指针式（−78%）；④ 按编排层裁剪（但契约级有引用需求的层不裁，否则砍到可追溯不变式）；⑤ 截断照实说（"共 N 条，只带了前 M 条"）。
- **依据**：`application/context.py`、`07-记忆层.md`。

### 4.6 工程化与可观测

**Q：你的系统怎么保证生产可用？**
- **答**：① **韧性三件套**（熔断/隔离舱/重试预算 + 抖动退避）；② **失败必须是失败**（模型失败不静默降级、空回包/非 JSON 留痕）；③ **混沌矩阵**（真注入 5xx/断 Redis/写锁/磁盘满）；④ **架构守卫**（AST 强制分层 + "守卫自己有没有效"）；⑤ **真模型证据**（生产路径不提供假模型开关）。
- **依据**：`harness/model/resilience.py`、`scripts/chaos_matrix.py`、`tests/architecture/`。

**Q：熔断的判据是什么？为什么不自己写？**
- **答**：只计"依赖不健康"的失败（timeout/5xx/限流），**用户输错密码不能熔断上游**。不自己写判据：实测 pybreaker **没有滑动窗口失败率**（50% 失败率实测永不开闸），采纳其"累计失败计数、成功即清零"语义，只在 `exclude` 扩展点表达"什么算失败"。**踩坑**：pybreaker 的 `call_async` 在不装 tornado 时恒 `NameError`（`gen` 未定义），改用同步上下文管理器 `calling()` 走同一状态机；半开迁移必须自己做（库的 `before_call` 走同步 `call()`，协程从没被 await 却被记成探针成功）。
- **依据**：`harness/model/resilience.py` 的注释（这段是极好的面试素材）。

### 4.7 项目深挖

**Q：这个项目最难的地方是什么？**
- **答**：不是"调通模型"，而是**把模型能力从业务里解耦成运行时控制平面**，并用机器（AST 守卫）而不是约定来守住分层。另一个难点是**让"失败可解释"**——每个席位意见没进卡片都要能说清为什么（`DroppedItem` 四个来源）。
- **依据**：`harness/` 层设计、`AGENTS.md` 三条硬规矩。

**Q：如果重做，你会改什么？**
- **答**：① 更早引入 MCP 把工具层标准化；② 评测前置（先有 eval 再改检索参数，而不是事后补）；③ 向量库在文档量上来后迁到 Qdrant。
