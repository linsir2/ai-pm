# 可复用经验

> 只记"会重复用到、且能说清来源"的东西。每条带：置信度、来源、涉及文件、失效条件。
> 一次性观察别写进来，先留在过程记录里。

---

**L1 · 通用角色编制问不出领域问题**
置信度 9 / 来源：observed（本会话设计对比）
内容：Analyzer/Skeptic/Writer/Reviewer 这类编制，面对"订单导出"和"医疗排班"会问出同一批
通用问题。信息密度来自**席位是否领域化**，所以编排第一步是席位提名，不是提问。
失效条件：如果将来引入能自动检索领域知识的席位生成器，这条会更弱。

**L2 · 空返回不等于无发现**
置信度 10 / 来源：observed（真实事故：并行子智能体没收到任务，返回"我准备好了"）
内容：如果席位输出不做 schema 校验，空结果会被当成"该专家无意见"，文档会静默缺掉
一整个专业面。修法：空 findings 必须带理由，解析失败即该席位失败、整轮失败可重试。
失效条件：无。

**L16 · 旁路要是真的旁路：留样炸掉把整轮搞失败了**
置信度 9 / 来源：observed（P5c 真模型第一次跑：TypeError 把整轮打成 502）
内容：留样（`model_calls`）设计成"可开可关、只给排查用"，但第一版只在 SQLite 出错时兜底；
真模型跑起来时 litellm 的 `usage` 里带 pydantic 包装对象（`CompletionTokensDetailsWrapper`），
`json.dumps` 抛 TypeError → 异常穿过网关 → 整轮 502。
规矩：
1. **旁路组件的失败边界要按"它能碰到的所有东西"写**，不是按"我以为会出错的地方"写：
   序列化（TypeError/ValueError）、IO、连接都在内。
2. 给旁路的输入先**规范化**（网关 `_jsonable()`：认不出的对象 `str()`），别把"能不能序列化"
   这个难题甩给下游。
3. 判断"旁路真的旁路了"的唯一办法是让它跑在真数据上——测试里我造的是干净 dict，永远不会触发。
失效条件：无。

**L17 · 真模型会把"给人看的表格"整行抄进结构化字段**
置信度 8 / 来源：observed（P5c 真模型：`section_id: "s3 用户与受众"`、`{section_id: s1, field: one_liner}`）
内容：提示词里章节表渲染成 `- s3 用户与受众`（给人读很自然），模型就把整行当 id 抄了进去；
同一轮里它还把"功能字段名"（`one_liner` / `goal`）当成"章节的字段"用——
因为提示词里"章节"与"功能字段"两套命名空间只在一处并列，模型没有"这两者互斥"的硬规则。
规矩：
1. **给人看的枚举表要额外写一句"字段只能填前面那个短 id，不带标题/空格"**。
2. 两套命名空间（章节 / 章节槽 / 功能字段）必须**各给一个正确写法 + 一个反例**；
   只给正确写法时，模型会把两套混起来用（这一轮连错两次，第二次提示词里已经带着第一次的报错）。
3. 这类错会在**重试时复现**：重试把同一段提示词再喂一遍，模型大概率再犯——
   所以"打回重装一次"对提示词缺口基本无效，要么改提示词，要么把那条内容降级留痕。
失效条件：换用能约束解码到枚举的网关（把 section_id 限成 enum）之后，第 1、2 条可以放松。

**L18 · `default_db` 不是覆盖：环境变量优先，于是 eval 写进了工作库**
置信度 9 / 来源：observed（P5c：eval 跑完发现 `backend/data/pmstudio.db` 多了一个项目）
内容：`Settings.from_env()` 的解析顺序是 `PMSTUDIO_DB` 优先、`default_db` 只是兜底。
我按"传 `default_db=/tmp/...` 就安全"的直觉写脚本，可一旦 shell 里 source 过 `.env`，
`PMSTUDIO_DB=data/pmstudio.db` 就赢了 → 一次 eval 往作者的工作库建了项目与轮次。
（这次没有写文档：eval 不确认草案。但库被动过就是被动过。）
规矩：
1. 凡是"会在库里造东西"的脚本（eval / 压测 / 实验），**必须显式把库定死**，
   用 `dataclasses.replace(settings, db_path=…)` 这种**覆盖**，而不是 `default_db=` 这种**兜底**。
2. 顺手加一道守卫：解析出来的库 == 工作库就**拒绝运行**（并打印用的是哪个库）。
3. 给工作库做实验前，先用只读方式确认它长什么样（`file:…?mode=ro`），
   跑完再确认一次（我这次就是靠这个发现的）。
失效条件：无。

**L19 · 写进 `.env` 的值要能被 `source` 直接吃**
置信度 8 / 来源：observed（P5c：`PMSTUDIO_MODEL_PARAMS={"extra_body": ...}` 一 source 就报
`{enable_thinking:: 未找到命令`）
内容：`dev.py` 自己写的 `.env` 解析器没事（它按 KEY=VALUE 拆、顺手剥引号），
但我自己跑脚本时习惯 `set -a && . ./.env`，bash 见到 `{` 与空格就当成命令了。
于是"模板里写的那行"和"我能直接 source 的那行"是两回事。
规矩：
1. `.env.example` 里凡是 JSON / 含空格 / 含特殊字符的值，**一律带单引号**，
   并在注释里点明原因（`dev.py` 的解析器会剥掉那层引号，两边都安全）。
2. 改完 `.env` 就**当场 source 一次**验证（这一步能立刻抓到这类问题）。
失效条件：无。

**L3 · 门禁条款写成形容词就会退化**
置信度 8 / 来源：inferred + 借用 main 的分支设计
内容："至少存在一个被认真考虑过的备选方案"这类条款机器判不了，若交给模型判断，
整张门禁会退化成永远通过。改写成"某字段存在且非空"就能机械判定。
失效条件：无（这是通用的可测试性规律）。

**L4 · 卡片不能编辑内容**
置信度 9 / 来源：borrowed（main 分支 PRD §9.5）
内容：一旦卡片里能改文案，就必须回答"卡片改的和文档改的谁优先"，还得再定一套合并规则。
结论：卡片只收敛决定（要/不要），编辑归文档。
失效条件：若文档本身不可编辑，这条要重新评估（v1 的取舍见 07 问题 10）。

**L5 · 先读已有的设计再动手设计**
置信度 10 / 来源：observed（本会话在没读 main 分支设计的情况下重新推导了一遍，
其中三处还推出了与已有设计冲突的结论）
内容：本仓 `main` / `redesign` 分支已有一套完整设计（PRD / CONTRACTS / DECISIONS）
与后端实现。设计前先读，能省掉大半天。
失效条件：若那些分支被删除或废弃。

**L6 · 双真相源是本项目的明令禁止项**
置信度 10 / 来源：borrowed（main 分支 PRD §0）
内容：同一件事在两处各写一遍，迟早不一致，然后没人知道信哪份。字段级定义只写一次。
本项目的落点：`.codex/docs/设计/`，别处只引用不复述。
失效条件：无。

**L7 · 单用户系统必须有外部检验**
置信度 7 / 来源：inferred（模拟专家组评审时得出）
内容：只有一个用户时，判断容易自洽；真正有力的检验是让一个没有上下文的读者只读文档，
把看不懂的地方列出来（对应设计里的"陌生人读者"）。
失效条件：若将来引入第二个真实读者。

**L8 · 席位限制读取范围会漏信息**
置信度 9 / 来源：user-stated（作者指出"不读全文档怎么确保读全"）
内容：只让席位读它负责的章节，它就无法判断这件事与别处的关系。改法：
必读高密度摘要（章节状态表）+ 章节全文按需 + 可申请扩读并留痕。
失效条件：无。

**L9 · 模型的字段级笔误不该判死整轮**
置信度 10 / 来源：observed（P2 真模型冒烟，qwen3.8-flash，一晚上连撞五次）
内容：真模型会在**结构化字段之间的依赖关系**上滑跤，而且重装一次也未必改对：
`field` 不带 `feature_slug`、`feature_slug` 挂在 s12 上、`label=preference` 却给 `zone=body`
与功能字段、某条意见既没依据编号也没写 why。这些撞的都是领域不变量（D3 / LB1 / AG1），
如果按"失败必须是失败"直接判整轮失败，代价是**整轮（十几次模型调用 + 用户已答的问卷）作废**。
改法（判据要分清）：
1. **能在领域规则内规范化**的，规范化并把决定变得可见：功能必然在 s5 → 纠正；
   标签才是权威分类 → 以标签定分区；没给依据的意见 → 降级成"它提议的"（最低权威、默认不勾）
   并写明"模型没给依据"；有内容但没写读了什么 → 标注后继续。
2. **真正不可用**的才失败：不是 JSON、报文缺必填字段、既没意见也没说读了什么（L2）、
   章节 id 是幻觉（s99）。
3. 失败要报成"模型输出不可用"（502），别让领域异常漏成 409——P2 实测漏过一次。
配套：**把字段表喂进提示词**（`from authoring/schema.py` 生成，不许手抄），否则模型只能编字段名。
失效条件：如果将来模型在结构化输出上足够稳（或换成强约束解码），第 1 条可以收紧回严格。

**L10 · 假模型跑一百遍也发现不了这些**
置信度 9 / 来源：observed（P2：脚本化模型的 e2e 全绿之后，真模型第一轮就撞四处）
内容：假模型返回的是**我们手写的合法报文**，它天然不会犯"字段依赖写错"这类错。
所以"闭环通了"的证据必须是真模型跑出来的；假模型 e2e 只能证明**结构**通。
做法：保留一条不依赖浏览器、不依赖人眼的真模型命令（`backend/scripts/smoke.py`），
每轮改完提示词/契约就跑一次。
失效条件：无。

**L13 · 提示词里不许出现"像编号的非编号"**
置信度 9 / 来源：observed（P4：作者真跑整轮失败 + 4 次重放复现，1 次泄漏）
内容：席位意见曾经渲染成 `[判断] [O1] …`，小标题还写着"编号就是这条判断的出处"——
而 `evidence_refs` 只收 E 编号。模型于是把席位条目地址当编号写进去，甚至连带席位名拼成
`seat.business_rules:O1`（它知道裸 O1 有歧义，却没有合法写法可用）→ 校验判死整轮，
重试拿同一句提示词再撞一堵墙。
规矩：
1. 给模型的每一种身份都要有**唯一的写法与唯一的名字**：`E7` = 出处编号、`seat.x:O2` = 席位条目
   地址，两处在同一条意见里分别写明；不许出现"看着像编号但其实是别的东西"的 token。
2. 模型引不到的东西，要么给它一个合法的引用通道（如 `from_opinions` 归因字段），
   要么根本不给它看那个 token——**留一个它想引、系统不认的东西，就是在训练它编**。
3. 这类错是概率性的（4 次重放 1 次中），所以"跑过一次没出现"不算证据；重放要跑几次。
失效条件：换用强约束解码把字段限死之后，第 1 条可以放松成"命名清晰即可"。

**L14 · 领域能力躺在代码里没人调用 = 没测过的雷**
置信度 9 / 来源：observed（P5b：`Document.rollback_to` 有实现、有测试，一接上界面就炸）
内容：回退一直"已实现且测试通过"，但唯一那条测试只覆盖"回退到 v1（空骨架）"。
真正会出事的场景是"回退到一个**含后来被删掉的块**的快照"：`rollback_to` 恢复旧快照时不动墓碑，
而 `_validate` 要求活块 id 与墓碑 id 不重叠 → 写出一个**落库没事、下次读回来抛
`DuplicateBlockId`** 的文档，整个项目打不开。
规矩：
1. "能力已实现"不算证据，"**从界面真能走到**并且走完再读回来"才算——接上入口时先把这条路径
   从头到尾跑一遍（落库、重读、再写）。
2. 领域里那些"恢复 / 回退 / 迁移"语义的写操作，测试至少要覆盖**非空历史**（有删除、有墓碑、
   有偏好区），空历史那条最省事也最没用。
3. 任何"恢复快照"的操作都要问一句：**派生状态（墓碑、索引、计数）跟着重算了吗**。
失效条件：无。

**L15 · "全都记下来"要有一条通道，且每个来源都要能核**
置信度 8 / 来源：observed（P5b：设计只写"模型申报丢弃"，核验时发现草案路径整条丢痕）
内容：留痕（"这条为什么没进卡片"）最初只有两个来源：模型自己在报文里申报、装配层发现归因对不上。
两个问题：① 只在"出问卷"那条路上被写进轮次，走草案的一轮全丢；② 只靠模型自觉，
它不申报就等于没发生。
做法：**一条通道 + 三个来源**，其中 `unaccounted`（既没被引用、也没被申报）由装配层用纯代码核出，
边界写死（被题引用 / 自己的编号被引用 / 模型申报过，三者满足其一就算交代过）。
附带发现：`local_id`（`O1`）在**同一轮的多趟席位轮之间会重号**，所以留痕必须带 `pass_index`，
否则界面不知道该挂到哪个席位包下面。
失效条件：无。
