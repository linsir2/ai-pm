# 可复用经验

> 只记"会重复用到、且能说清来源"的东西。每条带：置信度、来源、涉及文件、失效条件。
> 一次性观察别写进来，先留在过程记录里。

---

**L1 · 通用角色编制问不出领域问题**
置信度 9 / 来源：observed（本会话设计对比）
内容：Analyzer/Skeptic/Writer/Reviewer 这类编制，面对"订单导出"和"医疗排班"会问出同一批
通用问题。信息密度来自**席位是否领域化**，所以编排第一步是席位提名，不是提问。
失效条件：如果将来引入能自动检索领域知识的席位生成器，这条会更弱。

**L2 · 空返回不等于无发现**
置信度 10 / 来源：observed（真实事故：并行子智能体没收到任务，返回"我准备好了"）
内容：如果席位输出不做 schema 校验，空结果会被当成"该专家无意见"，文档会静默缺掉
一整个专业面。修法：空 findings 必须带理由，解析失败即该席位失败、整轮失败可重试。
失效条件：无。

**L3 · 门禁条款写成形容词就会退化**
置信度 8 / 来源：inferred + 借用 main 的分支设计
内容："至少存在一个被认真考虑过的备选方案"这类条款机器判不了，若交给模型判断，
整张门禁会退化成永远通过。改写成"某字段存在且非空"就能机械判定。
失效条件：无（这是通用的可测试性规律）。

**L4 · 卡片不能编辑内容**
置信度 9 / 来源：borrowed（main 分支 PRD §9.5）
内容：一旦卡片里能改文案，就必须回答"卡片改的和文档改的谁优先"，还得再定一套合并规则。
结论：卡片只收敛决定（要/不要），编辑归文档。
失效条件：若文档本身不可编辑，这条要重新评估（v1 的取舍见 07 问题 10）。

**L5 · 先读已有的设计再动手设计**
置信度 10 / 来源：observed（本会话在没读 main 分支设计的情况下重新推导了一遍，
其中三处还推出了与已有设计冲突的结论）
内容：本仓 `main` / `redesign` 分支已有一套完整设计（PRD / CONTRACTS / DECISIONS）
与后端实现。设计前先读，能省掉大半天。
失效条件：若那些分支被删除或废弃。

**L6 · 双真相源是本项目的明令禁止项**
置信度 10 / 来源：borrowed（main 分支 PRD §0）
内容：同一件事在两处各写一遍，迟早不一致，然后没人知道信哪份。字段级定义只写一次。
本项目的落点：`.codex/docs/设计/`，别处只引用不复述。
失效条件：无。

**L7 · 单用户系统必须有外部检验**
置信度 7 / 来源：inferred（模拟专家组评审时得出）
内容：只有一个用户时，判断容易自洽；真正有力的检验是让一个没有上下文的读者只读文档，
把看不懂的地方列出来（对应设计里的"陌生人读者"）。
失效条件：若将来引入第二个真实读者。

**L8 · 席位限制读取范围会漏信息**
置信度 9 / 来源：user-stated（作者指出"不读全文档怎么确保读全"）
内容：只让席位读它负责的章节，它就无法判断这件事与别处的关系。改法：
必读高密度摘要（章节状态表）+ 章节全文按需 + 可申请扩读并留痕。
失效条件：无。
