# 主闭环规格 v1

> 定位：**只定义打通闭环必需的东西**。其余一律标"以后"，不进 v1。
> 状态：待确认 · 2026-09-21
> 参照：main 分支的 PRD / CONTRACTS / DECISIONS（汲取思路，不搬契约）。

---

## 0. 闭环是什么

一句话：**一段零散输入，经过编排，变成文档里的草案，用户确认后落进 block 树，产生一个版本。**

四个动作不可少：**输入 → 问 → 答 → 写**。凡是与这四步无关的，v1 都不做。

---

## 1. 六个环节，三次中断

```
输入
 → ① 切分 + 定性                        Analyzer
 → ② 开场卡（复述 + 席位提名）            ← 中断 1
 → ③ 席位并行发现 → Validator 召回
      → Integrator 整合 → 问卷           ← 中断 2
 → ④ 作答 → 答案走统一入口 → 必要时第二次问卷
 → ⑤ 草案（Writer）→ Validator 校验      ← 中断 3
 → ⑥ 确认 → 写入 → 版本快照
```

三次中断，每一处都对应一个"必须有人决定"的点：**我理解得对不对 / 这个问题你怎么答 / 这样写要不要**。

---

## 2. 每一环的产出（结构化，可直接被下一环消费）

| 环节 | 产出 | 关键字段 |
|------|------|---------|
| ① 切分定性 | 主张清单 | 证据编号 `E`、原文、**七种标签之一**、归属章节 |
| ③ 席位发现 | finding | 席位名、指向（章节+字段）、依据（E 编号）、要问的问题 |
| ③ 整合 | 问卷 | 题目（目标字段、为什么问、选项、不答的后果） |
| ④ 作答 | 新证据 | 新 `E` 编号、内容、来源（哪张卡的答案） |
| ⑤ 草案 | 提案 | 目标 block、动作（追加/替换）、内容、依据（E 编号） |
| ⑥ 确认 | 版本 | 版本号、触发者（手改/确认）、变更的 block id 列表 |

七种标签：**事实 / 需求 / 目标 / 约束 / 偏好 / 猜测 / 决定**。
其中两条按硬规则处理：**偏好不进正文**（单独存），**猜测升格为假设**（带失败后果与验证方式）。

---

## 3. 三条不变式（v1 必须成立，其余都可以缓）

1. **AI 不写文档。** 图只产出"待写入清单"，写入只有一个入口（确认端点）。
2. **统一入口不变式。** 凡是进入文档的信息——首轮输入、问卷答案、以后的外部导入——
   都必须经过：切分 → 定性 → 人确认标签。
3. **先有编号，后有内容。** 每条断言都带证据编号；没有编号支撑的内容不许进正文，只能进开放问题。

---

## 4. 最小角色集

| 角色 | 类型 | v1 职责 |
|------|------|---------|
| Analyzer | 智能体 | 切分 + 定性 + 初归位 |
| 领域席位 ×2–4 | 智能体 | 按提名上场，独立发现，只出 finding |
| Integrator | 智能体 | 归一化 / 合并去重 / 归类，**只出问卷，不碰草案** |
| Writer | 智能体 | 把已确认信息写成提案，不引入新信息 |
| Validator | **代码** | 证据编号、字段形状、结构校验；候选召回 |
| 人 | — | 唯一能写入的人 |

**v1 不做**：Reviewer 自动挑刺、Memory Curator、陌生人读者、范围守卫、席位权重与记忆、
门禁的完整实现、讨论区、工具层、注册层的完整权限矩阵。
这些都在设计里留着位置，但不写进这一版。

---

## 5. 借来的规矩（直接用，不重新发明）

从已有的那份设计里挑出与主闭环直接相关的，v1 照办：

| 规矩 | 内容 |
|------|------|
| 卡片是问卷 | 提交前可以回到任意一张改，提交后整组冻结（交卷语义） |
| 一批最多 5 张 | 一张卡只针对一个议题；**草案卡单独成批** |
| 卡片只有"要/不要" | **编辑归文档**，卡片里不设编辑器（否则要回答"哪边优先"） |
| 复述要有信息量 | 复述里必须包含**至少一个只有读了文档才知道的信息**，否则就是复读原话 |
| 分歧要暴露 | 矛盾题把双方的立场与依据并列摆出，不给被抹平的单方结论 |
| 一次改动 = 一版 | 确认写入、手动保存、回退，三条路径都产生版本；回退不删历史 |
| 不建桩 | 未实现的模块不写空壳，用显式"缺失清单"表示 |

## 6. 界面（三个面，本地 Web）

- **输入区**：一段输入 + 运行状态（分析中 / 等你回答 / 已完成）
- **文档区**：block 树只读展示（能看出章节、功能子树、缺口）
- **卡片区**：开场卡 / 问卷 / 草案卡，一次一批

---

## 7. 实现上还没定的（三个选择）

1. 存储：SQLite，还是文档直接存 JSON 文件
2. 模型接入：OpenAI 兼容接口（`base_url` + `key` + `model` 环境变量），还是先只接一家
3. 前端：React（Vite），还是先一个单页 + SSE 的轻量界面

---

## 8. 验收（主闭环算通了的标准）

在一次真实操作里能连续做到：

1. 输入一段零散想法 → 看到开场卡，且复述里包含只有读了文档才知道的信息
2. 确认后 → 收到一张问卷，题目前后不重复、每题都能落到具体章节字段
3. 作答 → 答案变成带编号的证据，必要时出现第二次问卷
4. 出现草案卡 → 每条提案带依据编号，可选要或不要
5. 确认 → 文档新增内容，版本号 +1，历史可查
6. 全程没有任何一步让 AI 直接改动文档
