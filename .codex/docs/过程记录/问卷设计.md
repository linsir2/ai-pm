# 问卷设计 · 提问合并 · 回答后的编排

> 状态：设计稿 · 2026-09-21 · 待裁决
> 变更：把"一张一张弹卡片"改成**一张问卷、逐题填写**；并定义问题之间如何解耦与去重，
> 以及用户答完之后流程怎么走。

---

## 一、为什么改成问卷

逐张弹卡有三个问题：

1. **看不到全貌。** 用户不知道后面还有几张、要花多久，于是每张都倾向于"快点过掉"。
2. **无法发现题与题的关系。** 逐张出现时，第二题来了，用户已经忘了第一题自己答了什么。
   而很多问题是一组的（量级、并发、超时是同一个判断的三个面）。
3. **重复无法被察觉。** 两个席位问同一件事，逐张弹出来用户会觉得"你刚问过"，
   但系统自己也不知道重复了。

一张问卷一次性解决这三件事：**看得见全貌、答得动、且可以在填写前就完成去重。**

## 二、题目结构

```jsonc
{
  "q_id": "Q3",
  "group": "s8 非功能需求",           // 主分组按章节——因为文档才是最终产物
  "asked_by": ["seat.data_scale"],    // 谁在问。合并后可能列出多个席位
  "target": { "section": "s8", "field": "性能上限" },   // 这个答案要落到的位置
  "type": "single_choice",            // single | multi | number | text
  "title": "单次导出的最大行数大概是多少？",
  "why": "1 万行可以同步导出；10 万行以上必须走异步任务加文件存储，是两套实现。",
  "options": ["少于 1 万", "1 万 – 10 万", "超过 10 万", "不确定，需要去看"],
  "allow_free_text": true,            // 选项之外可以自己写
  "depends_on": null,                 // 条件题：["Q1 = A"]
  "consequence_if_skipped": "第五章主流程和第八章性能上限都写不出来，只能留空。",
  "evidence_refs": ["E1", "E4"],
  "consumer": ["s5 主流程", "s8 性能上限", "数据规模席"]   // 谁会用到这个答案
}
```

四个字段是这套设计的重点：

- **`target`（落到哪里）**：每个问题必须指向一个具体的章节+字段。指不出来的问题**不许进问卷**
  ——这是防止"泛泛而问"的硬闸门。
- **`why`（为什么问）**：不是客套，是让用户判断该不该认真答。
- **`consumer`（谁会用到）**：答完之后谁消费这个答案。这条建立信任——
  用户知道自己的每个答案都有去处，不是填进黑洞。
- **`consequence_if_skipped`（不答的后果）**：跳过不是免费的，代价要写在题面上。

## 三、问卷长什么样

```
┌ 第 3 轮 · 8 个问题 · 已答 3 ────────────────────────────────┐
│                                                            │
│ ▾ s8 非功能需求                                     3 题    │
│   Q3 单次导出的最大行数大概是多少？            [数据规模席]  │
│      1 万行可同步导出；10 万行以上必须异步。                  │
│      ○ 少于 1 万   ○ 1万–10万   ○ 超过 10万   ○ 不确定      │
│      不答的后果：s5 主流程与 s8 性能上限都只能留空            │
│                                                             │
│ ▾ s4 范围与边界                                     1 题    │
│   Q7 ⚠ 你上轮定过"不做定时导出"，本轮的"每天定时导出"…       │
│      ● 改非目标（做定时导出）  ○ 维持不做   ○ 暂不决定       │
│                                                             │
│ ▾ s5 功能需求                                       2 题    │
│   …                                                         │
│                                                             │
│ ▸ 已跳过 1 题（会在交付前提醒）                              │
│                                                             │
│              [ 全部填完并继续 ]   [ 先提交已答的 ]            │
└─────────────────────────────────────────────────────────────┘
```

- 按**章节**分组（不是按席位）——因为用户的最终目标是那份文档，按章节分组能让他看出
  "这一章还缺什么"
- 每题标注**提问席位**，保留"谁在问"的信息
- 题目上限 12 题；超出的降级成清单项（可批量确认，不占注意力）

## 四、问题怎么解耦、怎么去重

这是你点出的关键。四个席位各问各的，必然出现"两个专家问同一件事"和"一题塞了三件事"。
四道处理，按顺序做：

### 第 1 道 · 归一化到 target（最有力的一道）

**每个问题必须先映射成一个 `target`（章节 + 字段）。映射不出来的问题不许进问卷**，
打回给提问席位重写。

这一道就解决了大半重复：两个席位用完全不同的措辞问同一件事，只要它们指向同一个
`target`，就会被排到一起。

### 第 2 道 · 同 target 合并

同一 `target` 上的多个问题合并成一题：

- 一个问题的选项集合是另一个的子集 → 取更全的那题，合并选项
- 粒度不同（"量级多大" vs "精确值是多少"）→ 取较粗的那题，把精确值降级进 `free_text`
- 合并后 `asked_by` **保留全部席位**——让用户看见"这是两个专家都关心的点"，
  这种题值得认真答

### 第 3 道 · 依赖显式化（"解耦"的正确含义）

解耦**不是**把相关的题拆散不管，而是两条相反的规则各管一头：

- **禁止复合题**："数据量多大、并发多少、超时怎么办"必须是**三题**，不许合成一题
- **允许条件题**：题与题的关系用 `depends_on` 显式声明。
  Q8 只在 Q7 选"改非目标"时才出现；Q3 答"少于 1 万"时 Q4（并发）自动降级为不必答

解耦的目标是**每题只问一件事**；依赖不藏在措辞里，写在结构里。

### 第 4 道 · 与已有内容去重（最容易漏的一道）

去重的对象不只是"本轮的其他问题"，还有**文档里已经有的答案**：

- 问题命中的字段已有内容 → 不问（除非意图是更新它）
- 问题命中的字段与已有内容矛盾 → 它不是"提问"，而是**矛盾裁决**，走另一种题型

### 判定手段从便宜到贵

1. `target` 完全相同 → 直接判重（零成本，覆盖大多数）
2. 同一章节 + 标题词重叠 → 候选重复（零成本）
3. 语义相似（嵌入）→ 兜底，只在候选数量超阈值时启用

顺序不能反：**先用便宜手段筛掉九成，贵的只用在剩下的少数上。**

## 五、回答之后怎么编排（你问的重点）

答案进来后，按**影响半径**分四类处理，而不是统一重跑一遍：

| 类型 | 判定 | 处理 |
|------|------|------|
| **补全型** | 直接填进某个空缺字段 | 生成证据编号 → 机械进"待写入清单" |
| **改判型** | 改变了上游定性（例如把某条从"猜测"确认为"事实"） | 触发定性修订：标签变化写入版本记录，并标记依赖它的字段为待复核 |
| **派生型** | 答案里含还没结构化的新信息（"不确定，得去看"） | 拆成新的原子主张 + 新证据编号，走一次轻量归位；仍缺才进补问 |
| **冲突型** | 与既有内容或本轮其他答案冲突 | 不当场解决，升级成下一题（本轮内最多补问 1 次），否则落成开放问题 |

### 5.1 回答之后，先回到复述层（你这条把整条链路补完整了）

正确的顺序不是"答案 → 直接进草案"，而是：

```
作答 → 答案当作新输入 → 切分 + 定性（七种标签）→ 复述确认 → 才进草案
```

理由是**答案是二等信息里最容易出错的地方**："我以为你选的是 A，其实你选了 B 并在补充里
写了别的"——这种偏差如果直接进草案，就会变成文档里一条有证据编号、却没有归属的错话。

答案尤其容易产生两种标签：**猜测**（"大概几万吧"）和**偏好**（"我觉得 PDF 好一些"）。
而这两类恰恰是必须被显式处理的（猜测升格为假设、偏好不进正文）。所以在复述层拦住它们，
比在草案里改回来便宜得多。

这引出一条贯穿全系统的**统一入口不变式**：

> **凡是进入文档的信息，无论来自首轮输入、问卷答案，还是将来的外部导入，
> 都必须经过同一个入口：切分 → 定性 → 人确认标签。**

复述层因此是**可重入**的：它不只服务首轮输入，而是服务每一次"有新信息要进文档"的时刻。

### 5.2 答案轮：复用同一套编制，不另起一个"收口"

我上一版在这里设计了一个轻量的"收口卡"（复述 + 至多 3 道新问题），这是错的：

**它假设了"新问题"可以由 Analyze 一个人拍出来，而真实情况是——新问题必须由相关席位提出。**
比如你答"要按门店分开导出"，这立刻是数据模型层面的问题（门店维度怎么存、跨门店权限怎么算），
只有数据模型席和权限席提得出来，一个复述步骤是凑不出来的。

所以答案之后的正确做法是：**复用原来那套编制，只是按影响面缩编。**

```
答案当作新输入
   ↓
Analyzer：重新切分 + 定性（统一入口不变式）
   ↓
复述确认（标签可改）              ← 与第一次同源，不是新机制
   ↓
按影响面提名：只请与本轮答案相关的席位（可能只请 1–2 个）
   ↓
席位独立发现 → Validator 候选召回 → Integrator 整合
   ↓
若仍产生矛盾或缺口 → 第二次问卷（矛盾组 + 缺失信息组）
   ↓
直到不再产生新问题 → 进草案
```

**终止条件**（必须有，否则会无限打断）：默认最多两轮问卷——输入轮一次、答案轮一次。
第二轮之后仍然存在的问题，一律降级为开放问题（阻塞型 / 记录型），不再追问。
如果用户自己觉得还有必要，可以主动点"继续深挖"。

**可以跳过复述的情况**：如果答案满足三个条件——① 全是选项选择、没有自由文本；
② 没有引入新的原子主张；③ 没有改变任何已有证据的标签——则跳过这一轮的重走流程，
直接进草案，并在草案卡顶部回显一行"本轮答案无歧义，未做二次复述"。
这是唯一允许跳过的情形，而且跳过是**显式写在草案卡上**的，不是静默省略。

然后收口：

- **未答 / 跳过的题**按题面的 `consequence_if_skipped` 落成开放问题；
  命中必填字段的跳过 → 阻塞型（挡交付）
- 答案轮不再产生新问题之后 → 进草案生成

### 一条铁律：先有编号，后有内容

**答案必须先变成证据编号，再变成文档内容。** 顺序反过来，追溯链就断了——
你就再也说不出"这句话是因为我在第 3 轮答了那道题才写上去的"。

### 为什么回答后不重跑全部席位

成本高，而且会推翻刚刚答完的东西：用户答完 Q3，系统重跑一遍分析，可能又冒出一批新问题，
用户会觉得"我刚才白答了"。所以回答后只做**局部增量**，把"还需要更多信息"收敛到
本轮唯一一次补问里。

## 六、问卷与草案确认是两件事

- **问卷**回答的是"我不知道，你告诉我"——本质是**答题**
- **草案确认**回答的是"这样写对不对、要不要改"——本质是**审 diff**

草案确认不该塞进问卷：它需要 before/after 对照、逐条确认/编辑/删除，把它做成选择题
会丢掉"我能改内容"这个最重要的能力。所以界面上分开，但**同属一次 run 的两步**：
问卷在前，草案确认在后。

### 一轮完整的中断序列

```
① 开场卡      理解复述 + 席位提名 + 遗留阻塞项 + 预期管理
② 问卷        矛盾组 + 缺失信息组（按章节排序，至多 12 题）
③ 答案轮      复述确认 + 缩编席位的重新发现 + 可能引出第二次问卷  ← 无歧义时可跳过
④ 草案卡      before/after 逐条确认、编辑、删除
```

最坏四次、常见三次、最省两次。每一次中断都有明确目的，没有纯粹的形式主义打断。

## 七、待裁决

1. 12 题上限是否合适？（经验值：超过 12 题，填写率会明显下降。）
2. 条件题（`depends_on`）v1 就实现，还是先只做"标注依赖但全部展示"？
3. 改判型答案把依赖字段标为"待复核"之后，要不要**自动重问**这些字段？
   我倾向不自动重问，只在草案卡里显式提示"这条受 Q2 的答案影响"。
4. 跳过答案复述的三个条件（全选项 / 无新主张 / 无标签变更）由代码判定即可，
   但**判定结果要不要显示给用户**？我倾向显示成草案卡顶部的一行回显，
   否则用户会怀疑"它到底有没有认真看我的答案"。
