# 07 · 记忆层与上下文组装

> **性质**：总览与现状基线（2026-10-09）。字段/契约以**代码**与 `02`/`05` 为准，本文不另立契约
> （双真相源是本项目明令禁止的）。本文的用途：给"记忆层重构"提供一张可核对的地图。

## 1. 记忆层：五层

| 层 | 类 / 文件 | 存储表 | 生命周期 | 谁写 | 谁读 |
|---|---|---|---|---|---|
| **L1** 项目上下文 | `ProjectContext` `domain/memory/context.py` | **不落库**（每轮现算） | 每轮 | `application/context.py::build_project_context` | analyzer / seat / integrator |
| **L2** 轮次观察 | `RoundObservation` `domain/memory/observations.py` | `observations` | 永久/项目 | 席位轮后 `extract_observations_from_reviews` | seat / integrator（只标题 ≤5） |
| **L3** 灵感档案 | `InspirationItem` `domain/memory/inspiration.py` | `inspirations` | 永久/项目 | 用户"收下"时（讨论/探索/模拟三入口） | **仅** integrator（≤5） |
| **L4** 轮次摘要 | `RoundDigest` `domain/memory/digest.py` | `round_digests` | 永久/项目 | 确认草案时 `build_round_digest` | **仅** integrator（≤3） |
| **M6** 跨轮记忆 | `ProjectMemory`/`MemoryEntry` `domain/memory/memory.py` | `project_memory` | 永久/项目，**用户确认** | Curator 提议 → 用户确认 → `apply()` | seat / integrator / inquirer / sim_inquiry / sim_review（≤20 行，**不带 id**） |

**逐层口径**：

- **L1 不落库**是刻意的——避免与文档/M6 变成两个真相源。`top_decisions` 从 M6 抽、`open_questions` 从 s11 抽、`features_defined` 从 s5 抽、`sections_covered` 现算。
- **L2 去重**：同 `source_ref`（`seat_id:local_id`）**读时**只留最新（B3）。
- **L3**：`origin ∈ {discussion, exploration, sim_inquiry}`；收下**不去重**（每次新增）。
- **L4**：按 `round_id` 覆盖（`ON CONFLICT`）。

### M6 的两条硬约束（其余都是推论）
1. **一条记忆必须带至少一个账本里存在的出处编号 `E…`**——记忆会注入之后每一轮的提示词，没有出处的"教训"= 让模型凭一句话改掉以后所有判断。
2. **只有人的确认能改它**——`apply()` 是唯一入口，Curator 只能出 `MemoryChange`（提议）。

**容量**：60 条（对齐"教训区 ≤60 行"）、每条 ≤2 行。
**两阶段拦截，共用一套判据 `_reject()`**：
- 提议侧 `screen_changes()`（出草案那刻）：不合法的那几条丢掉 + 留痕（不抛错）；
- 写入侧 `apply()`（确认事务里）：任一条不合法 → **整批抛错、什么都不写**。
- **机械回填出处**（M6e）：模型连着两趟不写 `refs` 时，用本轮账本编号回填（最多 3 个）。

## 2. 上下文组装

**唯一出口**：`application/context.py`（所有 `render_*` / `build_*`）。每个 agent 一个 `.md` 模板 + 一组 **slot**（`agents/definitions.py` 声明），调用处（`use_cases.py`）填槽。

**9 个 agent + 1 个归因小调用**：
`analyzer` · `seat_reviewer` · `integrator` · `inquirer` · `discusser_say` · `discusser_cards` · `memory_curator` · `sim_inquiry` · `sim_review`（+ `opinion_dispositions`）。

**共享段落**（渲染器 → 消费 agent 数）：

| 段落 | 渲染器 | 消费数 |
|---|---|---|
| 文档全文 + 缺口 | `render_document_state` | 8 |
| 已确认记忆（不带 id） | `render_memory` | 5 |
| 本轮主张 | `render_claims` | 4 |
| L1 项目上下文 | `render_project_context` | 3 |
| 用户已答 | `render_answers` | 2 |
| 席位意见 | `render_reviews` | 2 |
| 材料 + 联网 | `external_material_text` | 5 |
| 观察索引（L2） | `render_observations_index` | 2 |
| `schema_json` / `validation_error` | harness 注入 | 全部 |

**只给整合者**：`render_digests`(L4)、`render_inspirations_index`(L3)。
**只给记忆整理者**：`render_memory_state`（**带 id**，要写 `target_id`）+ `render_round_digest`（本轮完整回放）。

**三条防坑口径**（真跑踩出来的）：
- **双身份分开命名**：席位意见同时标 `seat.x:O2`（地址）与 `E7`（出处编号）——模型会把地址当编号引（`04` C9）。
- **记忆 id 隔离**：给模型的 `render_memory` **不渲条目 id**（M6f）。
- **不留空节 / 截断照实说**：没材料写"（这一轮没有外部材料）"；超限写"只带了前 N 条"。

## 4. 对话 / 历史上下文

**只有两处局部历史，没有全局对话历史：**

1. **讨论线程历史**（`discussion.py::render_thread_history`）：取**后 6 轮**（`MAX_SAY_HISTORY=6`），注入 `discussion_say.md` / `discussion_cards.md`；**跨线程不共享**。
2. **问卷历史**（`Round.questionnaire_history`）：同一轮里多批问卷，题面按"出题那一批"回找——是**轮内多批**的历史，不是对话。

**没有的东西**：
- **全局对话历史**——不存在。
- **轮次即历史**：每轮的用户输入/主张/席位意见/问卷答案/提案全在 `Round.payload`，但**不作为"对话"塞回提示词**。
- 跨轮"记得"靠 **L2 + L3 + L4 + M6** 四层**显式注入**（提炼过的记忆），而不是原始对话回放——刻意为之：原始回放会撑爆上下文、且没有出处约束。

---

## 5. 设计口径（三条）
1. **AI 不写文档，记忆也一样**：所有编排只产 `Proposal`/`MemoryChange`，唯一写路径是 `ConfirmDraft → ProposalCommitter`。
2. **记忆是旁路能力**：Curator 挂了不打崩这一轮——草案照出、留一行痕。
3. **唯一出口**：`context.py` 是所有 agent 上下文的唯一渲染源。

---

## 6. 已知的现状特征（供重构时评估）
- **注入面不对称**：L3/L4 只给整合者；L2 给席位+整合者；M6 给 5 个 agent；L1 给 3 个。
- **席位看不到 L3/L4**：席位只看 L1/L2/M6——跨轮"灵感/摘要"对席位不可见。
- **没有"预算"概念**：各层靠条数上限（≤5/≤3/≤20 行）硬控，不是 token 预算（`04` 明确"改 token 预算需 tokenizer，是大工程"）。
- **没有按需检索**：L2/L3 只给"索引/标题"，靠模型自己拉——但当前并没有"拉详情"的工具通道（渐进式披露只做了一半）。
- **历史是"提炼品"**：原始轮次 payload 不回流；跨轮只靠四层显式记忆。

## 7. 记忆层重构：调研结论与候选方案（2026-10-09）

> 本节是**候选方案**（未拍板）。§1–6 是现状基线。

### 7.1 真跑硬数据（31 个 `.db` / 1,554 次调用）

> **口径（2026-10-09 修）**：`model_calls.prompt_text` 是**留样截断后**的文本（头 10000 + 标记 + 尾 10000）。
> 真实长度必须用 `scripts.telemetry.real_prompt_length()` 还原（存储长度 − 标记整段 + 略去数）。
> **直接 `len(prompt_text)` 会把 64% 的大提示词压成 20,016 的假平原**——本节以下数字全部按还原口径计。

| 事实 | 数字 | 出处 |
|---|---|---|
| 整合提示词 | 中位 **21,680 字符**，**65.2% 超 20,000** | 真跑库 `model_calls`（还原口径） |
| 席位提示词 | 中位 12,000，23.3% 超 20,000 | 同上 |
| 最大 slot | **`opinions`/`opinions_so_far`：席位 50.5% / 整合 36.9%** | 未截断样本切分 |
| 次大 slot | `schema_json`（整合 25.1%）· `limits`（整合 18.6%）——**静态合计 43.7%** | 同上 |
| `document_state` | 仅 4–6% | 同上 |
| 记忆四层合计 | 通常 **< 10%** | 同上 |
| 输出截断 | 整合回包 21.7K 字符撞 `max_tokens=8192`（已用 16384 修） | `04` F34 |
| 材料预算 | **从未触顶**（L3 最大 2,424 / 上限 4,000） | `04` C-2c-3 |
| 跨轮重问 | **0 条/项目** | `04` P28 测量 |
| L3 灵感 | **无出处编号**，整合者"看得见、引不了" | `inspiration.py` |
| M6 淘汰 | "连续 5 轮未命中→删除候选"**只是注释，未实现** | `memory.py` |
| L2/L3/L4 | **无容量上限、无淘汰**，limit 全硬编码（5/5/3/20） | 仓储 + `context.py` |

### 7.2 三个误导（照数据照出来的）

1. **"记忆层膨胀"是伪命题**——最大膨胀源是**本轮产物**（席位意见），不是记忆层。
2. **"多注入以防万一"是已证失败模式**——材料零引用（F35）、`unaccounted` 167 条、`list_items` 承诺不兑现。
3. **"上 embedding/RAG"过早**——预算没触顶、重问 0 条、零依赖是本仓硬约束。

**最深的误导**：把问题当"记忆系统"。真相是——**每次 agent 调用都是一次无状态推理**；记忆只是 4 个来源之一，却背了全锅。

### 7.3 重解

- 这不是"记忆层优化"，是**"上下文预算与相关性在 agent 边界上的治理"**。
- 稀缺资源是**注意力**不是 token（`context rot`、`Lost in the Middle`：头尾最好、中间最差）。
- **Round 聚合是唯一真相源，agent 是无状态视图** → 架构 = 一个规范状态 + 每场景一份投影 + 位置感知组装。
- **记忆是"确认"的副产品** → 本质是**事件日志 → 物化视图**，压缩=重投影。

### 7.4 十条候选（★=值得继续）

1. ★ **上下文契约清单**：`agent × slot × 来源 × 预算(字符) × 必需 × 位置`；溢出→**显式降级**，不许静默截断。
2. ◐ **按需检索（JIT）**：L2/L3 只放索引+稳定 id，详情按需拉——**前提是先建工具通道**（现在缺）。
3. ★ **席位意见按趟折叠**：本趟逐字 + 旧趟压成一行结论/疑问清单（直砍 50%）。
4. ★ **位置感知组装**：承重块（claims/当前问题）放头尾，参考块（文档全文/schema）放中间。
5. ★ **给记忆编号（memory EIDs）**：给 L2/L3 稳定 id，使其可被引用/盖章（复用席位冲突那台盖章机器）。
6. ★ **角色化视图注册表**：一个规范状态 + 一张视图表，取代散在 `use_cases.py` 的 `render_*` 调用。
7. ◐ **记忆命中追踪**：加 `last_hit_round`，长期未命中→**标记复核**（不自动删，守 M6 铁律）。
8. ◐ **事件溯源式记忆**：记忆=确认事件日志，视图=物化投影；压缩=重投影（可审计、可回滚）。
9. ★ **消费遥测**：追踪"注入的 slot 里模型实际引用了哪些编号"——把"有效上下文"从猜变成**可测**。
10. ⚠ **坏味道：记忆当垃圾桶**——L2/L3/L4 无上限无淘汰，只增不减；每层必须给**生命周期+owner+裁剪规则**。

**新奇但没用**：embedding/RAG 检索记忆（过早）· 给席位补 L3/L4（会变新噪音）· 长期未命中自动删（违铁律）· 每类记忆一个 sub-agent（过度设计）· tokenizer 精确预算（本仓已裁）。

### 7.5 最佳方案（四段式）

```
规范状态（真相源）：文档 + Round 聚合 + 账本(E) + 已确认记忆(M6)
      │
      ▼  ① 上下文契约清单
投影层（新）
  write   ：规范状态持久化（已是）
  select  ：索引+稳定 id 进窗口；详情按需拉（②，需工具通道）
  compress：本趟逐字 + 旧趟折叠；旧轮用 L4；记忆用事件重投影（③⑧）
  isolate ：每个 agent 只拿本角色投影，绝不拿全量（⑥）
      │
      ▼  ④ 位置感知组装
一次 agent 调用（无状态）
      │
      ▼  ⑨ 消费遥测 → 回喂裁剪
```

**三个"不做"**：不加 embedding/RAG（除非遥测证明该拉没拉）· 不自动删记忆（只标记复核）· 不给席位堆 L3/L4（先证明会被引）。

**落地顺序（最小步先行）**：
1. **⑨ 消费遥测**——算"注入 vs 引用"表（**不改生产路径，先量**）。
2. **③ 意见按趟折叠 + ④ 位置感知**——零依赖砍最大 slot，用现有 eval 验"质量不降、字符降"。
3. **① 上下文契约清单**——规则固化成表，组装器照表执行、溢出显式降级。
4. **⑤ 记忆编号 + ⑥ 视图注册表**——L3/L2 加稳定 id（可引用/盖章），散落 `render_*` 收进视图表。
5. **② JIT 检索 + ⑧ 事件溯源记忆**——建工具通道、记忆改事件重投影（中期）。

**成功判据**：整合提示词 P50 20,016 → <15,000、截断率 56% → <10%；eval 全绿不回退；`opinions` 占比 50% → <25%；"注入了但零引用"的 slot 数下降。

### 7.6 消费遥测 v1 已落地（2026-10-09，§7.5 第 1 步）

**工具**：`backend/scripts/telemetry.py`（只读）。口径见 §7；`assembly.cited_eids` 是"引用"的唯一实现（同时替掉了 `_accounted`/`_unreferenced_materials_for` 的两处重复）。

**真跑实测**（`.codex/runs/**/*.db`，31 库 · 116 轮）：

| 槽 | 注入 | 引用 | 引用率 |
|---|---|---|---|
| claims（USER_INPUT） | 1089 | 945 | **87%** |
| answers（CARD_ANSWER） | 29 | 21 | 72% |
| reviews（AGENT_*） | 2005 | 1216 | **61%** |
| materials（EXTERNAL） | 9 | 0 | **0%** |

**读数**：
- **materials 0/9** = F35 的机械确认：材料注入了、零引用。
- **reviews 61% 是下界**——整合者常用 `from_opinions`（席位条目地址）归因，而非引判断自己的 E 编号；"按 EID 引用"低估了实际使用。
- **claims 87%** 最健康。

**结论**：材料槽是第一个明确的裁剪候选；reviews 要看留样分辨"隐式用 vs 真没用"。这是 §7.5 后续步骤（③意见折叠 / ①契约清单）的证据基础。

**测不了**：L2 观察 / L3 灵感 / L4 摘要 / M6 记忆——没有 E 编号，模型"引不了"（想法⑤要解决的）。

### 7.7 第二步已落地：④ 位置感知 + ③ 消融后定成"覆盖清单"（2026-10-09，§7.5 第 2 步）

**④ 位置感知组装**（**纯模板，零代码**）：`integrator.md` / `seat_review.md` 把承重块
（`claims`/`opinions`/冲突）提到**头部**，参考块居中。
（~~输出约束（`limits`/`schema`）收尾~~——**这一半已于 2026-10-10 被 `02 §11.0.55` 顶掉**：
静态块前移以拿缓存前缀。承重块优先这一半仍然有效，`test_llm.py` 继续钉着。）
顺序纯由 `.md` 的 `$slot` 位置决定（`Template.substitute`）。守卫
`test_prompts_lead_with_what_the_agent_must_process`；既有集合守卫保证不丢槽。

**③ 先落成"按趟折叠"，再被消融实验推翻、定成"覆盖清单（list）"**：

1. 折叠版（最近一趟逐字 + 更早趟一行）实测只降 **14%**（第 2 趟 0%——只有 1 个 prior 趟、
   折不动；第 3 趟 21%）——设计原文"直砍 50%"作废（席位并行跑、`seat_reviews` 里没有"本趟"）。
2. **消融实验**（临时开关 `PMSTUDIO_SEAT_HISTORY`，4 用例 × 3 变体 × 真跑）：

| 变体 | `opinions_so_far` 字符 | 跨趟重复 | 未交代 | 题目重复 | eval 通过 |
|---|---|---|---|---|---|
| fold（最近一趟逐字） | 42,803 | 45% | 0 | OK | 49/49 |
| **list（全折一行）** | **22,259（−48%）** | 34% | 0 | OK | **49/49** |
| off（不给） | 0 | 17% | 0 | OK | 49/49 |

3. **定成 list**：`context.render_reviews_compact` 应用到**所有** prior 趟

### 7.10 第①层做完了（2026-10-09）

**做了什么**
1. `_LeanSchemaGenerator`（`harness/model/structured.py`）：递归剥 **BaseModel 节点**上的
   `title` + `description`；`json.dumps` 加 `separators=(",", ":")`。
2. `schemas.py` 的 22 条类 docstring 逐字搬成 `#:` 注释（1,760 字符，一个字没删）——
   这一条本身就够，生成器那层是**兜底**（防止将来有人再写 docstring 进 schema）。
3. `LIMITS_TEXT` 两处与机制相反的话改成说真话（题位满 / 重复题），见 §7.9 记的两条。

**踩到的那一脚（真跑才发现，测试全绿都没抓到）**

第一版按"键名叫 `title` 就删"写：

```python
node.pop("title", None)          # ❌
```

**`title` 在本项目里是一个真实字段名**——`QuestionDraft.title`（题面）。按键名无差别 `pop`
把它连同它在 `required` 里的义务一起删掉了：模型看不见这个字段，改为把题干写进 `why`，
于是整包 `questions[*].title is required` 校验失败 → 两次重装都不行 → 整合降级 →
**草案里 0 条功能内容，全部落进 s11**（真跑三次连跑复现）。

单元测试当时全绿（1954 passed），因为**没有任何测试把"瘦版 schema 与厚版的字段集合相等"
当成判据**——钉住 `required` / `properties` 的那条用的是**裸** `model_json_schema()`。

修法：判据只能是"这个节点描述一个 BaseModel"（有没有 `properties` 兄弟键）。
并补了 `test_slimming_never_removes_a_field`——它把**字段级**的机造词留着再比，
所以任何"少了一个字段"的写法都会红。

**教训（与 `07 §7.7` 那条同源）**：把一样东西从提示词里删出去时，判据必须是
"**删完之后剩下的东西一个都没少**"，而不是"我要删的那个不见了"。前者才抓得住
"顺带删掉了不该删的"——**这次是字段名撞上了元数据键名，属于最隐蔽的一类**。

**效果**（真模型，两次连跑都对）
- schema 19,242 → 16,844 字符（−2,398，−12.5%）；整合者那份 4,097 → 3,592
- 端到端：草案 13–15 条提案、s5 填 5/12 必填、写入 s5/s7/s8/s11 四章
- `LIMITS_TEXT` 从 3,354 → 3,504（**变长 150 字**）：两句从"教错做法"改成"说真机制"，
  贵的不是字数
- 全量 1955 passed、ruff 绿

**两个副产品**（与瘦身正交，值得单做）：整合者 schema 加一个**先行 `reasoning` 自由文本字段**
（`Let Me Speak Freely?` arXiv 2408.02442 解耦结论 + Instructor +60% 互相印证）；
加 "wrong-valid-schema" 观测位（席位没给 basis 这种"合法但坏"的输出 parser 抓不到）。

### 7.11 问过但没答的题，模型看不见——补一个槽（2026-10-09）

**这不是上下文预算问题，是可见性缺失。**四步查出来的：

1. `no_duplicate_questions` 判据恒真（读的是去重**之后**的问卷）→ C9b
2. 判据改读留痕后真跑报出 14 条 → 真实现象，不是假红
3. 14 条**全部 `pass_index=2`、全部 0 条答案**、**14/14 题面逐字相同**——不是措辞近似
4. 根因：`render_answers` 只渲染 `answer_sets`（已答）+ `skipped`。"用户一道都没答就点确认"
   是**正常主路径**（`use_cases` 整合那步明说「答案要么被引用、要么机械落地」；
   `AnswerSet.__post_init__` 又规定"交卷至少要有一条答案或显式跳过"⇒ 没有答案集 =
   这一批一道都没碰过）。所以那些题**一个字都不进提示词**，而装配层的 `seen_questions`
   照样把它们算作问过——**系统记得，模型看不见**，于是逐字重写、撞判重被丢。

**做法**：新槽 `$asked_questions`（`context.render_asked_questions`），身份按
`(form_id, question_id)` 认（题号跨批会重复，用裸题号会挂错题面）。

**为什么不塞进 `render_answers` 的第三段**（先写了、又推翻的那版）：调用侧
（`use_cases.py`）用 `.partition("--")` 把它的输出切成 `answered` / `skipped` 两段，
多塞一段会被切错位置，把没答的题显示在**「用户跳过」标题下**。有一条用例专门钉这件事。

**效果**（真跑 10 轮）：重复留痕 14 → 5。其中
- 撞**没答也没跳过**的题：14 → **0**（这段的功劳）
- 撞**已跳过**的题：0 → 5（`$skipped` 槽**本来就给模型看了**，与新槽无关，
  是"信息已给、模型仍不遵守"）

> **M14 已收口（2026-10-09）**：那 5 条其实是**正确行为**，已把判据拆成三类
> （自己写重 / 问出去过而用户没碰过 / 模型本来就知道），只让前两类亮红。
> 拆法与真跑复核数据见 `04-未决.md` C9b。**这条给我们的教训**：
> 一盏红灯报"系统做对的事"，比没有红灯更糟——它训练人忽略红灯。

**留痕与判据改动的净结果**：`no_duplicate_questions` 从恒真恢复成有鉴别力（改前
10/10 假绿）。eval 总体 4/10 → 6/10（另两条红是 `s6 steps` 与 `web_queries`，
与本题无关，改前就在红）。

## 7.12 上下文组装的按层分工（2026-10-10）

**动机是量出来的，不是审美**。真跑留样（183 次调用）的构成：

| agent | 最大块 | 占比 | 它真正的承重块 | 占比 |
|---|---|---|---|---|
| claims | `document_state` 文档现状 | **39.3%** | `user_input` 要切的输入 | 进不了前 11 |
| integration | `document_state` | 25.3% | `claims`+`opinions` | 22% |

**勘误（2026-10-10 当晚补）**：初版这里写过一行"seat_review 的 `opinions_so_far` 占 60.3%、
`claims` 只占 2.2%"，**那个数字是错的引用**——它出自 10-05 的真跑留样，而 10-09 的
§7.7 已把该槽从"折叠版"改成"一行一条"（22,259 字，−48%）；更关键的是查了领域才搞清楚：
`Round.seat_reviews` 只存**本轮**的意见（`round.py:197`），跨轮历史在 `observations`(L2)
与 `round_digests`(L4)，所以这个槽在**第一趟永远是空的**，只有问卷回来后的第二趟才有东西。

用真实数据重测（库里 seat_reviews 最多的那一轮：14 份席位 / 60 条意见）：
全量 compact **8,038 字** → 指针式 **1,836 字（−78%）**，这就是第 1 项的真实收益。
"90s×3 超时"也与此槽无关：那一轮 `opinions_so_far` 是空的，超时发生在 integration
（20,016 字的提示词 + 长输出）。**体积问题的真正大头是 `document_state`
（claims 里 39.3%、integration 里 25.3%）**，已顺位到第 2 项。

**八条原则（每条挂证据强度，不挂审美）**：

| # | 原则 | 证据 |
|---|---|---|
| ① | **删优先于排**：无关/语义相近的上下文是净伤害 | 强：LongMemEval oracle vs full 掉 30–66%；Chroma focused 87.3% vs full 62.4% |
| ② | 承重块贴指令，绝不埋中段 | 中：Liu U 型；Chroma 重复词任务里独特词越靠前越准 |
| ③ | 历史用**指针换内容**，不用摘要换内容 | 中：Manus 可恢复压缩；OpenAI SDK「存全文、发子集」 |
| ④ | 压缩粒度不低于「轮」 | 强：LongMemEval Value 实验——压到 fact 级净损失，轮是最优粒度 |
| ⑤ | 正向表述，删纯否定 | 强：否定问句下 37.4–71.1% 案例模型重复原答案；且呈逆规模律 |
| ⑥ | 控制条数、合并同类、每条带理由 | 中：指令数 N=80 时所有格式完美遵循率归零 |
| ⑦ | **隐性 salience 标记不可用**（⚠/IMPORTANT/大写） | 强（负向）：GUIDE、PASTA、SpotLight 一致——自然语言强调传达不出去 |
| ⑧ | 缓存靠「静态前 + 历史纯追加」，**不靠冻结历史** | 强：Anthropic lookback 机制（增长对话每轮新增 <20 块即命中）；DashScope 实测只改末尾 cached 仍 90% |

**⑧ 直接回答一个容易搞错的问题**：历史不需要冻结就能保缓存。Anthropic 的前缀匹配
按块回看（lookback 20 块），增长的对话只要每轮新增少于 20 块，上一次的写入会被找到。
毁缓存的是**回头改已写下的部分**，不是历史在变长。所以摘要一旦写下就不再改写。

**按编排层分工**（同一个「历史」在不同编排层身份相反，这是必须分层的原因）：

消费的 flag，而且**原型量法是错的**：手搓的 digest 悄悄丢掉了嵌套子块，量出 −59~69%，
忠实实现（保留结构只截正文）只有 −12~22%。改成目的单一的新函数后，真库实测

**edge-contradiction 的抖动**：改 claims 后该 case 从 2/3 过变成 1/3 过（各跑 3 次）。
机制上核实过——分析者**正确检出**互斥（c1↔c3 且理由准），失败在**未改动的整合者**
没把它变成题。n=3 差 1 例分辨不出，记为"测不出回归"，**不记为干净**。

**顺带逮到并修掉一个既有缺陷——条目编号与出处编号抢方括号**。真模型验证时暴露：
`_entry_line` 把条目渲染成 `[r-01b4e9d1#09] 正文`，而 `sim_review.md` 又写着
"文档里 `[条目编号]` 那种，**抄原样**"——模型照办，把方括号抄进 `entry_id`，
机械筛一律判"指向不存在的条目"（8 个样本**全中**）。根因是**格式撞车**：方括号在本项目里
已经是出处编号 `[E12]` 的专用格式（`render_materials` / `render_claims` 都用它）。

修法改渲染侧而不是筛侧：条目渲染成 `条目 <id>：正文`（自描述前缀，无方括号），
`render_existing_entries` 同步；`sim_review.md` 那条指令改成"只写编号本身，方括号是 `E…` 专用"。
新增守卫 `test_no_prompt_tells_the_model_to_copy_a_bracketed_token`——不再依赖
"别带括号"这种不可靠的自然语言提醒。**复验：括号类 issue 8 例 → 0 例。**

**2b 的质量判决（缺陷修掉之后才测得准）**：4 persona × 2 上下文，机械筛 issue 数
全文 0/1/2/3（合计 6）vs 窄化 1/1/0/0（合计 2）——**方向与①「删优先于排」一致**
（LongMemEval oracle-vs-full 掉 30–66%、Chroma focused 87.3% vs full 62.4%），
但 n=8 仍不足以声称显著。体积收益是确定的（−61%）。

**明确不做**（想过但被证据否掉）：U 型重排（已撤）· ⚠/IMPORTANT/大写强调（⑦）·
整段 prompt 重复（仅非推理模式有效，且翻倍 KV/FLOPs）· XML 换 markdown（四项实测无分离，
xml 贵 45% token）。
