# 02 · 编排与数据（系统怎么跑）

> 2026-09-22 第二次重写。三处改动：**席位职责收成一件事**（只出专业意见）、
> **问卷不是固定环节**（信息明确就直接出草案）、**答案回来后重新组装上下文继续任务**
> （不是机械消费选项）。契约也按"每个字段用来干啥"过了一遍，删掉了没有消费者的字段。

---

## 1. 一轮的粒度

**一轮绑定"一次用户输入"**，不绑定一个句子，也不绑定一个目标。

一次输入（20 句、含 3 件互不相关的事）→ 切分一次做完 → 一张复述卡列出全部主张 →
席位轮 → 整合 → （需要就问）→ 草案 → 确认 → 写入。

N 条主张共享同一轮的三次中断。**一轮的模型调用次数与句数无关**，只与席位数和席位轮数有关。
一轮里可以有多件事，不自动拆轮。

---

## 2. 全流程（席位轮是个环）

```
① 主张     切分 + 定性 + 归位                      [Analyzer]
② 开场卡   复述（含去处与范围）+ 席位编制            ← 中断 1
③ 席位轮   并行；每个席位只做一件事：出专业意见       [领域席位 ×N]
④ 整合     并入上下文 → 组装：待问的问题 + 内容候选   [Integrator]
⑤ 判断     还有必须问用户的吗？
              ├─ 有 → 问卷                           ← 中断 2
              │        → 答案并入上下文 → 回到 ③（缩编席位）
              └─ 没有 → ⑥ 草案卡                      ← 中断 3
⑦ 确认写入 唯一写入口 → 版本快照
```

三个要点：

1. **问卷不是固定环节**。它是"还有必须问用户的东西"时的产物。信息已经明确，
   整段跳过，直接出草案。
2. **答案回来不是消费掉就完**，而是**并入上下文后重新跑一次席位轮**（缩编：
   只请与本次答案相关的席位）——因为答案会让之前的一些判断变得可以落地，也会让
   另一些判断失效，还可能引出新缺口。
3. **循环有上限**：一轮内最多 3 次席位轮。到上限仍有缺口，就全部显式化
   （落 s11 开放问题 + 草案卡上标缺口），不再追问。
4. **两种编号各叫各的名字**（2026-09-24 定，见 `04-未决.md` C9）：
   `E7` 是**出处编号**（账本里的，能跳转、能引用）；`seat.x:O2` 是**席位条目地址**
   （"哪个席位的第几条意见"，只有判断会变成 E 编号，疑问没有编号）。
   提示词里两种写法分开写明——混在一起时模型会把地址当编号写进 `evidence_refs`。

## 3. 各部分职责

### ① 主张　[Analyzer]

输入：本轮用户输入 + 文档现状（章节状态表 + 本轮可能涉及的章节）。

1. **切分**：拆成原子主张，一条只讲一件事。
2. **定性**：七种标签（事实 / 需求 / 目标 / 约束 / 偏好 / 猜测 / 决定）。
3. **归位**：逐条给 `target`（章节 + 字段，若指向已有功能则带 feature）。**这一列就是写范围。**
   写范围分两级（2026-09-22 定）：**硬约束**只有两条——不得新增未授权 feature 子树、不得离开
   13 章；其余"跑出本轮去处"（如席位推的 s7 / s8 判断）**不拒绝**，而是在草案卡顶部显式标注
   "涉及本轮没提到的章节"。理由：静默拒绝会让席位的专业判断整批白干，用户永远看不到。

产出：主张清单。

### ② 开场卡　中断 1

两张卡：**复述理解**（列出全部主张，标签与去处可改，底部只读一行显示"本轮将改动哪几章、
还有几个历史问题没答"）+ **席位编制**。

席位编制**不是关键词匹配出来的**：Analyzer 在同一次调用里读完本轮输入与文档现状，
从注册表（`infrastructure/seats/definitions/*.toml`）挑出这一轮真正需要的席位，
每条给一句"为什么这一轮请它"（`seats[]`，与主张同一份报文、同一个事务落库）。
开场卡默认勾选这份名单，用户可以取消勾选，也可以从"目录里还有 N 个"里补上。
只有**老轮次**（分析时还没有挑席位这一步）才回落到"常驻 + 关键词"的目录匹配，
并且投影里标 `source="catalog"`、界面照实说"这名单没经过判断"。

合格标准（可验收）：复述里必须包含至少一个只有读了文档才知道的信息，否则视为复读原话。

### ③ 席位轮　[领域席位 ×N，并行且互不可见]

**一个席位只做一件事：以本领域的专业眼光，对"本轮输入 + 文档现状"给出意见。**
它不负责决定这些意见最后长什么样、写进哪个字段、要不要问用户。

意见只有两种形态：

| 形态 | 长什么样 | 例子 |
|------|---------|------|
| **疑问** | 我判断这里缺一个信息，而且这个信息只有用户能给 | "量级是同步与异步的分界，必须问用户" |
| **判断** | 我判断这里应该是什么，依据是什么 | "量级在 1 万级，同步导出够用；同类导出通常以 60 秒为上限"（依据 E4） |

每条意见都必须带：**依据（已有编号）或显式声明无依据**、**理由一句话**。
无依据的判断允许存在，但会被整合者放进"提议"一档（见 ④）。

**席位不能做的事**：不新增 feature 子树（用户点名新功能时除外）；不把模糊变精确
（"要快"→"60 秒"必须作为疑问提出来）；不替用户做业务口径决定。

**失败处理**：返回不可解析 → 席位失败 → 整轮失败可重试。**空意见不等于没意见**：
必须给 `basis`（读了什么、为什么没必要补充）。

### ④ 整合　[Integrator]

席位给的是"专业意见"，形状是散的；**把它变成可以进文档、可以直接问人的东西，是整合者的活**。
这是两个不同能力：席位提供内容（需要领域知识），整合者提供结构与形状（需要 schema 知识）。

**四步**

1. **并上下文**：把本轮主张、已有文档、各席位意见、以及上一轮的答案（如果有）合成一份工作集。
2. **组装**：
   - 疑问 → 归并成**题目**（给 target、给候选项、给不答的后果、给依据）
   - 判断 → 归并成**内容候选**（给 target、`origin = derived`，把理由变成 `rationale`，
    把依据变成 `refs`）
   - 无依据的判断 → `origin = proposed`，单独一档
   - 与已有文档或历史问卷重复的 → 丢弃
   - **丢弃要留痕**（2026-09-24 定，补 `04` C5 的后半）：报文加
     `dropped_opinions: [{handle, reason}]`（handle 形如 `seat.x:O1`）。装配层把它与
     "归因对不上"的条目合并成 `Round.dropped: [{handle, reason, source}]`，
     `source ∈ {integrator, assembly}`。界面上每个席位包显示"它说的 N 条里，M 条没进卡片"。
3. **编号**：给每个内容候选分配全局编号（席位并行时只能给局部 id，全局编号在这里统一分配）。
   席位意见在提示词里的写法是 `（席位条目 seat.x:O2 · 出处编号 E7）`：**只有判断**在汇合点
   进账本、拿到 E 编号；**疑问不进账本**（它是"要问什么"，不是文档内容的来源），所以写的是
   "没有出处编号"。题目的 `evidence_refs` 只能放 E 编号；要把"这道题是谁提的"带到界面上，
   写 `from_opinions`（席位条目地址），**归因由装配层算**——`asked_by` 不再由模型自填，
   真模型给两个空手席位安过"提问者"的帽子。
4. **判断出口**：还有必须问的 → 出问卷；没有了 → 直接出草案。**一批最多 5 题**，
   超出部分降级成清单项。
5. **归因对不上号就留痕**：`from_opinions` 指向不存在的席位条目时，只丢那一条归因、
   写进 `Questionnaire.dropped`（问卷卡上显示"哪几条没算数"），不判死整轮；
   依据编号写错（引用了不存在的 E 编号）仍然整轮失败。

**边界**：整合者**不产生新的专业判断**——它只组装别人的判断，以及决定"这条是问还是写"。

### ⑤ 问卷　中断 2（可整段跳过）

题目含：`target`、`type`、`title`、`why`（为什么问）、`options`、`consequence_if_skipped`、
`evidence_refs`（E 编号，**可以空**——疑问自己没有编号，引不到就留空）、
`asked_by`（装配层算出来的，合并后可能多个席位）、
`from_opinions`（模型给的归因线索，只用来算 `asked_by`，不当出处）。

题目还带 **`blocking: bool`**（2026-09-24 定，补 §⑤ 早就写着但没实现的那条）：
**由规则算，不问模型**——`target.field ∈ 必填功能字段`，或章节级 `target.section_id ∈
{s1,s2,s3,s4,s5,s8,s10,s12}`（那几章的合格标准是 blocker 级）→ 阻塞。
跳过的阻塞题落成 s11 开放问题时，文本前缀写 `〔未决·阻塞〕`（判据据此识别；
将来出现第二种标记就升级成 `Entry.flags`，见 `01` §7）。

一批一次交卷；提交前可改、提交后冻结；允许部分作答与跳过。

**答案回来后**：答案作为 `card_answer` 进出处账本（带 `question_id`），然后**重新组装上下文
回到 ③**——带着"用户已经答了什么"再问一次席位，让它们把之前的判断落地或修正。

跳过的题按题面写明的后果落成 s11 开放问题（不挡交付）；命中必填字段的标阻塞型。

### ⑥ 草案卡　中断 3

唯一一张卡，提案按来源分三组：

```
【你说过的】      ← 挂 user_input / card_answer
【它替你判断的】   ← 挂 agent_derived，可展开看理由与依据
【它提议的】      ← 挂 agent_proposed（无依据），默认不勾选
顶部一行：写入后本章仍有 N 项必填缺口
```

每条只有 **[要] [不要]**；卡片里不编辑内容（编辑归文档）。

### ⑦ 确认写入　[确认端点]

事务写入 → 版本快照（`trigger = confirm`，记录变更的 block id）→ 推送变更通知。
编排层、席位、整合者都拿不到写库能力。

## 4. 数据对象（每个字段都要有消费者）

### 4.1 出处链

```
文档里的内容
  └─ refs: [E12, E17]
       └─ 出处账本（只增不改，编号永不复用）
            ├─ user_input      用户在哪一轮说的（带原话片段）
            ├─ card_answer     用户答的哪道题
            ├─ agent_derived   席位判断的（必须带依据 + 理由）
            ├─ agent_proposed  席位判断但无依据
            ├─ system_default  系统默认值（清单项接受后生成）
            └─ external        外部材料（v1 留位）
```

**可追溯不变式**：任何进正文的内容，顺着 `refs → derived_from` 回溯，必须至少到达一条
`user_input` 或 `card_answer`；到不了的只能作为 `proposed` 出现且默认不勾选。

### 4.2 出处条目

| 字段 | 用来干啥 |
|------|---------|
| `eid` | 被内容引用（角标、跳转、回溯） |
| `kind` | 决定界面怎么标（你说的 / 它判断的 / 它提议的 / 系统默认） |
| `text` | 这条出处的规范表述 |
| `source` | 形状随 kind 变：`run_id`（哪轮）+ `raw_span`（原话，可跳转）/ `seat_id`（谁判断的）/ `question_id`（答的哪题）/ `derived_from`（依据，agent_derived 必填）/ `rationale`（为什么这么判断） |
| `supersedes` | 修订时指向被替代的旧编号（旧条目作废但不删） |

### 4.3 主张 Claim

`eid`、`text`、`label`（七种标签之一）、`target`（章节 + 可选 feature + 字段）。
四个字段就够：标签决定处理方式，target 决定落哪儿，其余两个是内容本身。

七种标签的硬规则：**偏好**不进正文（进偏好区）；**猜测**升格为假设（带失败后果与验证方式）；
**决定**记录决策者与时间。

### 4.4 信息包 Packet（智能体之间唯一的通信形状）

| kind | 产出者 | payload |
|------|--------|---------|
| `claims` | Analyzer | 主张清单 |
| `seat_review` | 领域席位 | `opinions`（疑问 / 判断，各带依据与理由）+ `basis` |
| `questionnaire` | Integrator | 题目数组 + 清单项 |
| `draft` | Integrator | 提案数组（按来源分组） |

信封：`packet_id`、`run_id`、`kind`、`produced_by`、`basis`、`payload`。
（删掉了 `confidence` 与 `emitted_refs`：前者 v1 没有消费者，后者可由 payload 推出。）

```jsonc
// 席位包
{
  "packet_id": "pkt_07", "run_id": "r3", "kind": "seat_review",
  "produced_by": "seat.data_scale",
  "basis": "读了 s5 / s8 与本轮 E1–E8",
  "payload": {
    "opinions": [
      { "local_id": "O1", "form": "question",        // question | judgment
        "about": "导出的数据量级",
        "claim": "量级决定同步还是异步，必须问用户",
        "because": "1 万行以内可同步，10 万行以上必须异步，是两套实现",
        "evidence_refs": ["E4"] },
      { "local_id": "O2", "form": "judgment",
        "about": "导出的性能上限",
        "claim": "单次导出应在 60 秒内完成",
        "because": "量级在 1 万级，同步实现可满足；同类导出常见上限 60 秒",
        "evidence_refs": ["E4"] }
    ]
  }
}
```

### 4.5 内容候选与提案

`target`（章节 + 可选 feature + 字段）、`text`、`origin`（`{type: user|derived|proposed,
from: [eid], rationale}`）、`state`（kept / dropped）。

**v1 限制**：`target` 只能落在已有 feature 的字段上，不能新增子树（用户点名的新功能除外）。

### 4.6 问卷、版本、运行

- **问卷**：`form_id`、`round_id`、`questions`（题目数组）、`list_items`（降级项）。
  题目字段见 ⑤。**删掉了 `option_means`**：答案不再被机械消费，而是回到席位轮重新判断，
  选项含义由席位在下一轮解释。
- **版本**：`version_id`（递增）、`trigger`（confirm / manual / rollback）、
  `changed_block_ids`、`snapshot`、`summary`。
- **一轮（round）**：`round_id`、`project_id`、`step`（已完成的步骤）、
  `waiting_on`（在等什么：开场卡 / 问卷 / 草案卡 / 无）、`seats`、`fail_reason`。
  恢复 = 从 `step` 之后继续；`waiting_on` 决定界面显示什么。

**2026-09-24 新增的三个字段**

| 字段 | 在哪 | 用来干啥 | 为什么必须落库 |
|---|---|---|---|
| `Question.blocking` | Round | 阻塞型未决 → 就绪度 L3 判据 | 跨轮：上一轮跳过的阻塞题要影响这一轮的交付判定 |
| `Round.dropped` | Round | 意见/归因被丢弃的留痕（§④）。**一条通道三个来源**：`integrator`（模型申报）/ `assembly`（归因对不上号）/ `unaccounted`（装配层核出"既没说丢、也没交代落到哪儿"）；每条带 `handle / seat_id / pass_index / reason / source` | 用户要能查"为什么这条没进卡片"；`pass_index` 是因为同一轮里席位会跑好几趟、`local_id` 每趟重号 |
| `Round.active_seats` | Round | 这一 pass 实际要跑的席位名单（§7 缩编） | `pending_seats` 改成基于它算；`seats`（用户编制）不变，R7 不受影响 |

### 4.7 就绪度（Readiness）　[纯代码服务]

`ReadinessChecker.check(view: DocumentView) -> tuple[ReadinessItem, ...]`，
`ReadinessItem{section_id, code, title, detail, severity}`，规则见 `01-规格.md` §4 与 §7。
它是**只读服务**：不写文档、不调模型、不进任何事务。四个消费者：

1. `context.render_readiness()` → 追加进三个智能体的 `document_state`（"让 AI 被缺口驱动"）；
2. `dto.ReadinessItemView` → `WorkspaceView.readiness`（界面）；
3. `deliverable.render_markdown()` → 导出头部、空章标记、附录；
4. （将来）eval 断言"这一轮没有新增 blocker"。

两条实现约定：

- **同一 (章节, code) 只出一条**，明细塞进 `detail`——否则一个空项目上来就报二十几行。
- 判据读的是 `DocumentView`，其中 `feature_gaps`（功能必填字段缺口）由 `Document.view()`
  顺手带上（就是 `Document.gaps()` 的结果），**不重写第二套功能字段规则**。

### 4.8 章节槽（section slot）

13 章里只有 s8 有固定槽（性能 / 可用性 / 安全 / 兼容 / 可观测 / 成本）。槽表在
`domain/shared/sections.py::SECTION_SLOTS`（跟骨架同处，避免 shared → authoring 的反向依赖）：

```python
SlotSpec(name="performance", title="性能", kind=BlockKind.NFR)
slot_block_id("s8", "performance") == BlockId("s8.performance")
```

寻址规则（`Target`）：

| 写法 | 含义 | 落点 |
|---|---|---|
| `body("s8")` | 章节级内容（不指定槽） | 新开一个 `s8.bN` 块（老行为） |
| `body("s8", field="performance")` | **章节槽** | 复用或新建 `s8.performance` 块 |
| `body("s5", feature_slug="x")` | 功能根 | `feat-x` |
| `feature_field("x", "acceptance")` | 功能字段 | `feat-x.acceptance` |

两条校验：`field` 有 `feature_slug` → 必须命中**功能字段表**；没有 → 必须命中**该章的槽表**。
`Document.new` 顺手把六个空槽建出来（它们是骨架，不是内容，所以不算"有内容"）。

## 5. 架构分层

```
L1 界面    React 单页：文档区（主导）+ 闭环区
L2 API     FastAPI：HTTP 动作入口 + SSE 推送口
L3 编排    LangGraph 图：主张 → 席位轮 ⇄ 问卷 → 草案；人机中断在这里
L4 领域    纯 Python：block 树、13 章 schema、出处账本、校验、版本
L5 模型    可配置（OpenAI 兼容：base_url + key + model）
L6 存储    SQLite
```

两条硬规矩：**L4 不依赖 L2/L3/L5**（可无网络单测）；**写入路径唯一**（只有确认端点能写）。

## 7. 失败、暂停与恢复

- 席位返回不可解析 → 该席位失败 → 整轮失败可重试（不静默跳过）。
- 达到席位轮上限（3 次）仍有缺口 → 全部显式化，不追问。
- **网关必须带超时**（2026-09-24 定）：`PMSTUDIO_MODEL_TIMEOUT`（默认 120 秒）。
  真跑实测过 provider 卡住十几分钟不返回——没有超时，这一轮就永远停在"正在跑"。
  超时按瞬时失败重试（最多 3 次），仍失败走下面的降级或失败。
- **可以放弃这一轮**（2026-09-24 定）：`POST /rounds/{id}/abandon` → 取消正在跑的
  `asyncio.Task` → `Step.ABANDONED`。为什么安全：模型调用一律在事务外，
  `CancelledError` 只可能落在 `await` 点，不会落在 `with uow:` 中间（不会有写了一半的文档）。
  `abandon` 不走 `RoundRunner.run()`，所以不受"一轮同时只许一个动作"的限制——
  被拦住的正是"重试"，而放弃是另一个出口。

  **落地口径（2026-09-28 实现，P5c）**：**先写 `abandoned`、再取消**——写状态只有
  `AbandonRound` 一处，取消本身不写任何业务状态；取消异常**不吞**（交回调用者），
  前端用 `abandoning` 标志位吞掉那条注定失败的在途请求的报错。
  没有在跑的任务也要能放弃（进程崩过、或停在等人时，那一轮不该永远占着）。
- 运行中断（关掉页面）→ 保留 `step` 与 `waiting_on`，回来继续，已冻结的卡片不重问。
- 校验不通过 → 打回整合者重装（一次）；**仍不过就走降级出口**（2026-09-24 改，见
  `04-未决.md` C9）：把本轮席位交回的**疑问原样**落成 s11 开放问题，出草案卡，
  失败原因与未归并条数写进缺口行。一条疑问都没有时才判整轮失败。
  为什么不再让用户点"继续/重试"硬顶：失败点在 `seats_running`，重试只是拿同一句
  提示词再撞一堵墙（真跑时点了 3 次，6 次模型调用，原地不动）。
- **claims 也重装一次**（2026-09-28 加，P5d）：主张报文不合格（`PacketParseError`）时，
  带上"上一次错在哪"（`repair_note`）再调一次；两次都过不了才判这一轮失败
  （理由"主张两次都过不了校验：…"）。口径与整合者对称，上限见下面这张表。
  **网关类失败不重装**——网关自己已经是 3 次尝试 + 退避，报文重装解决不了超时与 5xx。

- **席位也重装一次**（2026-09-28 加，P6）：单个席位的报文不合格（`PacketParseError`）时，
  只重跑**那个席位**（带上"上一次错在哪"），其余席位不动；两次都过不了才让整轮失败。
- **条数超限不再判死**（2026-09-28 加，P6）：容器（单席位意见 / 提案 / 未采用意见申报）
  超上限时先重装一次让它自己精简，仍超限就**截断保留**，溢出的每一条记留痕、
  草案卡上加一行缺口。详见 §11.0.7。
- **引用编号归一化**（2026-09-28 加，P6）：`E08` / `e8` / 全角 `Ｅ８` 都归到 `E8`；
  **归一化后仍不在账本里的编号照样判死**（GB1 不动）。详见 §11.0.7。
- **目录外的席位提名丢人不丢轮**（2026-09-28 加，P6）：提名里混进目录里没有的席位 →
  丢掉那一条 + 留痕，其余照跑；只有"一条都不剩"才判死（R7 要求一轮至少一个席位）。
- **顶层数组按元素签名重建**（2026-09-28 加，P7）：模型把整包漏掉外层对象、直接回一个数组时，
  只要每个元素能用签名唯一归到一类内容（题/清单/提案/申报），就机械补壳；补不了照旧判死。
  详见 §11.0.8。
- **整合的解析错也重装**（2026-09-28 加，P7）：以前 `except ApplicationError` 把
  `PacketParseError` 和网关失败一起判死，导致纠错指引对整合从来没生效过；现在只有
  `ModelCallFailed` 立刻失败，形状/结构/内容错都走重装那一圈。

**一轮的调用上限（一处写清，别再散着算）**

| 步骤 | 上限 | 两次都失败怎么办 |
|---|---|---|
| 主张 claims | 重装 1 次（共 2 次） | `fail_round`（claims 是地基，硬编比失败更糟） |
| 席位轮 | 3 轮 | 剩余缺口全部显式化，不追问 |
| 席位轮 · 单席位报文不合格 | 该席位重装 1 次（共 2 次） | 超限 → 截断保留 + 留痕，整轮继续；别的错 → 整轮失败 |
| 整合 | 重装 1 次（共 2 次） | 有席位疑问 → 降级成 s11 开放问题；否则 `fail_round` |
| 整合 · 报文形状/结构错（含顶层数组） | 重装 1 次（共 2 次） | 与内容错同一个出口（降级或 `fail_round`） |
| 整合 · 容器超限 | 重装 1 次（共 2 次） | 截断保留 + 留痕 + 草案卡缺口行，整轮继续 |
| 问卷 | 2 批 | 剩余题目按 C6 显式化（落 s11）；**轮内队列里的题也一并落 s11**，一条不丢 |
| 单次网关调用 | 3 次尝试（+1s / +3s 退避） | `ModelCallFailed`（整轮失败可重试） |
| 留样（`PMSTUDIO_TRACE_MODEL=1`） | 每次**尝试**一行（含失败那几次），带 `attempt`/`ok`/`error`；提示词超 20000 字符头尾各半 | 见 §11.0.15 |

最坏 ≈ **46 次**模型调用（claims 2 + 席位 3×7×2 + 整合 2；席位那 42 是"每席位都重装一次"的
理论极值，实际一轮 2–6 个席位、重装极少触发）。
- 模型不可用 → `generation.failed`，界面显示哪一步失败、人话原因、能否重试。
- 失败点只记第一次（`Round.fail` 幂等）：并发的第二次失败不许把"从哪一步重跑"覆盖掉；
  同一个 round 同时只允许一个动作（`RoundBusy` → 409），双击重试不再能锁死一轮。

### 7.1 答案轮缩编（C8，2026-09-24 定）

现在每答一批就把整批席位全量重跑。缩编要"谁管这个面"的映射——补进席位 TOML：

```toml
sections = ["s5", "s8", "s10"]      # 这个席位负责哪几章
fields   = ["acceptance", "rules"]  # 以及哪些功能字段
```

**下一 pass 的名单** = ① 上一轮对该 `target` 出过意见的席位 ∪ ② 映射命中该 `target` 的席位。
常驻席位**不再**强制入选（否则缩不掉）。名单落进 `Round.active_seats`；
`round_.seats`（用户编制）不动，所以复述卡与 R7 都不受影响。
兜底：缩编后整合者若认为信息不够，仍可出题（`from_opinions` 为空是合法的），
界面把 `asked_by` 为空的题标成"整合者提的"。

**落地口径（2026-09-28 实现，P5c）**：

- 命中只有两条路：① 这道题是**哪些席位提的**（`question.asked_by`，装配层算的）∪
  ② 席位 TOML 的 `sections` / `fields` 命中这道题的 target。
  席位意见本身**没有 target**，所以"上一趟提过这个面"只能从题上来。
- 结果永远在**用户编制**之内（`Round.seats` 不动，R7 与复述卡不受影响）；
  名单落 `Round.active_seats`（开场卡确认时 = 编制），`pending_seats` 基于它算。
- **命中为空 → 全跑**（宁多勿缺：多跑一个席位是钱，漏一个面是缺陷）；
  没答也没跳过的题不算。

## 10. 就绪度与交付的数据流（2026-09-24 定）

```
Document（聚合，唯一真相源）
  └→ view(): DocumentView           ← 已有投影，够用：sections→blocks→entries/field/feature_slug
       │
       ├─→ ReadinessChecker.check(view)                ← 纯代码，无 IO，无模型
       │        └→ tuple[ReadinessItem]
       │             ├→ context.render_readiness() → 追加到三个提示词的 $document_state
       │             ├→ dto.ReadinessItemView → WorkspaceView.readiness → 界面
       │             └→ 导出：头部盖章 + 空章标记
       │
       └─→ deliverable.render_markdown(view, refs, readiness, versions)
                ├─ 正文：13 章 + 功能子树（偏好区不进正文）
                ├─ s13：由 Version[] 生成（不读 block 树）
                ├─ 附录 A：编号 + kind + 一句话摘要（不带 raw_span，遵守 04 D5）
                └─ 附录 B：偏好区（标注"不进交付物"）

GET /projects/{id}/export/markdown  ← 纯读，一次渲染，无事务
```

三条实现约束（都要有测试钉住）：

1. **确定性**：同一份 `DocumentView` + 同一份账本 → 同一份字节。渲染函数里没有时间戳以外的
   随机源；时间戳来自调用方传入的 `now`（可注入，测试才能断言）。
2. **只读**：导出路径不持有 `DocumentWriter`（守卫白名单里永远只有 `ProposalCommitter`）。
3. **可判据**：导出里出现的"未完成项"必须逐条来自 `ReadinessItem`，不允许导出层自己再判一套。

## 11. 版本与出处（2026-09-28 定，P5b）

### 11.0 韧性三件（2026-09-28 落地，P5c）

**超时**：`PMSTUDIO_MODEL_TIMEOUT`（默认 90 秒，**按次**算）→ 网关同时传
`timeout` 与 **`num_retries=0`**。为什么必须关 SDK 自己的重试：实测只传 `timeout=2`
实际跑 7.8 秒（SDK 内部重试把墙钟放大 ~4 倍），加了 `num_retries=0` 才是 2.0 秒；
重试只由我们那一圈负责，墙钟上界 = `max_attempts × timeout + 退避(1+3s)`。
失败详情带 `timeout_seconds / attempts / cause`。

**供应商参数（关思考）**：`PMSTUDIO_MODEL_PARAMS`（JSON 对象）透传给 LiteLLM，
当 kwargs 的**基底**用——我们自己的键（`model` / `messages` / `timeout` / `num_retries`）
永远覆盖它，所以配置改不动超时与重试。DashScope 的 qwen3 系列默认开着思考，实测
（2026-09-28，同一模型同一输入）：

| purpose | 开思考 | 关思考（`{"extra_body": {"enable_thinking": false}}`） |
|---|---|---|
| claims | 63.2s（另一次 81.6s） | **13.7s** |
| seat_review | 366.9 / 370.6 / 371.1s（另一批 57–84s） | **5.7 / 14.0 / 14.5 / 17.1s** |
| integration | 104.3 / 93.0s（另一次 116.9–179.4s） | **20.3s** |

关掉之后整轮的模型时间从 10+ 分钟掉到 ~1.5 分钟，默认 90 秒超时有 4 倍余量。
**默认超时保持 90**；真要撞上更慢的供应商，把它调到 240–300 是兜底（一行配置）。

**留样**：`model_calls` 表 + `PMSTUDIO_TRACE_MODEL`（默认关）。存**提示词原文**
（截断 20 000 字符）+ 回复 + `prompt_sha` + `usage` + `duration_ms` + `round_id`；
只存哈希复现不了，而复现是这张表唯一的目的。它是**旁路**：写不进去不许影响这一轮
（真模型踩过一次：litellm 的 `usage` 里有 pydantic 包装对象，`json.dumps` 一炸把整轮搞失败了）。

**最小 eval**：`backend/evals/cases/*.json` + `scripts/eval.py`（真模型、不进 CI）；
七条**结构性**断言在 `evals/assertions.py`（纯函数，有离线测试）。它直接调用用例
而不是走 HTTP——eval 要测的是提示词与编排，不是传输层。

### 11.0.1 超时诊断（我的活，不是功能）

每次网关超时，报告"哪一步、第几次调用、`duration_ms`、提示词多大、`cause`、重试几次"
并给判断。材料就是留样表 + `ModelCallFailed.details`，**产品里不加诊断逻辑**。

### 11.0.2 去处写错：只丢那一条（2026-09-28 作者拍板）

整合报文里某条的 `target` 不合法时：**丢这一条 → 写进 `Round.dropped`
（`handle="提案 #3"` 这种、`source=assembly`、`reason=错误原文`）→ 继续处理同一批里的其它条目**。
理由：真模型实测，一次笔误让两次整合都过不了校验、整轮降级、所有席位疑问掉进 s11；
而"不知道放哪儿"跟"编号写错（内容没有出处、追溯链断了）"不是一回事——
**后者仍然整轮失败**（GB1 不松口）。

### 11.0.3 来源分组按**账本**算，不采信模型自报（2026-09-28 作者拍板）

整合报文里的 `origin_type` 只是**建议**：模型写 `user` / `derived` 的，装配层会用
`TraceabilityChecker` 顺着 `refs → derived_from` 检查一遍——**回溯不到 `user_input` 或
`card_answer` 的，一律降级成 `proposed`（"它提议的"，默认不勾）**。模型写 `proposed` 的原样保留。

为什么：真模型实测，席位给的"没有依据的判断"会被整合者标成 `derived` 进"它替你判断的"那组，
用户勾选后提交时才撞 `invariant:E4 回溯不到用户输入或问卷答案`——卡片上没有任何提示，
用户以为系统坏了。`02` §4.1 本来就写着"到不了的只能作为 proposed 出现且默认不勾选"，
这条只是把那句话实现出来。**提交端的不变式不动**（GB1 仍是最后一道闸）。

### 11.0.4 复述对齐：认省略号、不许拿说明当原话（2026-09-28 作者拍板）

`raw_span` 只有一个用途——点编号跳回原文，所以判据只该问一件事：这段是不是原文里
**真实存在**的一段。真模型实测（完整 eval 的 `case-a`，3 次里 2 次产出逐字相同的那条）：
`'想做个订单导出的功能...最好能按时间筛选'`——两段原话都在输入里，**省略号 3 个字却计进
分母**，最长匹配 10 字撞上 10.5 字门槛，**差 0.5 字把整轮判死**（502，用户只能手动重试）。
同一句话把省略号写成 `…`（1 个字）就能过：能不能过取决于模型的标点习惯，这不是判据该管的事。

**落地口径**（`analyzer.grounded_span`）：

| 情形 | 判法 | 返回 |
|---|---|---|
| 整串逐字命中（原文里真的写了 `...`） | 不切段 | 原样返回 |
| 明写拼接标记（`...` / `…` / `。。。`） | 切段，**每段各自走同一条判据、全段都要站得住**；空段（`A...`）忽略 | 最长的真实片段（并列取靠前） |
| 没写标记（逗号拼出来的那种） | 整串最长连续匹配（`≥ max(6 字, 0.5×候选长度)`）——**与改动前一字不变** | 最长连续匹配 |
| 有任何一段站不住 | 整条不认 → `PacketParseError`（整轮失败，可重试） | — |

为什么"写了标记就按段判"：模型写了 `...` 就等于**自己把切分点交出来了**，这时按段判是它
应得的对待——顺带把"一半真一半编"堵死（`A...B` 里 A 真 B 编的，改前会因为整串恰好过 50%
而被放行，实测就是这样）。没写标记才只能整串估，所以那条路一字不改。
**反编造一点没松**：`（隐含于上下文，仅提及订单导出）` 这种"说明当原话"在 `edge-long`
上真的又出现过，它连一段都站不住，照样判死。

**提示词同步说**（口径的入口不止一个，改一处要说三处）：

- `analyzer.md` 硬规矩 2：必须**连续**、不许用省略号拼两段、**原话里找不到落点就不要切这条主张**；
- `ClaimDraft.raw_span` 的字段描述同口径（这个 schema 会被内联进提示词，写在字段旁最不容易漂）；
- 席位 id 要**连 `seat.` 前缀一起照抄**（真模型写过裸名 `tech_approach` / `data_scale`，整轮被判死）；
- 整合者硬规矩补"**同一个去处一批里只出一题**"——eval 那条 `no_duplicate_questions`
  以前是**只考不教**，真模型在 `edge-one-constraint` 上就 s7 出了两道题。

**口径**：**断言考的东西，提示词必须先说**；考一件没交代过的事，等于在惩罚模型的猜测。

### 11.0.5 报文不合格：重装一圈（2026-09-28 作者拍板，P5d）

**问题**：claims 一次不过就 `fail_round`，而真模型是**抖的**——同一份输入换个采样就过
（完整 eval 三轮里 claims 崩过 4 次：3 次是提示词/守卫的问题，剩下的纯抖动）。
让用户手动点"重试"来兜模型的抖动，是把成本推给人。

**口径**（与整合者对称）：

| 触发 | 喂什么 | 上限 | 两次都失败 |
|---|---|---|---|
| claims 的 `PacketParseError` | `repair_note()`：第几条 / 哪个字段 / 要求是什么 | 2 次 | `fail_round`（理由"主张两次都过不了校验：…"） |
| 整合的 `PacketParseError` / `DomainError`（原有） | 上一次的 `message` | 2 次 | 有席位疑问 → s11 开放问题；否则 `fail_round` |
| 网关传输异常（原有） | 退避后重发同一请求 | 3 次 | `ModelCallFailed`（**claims 不再重装它**） |

**两条自己的规矩**：

1. 重装**必须**带纠错指引——拿同一句提示词再撞一堵墙是 L13 定性过的失败模式；
2. 指引**不复制模型写出的内容片段**（`raw_span` / 正文 / 选项措辞），只说位置与要求——
   把写错的那串喂回去，等于给它一个可以照抄的模板（`（隐含于上下文…）` 被填进
   `raw_span` 过两次，见 §11.0.4）。

**不新增产品字段**：重装次数不进 `Round`、不进界面（第二份真相源）。要查就查留样表：

```sql
SELECT purpose, count(*) FROM model_calls WHERE round_id = 'r-…' GROUP BY purpose;
```

claims 一步一轮只该调一次，出现 **2 条就是重装过一次**——诊断是我的活，不是产品功能
（§11.0.1 同一口径）。

### 11.0.6 两条 eval 断言的判据修正（2026-09-28 作者拍板）

**① 重复题：判据是"同一个去处 + 同一个问法"，不是"同一个去处"**

原判据只看 `target_label`，于是"同一章节上的两件不同的事"被判成重复。真模型实测
（第四轮 eval 的 `case-a`）：`s8.availability` 上出了两道题——
"订单导出幂等性与重试策略确认" 与 "订单导出对端不可用时的降级策略确认"。
它们是**两道真问题**，各自带 `options` 与 `consequence_if_skipped`：

- 合并成一道会丢结构（跳过后果只剩一份）；
- 丢掉任何一道都是把用户该填的题吞了——**这不是留痕能替代的东西**。

新判据：`(target_label, 归一化标题)` 相同的才算重复（标点与空白不参与比对）。
同一去处的两件不同事照问。整合者提示词同步改成"同一件事不要问两遍；同一去处的两件不同事
各出一题"（早先写反过一版"同一个去处只出一题"，已撤）。

**② `no_unauthorized_features` → `outside_scope_items_are_labeled`**

旧断言把 `advisories` 一律当失败，而 `advisories` 只有一种来源：`ScopeGuard` 的
**"这条落在 X，不在本轮去处里"**——那正是 §3①（2026-09-22 定）明确要求**放行并标注**的行为
（"静默拒绝会让席位的专业判断整批白干"）。旧断言的注释还写错了前提：`ScopeGuard`
**不标**"未授权的新功能"；那条走的是 `assemble` 的 `pending_features` →
`new_feature_yes` 决策题（用户点头才授权）。

新断言只盯**标注这条路没断**：① 草案卡上带标注的提案数 == 顶部提示数（两处不许漂移）；
② 标注是人话（写清"不在本轮去处里"）。
**硬约束仍在**：不得新增未授权功能子树，由装配层的决策题 + 领域层授权集合守着，
单测 `tests/application/test_assembly.py::test_assemble_creates_feature_subtree_only_when_authorized`。

这条断言**管不了"跑出去的条目该不该有"**——那是设计允许的；别把它的绿灯读成"模型很守规矩"。

### 11.0.7 超限不判死、编号归一化、席位丢人不丢轮（2026-09-28 作者拍板，P6）

**来历**：四项目真跑（15 轮、250 次模型调用）里，**每一次整轮判死都不是因为内容错，而是因为形状**——
报告 F2/F3/F4/F11/F13：

| 触发 | 真跑次数 | 改前代价 |
|---|---|---|
| 提案 44 条 > 上限 30（3 棵功能树 × 12 字段 = 36 就已经越界） | 1 | 整轮 502，**44 条内容一条没落地** |
| 单席位意见 10 条 > 上限 8（提示词却写着"最多 5 条判断"） | 1 | 整轮 502，4 个席位重跑 |
| 未采用意见申报 35 条 > 上限 30（提示词要求"一条都不许默默丢掉"） | 1 | 整轮 502，重试给出 33 条又挂 |
| 出处编号写成 `E07`/`E08`、`r-… #08` | 5 | 每次整轮 502 + 4–6 个席位重跑 |
| 提名目录里没有的 `seat.observability` | 1（连错两次） | **轮次都创建不了** |

**口径（三条，各自独立）**

1. **上限按"装得下一棵完整功能树"重定**，并**与提示词口径对齐**：

| 容器 | 旧 | 新 | 算术 |
|---|---|---|---|
| 单席位意见 `opinions` | 8 | **12** | 提示词允许 5 条判断；再给疑问留 7 条 |
| 提案 `proposals` | 30 | **60** | 一棵功能树 12 字段 × 4 棵 = 48，再留章节级内容 |
| 未采用意见申报 `dropped_opinions` | 30 | **84** | 7 个席位 × 12 条——"一条都不许丢"必须**数学上成立** |

2. **超限先重装、再截断，不判死整轮**：
   - 解析期：`parse_packet_trimmed()` 只在"**所有**报错都是 `too_long`"时截断；
     出现任何别的错照旧抛（"错就是错"不许被截断掩盖）；
   - 用例期：第一趟发现超限 → 带定向纠错（`repair_note` 的 `overflow` 分支，
     说清"你给了 44 条，上限 60，按什么优先级精简"）再调一次；第二趟仍超限 → 截断保留；
   - **截断保留模型给出的前 N 条**（顺序即它自己的优先级，我们不替它重排）；
   - 溢出的部分：每条记一条 `Round.dropped` 留痕，草案卡上加一行
     "本轮有 N 条内容因单轮上限未进卡片（可在下一轮继续提）"——**绝不静默丢**。

3. **引用的写法归一化，但幻觉照旧判死**：
   - `normalize_ref()` 认 `E08`/`e8`/全角 `Ｅ８`/带空格 → 规范成 `E8`；**只有落回账本才算数**；
   - `E999`、`r-… #08`（提案编号）、`seat.x:O1`（席位地址）照旧判死；
     但错误信息要指明命名空间（"这是提案编号，不是出处编号"），并给数字相邻的候选编号；
   - 为什么不一并放松：编号不认识意味着"这条内容没有出处"，追溯链断了（GB1），不能进文档。

4. **目录外的席位提名：丢人不丢轮**：
   - 提名里混进目录外 id → 丢掉那一条 + 留痕（"席位提名 seat.observability：目录里没有这个席位"），
     其余席位照跑；
   - 只有"**一条都不剩**"才判死——R7（一轮至少一个席位）不许破；
   - 来时：模型照着 s8 的**章节槽**名字（`observability`）挑席位，而席位目录是另一套命名空间。

**不新增产品字段**：溢出与截断只进既有的 `Round.dropped` 与 `Draft.gaps`；
重装次数不进 `Round`、不进界面——要查就查留样表（`model_calls` 按 `round_id` 数条数），
与 §11.0.5 同一口径。

**验收**：`tests/application/test_packet_overflow.py`（上限与截断）、`test_repair.py`（超限指引）、
`test_seat_round.py`（单席位重装 / 截断留痕）、`test_dropped_trace.py`（溢出进留痕与缺口）、
`test_evidence_refs.py`（归一化）、`test_assembly.py` / `test_seat_agent.py`（E08 通过）、
`test_start_round.py`（目录外席位不挡轮次）；真模型口径见计划 T11。

### 11.0.8 整包回成数组：形状重建 + 整合重装（2026-09-28 作者拍板，P7）

**来历（留样为证）**：P6 验证里两次真实失败长一个样——**整包是一个数组**：

| 来源 | 轮次 | 报文 |
|---|---|---|
| 端到端真跑 | `r-12353e02` 留样 15 | 顶层数组、5 个元素，每个都是 `QuestionDraft`（`title`/`why`/`consequence_if_skipped`/`target`） |
| 完整 eval | `r-8d65170f` 留样 66 | 同一形状，4 个元素 |

**同时暴露的第二个缺陷**：`IntegrateRound._integrate_with_repair` 的
`except ApplicationError` 把 `PacketParseError` 和网关失败一起判死了——
留样 15 的插入时间与那次 502 是**同一秒**，留样 16 出现在 55 秒之后（我手动点重试才有的）。
也就是说：`repair_note` 给整合写了纠错指引，**却从来没有第二次机会用它**。
claims（P5d）与席位（P6）都早有重装，整合是唯一漏的那个。

**口径（两条）**

1. **形状重建：只补壳，不猜内容**

   | 报文 | 顶层数组能不能重建 | 原因 |
   |---|---|---|
   | `IntegrationPacket` | **能** | 四个容器都有默认值；补一层壳不需要造任何字段 |
   | `SeatPacket` | 不能 | `basis` 必填，数组里没有——补空串等于替模型填字段 |
   | `ClaimsPacket` | 不能 | `basis` 必填 + `seats` 至少一个，补不了 |

   签名表（**顺序即判据**，命中即停）：

   | 顺序 | 元素里有 | 归到 | 为什么唯一 |
   |---|---|---|---|
   | 1 | `handle` | `dropped_opinions` | 只有它要 `handle` |
   | 2 | `title` 或 `consequence_if_skipped` | `questions` | 只有它有题面/跳过后果 |
   | 3 | `text` + `target` + `reason` | `list_items` | 只有它同时有 `text` 与 `reason` |
   | 4 | `evidence_refs` 或 `op` | `proposals` | 只剩它（题目已在顺序 2 拦下） |
   | 5 | 都不命中 | **判死** | 无法唯一归位 → 不猜 |

   顺序 2 必须在顺序 4 之前：题目也可能带 `evidence_refs`。
   重建之后**照旧受上限约束**（数组里的 70 条提案一样会截断 + 留痕）。
   **空数组不重建**（L2：空返回不等于没意见），照旧判死、由重装兜。

2. **重装：整合的解析错也算可修复**

   `ModelCallFailed`（网关类）立刻失败；`PacketParseError` / `DomainError` 走重装一圈，
   第二次仍失败才进既有出口（有席位疑问 → 降级成 s11 草案；否则 `fail_round`）。
   重装带的东西分两种：解析错用 `repair_note`（形状 / 超限 / 字段路径都有结构化细节），
   领域错用领域自己的话术（如"选择题至少两个选项"，比通用话更具体）。

**不留产品字段**：重建只发生在解析期，产物仍是既有的 packet；
"模型回错过"这件事在留样里看得见（同一轮 integration 两次调用 = 重装；一次调用但报文是数组 = 走了重建），
所以不为它单开留痕通道（那会让"留痕 = 没进卡片"的语义变浑）。

**验收**：`tests/application/test_packet_overflow.py`（签名互斥 / 重建 / 归不了位判死 /
claims 不猜 / 重建后仍截断 / 空数组不重建）、`test_dropped_trace.py`（第一次数组→重装→过；
两次数组→走既有降级出口）、`test_repair.py`（形状指引话术）。

### 11.0.9 字段级容错与"功能候选为空"的提醒（2026-09-28 作者拍板，P8）

**来历**：P7 验证时席位把 `evidence_refs` 写成 `null`（留样 7）→ 报 `list_type` → 只能靠
"该席位重装一次"兜；而整合者提示词里**没有**"本轮哪些功能已授权"，模型于是整轮不产功能候选，
s5 整章空着（报告 F1）。

**口径一：字段级归一化（解析期，三档）**

| 档 | 规则 | 例 | 为什么安全 |
|---|---|---|---|
| L1 | **列表字段**收到 `null` → `[]` | `evidence_refs: null` → `[]` | 空列表在本仓库有明确定义：席位意见没依据 → 走既有降级（标"模型没给依据"、按"它提议的"处理）；提案没依据 → schema `min_length=1` 照旧失败（GB1 不破） |
| L2 | `list[str]` 收到**字符串** → 单元素列表 | `evidence_refs: "E4"` → `["E4"]` | 一个编号写成一个字符串，意图唯一；`"E4, E9"` 不拆，交给"编号不存在"那条报错 |
| L3 | **非 Optional、有默认值**的字段收到 `null` → 用默认值 | `kind: null` → `gap` | "没给值"用 schema 的默认值，不猜内容；命中的都是 `kind` / `type` / `zone` / `origin_type` 这类**分类提示** |
| — | **黑名单**：`op` / `entry_id` / `form` 不适用 L3 | `op: null` → 照旧判死 | 前两个决定写/改/删哪一条；`form` 决定这条意见**进不进账本、有没有编号**——用默认值会悄悄改语义 |

**不救内容字段**（`text` / `title` / `why` / `claim` / `about` / `because` / `consequence_if_skipped`）：
内容没有"形状"可推断，编出来就是编内容。

规则由 **schema 注解**驱动（`list[str]` / `list[BaseModel]` / 嵌套 `BaseModel` 递归），不写字段名字表——
以后加字段自动覆盖，不会出现"某张表忘了加"。归一化在 `_normalize_payload`（P7 的顶层数组重建）**之后**执行，
两道可以叠加（顶层是数组 + 字段是 `null` 也救得回来）。

**口径二：字段级纠错话术**（`repair_note` 的 `errors` 分支）

不再只给字段路径（`opinions.2.evidence_refs`）——那是"错在哪"，模型要的是"该是什么"：

| pydantic 错误类型 | 话术 |
|---|---|
| `list_type` | 这里要是数组；没有内容就写 `[]`（不要写 `null`） |
| `string_type` / `dict_type` / `int_type` / `bool_type` | 这里要是字符串 / 对象 / 整数 / true·false |
| `missing` | 是必填字段，必须给 |
| `literal_error` | 取值只能从枚举里挑（附 `expected` 里的允许值） |

**口径三："这一轮已授权的功能"进提示词**（`$authorized_features`）

`round_.authorized_feature_basis`（主张点名 → 已授权，出处编号是点名它的那条主张）+ 文档里已有的功能，
渲染成清单交给整合者，并配两条硬规矩：
① 这些功能**已授权**，内容必须落到 `{section_id: s5, feature_slug: …, field: …}`，拿不准也别降级成章节级；
② 一条功能内容都没有时，先把点到的每个功能写成 `name` / `one_liner` / `goal` / `audience` /
`exceptions` / `acceptance` 里的至少一条，别让 s5 空着。

真跑验证（P8）：同一份"叙述式输入"（`试点/input-01.md`）**从 0 条 s5 提案变成 12 条**
（两个功能 × 六个字段），F1 的"功能章整章空"被解掉。

**口径四：零功能候选 → 草案卡置顶告警**（`dto.feature_coverage_advisory`）

**纯投影**：读 `round_.claims` 与 `round_.draft`，不写任何东西、不进文档——只出现在这一轮的卡片上
（前端 `DraftDrawer` 按顺序渲染 `advisories`，所以插到最前就是"置顶"）。
判据刻意保守：只有"主张点名过功能"且"草案里**一条** s5 功能提案都没有"才报；输入本来没提功能不报。

**已知副作用（2026-09-28 记，待作者定）**：口径三让模型把功能的**全部字段**都写了，而
`write_scope`（本轮去处）是按主张给的**精确字段**算的——于是同一功能的其它字段也被判"不在本轮去处里"，
真跑里一轮出现 **20 条 advisory**（15 条功能字段 + 5 条章节级），把置顶位置刷掉了。
两个候选修法（都没实现，等拍板）：**A** 写范围按**功能级**匹配（同一 `feature_slug` 的其它字段也算在范围内），
**B** advisories 按"章节 / 功能"折叠计数显示。

### 11.0.10 未决队列：被挤掉的题有去向 + 排队消化（2026-09-28 作者拍板，P9）

**来历**（报告 F12/F14，都有代码与真跑证据）：

| 事实 | 出处 |
|---|---|
| 超 5 题的溢出被写成 `list_items`，理由"本批只问 5 题，这条留到下一轮" | `assembly.py`（旧实现） |
| 但 `list_items` 只挂在**当轮问卷**上，答完就被覆盖 → 那句承诺**从来没兑现**，题凭空消失 | `dto.py`（`RoundView.list_items` 取自 `questionnaire`） |
| s11 未决条目**没有任何消费/撤下机制**，readiness 只数条数 | `readiness.py::_open_questions` |
| 真跑里 s11 阻塞数只涨不消：3 → 9 → 11 → 11 → **13** | `.codex/runs/2026-09-28/报告.md` F14 |

**口径一：两层队列，一份真相源**

| 层 | 存在哪 | 生命周期 |
|---|---|---|
| **轮内队列**（本批没问上的题） | `Round.deferred`（payload 键 `deferred_questions`，老行 `.get` 读回空） | 只在**本轮**有活路：下一批优先问；出草案或问卷到顶时**清空并落 s11** |
| **跨轮队列**（前几轮留下的未决项） | **就是文档 s11 里的未决条目本身**（不新建表、不搞第二真相源） | 每批挑**最老的 2 条**（`MAX_OPEN_ITEMS_PER_BATCH`）变成 carried 题问回来；被回答过就机械撤下 |

队列**不设硬上限**：上限之外的那部分只能在问卷步骤落地，而问卷那一支不写提案——
要么丢内容，要么借 `list_items` 复活假承诺。体积本来就被"每批题目数 × 批数"限住（个位数）。

**口径二：carried 题优先，且不重复问**

- carried（s11 未决项 + 轮内队列）排在 `ordered` **最前**，统一重编号；模型又问一遍同一件事
  （同一个去处 + 同一个问法）时**留 carried 那份**；
- 本轮已经 carried 过的 s11 条目**不再问第二次**（`skip_entries`）——否则"没撤下之前它一直会被拉进来"，
  永远出不了草案。

**口径三："答过就撤下"是机械动作，不指望模型**

- 来源键是 **`form_id#question_id`**：`question_id` 在同一轮每一批都从 `q1` 重排，
  只按 question_id 记会把上一批的来源覆盖掉（真跑第 2 轮实测到，已修）；
- 出草案那一刻：**被回答过**、且来自 s11 未决条目的题 → 各出一条 `remove`

### 11.0.11 题号在轮内唯一：答案的身份是 `(轮次, 题号)`（2026-09-29 作者拍板 D4/D5）

**来历**（报告 F6 + 三段探针）：一份"第二批的答案"在提示词里是这样出现的——

```
- q1 对端不可用时怎么降级？ → 10万〔E1〕
- q1 对端不可用时怎么降级？ → 重试三次〔E1〕      ← 两行都挂第二批的题面、都写 E1，E2 根本没出现
```

**证据编号（`E1…En`）没问题**：账本按**项目**单调分配，唯一、不复用、可跨轮引用
（"把所有证据统一编号再给模型"这套机制一直在跑）。错的是**指针**：题号原来按**批次**发
（每批 `q1…q5`），于是"按题号回查"的地方一共有**六处**，第二批发到同一个号就全部指错：

| # | 位置 | 症状 |
|---|---|---|
| 1 | `context.render_answers` | 答案行挂别的批的题面 |
| 2 | `context._answer_eid` / `answer_eids` | 编号只按裸题号找 → **第二轮引到第一轮的答案** |
| 3 | `assembly.open_question_proposals` | 第一批**跳过**的题落 s11 时用第二批的题面与后果 |
| 4 | `use_cases._system_defaults` | 同上（补 system_default 出处的文本错） |
| 5 | `use_cases._retire_answered_open_items` | `remove` 引到别批的答案编号 |
| 6 | `Round.write_scope` | 第一批答案的**去处丢了**、第二批的**混进来**（实测 `['s2','s8']`，应是 `['s2','s5']`） |

**口径（两条）**

1. **题号按轮次单调发**：`Round.asked_question_count`（= 本轮问出去的题数）决定起点，
   第一批 `q1–q5` ⇒ 第二批从 `q6` 起。轮内唯一 ⇒ 答案的身份 = `(轮次 id, 题号)`，
   **不需要给出处表加字段**（`Round.round_id` 本来就在 `card_answer` 上）。
2. **问卷历史追加不覆盖**：`Round.questionnaire_history`（payload 键 `questionnaire_history`）。
   题面、跳过后果、选项文案都要回**出题那一批**去找——当前批仍然是 `questionnaire`（既有读法不动）。

**回退（宁可不显示，也不显示错的）**：老 payload 没有历史键 → 读侧回落到"只有当前这一批"；
老库里已经重排过的同一轮两个 `q1` → **不显示 E 编号**（`_answer_eid` / `answer_eids` 命中两条即放弃），
席位的 `q# → E#` 翻译表也**只收本轮**。

**连带简化**：P9 为绕开重排而引入的 `carried_sources` 键 `form#qid` 保留（无害），
但"键必须带 form_id"的那条理由已经不存在——根因（重排）被拔掉了。

**验收**：`tests/domain/test_round_questionnaire_history.py`、`tests/application/test_context_answered.py`
（两行各挂各的题面/编号、跨轮不串、老库撞号不显示）、`test_write_scope.py` 的批次归属、
`test_assembly.py` 的跳过题题面与编号接续。

### 11.0.12 答案的去向：引用或机械落地（2026-09-29 作者拍板 D3）

跨轮去重的真相源只有**文档**（§11.0.10 定过：不新建第二真相源；`PROJECT.md`/记忆层 v1 不做）。
一条答案要是没落进文档，下一轮**必然**再问一遍（报告 F6 跨轮那一半的根）。

**口径**：出草案那一刻，装配层核查每条答案的出处编号**有没有被这一趟的提案/题目引用**；
没有引用的，机械落一条 `Proposal`：

| 项 | 取值 |
|---|---|
| 去处 | 那道题的 `target` |
| 文本 | `用户已定：<选项文案 或 自由文本>`（**用选项文案**，`new_feature_no` 这种机器 id 不进正文） |
| 出处 | 这条答案自己的 E 编号 |
| 来源 | `origin=user`（用户自己说的话，卡片上默认勾选） |

**三种不落地**（各自在草案卡的 `gaps` 里留一句话，绝不静默）：
① 题的 `target` 是**未授权的新功能 slug**——落下去等于凭空建功能子树，直接撞硬约束
（这一条的用户决策已经被 `authorize_new_feature` / "不新建"两条结构动作消费掉）；
② 题来自 **s11 未决条目**（`carried_sources` 命中）——答完已有机械 `remove`（§11.0.10），再 ADD 会当场对冲；
③ 答案已经被引用（整合者干完了活）。**空答**不落也不留噪声；**去处不合法**（如功能字段表里没有这个名字）
只跳过 + 留一句话——这段跑在事务里，不许打崩整轮。

**验收**：`tests/application/test_answer_landing.py`（7 条）、`test_integrate_answers.py` 的两条
（没引用 ⇒ 落地；引用过 ⇒ 不落地）。

### 11.0.13 跨批去重：本轮问过的题不再问第二遍（2026-09-29 作者拍板 D2）

去重的身份仍是 `question_key = (去处, 归一问法)`（`assembly.question_key`），
但**种子**扩到"本轮问过的每一道题"（`questionnaire_history`），**已答与已跳过都算问过**：

- 已答 → 结论由 §11.0.12 保证有去向（被引用或机械落地），不留缺口；
- 已跳过 → 出草案那一刻已经按题面后果落成 s11 未决条（原 `open_question_proposals`），
  同一轮再问一遍等于当着用户的面反悔（用户刚说"跳过"）。

**验收**：`test_assembly.py` 的"问过的不再问 / 换个问法照问"、`test_integrate_answers.py`。

### 11.0.14 写范围按功能级匹配 + `conflict` 判据 + eval 断言解耦（2026-09-29 作者拍板 D1）

- **写范围**（§11.0.9 的已知副作用，方案 **A**）：`Round.write_scope` 把带 `feature_slug` 的
  scope 折叠成**功能级**（`round.widened()`），于是"主张点了 `one_liner`、整合者写 `.goal`"
  不再被标成跑出本轮去处；**只对功能字段放宽**（章节槽 `s8.compatibility` → `s8.security` 照样报），
  功能级**不得新增未授权子树**那条硬约束一个字没动（`assembly.pending_features` + `Document.apply`）。
- **`conflict` 判据**（报告 F7）：`integrator.LIMITS_TEXT` 从"与文档既有结论冲突"扩到三种
  （与文档冲突 / **本轮输入内部互斥** / 两席位判断互斥），并写明**反例**——
  "只是还没定"是 `gap`，别把缺信息题也标成 conflict（界面上两者分开显示）。
  新增 eval 断言 `contradiction_is_labelled_conflict`，只挂在 `06-edge-contradiction` 上
  （用 `case.extra_assertions` 追加，不必整份替换 `EVAL_ASSERTIONS`）。
- **eval 断言解耦**：`outside_scope_items_are_labeled` 原来拿"顶部提示总行数"比"带标注的提案数"，
  而置顶告警（`dto.feature_coverage_advisory`）不挂在任何提案上 → 两者同时出现就**假红**
  （真跑前离线复现）。现在只比"含『不在本轮去处里』的行数"，并要求顶部除越界提示外
  只能出现以 `⚠` 开头的置顶告警。

### 11.0.15 留样补真：每次尝试一行 + 提示词头尾保留（2026-09-29 作者拍板）

报告 §四的两条诊断结论落地（**不是**新增"超时诊断功能"，只是把已有的旁路补真）：

- **每次尝试一行**：网关原来只在"最后一次尝试失败"时写留样，于是那次
  "超时 90 → 退避 → 重试成功"的 120.4s 看起来像一次慢成功，"为什么慢/为什么重试"一行都查不到。
  现在每次尝试都写，`duration_ms` 记**单次**耗时，并带 `attempt` / `ok` / `error`（失败原因原文）。
- **提示词头尾保留**：`PROMPT_LIMIT`（20000）以内原样；超了**头尾各半**（中间插"略去 N 字符"）。
  原来只留头，切掉的正好是末尾的硬规矩与输出 schema——复盘"模型为什么这么答"最想看的一段。
- **表结构**：`model_calls` 加 `attempt` / `ok` / `error` 三列；`database.connect()` 里
  **幂等 `ALTER TABLE`** 补老库（`USER_VERSION` 1 → 2），只加列、不删数据。

**验收**：`tests/infrastructure/test_llm.py`（重试后成功 ⇒ 两行；三次都失败 ⇒ 三行）、
`test_model_calls.py`（旧 DDL 建库 → 补列且老行可读、幂等、头尾保留）。

### 11.1 留痕：一条通道，三个来源

```
本轮席位意见（current_reviews）
  ├─ 模型申报        → dropped_opinions[{handle, reason}]  ─┐
  ├─ 归因对不上号    → 装配层（from_opinions 指向不存在的条目）─┤→ Round.dropped[]
  └─ 没人交代过      → 装配层核查（unaccounted）              ─┘   （累加，跨趟保留）
                                                                   └→ rounds.payload.dropped
                                                                        └→ RoundView.dropped[] → 闭环区
```

**"算交代过"的三条**（任一条成立就不报 `unaccounted`，这是把假阳性压到最低的边界）：
① 地址出现在某道题的 `from_opinions` 里；② 它自己的出处编号（只有判断有）出现在某条提案或
某道题的引用里；③ 模型在 `dropped_opinions` 里申报过。**结构性豁免**：整合失败走降级出口时，
这一趟的疑问会被原样落进 s11，所以算交代过；没落地的判断照报。

形状：`DroppedItem{handle, reason, source, seat_id, pass_index}`。`handle` 的形状**故意不校验**
（模型写歪的地址正是要留痕的东西）。

### 11.2 版本：读两条、写一条

| 动作 | 端点 | 实现 |
|---|---|---|
| 列版本 | `GET /projects/{id}/versions` | `GetVersions` → 聚合里的 `versions` → `VersionListView` |
| 看差异 | `GET /projects/{id}/versions/{a}/diff?to=b` | **纯函数** `domain/authoring/diff.py::diff_snapshots`（按 `entry_id`） |
| 回退 | `POST /projects/{id}/versions/{n}/rollback` | `RollbackVersion` → `ProposalCommitter.rollback_to`（唯一写路径）→ 新版本 `trigger=rollback` |

diff 的两条实现约定：**功能名两版共用一张表**（`after` 优先），否则改个功能名会让同一批条目
在两侧落到不同组里、看着像"全删了又全加了"；**不做块移动 / 重排检测**（没有写入路径会移动块）。

回退的硬要求：恢复快照时**重算墓碑**（活过来的块不能再算墓碑，否则"活块 id"与"墓碑 id"重叠，
下次重建聚合直接抛 `DuplicateBlockId`、整个项目打不开），并且候选状态先过校验——与 `apply()` 同一条规矩。
