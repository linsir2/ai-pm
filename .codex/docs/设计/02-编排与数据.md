# 02 · 编排与数据（系统怎么跑）

> 2026-09-22 第二次重写。三处改动：**席位职责收成一件事**（只出专业意见）、
> **问卷不是固定环节**（信息明确就直接出草案）、**答案回来后重新组装上下文继续任务**
> （不是机械消费选项）。契约也按"每个字段用来干啥"过了一遍，删掉了没有消费者的字段。

---

## 1. 一轮的粒度

**一轮绑定"一次用户输入"**，不绑定一个句子，也不绑定一个目标。

一次输入（20 句、含 3 件互不相关的事）→ 切分一次做完 → 一张复述卡列出全部主张 →
席位轮 → 整合 → （需要就问）→ 草案 → 确认 → 写入。

N 条主张共享同一轮的三次中断。**一轮的模型调用次数与句数无关**，只与席位数和席位轮数有关。
一轮里可以有多件事，不自动拆轮。

---

## 2. 全流程（席位轮是个环）

```
① 主张     切分 + 定性 + 归位                      [Analyzer]
② 开场卡   复述（含去处与范围）+ 席位编制            ← 中断 1
③ 席位轮   并行；每个席位只做一件事：出专业意见       [领域席位 ×N]
④ 整合     并入上下文 → 组装：待问的问题 + 内容候选   [Integrator]
⑤ 判断     还有必须问用户的吗？
              ├─ 有 → 问卷                           ← 中断 2
              │        → 答案并入上下文 → 回到 ③（缩编席位）
              └─ 没有 → ⑥ 草案卡                      ← 中断 3
⑦ 确认写入 唯一写入口 → 版本快照
```

三个要点：

1. **问卷不是固定环节**。它是"还有必须问用户的东西"时的产物。信息已经明确，
   整段跳过，直接出草案。
2. **答案回来不是消费掉就完**，而是**并入上下文后重新跑一次席位轮**（缩编：
   只请与本次答案相关的席位）——因为答案会让之前的一些判断变得可以落地，也会让
   另一些判断失效，还可能引出新缺口。
3. **循环有上限**：一轮内最多 3 次席位轮。到上限仍有缺口，就全部显式化
   （落 s11 开放问题 + 草案卡上标缺口），不再追问。
4. **两种编号各叫各的名字**（2026-09-24 定，见 `04-未决.md` C9）：
   `E7` 是**出处编号**（账本里的，能跳转、能引用）；`seat.x:O2` 是**席位条目地址**
   （"哪个席位的第几条意见"，只有判断会变成 E 编号，疑问没有编号）。
   提示词里两种写法分开写明——混在一起时模型会把地址当编号写进 `evidence_refs`。

## 3. 各部分职责

### ① 主张　[Analyzer]

输入：本轮用户输入 + 文档现状（章节状态表 + 本轮可能涉及的章节）。

1. **切分**：拆成原子主张，一条只讲一件事。
2. **定性**：七种标签（事实 / 需求 / 目标 / 约束 / 偏好 / 猜测 / 决定）。
3. **归位**：逐条给 `target`（章节 + 字段，若指向已有功能则带 feature）。**这一列就是写范围。**
   写范围分两级（2026-09-22 定）：**硬约束**只有两条——不得新增未授权 feature 子树、不得离开
   13 章；其余"跑出本轮去处"（如席位推的 s7 / s8 判断）**不拒绝**，而是在草案卡顶部显式标注
   "涉及本轮没提到的章节"。理由：静默拒绝会让席位的专业判断整批白干，用户永远看不到。

产出：主张清单。

### ② 开场卡　中断 1

两张卡：**复述理解**（列出全部主张，标签与去处可改，底部只读一行显示"本轮将改动哪几章、
还有几个历史问题没答"）+ **席位编制**。

席位编制**不是关键词匹配出来的**：Analyzer 在同一次调用里读完本轮输入与文档现状，
从注册表（`infrastructure/seats/definitions/*.toml`）挑出这一轮真正需要的席位，
每条给一句"为什么这一轮请它"（`seats[]`，与主张同一份报文、同一个事务落库）。
开场卡默认勾选这份名单，用户可以取消勾选，也可以从"目录里还有 N 个"里补上。
只有**老轮次**（分析时还没有挑席位这一步）才回落到"常驻 + 关键词"的目录匹配，
并且投影里标 `source="catalog"`、界面照实说"这名单没经过判断"。

合格标准（可验收）：复述里必须包含至少一个只有读了文档才知道的信息，否则视为复读原话。

### ③ 席位轮　[领域席位 ×N，并行且互不可见]

**一个席位只做一件事：以本领域的专业眼光，对"本轮输入 + 文档现状"给出意见。**
它不负责决定这些意见最后长什么样、写进哪个字段、要不要问用户。

意见只有两种形态：

| 形态 | 长什么样 | 例子 |
|------|---------|------|
| **疑问** | 我判断这里缺一个信息，而且这个信息只有用户能给 | "量级是同步与异步的分界，必须问用户" |
| **判断** | 我判断这里应该是什么，依据是什么 | "量级在 1 万级，同步导出够用；同类导出通常以 60 秒为上限"（依据 E4） |

每条意见都必须带：**依据（已有编号）或显式声明无依据**、**理由一句话**。
无依据的判断允许存在，但会被整合者放进"提议"一档（见 ④）。

**席位不能做的事**：不新增 feature 子树（用户点名新功能时除外）；不把模糊变精确
（"要快"→"60 秒"必须作为疑问提出来）；不替用户做业务口径决定。

**失败处理**：返回不可解析 → 席位失败 → 整轮失败可重试。**空意见不等于没意见**：
必须给 `basis`（读了什么、为什么没必要补充）。

### ④ 整合　[Integrator]

席位给的是"专业意见"，形状是散的；**把它变成可以进文档、可以直接问人的东西，是整合者的活**。
这是两个不同能力：席位提供内容（需要领域知识），整合者提供结构与形状（需要 schema 知识）。

**四步**

1. **并上下文**：把本轮主张、已有文档、各席位意见、以及上一轮的答案（如果有）合成一份工作集。
2. **组装**：
   - 疑问 → 归并成**题目**（给 target、给候选项、给不答的后果、给依据）
   - 判断 → 归并成**内容候选**（给 target、`origin = derived`，把理由变成 `rationale`，
    把依据变成 `refs`）
   - 无依据的判断 → `origin = proposed`，单独一档
   - 与已有文档或历史问卷重复的 → 丢弃
   - **丢弃要留痕**（2026-09-24 定，补 `04` C5 的后半）：报文加
     `dropped_opinions: [{handle, reason}]`（handle 形如 `seat.x:O1`）。装配层把它与
     "归因对不上"的条目合并成 `Round.dropped: [{handle, reason, source}]`，
     `source ∈ {integrator, assembly}`。界面上每个席位包显示"它说的 N 条里，M 条没进卡片"。
3. **编号**：给每个内容候选分配全局编号（席位并行时只能给局部 id，全局编号在这里统一分配）。
   席位意见在提示词里的写法是 `（席位条目 seat.x:O2 · 出处编号 E7）`：**只有判断**在汇合点
   进账本、拿到 E 编号；**疑问不进账本**（它是"要问什么"，不是文档内容的来源），所以写的是
   "没有出处编号"。题目的 `evidence_refs` 只能放 E 编号；要把"这道题是谁提的"带到界面上，
   写 `from_opinions`（席位条目地址），**归因由装配层算**——`asked_by` 不再由模型自填，
   真模型给两个空手席位安过"提问者"的帽子。
4. **判断出口**：还有必须问的 → 出问卷；没有了 → 直接出草案。**一批最多 5 题**，
   超出部分降级成清单项。
5. **归因对不上号就留痕**：`from_opinions` 指向不存在的席位条目时，只丢那一条归因、
   写进 `Questionnaire.dropped`（问卷卡上显示"哪几条没算数"），不判死整轮；
   依据编号写错（引用了不存在的 E 编号）仍然整轮失败。

**边界**：整合者**不产生新的专业判断**——它只组装别人的判断，以及决定"这条是问还是写"。

### ⑤ 问卷　中断 2（可整段跳过）

题目含：`target`、`type`、`title`、`why`（为什么问）、`options`、`consequence_if_skipped`、
`evidence_refs`（E 编号，**可以空**——疑问自己没有编号，引不到就留空）、
`asked_by`（装配层算出来的，合并后可能多个席位）、
`from_opinions`（模型给的归因线索，只用来算 `asked_by`，不当出处）。

题目还带 **`blocking: bool`**（2026-09-24 定，补 §⑤ 早就写着但没实现的那条）：
**由规则算，不问模型**——`target.field ∈ 必填功能字段`，或章节级 `target.section_id ∈
{s1,s2,s3,s4,s5,s8,s10,s12}`（那几章的合格标准是 blocker 级）→ 阻塞。
跳过的阻塞题落成 s11 开放问题时，文本前缀写 `〔未决·阻塞〕`（判据据此识别；
将来出现第二种标记就升级成 `Entry.flags`，见 `01` §7）。

一批一次交卷；提交前可改、提交后冻结；允许部分作答与跳过。

**答案回来后**：答案作为 `card_answer` 进出处账本（带 `question_id`），然后**重新组装上下文
回到 ③**——带着"用户已经答了什么"再问一次席位，让它们把之前的判断落地或修正。

跳过的题按题面写明的后果落成 s11 开放问题（不挡交付）；命中必填字段的标阻塞型。

### ⑥ 草案卡　中断 3

唯一一张卡，提案按来源分三组：

```
【你说过的】      ← 挂 user_input / card_answer
【它替你判断的】   ← 挂 agent_derived，可展开看理由与依据
【它提议的】      ← 挂 agent_proposed（无依据），默认不勾选
顶部一行：写入后本章仍有 N 项必填缺口
```

每条只有 **[要] [不要]**；卡片里不编辑内容（编辑归文档）。

### ⑦ 确认写入　[确认端点]

事务写入 → 版本快照（`trigger = confirm`，记录变更的 block id）→ 推送变更通知。
编排层、席位、整合者都拿不到写库能力。

## 4. 数据对象（每个字段都要有消费者）

### 4.1 出处链

```
文档里的内容
  └─ refs: [E12, E17]
       └─ 出处账本（只增不改，编号永不复用）
            ├─ user_input      用户在哪一轮说的（带原话片段）
            ├─ card_answer     用户答的哪道题
            ├─ agent_derived   席位判断的（必须带依据 + 理由）
            ├─ agent_proposed  席位判断但无依据
            ├─ system_default  系统默认值（清单项接受后生成）
            └─ external        外部材料（v1 留位）
```

**可追溯不变式**：任何进正文的内容，顺着 `refs → derived_from` 回溯，必须至少到达一条
`user_input` 或 `card_answer`；到不了的只能作为 `proposed` 出现且默认不勾选。

### 4.2 出处条目

| 字段 | 用来干啥 |
|------|---------|
| `eid` | 被内容引用（角标、跳转、回溯） |
| `kind` | 决定界面怎么标（你说的 / 它判断的 / 它提议的 / 系统默认） |
| `text` | 这条出处的规范表述 |
| `source` | 形状随 kind 变：`run_id`（哪轮）+ `raw_span`（原话，可跳转）/ `seat_id`（谁判断的）/ `question_id`（答的哪题）/ `derived_from`（依据，agent_derived 必填）/ `rationale`（为什么这么判断） |
| `supersedes` | 修订时指向被替代的旧编号（旧条目作废但不删） |

### 4.3 主张 Claim

`eid`、`text`、`label`（七种标签之一）、`target`（章节 + 可选 feature + 字段）。
四个字段就够：标签决定处理方式，target 决定落哪儿，其余两个是内容本身。

七种标签的硬规则：**偏好**不进正文（进偏好区）；**猜测**升格为假设（带失败后果与验证方式）；
**决定**记录决策者与时间。

### 4.4 信息包 Packet（智能体之间唯一的通信形状）

| kind | 产出者 | payload |
|------|--------|---------|
| `claims` | Analyzer | 主张清单 |
| `seat_review` | 领域席位 | `opinions`（疑问 / 判断，各带依据与理由）+ `basis` |
| `integration` | Integrator | 题目数组 / 提案数组 / 清单项 / 归因申报（**一包两用**，见下） |
| `opinion_dispositions` | Integrator（小调用） | 只回答"我点名的那些里哪些没采用"（`§11.0.37`） |
| `memory_curation` | MemoryCurator | 记忆变更指令集（`§11.0.44`） |
| `sim_inquiry` | SimInquiryAgent | 处境切片 + 假设 + 盲区（`§11.0.47`；M8 的 `inquiry` 另有其包，不混） |

信封：`packet_id`、`run_id`、`kind`、`produced_by`、`basis`、`payload`。
（删掉了 `confidence` 与 `emitted_refs`：前者 v1 没有消费者，后者可由 payload 推出。）

**两处 2026-10-04 校正**（实现落地时发现的原文缺口）：

1. **原表把整合者写成 `questionnaire` 与 `draft` 两行，但真实情况是"一次调用产出哪一类"
   由那一趟的状态决定**——同一份 `IntegrationPacket` 里四个容器都可能非空。所以
   `kind` 记 `integration`（这一包是谁产出的），"这一包是问卷还是草案"的真相源仍然是
   `Round.step` / `waiting_on`，**不在信封里再编一份**。加上 `opinion_dispositions` 与
   `memory_curation` 两个真实存在的 kind，一共五种。
2. **信封落地在 `harness/model/envelope.py` 的 `Envelope`**，六字段一字不多；
   `basis` 取自 payload 里模型自己写的那份（没有就是没有，不替它编）。
   **另带四类"这一趟的实况"**（各有消费者，不是装饰）：`packet`（校验后的报文）、
   `overflow` / `discarded`（没进卡片的那些条 → `Round.dropped`）、
   以及 `payload` 本身（补壳后的原始形状，复现与审计靠它）。
   `raw` / `model` / `usage` **刻意不放**：它们与网关旁路留样表（`model_calls`）
   逐字同源，而那张表连"空回包 / 非 JSON"那两条路都记，是更完整的一份。

   **身份由协调者（用例层）分配**：agent 只知道自己是谁产出的，不知道这是同一席位的
   第几趟第几次重试——那信息在用例层的重试环里。所以 `packet_id` 由用例层通过
   `packet_slot` 传下来，格式只有 `make_packet_id` 一处说了算：

   ```text
   pkt-{run_id}-{kind}-{produced_by}[-{slot}]
   ```

   槽位取值：席位 `p{席位轮次}a{第几次重装}`、整合 `i{已整合次数}a{第几次重装}`、
   归因补交代 `i{已整合次数}d{第几次}`、分析者与记忆整理 `a{第几次重装}`。
   **`i{已整合次数}` 必须落在 Round 聚合上**（`Round.integration_seq`），不能用用例层的
   局部重试计数——那个计数每次进入整合都重置，用它当槽位会让第二次整合拿到与第一次
   一样的 id（2026-10-04 自查实测撞过）。 `run_id` 当前等于 `round_id`（轮次）或探索 id（调研，M8.1 起留样可查）；
   将来若引入独立 runs 表，只换赋值源、信封字段不动。

   **消费者**：`packet.emitted` 事件带 `packet_id` / `run_id` / `kind` / `produced_by`，
   `basis` 从信封取——"这一趟交回的东西后来哪些没进卡片"按 id 一查即可。
   （留痕条目 `Round.dropped` 还没带 `packet_id`，那是 M3 的活。）

```jsonc
// 席位包
{
  "packet_id": "pkt_07", "run_id": "r3", "kind": "seat_review",
  "produced_by": "seat.data_scale",
  "basis": "读了 s5 / s8 与本轮 E1–E8",
  "payload": {
    "opinions": [
      { "local_id": "O1", "form": "question",        // question | judgment
        "about": "导出的数据量级",
        "claim": "量级决定同步还是异步，必须问用户",
        "because": "1 万行以内可同步，10 万行以上必须异步，是两套实现",
        "evidence_refs": ["E4"] },
      { "local_id": "O2", "form": "judgment",
        "about": "导出的性能上限",
        "claim": "单次导出应在 60 秒内完成",
        "because": "量级在 1 万级，同步实现可满足；同类导出常见上限 60 秒",
        "evidence_refs": ["E4"] }
    ]
  }
}
```

### 4.5 内容候选与提案

`target`（章节 + 可选 feature + 字段）、`text`、`origin`（`{type: user|derived|proposed,
from: [eid], rationale}`）、`state`（kept / dropped）。

**v1 限制**：`target` 只能落在已有 feature 的字段上，不能新增子树（用户点名的新功能除外）。

### 4.6 问卷、版本、运行

- **问卷**：`form_id`、`round_id`、`questions`（题目数组）、`list_items`（降级项）。
  题目字段见 ⑤。**删掉了 `option_means`**：答案不再被机械消费，而是回到席位轮重新判断，
  选项含义由席位在下一轮解释。
- **版本**：`version_id`（递增）、`trigger`（confirm / manual / rollback）、
  `changed_block_ids`、`snapshot`、`summary`。
- **一轮（round）**：`round_id`、`project_id`、`step`（已完成的步骤）、
  `waiting_on`（在等什么：开场卡 / 问卷 / 草案卡 / 无）、`seats`、`fail_reason`。
  恢复 = 从 `step` 之后继续；`waiting_on` 决定界面显示什么。

**2026-09-24 新增的三个字段**

| 字段 | 在哪 | 用来干啥 | 为什么必须落库 |
|---|---|---|---|
| `Question.blocking` | Round | 阻塞型未决 → 就绪度 L3 判据 | 跨轮：上一轮跳过的阻塞题要影响这一轮的交付判定 |
| `Round.dropped` | Round | 意见/归因被丢弃的留痕（§④）。**一条通道三个来源**：`integrator`（模型申报）/ `assembly`（归因对不上号）/ `unaccounted`（装配层核出"既没说丢、也没交代落到哪儿"）；每条带 `handle / seat_id / pass_index / reason / source` | 用户要能查"为什么这条没进卡片"；`pass_index` 是因为同一轮里席位会跑好几趟、`local_id` 每趟重号 |
| `Round.active_seats` | Round | 这一 pass 实际要跑的席位名单（§7 缩编） | `pending_seats` 改成基于它算；`seats`（用户编制）不变，R7 不受影响 |

### 4.7 就绪度（Readiness）　[纯代码服务]

`ReadinessChecker.check(view: DocumentView) -> tuple[ReadinessItem, ...]`，
`ReadinessItem{section_id, code, title, detail, severity}`，规则见 `01-规格.md` §4 与 §7。
它是**只读服务**：不写文档、不调模型、不进任何事务。四个消费者：

1. `context.render_readiness()` → 追加进三个智能体的 `document_state`（"让 AI 被缺口驱动"）；
2. `dto.ReadinessItemView` → `WorkspaceView.readiness`（界面）；
3. `deliverable.render_markdown()` → 导出头部、空章标记、附录；
4. （将来）eval 断言"这一轮没有新增 blocker"。

两条实现约定：

- **同一 (章节, code) 只出一条**，明细塞进 `detail`——否则一个空项目上来就报二十几行。
- 判据读的是 `DocumentView`，其中 `feature_gaps`（功能必填字段缺口）由 `Document.view()`
  顺手带上（就是 `Document.gaps()` 的结果），**不重写第二套功能字段规则**。

### 4.8 章节槽（section slot）

13 章里只有 s8 有固定槽（性能 / 可用性 / 安全 / 兼容 / 可观测 / 成本）。槽表在
`domain/shared/sections.py::SECTION_SLOTS`（跟骨架同处，避免 shared → authoring 的反向依赖）：

```python
SlotSpec(name="performance", title="性能", kind=BlockKind.NFR)
slot_block_id("s8", "performance") == BlockId("s8.performance")
```

寻址规则（`Target`）：

| 写法 | 含义 | 落点 |
|---|---|---|
| `body("s8")` | 章节级内容（不指定槽） | 新开一个 `s8.bN` 块（老行为） |
| `body("s8", field="performance")` | **章节槽** | 复用或新建 `s8.performance` 块 |
| `body("s5", feature_slug="x")` | 功能根 | `feat-x` |
| `feature_field("x", "acceptance")` | 功能字段 | `feat-x.acceptance` |

两条校验：`field` 有 `feature_slug` → 必须命中**功能字段表**；没有 → 必须命中**该章的槽表**。
`Document.new` 顺手把六个空槽建出来（它们是骨架，不是内容，所以不算"有内容"）。

## 7. 失败、暂停与恢复

- 席位返回不可解析 → 该席位失败 → 整轮失败可重试（不静默跳过）。
- 达到席位轮上限（3 次）仍有缺口 → 全部显式化，不追问。
- **网关必须带超时**（2026-09-24 定）：`PMSTUDIO_MODEL_TIMEOUT`（默认 120 秒）。
  真跑实测过 provider 卡住十几分钟不返回——没有超时，这一轮就永远停在"正在跑"。
  超时按瞬时失败重试（最多 3 次），仍失败走下面的降级或失败。
- **可以放弃这一轮**（2026-09-24 定）：`POST /rounds/{id}/abandon` → 取消正在跑的
  `asyncio.Task` → `Step.ABANDONED`。为什么安全：模型调用一律在事务外，
  `CancelledError` 只可能落在 `await` 点，不会落在 `with uow:` 中间（不会有写了一半的文档）。
  `abandon` 不走 `RoundRunner.run()`，所以不受"一轮同时只许一个动作"的限制——
  被拦住的正是"重试"，而放弃是另一个出口。

  **落地口径（2026-09-28 实现，P5c）**：**先写 `abandoned`、再取消**——写状态只有
  `AbandonRound` 一处，取消本身不写任何业务状态；取消异常**不吞**（交回调用者），
  前端用 `abandoning` 标志位吞掉那条注定失败的在途请求的报错。
  没有在跑的任务也要能放弃（进程崩过、或停在等人时，那一轮不该永远占着）。
- 运行中断（关掉页面）→ 保留 `step` 与 `waiting_on`，回来继续，已冻结的卡片不重问。
- 校验不通过 → 打回整合者重装（一次）；**仍不过就走降级出口**（2026-09-24 改，见
  `04-未决.md` C9）：把本轮席位交回的**疑问原样**落成 s11 开放问题，出草案卡，
  失败原因与未归并条数写进缺口行。一条疑问都没有时才判整轮失败。
  为什么不再让用户点"继续/重试"硬顶：失败点在 `seats_running`，重试只是拿同一句
  提示词再撞一堵墙（真跑时点了 3 次，6 次模型调用，原地不动）。
- **claims 也重装一次**（2026-09-28 加，P5d）：主张报文不合格（`PacketParseError`）时，
  带上"上一次错在哪"（`repair_note`）再调一次；两次都过不了才判这一轮失败
  （理由"主张两次都过不了校验：…"）。口径与整合者对称，上限见下面这张表。
  **网关类失败不重装**——网关自己已经是 3 次尝试 + 退避，报文重装解决不了超时与 5xx。

- **席位也重装一次**（2026-09-28 加，P6）：单个席位的报文不合格（`PacketParseError`）时，
  只重跑**那个席位**（带上"上一次错在哪"），其余席位不动；两次都过不了才让整轮失败。
- **条数超限不再判死**（2026-09-28 加，P6）：容器（单席位意见 / 提案 / 未采用意见申报）
  超上限时先重装一次让它自己精简，仍超限就**截断保留**，溢出的每一条记留痕、
  草案卡上加一行缺口。详见 §11.0.7。
- **引用编号归一化**（2026-09-28 加，P6）：`E08` / `e8` / 全角 `Ｅ８` 都归到 `E8`；
  **归一化后仍不在账本里的编号照样判死**（GB1 不动）。详见 §11.0.7。
- **目录外的席位提名丢人不丢轮**（2026-09-28 加，P6）：提名里混进目录里没有的席位 →
  丢掉那一条 + 留痕，其余照跑；只有"一条都不剩"才判死（R7 要求一轮至少一个席位）。
- **顶层数组按元素签名重建**（2026-09-28 加，P7）：模型把整包漏掉外层对象、直接回一个数组时，
  只要每个元素能用签名唯一归到一类内容（题/清单/提案/申报），就机械补壳；补不了照旧判死。
  详见 §11.0.8。
- **整合的解析错也重装**（2026-09-28 加，P7）：以前 `except ApplicationError` 把
  `PacketParseError` 和网关失败一起判死，导致纠错指引对整合从来没生效过；现在只有
  `ModelCallFailed` 立刻失败，形状/结构/内容错都走重装那一圈。

**一轮的调用上限（一处写清，别再散着算）**

| 步骤 | 上限 | 两次都失败怎么办 |
|---|---|---|
| 主张 claims | 重装 1 次（共 2 次） | `fail_round`（claims 是地基，硬编比失败更糟） |
| 主张 claims · 容器里的**非对象元素** | 重装 1 次（共 2 次） | 丢掉那一条 + 留痕（`主张 #2（不是对象）`），整轮继续；互斥对子的序号按原位置重映射（§11.0.35） |
| 席位轮 | 3 轮 | 剩余缺口全部显式化，不追问 |
| 席位轮 · 单席位报文不合格 | 该席位重装 1 次（共 2 次） | 超限 → 截断保留 + 留痕，整轮继续；别的错 → 整轮失败 |
| 席位轮 · 容器里的**非对象元素** | 该席位重装 1 次（共 2 次） | 丢掉那一条 + 留痕（`seat.x:opinions[2]`），整轮继续（§11.0.35） |
| 整合 | 重装 1 次（共 2 次） | 有席位疑问 → 降级成 s11 开放问题；否则 `fail_round` |
| 整合 · 报文形状/结构错（含顶层数组） | 重装 1 次（共 2 次） | 与内容错同一个出口（降级或 `fail_round`） |
| 整合 · 容器超限 | 重装 1 次（共 2 次） | 截断保留 + 留痕 + 草案卡缺口行，整轮继续 |
| 整合 · 容器里的**非对象元素** | 重装 1 次（共 2 次） | 丢掉那一条 + 留痕（`提案 #2（不是对象）`）+ 草案卡缺口行，整轮继续（§11.0.35 末） |
| 整合 · **归因补交代** | **1 次（另算一本账）** | 仍有没交代的 → 接受 + 写进 `Round.dropped`（`unaccounted`），不再追问（§11.0.37） |
| 问卷 | 2 批 | 剩余题目按 C6 显式化（落 s11）；**轮内队列里的题也一并落 s11**，一条不丢 |
| 单次网关调用 | 3 次尝试（+1s / +3s 退避） | `ModelCallFailed`（整轮失败可重试） |
| 讨论 · 说一轮（say） | 1 次业务调用 + 重装 1 次（**另算第四本账**） | 两次不过 → 502，**线程原样不动**（不许出现"只有用户那半句"的裸奔轮次） |
| 讨论 · 总结成卡（cards） | 1 次业务调用 + 重装 1 次（**另算第四本账**） | 同上；线程累计满 6 张 → T4 拒 |
| 模拟 · 跑一趟 | 1 次业务调用 + 重装 1 次（**另算第五本账**） | 两次不过 → 502，**轮次不动**；筛完没剩 → 502，轮次不动 |
| 留样（`PMSTUDIO_TRACE_MODEL=1`） | 每次**尝试**一行（含失败那几次），带 `attempt`/`ok`/`error`；提示词超 20000 字符头尾各半 | 见 §11.0.15 |

最坏 ≈ **66 次**模型调用（claims 2 + 席位 3×10×2 + 整合 2 + 记忆整理 2；席位那 60 是
"每席位都重装一次、且开满 3 轮"的理论极值，实际一轮 2–6 个席位、重装极少触发）。
**归因补交代的 2 次另算一本账**（上表末行那个"1 次（另算一本账）"），并进来是 68。
**探索（调研）另算第三本账**（M8）：一趟调研 = 1 次业务调用（`inquiry`），报文不合格重装 1 次
（共 2 次）；网关失败落 `failed` 可重跑，**不占轮次的 66**。产物上限：假设 6 条 / 盲区 3 条
（超限由解析层截断，截断条数记进探索 payload，界面照实说）；过一次目台最多回 20 趟探索。
同项目同时只允许一趟探索在跑（与轮次锁相互独立——问卷卡住时可以把题拿去调研）。
**讨论另算第四本账**（M9）：`say` 一说 = 1 次（`discussion`，重装 1 次）；`cards` 一次总结 =
1 次（`discussion_cards`，重装 1 次）；**既不占轮次的 66，也不占调研那本**。
上限：一趟线程 **12 轮**（= 6 个来回，说满 T4 拒并给话）、一次总结 1–3 张卡、线程累计 **6 张**、
列表回 20 趟；**同项目可以并存多趟线程**——"同时只允许一趟"那把锁只在调研那边（讨论的说与收
都是单调用，请求内跑完，与过目台的收下同类）。
**模拟调研另算第五本账**（M10）：跑一趟 = 1 次业务调用（`sim_inquiry`），报文不合格
重装 1 次（共 2 次）；**既不占轮次的 66，也不占调研/讨论那几本**。产物上限：切片 3 /
假设 6 / 盲区 3；每轮最多跑 **2 趟**（R8，到顶 409，请先收下或换一轮）。
**这个数由 `tests/contracts/test_limits.py` 从代码常量算出来并与本行对照**——
原来这里是手写的 `46`，两处错：漏了记忆整理者（`IntegrateRound` 每轮调 `_curate`，
最多 2 次），且用的席位数 **7 没有出处**——席位目录里实际有 10 个
（`infrastructure/seats/definitions/*.toml`），代码里**也没有席位数上限**
（席位来自目录，用户在开场卡上勾）。2026-10-04 M6a 修正。
- 模型不可用 → `generation.failed`，界面显示哪一步失败、人话原因、能否重试。
- 失败点只记第一次（`Round.fail` 幂等）：并发的第二次失败不许把"从哪一步重跑"覆盖掉；
  同一个 round 同时只允许一个动作（`RoundBusy` → 409），双击重试不再能锁死一轮。

### 7.1 答案轮缩编（C8，2026-09-24 定）

现在每答一批就把整批席位全量重跑。缩编要"谁管这个面"的映射——补进席位 TOML：

```toml
sections = ["s5", "s8", "s10"]      # 这个席位负责哪几章
fields   = ["acceptance", "rules"]  # 以及哪些功能字段
```

**下一 pass 的名单** = ① 上一轮对该 `target` 出过意见的席位 ∪ ② 映射命中该 `target` 的席位。
常驻席位**不再**强制入选（否则缩不掉）。名单落进 `Round.active_seats`；
`round_.seats`（用户编制）不动，所以复述卡与 R7 都不受影响。
兜底：缩编后整合者若认为信息不够，仍可出题（`from_opinions` 为空是合法的），
界面把 `asked_by` 为空的题标成"整合者提的"。

**落地口径（2026-09-28 实现，P5c）**：

- 命中只有两条路：① 这道题是**哪些席位提的**（`question.asked_by`，装配层算的）∪
  ② 席位 TOML 的 `sections` / `fields` 命中这道题的 target。
  席位意见本身**没有 target**，所以"上一趟提过这个面"只能从题上来。
- 结果永远在**用户编制**之内（`Round.seats` 不动，R7 与复述卡不受影响）；
  名单落 `Round.active_seats`（开场卡确认时 = 编制），`pending_seats` 基于它算。
- **命中为空 → 全跑**（宁多勿缺：多跑一个席位是钱，漏一个面是缺陷）；
  没答也没跳过的题不算。

## 8. 四条不变式落在哪

| 不变式 | 靠什么保证 |
|--------|-----------|
| AI 不写文档 | 编排层拿不到写入能力，写入只由确认端点触发 |
| 统一入口 | 答案与首轮输入走同一处理路径（都要回到席位轮重新判断） |
| 先有编号再有内容 | Validator 校验每条内容都有 `refs` |
| 可追溯 | Validator 回溯 `refs → derived_from`，必须落到用户输入或答案 |

## 10. 就绪度与交付的数据流（2026-09-24 定）

```
Document（聚合，唯一真相源）
  └→ view(): DocumentView           ← 已有投影，够用：sections→blocks→entries/field/feature_slug
       │
       ├─→ ReadinessChecker.check(view)                ← 纯代码，无 IO，无模型
       │        └→ tuple[ReadinessItem]
       │             ├→ context.render_readiness() → 追加到三个提示词的 $document_state
       │             ├→ dto.ReadinessItemView → WorkspaceView.readiness → 界面
       │             └→ 导出：头部盖章 + 空章标记
       │
       └─→ deliverable.render_markdown(view, refs, readiness, versions)
                ├─ 正文：13 章 + 功能子树（偏好区不进正文）；功能名也挂自己的编号
                ├─ s13：由 Version[] 生成（不读 block 树）
                ├─ 附录 A：**只列本文引用过的**编号 + kind + 一句话摘要
                │         （不带 raw_span，遵守 04 D5）
                │         准入判据 = `cited_evidence_ids(view, skip_sections={s11})`：
                │         **只被未决清单引用**的不进附录（M7 B，2026-10-04），
                │         正文里的 s11 条目照旧挂编号（系统里可查）
                │         两类"没进附录"的分别用一行说明条数（P31 + M7）
                └─ 附录 B：偏好区（标注"不进交付物"）

GET /projects/{id}/export/markdown  ← 纯读，一次渲染，无事务
```

**附录 A 为什么不是账本全量（2026-10-02，P31）**：账本是项目级、跨轮、只增的（E1/E2），
它装的不只是"进了文档的东西"——未被采纳的提案、被跳过的题、更早的轮次都在里面。
正文里没有的编号，读者既找不到落点、又分不清哪些才是这句正文的出处；
真跑 59 份导出实测附录 A 占全文 51%（中位），其中 63% 从未被引用。
**账本本身一个字不动**（不裁剪、不归档）——过滤只发生在渲染这一层，
`cited_evidence_ids(view)` 与 `dto.used_by_entries()`（界面"这个编号被谁引用着"）
**共用同一条条目遍历**，免得两处判据漂移。

三条实现约束（都要有测试钉住）：

1. **确定性**：同一份 `DocumentView` + 同一份账本 → 同一份字节。渲染函数里没有时间戳以外的
   随机源；时间戳来自调用方传入的 `now`（可注入，测试才能断言）。
2. **只读**：导出路径不持有 `DocumentWriter`（守卫白名单里永远只有 `ProposalCommitter`）。
3. **可判据**：导出里出现的"未完成项"必须逐条来自 `ReadinessItem`，不允许导出层自己再判一套。

### 11.0 韧性三件（2026-09-28 落地，P5c）

### 11.0.2 去处写错：只丢那一条（2026-09-28 作者拍板）

整合报文里某条的 `target` 不合法时：**丢这一条 → 写进 `Round.dropped`
（`handle="提案 #3"` 这种、`source=assembly`、`reason=错误原文`）→ 继续处理同一批里的其它条目**。
理由：真模型实测，一次笔误让两次整合都过不了校验、整轮降级、所有席位疑问掉进 s11；
而"不知道放哪儿"跟"编号写错（内容没有出处、追溯链断了）"不是一回事——
**后者仍然整轮失败**（GB1 不松口）。

**2026-10-01 补（P25）："要改的条目不存在"同此。** `replace` / `remove` 指到一个不存在的
`entry_id` 时，也**丢那一条 + 留痕**（`handle="提案 #3"`、`reason="要改的条目不存在：…"`）。
现场：P24 真跑里模型两次都写了不存在的条目 id → 整包两次过不了校验 → 整轮降级，
**12 条判断全成"没交代"**（`.codex/runs/2026-10-01/P24验证.md` §三）。理由与上面那条一字不差：
一条笔误不该让整批白干。规则只有一份实现（`assembly._entry_target_missing`）。
**不放松的两处**：`replace`/`remove` **没给** `entry_id`（字段缺失，`entry_id` 在
`_WRITE_SEMANTICS_FIELDS` 黑名单里）照旧判死；引用不存在的**出处编号**照旧判死（GB1）。

**配套的一条守卫（同批）**：装配完"题 / 提案 / 清单项"**什么都不剩**时，判成 `PacketParseError`
（走既有的"重装 → 仍不行就降级"出口），**不再一路走到 `draft_of(...) is None` → `ShapeError`
→ HTTP 409**。判据用**装配后**的产物，不用报文——被丢掉的（去处写错 / 条目不存在 / 与文档重复）
都算在内，那才是用户真能拿到的东西。顺带把"整包是空对象"这个老洞一起堵上。

### 11.0.2a 空文本提案：`remove` 补正文、`add`/`replace` 丢一条（2026-10-01，P26）

**现场（先看清再下手）**：跨 5 个真跑库统计空文本提案——**22 处全部是 `op=remove`**
（`add`/`replace` 一处没有），都是"要撤下 s11 的某条未决条目、但没写文本"。
而"所有提案文本非空"这条**从没写进提示词**（L22）。旧行为：整包两次不过 → 整轮降级
（P25 那 4 条 `unaccounted` 就是它）。

**三条口径**：

1. **`remove` 的空文本照收，并补上"被撤下那条的正文"**（从文档里引用，不是编内容）。
   为什么不是"丢掉那一条"：丢掉一条 `remove` 等于**那条该撤下的内容留在文档里**——
   是功能损失。补正文之后卡片上是「删除｜<那句话>」而不是一行空白，
   而且 `Proposal` / `WriteInstruction` 的"文本非空"**不变量一个都没松**。
2. **`add` / `replace` 的空文本 → 丢这一条 + 留痕**（与去处写错同口径）：没有内容可写。
3. **去重只对 `add` 生效**（同族老 bug 一并修）：`replace`/`remove` 是在改既有内容，
   拿它们的文本去跟文档比"是不是已经有了"没有意义——踩到过的坏后果是"模型写一条 `remove`、
   文本正好照抄了被删那条 → 被当成重复静默跳过 → 该撤下的内容留下"。

**提示词同步说**：`ProposalDraft.text` 的字段描述与 `$limits` 都写明"`remove` 的 text 可以留空"。

**真跑（P26，同车道两轮）**：`unaccounted` **34 → 18 → 12 → 4 → 0**、整轮降级 **1 → 0**；
零成本回放（`bin/replay_p26.py`）把 P25 那两次真降级的报文重跑，两条 `remove` 都保住并补上了正文。

**补段（2026-10-03，P32 · M1）：同一条目被撤两次 = 一条指令，只算一条。**

**现场**：P30 审计的 L4 第 3 轮，草案里**两族** `remove` 指向同一批 s11 条目——
整合者那条路（`p14`–`p21`，文本是被撤下条目的正文）与"被回答过的未决项要撤下"那条机械路
（`use_cases.py::_retire_answered_open_items()`，`p34`–`p39`）。两条都对，但说的是同一件事；
用户两条都勾了，确认写入时第一条把条目摘掉、第二条撞 `UnknownEntry` →
**`POST /confirm` 422、整批一条都没写**（`04` G10 · F28）。真数据回放：那份草案 50 条里
**6 个条目各被撤了两次**。

**口径**：**同一 `entry_id` 的多条 `remove` 是同一条指令**——留第一条，其余合并。

- `remove` 撤下哪一条**只由 `entry_id` 决定**，文本只是卡片展示、不入库，所以合并无副作用；
- **只合并 `remove`**：`replace` 两条是顺序语义（后一条覆盖前一条），`add` 每条都是新编号；
- 落点在两处，**规则只有一份**（`domain/round/draft.py::merge_duplicate_removes`）：
  装配层 `draft_of()`（新的卡片上不再出现两行一样的"删除"）+ 写入端 `ProposalCommitter._resolve()`
  （**修好之前存下来的老草案**照样能确认写入）；
- **合并掉的不进任何留痕通道**（它不是内容，是同一件事的第二次陈述，条目照样被撤下）；
  可断言的地方在 `CommitResult.merged_removes`。
  **连带**：`proposed_accepted` 必须按**用户接受的 id** 算，不然被合并的那条会漏计（C4 的输入）。

### 11.0.3 来源分组按**账本**算，不采信模型自报（2026-09-28 作者拍板）

整合报文里的 `origin_type` 只是**建议**：模型写 `user` / `derived` 的，装配层会用
`TraceabilityChecker` 顺着 `refs → derived_from` 检查一遍——**回溯不到 `user_input` 或
`card_answer` 的，一律降级成 `proposed`（"它提议的"，默认不勾）**。模型写 `proposed` 的原样保留。

为什么：真模型实测，席位给的"没有依据的判断"会被整合者标成 `derived` 进"它替你判断的"那组，
用户勾选后提交时才撞 `invariant:E4 回溯不到用户输入或问卷答案`——卡片上没有任何提示，
用户以为系统坏了。`02` §4.1 本来就写着"到不了的只能作为 proposed 出现且默认不勾选"，
这条只是把那句话实现出来。**提交端的不变式不动**（GB1 仍是最后一道闸）。

### 11.0.4 复述对齐：认省略号、不许拿说明当原话（2026-09-28 作者拍板）

`raw_span` 只有一个用途——点编号跳回原文，所以判据只该问一件事：这段是不是原文里
**真实存在**的一段。真模型实测（完整 eval 的 `case-a`，3 次里 2 次产出逐字相同的那条）：
`'想做个订单导出的功能...最好能按时间筛选'`——两段原话都在输入里，**省略号 3 个字却计进
分母**，最长匹配 10 字撞上 10.5 字门槛，**差 0.5 字把整轮判死**（502，用户只能手动重试）。
同一句话把省略号写成 `…`（1 个字）就能过：能不能过取决于模型的标点习惯，这不是判据该管的事。

**落地口径**（`analyzer.grounded_span`）：

| 情形 | 判法 | 返回 |
|---|---|---|
| 整串逐字命中（原文里真的写了 `...`） | 不切段 | 原样返回 |
| 明写拼接标记（`...` / `…` / `。。。`） | 切段，**每段各自走同一条判据、全段都要站得住**；空段（`A...`）忽略 | 最长的真实片段（并列取靠前） |
| 没写标记（逗号拼出来的那种） | 整串最长连续匹配（`≥ max(6 字, 0.5×候选长度)`）——**与改动前一字不变** | 最长连续匹配 |
| 有任何一段站不住 | 整条不认 → `PacketParseError`（整轮失败，可重试） | — |

为什么"写了标记就按段判"：模型写了 `...` 就等于**自己把切分点交出来了**，这时按段判是它
应得的对待——顺带把"一半真一半编"堵死（`A...B` 里 A 真 B 编的，改前会因为整串恰好过 50%
而被放行，实测就是这样）。没写标记才只能整串估，所以那条路一字不改。
**反编造一点没松**：`（隐含于上下文，仅提及订单导出）` 这种"说明当原话"在 `edge-long`
上真的又出现过，它连一段都站不住，照样判死。

**提示词同步说**（口径的入口不止一个，改一处要说三处）：

- `analyzer.md` 硬规矩 2：必须**连续**、不许用省略号拼两段、**原话里找不到落点就不要切这条主张**；
- `ClaimDraft.raw_span` 的字段描述同口径（这个 schema 会被内联进提示词，写在字段旁最不容易漂）；
- 席位 id 要**连 `seat.` 前缀一起照抄**（真模型写过裸名 `tech_approach` / `data_scale`，整轮被判死）；
- 整合者硬规矩补"**同一个去处一批里只出一题**"——eval 那条 `no_duplicate_questions`
  以前是**只考不教**，真模型在 `edge-one-constraint` 上就 s7 出了两道题。

**口径**：**断言考的东西，提示词必须先说**；考一件没交代过的事，等于在惩罚模型的猜测。

### 11.0.5 报文不合格：重装一圈（2026-09-28 作者拍板，P5d）

**问题**：claims 一次不过就 `fail_round`，而真模型是**抖的**——同一份输入换个采样就过
（完整 eval 三轮里 claims 崩过 4 次：3 次是提示词/守卫的问题，剩下的纯抖动）。
让用户手动点"重试"来兜模型的抖动，是把成本推给人。

**口径**（与整合者对称）：

| 触发 | 喂什么 | 上限 | 两次都失败 |
|---|---|---|---|
| claims 的 `PacketParseError` | `repair_note()`：第几条 / 哪个字段 / 要求是什么 | 2 次 | `fail_round`（理由"主张两次都过不了校验：…"） |
| 整合的 `PacketParseError` / `DomainError`（原有） | 上一次的 `message` | 2 次 | 有席位疑问 → s11 开放问题；否则 `fail_round` |
| 网关传输异常（原有） | 退避后重发同一请求 | 3 次 | `ModelCallFailed`（**claims 不再重装它**） |

**两条自己的规矩**：

1. 重装**必须**带纠错指引——拿同一句提示词再撞一堵墙是 L13 定性过的失败模式；
2. 指引**不复制模型写出的内容片段**（`raw_span` / 正文 / 选项措辞），只说位置与要求——
   把写错的那串喂回去，等于给它一个可以照抄的模板（`（隐含于上下文…）` 被填进
   `raw_span` 过两次，见 §11.0.4）。

**不新增产品字段**：重装次数不进 `Round`、不进界面（第二份真相源）。要查就查留样表：

```sql
SELECT purpose, count(*) FROM model_calls WHERE round_id = 'r-…' GROUP BY purpose;
```

claims 一步一轮只该调一次，出现 **2 条就是重装过一次**——诊断是我的活，不是产品功能
（§11.0.1 同一口径）。

### 11.0.6 两条 eval 断言的判据修正（2026-09-28 作者拍板）

**① 重复题：判据是"同一个去处 + 同一个问法"，不是"同一个去处"**

原判据只看 `target_label`，于是"同一章节上的两件不同的事"被判成重复。真模型实测
（第四轮 eval 的 `case-a`）：`s8.availability` 上出了两道题——
"订单导出幂等性与重试策略确认" 与 "订单导出对端不可用时的降级策略确认"。
它们是**两道真问题**，各自带 `options` 与 `consequence_if_skipped`：

- 合并成一道会丢结构（跳过后果只剩一份）；
- 丢掉任何一道都是把用户该填的题吞了——**这不是留痕能替代的东西**。

新判据：`(target_label, 归一化标题)` 相同的才算重复（标点与空白不参与比对）。
同一去处的两件不同事照问。整合者提示词同步改成"同一件事不要问两遍；同一去处的两件不同事
各出一题"（早先写反过一版"同一个去处只出一题"，已撤）。

**② `no_unauthorized_features` → `outside_scope_items_are_labeled`**

旧断言把 `advisories` 一律当失败，而 `advisories` 只有一种来源：`ScopeGuard` 的
**"这条落在 X，不在本轮去处里"**——那正是 §3①（2026-09-22 定）明确要求**放行并标注**的行为
（"静默拒绝会让席位的专业判断整批白干"）。旧断言的注释还写错了前提：`ScopeGuard`
**不标**"未授权的新功能"；那条走的是 `assemble` 的 `pending_features` →
`new_feature_yes` 决策题（用户点头才授权）。

新断言只盯**标注这条路没断**：① 草案卡上带标注的提案数 == 顶部提示数（两处不许漂移）；
② 标注是人话（写清"不在本轮去处里"）。
**硬约束仍在**：不得新增未授权功能子树，由装配层的决策题 + 领域层授权集合守着，
单测 `tests/application/test_assembly.py::test_assemble_creates_feature_subtree_only_when_authorized`。

这条断言**管不了"跑出去的条目该不该有"**——那是设计允许的；别把它的绿灯读成"模型很守规矩"。

### 11.0.7 超限不判死、编号归一化、席位丢人不丢轮（2026-09-28 作者拍板，P6）

**来历**：四项目真跑（15 轮、250 次模型调用）里，**每一次整轮判死都不是因为内容错，而是因为形状**——
报告 F2/F3/F4/F11/F13：

| 触发 | 真跑次数 | 改前代价 |
|---|---|---|
| 提案 44 条 > 上限 30（3 棵功能树 × 12 字段 = 36 就已经越界） | 1 | 整轮 502，**44 条内容一条没落地** |
| 单席位意见 10 条 > 上限 8（提示词却写着"最多 5 条判断"） | 1 | 整轮 502，4 个席位重跑 |
| 未采用意见申报 35 条 > 上限 30（提示词要求"一条都不许默默丢掉"） | 1 | 整轮 502，重试给出 33 条又挂 |
| 出处编号写成 `E07`/`E08`、`r-… #08` | 5 | 每次整轮 502 + 4–6 个席位重跑 |
| 提名目录里没有的 `seat.observability` | 1（连错两次） | **轮次都创建不了** |

**口径（三条，各自独立）**

1. **上限按"装得下一棵完整功能树"重定**，并**与提示词口径对齐**：

| 容器 | 旧 | 新 | 算术 |
|---|---|---|---|
| 单席位意见 `opinions` | 8 | **12** | 提示词允许 5 条判断；再给疑问留 7 条 |
| 提案 `proposals` | 30 | **60** | 一棵功能树 12 字段 × 4 棵 = 48，再留章节级内容 |
| 未采用意见申报 `dropped_opinions` | 30 | **84** | 7 个席位 × 12 条——"一条都不许丢"必须**数学上成立** |

2. **超限先重装、再截断，不判死整轮**：
   - 解析期：宽松档（`schemas.parse_packet_lenient()`，生产上**唯一**的一档）
     只在"**所有**报错都是 `too_long`"时截断；出现任何别的错照旧抛
     （"错就是错"不许被截断掩盖）；
   - 用例期：第一趟发现超限 → 带定向纠错（`repair_note` 的 `overflow` 分支，
     说清"你给了 44 条，上限 60，按什么优先级精简"）再调一次；第二趟仍超限 → 截断保留；
   - **截断保留模型给出的前 N 条**（顺序即它自己的优先级，我们不替它重排）；
   - 溢出的部分：每条记一条 `Round.dropped` 留痕，草案卡上加一行
     "本轮有 N 条内容因单轮上限未进卡片（可在下一轮继续提）"——**绝不静默丢**。

3. **引用的写法归一化，但幻觉照旧判死**：
   - `normalize_ref()` 认 `E08`/`e8`/全角 `Ｅ８`/带空格 → 规范成 `E8`；**只有落回账本才算数**；
   - `E999`、`r-… #08`（提案编号）、`seat.x:O1`（席位地址）照旧判死；
     但错误信息要指明命名空间（"这是提案编号，不是出处编号"），并给数字相邻的候选编号；
   - 为什么不一并放松：编号不认识意味着"这条内容没有出处"，追溯链断了（GB1），不能进文档。

4. **目录外的席位提名：丢人不丢轮**：
   - 提名里混进目录外 id → 丢掉那一条 + 留痕（"席位提名 seat.observability：目录里没有这个席位"），
     其余席位照跑；
   - 只有"**一条都不剩**"才判死——R7（一轮至少一个席位）不许破；
   - 来时：模型照着 s8 的**章节槽**名字（`observability`）挑席位，而席位目录是另一套命名空间。

**不新增产品字段**：溢出与截断只进既有的 `Round.dropped` 与 `Draft.gaps`；
重装次数不进 `Round`、不进界面——要查就查留样表（`model_calls` 按 `round_id` 数条数），
与 §11.0.5 同一口径。

### 11.0.8 整包回成数组：形状重建 + 整合重装（2026-09-28 作者拍板，P7）

**来历（留样为证）**：P6 验证里两次真实失败长一个样——**整包是一个数组**：

| 来源 | 轮次 | 报文 |
|---|---|---|
| 端到端真跑 | `r-12353e02` 留样 15 | 顶层数组、5 个元素，每个都是 `QuestionDraft`（`title`/`why`/`consequence_if_skipped`/`target`） |
| 完整 eval | `r-8d65170f` 留样 66 | 同一形状，4 个元素 |

**同时暴露的第二个缺陷**：`IntegrateRound._integrate_with_repair` 的
`except ApplicationError` 把 `PacketParseError` 和网关失败一起判死了——
留样 15 的插入时间与那次 502 是**同一秒**，留样 16 出现在 55 秒之后（我手动点重试才有的）。
也就是说：`repair_note` 给整合写了纠错指引，**却从来没有第二次机会用它**。
claims（P5d）与席位（P6）都早有重装，整合是唯一漏的那个。

**口径（两条）**

1. **形状重建：只补壳，不猜内容**

   | 报文 | 顶层数组能不能重建 | 原因 |
   |---|---|---|
   | `IntegrationPacket` | **能** | 四个容器都有默认值；补一层壳不需要造任何字段 |
   | `SeatPacket` | 不能 | `basis` 必填，数组里没有——补空串等于替模型填字段 |
   | `ClaimsPacket` | 不能 | `basis` 必填 + `seats` 至少一个，补不了 |

   签名表（**顺序即判据**，命中即停）：

   | 顺序 | 元素里有 | 归到 | 为什么唯一 |
   |---|---|---|---|
   | 1 | `handle` | `dropped_opinions` | 只有它要 `handle` |
   | 2 | `title` 或 `consequence_if_skipped` | `questions` | 只有它有题面/跳过后果 |
   | 3 | `text` + `target` + `reason` | `list_items` | 只有它同时有 `text` 与 `reason` |
   | 4 | `evidence_refs` 或 `op` | `proposals` | 只剩它（题目已在顺序 2 拦下） |
   | 5 | 都不命中 | **判死** | 无法唯一归位 → 不猜 |

   顺序 2 必须在顺序 4 之前：题目也可能带 `evidence_refs`。
   重建之后**照旧受上限约束**（数组里的 70 条提案一样会截断 + 留痕）。
   **空数组不重建**（L2：空返回不等于没意见），照旧判死、由重装兜。

2. **重装：整合的解析错也算可修复**

   `ModelCallFailed`（网关类）立刻失败；`PacketParseError` / `DomainError` 走重装一圈，
   第二次仍失败才进既有出口（有席位疑问 → 降级成 s11 草案；否则 `fail_round`）。
   重装带的东西分两种：解析错用 `repair_note`（形状 / 超限 / 字段路径都有结构化细节），
   领域错用领域自己的话术（如"选择题至少两个选项"，比通用话更具体）。

**不留产品字段**：重建只发生在解析期，产物仍是既有的 packet；
"模型回错过"这件事在留样里看得见（同一轮 integration 两次调用 = 重装；一次调用但报文是数组 = 走了重建），
所以不为它单开留痕通道（那会让"留痕 = 没进卡片"的语义变浑）。

**验收**：`tests/application/test_packet_overflow.py`（签名互斥 / 重建 / 归不了位判死 /
claims 不猜 / 重建后仍截断 / 空数组不重建）、`test_dropped_trace.py`（第一次数组→重装→过；
两次数组→走既有降级出口）、`test_repair.py`（形状指引话术）。

### 11.0.9 字段级容错与"功能候选为空"的提醒（2026-09-28 作者拍板，P8）

**来历**：P7 验证时席位把 `evidence_refs` 写成 `null`（留样 7）→ 报 `list_type` → 只能靠
"该席位重装一次"兜；而整合者提示词里**没有**"本轮哪些功能已授权"，模型于是整轮不产功能候选，
s5 整章空着（报告 F1）。

**口径一：字段级归一化（解析期，三档）**

| 档 | 规则 | 例 | 为什么安全 |
|---|---|---|---|
| L1 | **列表字段**收到 `null` → `[]` | `evidence_refs: null` → `[]` | 空列表在本仓库有明确定义：席位意见没依据 → 走既有降级（标"模型没给依据"、按"它提议的"处理）；提案没依据 → schema `min_length=1` 照旧失败（GB1 不破） |
| L2 | `list[str]` 收到**字符串** → 单元素列表 | `evidence_refs: "E4"` → `["E4"]` | 一个编号写成一个字符串，意图唯一；`"E4, E9"` 不拆，交给"编号不存在"那条报错 |
| L3 | **非 Optional、有默认值**的字段收到 `null` → 用默认值 | `type: null` → `single` | "没给值"用 schema 的默认值，不猜内容；命中的是 `type` / `zone` / `origin_type` 这类**分类提示**。**`kind` 从 2026-09-29 起退出 L3**——它改成必填（§11.0.17），默认值会把"忘了写"和"判断成 gap"混成一种 |
| — | **黑名单**：`op` / `entry_id` / `form` 不适用 L3 | `op: null` → 照旧判死 | 前两个决定写/改/删哪一条；`form` 决定这条意见**进不进账本、有没有编号**——用默认值会悄悄改语义 |

**不救内容字段**（`text` / `title` / `why` / `claim` / `about` / `because` / `consequence_if_skipped`）：
内容没有"形状"可推断，编出来就是编内容。

规则由 **schema 注解**驱动（`list[str]` / `list[BaseModel]` / 嵌套 `BaseModel` 递归），不写字段名字表——
以后加字段自动覆盖，不会出现"某张表忘了加"。归一化在 `_normalize_payload`（P7 的顶层数组重建）**之后**执行，
两道可以叠加（顶层是数组 + 字段是 `null` 也救得回来）。

**口径二：字段级纠错话术**（`repair_note` 的 `errors` 分支）

不再只给字段路径（`opinions.2.evidence_refs`）——那是"错在哪"，模型要的是"该是什么"：

| pydantic 错误类型 | 话术 |
|---|---|
| `list_type` | 这里要是数组；没有内容就写 `[]`（不要写 `null`） |
| `string_type` / `dict_type` / `int_type` / `bool_type` | 这里要是字符串 / 对象 / 整数 / true·false |
| `missing` | 是必填字段，必须给 |
| `literal_error` | 取值只能从枚举里挑（附 `expected` 里的允许值） |

**口径三："这一轮已授权的功能"进提示词**（`$authorized_features`）

`round_.authorized_feature_basis`（主张点名 → 已授权，出处编号是点名它的那条主张）+ 文档里已有的功能，
渲染成清单交给整合者，并配两条硬规矩：
① 这些功能**已授权**，内容必须落到 `{section_id: s5, feature_slug: …, field: …}`，拿不准也别降级成章节级；
② 一条功能内容都没有时，先把点到的每个功能写成 `name` / `one_liner` / `goal` / `audience` /
`exceptions` / `acceptance` 里的至少一条，别让 s5 空着。

真跑验证（P8）：同一份"叙述式输入"（`试点/input-01.md`）**从 0 条 s5 提案变成 12 条**
（两个功能 × 六个字段），F1 的"功能章整章空"被解掉。

**口径四：零功能候选 → 草案卡置顶告警**（`dto.feature_coverage_advisory`）

**纯投影**：读 `round_.claims` 与 `round_.draft`，不写任何东西、不进文档——只出现在这一轮的卡片上
（前端 `DraftDrawer` 按顺序渲染 `advisories`，所以插到最前就是"置顶"）。
判据刻意保守：只有"主张点名过功能"且"草案里**一条** s5 功能提案都没有"才报；输入本来没提功能不报。

**已知副作用（2026-09-28 记，待作者定）**：口径三让模型把功能的**全部字段**都写了，而
`write_scope`（本轮去处）是按主张给的**精确字段**算的——于是同一功能的其它字段也被判"不在本轮去处里"，
真跑里一轮出现 **20 条 advisory**（15 条功能字段 + 5 条章节级），把置顶位置刷掉了。
两个候选修法（都没实现，等拍板）：**A** 写范围按**功能级**匹配（同一 `feature_slug` 的其它字段也算在范围内），
**B** advisories 按"章节 / 功能"折叠计数显示。

**证据编号（`E1…En`）没问题**：账本按**项目**单调分配，唯一、不复用、可跨轮引用
（"把所有证据统一编号再给模型"这套机制一直在跑）。错的是**指针**：题号原来按**批次**发
（每批 `q1…q5`），于是"按题号回查"的地方一共有**六处**，第二批发到同一个号就全部指错：

| # | 位置 | 症状 |
|---|---|---|
| 1 | `context.render_answers` | 答案行挂别的批的题面 |
| 2 | `context._answer_eid` / `answer_eids` | 编号只按裸题号找 → **第二轮引到第一轮的答案** |
| 3 | `assembly.open_question_proposals` | 第一批**跳过**的题落 s11 时用第二批的题面与后果 |
| 4 | `use_cases._system_defaults` | 同上（补 system_default 出处的文本错） |
| 5 | `use_cases._retire_answered_open_items` | `remove` 引到别批的答案编号 |
| 6 | `Round.write_scope` | 第一批答案的**去处丢了**、第二批的**混进来**（实测 `['s2','s8']`，应是 `['s2','s5']`） |

**口径（两条）**

1. **题号按轮次单调发**：`Round.asked_question_count`（= 本轮问出去的题数）决定起点，
   第一批 `q1–q5` ⇒ 第二批从 `q6` 起。轮内唯一 ⇒ 答案的身份 = `(轮次 id, 题号)`，
   **不需要给出处表加字段**（`Round.round_id` 本来就在 `card_answer` 上）。
2. **问卷历史追加不覆盖**：`Round.questionnaire_history`（payload 键 `questionnaire_history`）。
   题面、跳过后果、选项文案都要回**出题那一批**去找——当前批仍然是 `questionnaire`（既有读法不动）。

**回退（宁可不显示，也不显示错的）**：老 payload 没有历史键 → 读侧回落到"只有当前这一批"；
老库里已经重排过的同一轮两个 `q1` → **不显示 E 编号**（`_answer_eid` / `answer_eids` 命中两条即放弃），
席位的 `q# → E#` 翻译表也**只收本轮**。

**连带简化**：P9 为绕开重排而引入的 `carried_sources` 键 `form#qid` 保留（无害），
但"键必须带 form_id"的那条理由已经不存在——根因（重排）被拔掉了。

**验收**：`tests/domain/test_round_questionnaire_history.py`、`tests/application/test_context_answered.py`
（两行各挂各的题面/编号、跨轮不串、老库撞号不显示）、`test_write_scope.py` 的批次归属、
`test_assembly.py` 的跳过题题面与编号接续。

### 11.0.12 答案的去向：引用或机械落地（2026-09-29 作者拍板 D3）

跨轮去重的真相源只有**文档**（§11.0.10 定过：不新建第二真相源；`PROJECT.md`/记忆层 v1 不做）。
一条答案要是没落进文档，下一轮**必然**再问一遍（报告 F6 跨轮那一半的根）。

**口径**：出草案那一刻，装配层核查每条答案的出处编号**有没有被这一趟的提案/题目引用**；
没有引用的，机械落一条 `Proposal`：

| 项 | 取值 |
|---|---|
| 去处 | 那道题的 `target` |
| 文本 | `用户已定：<选项文案 或 自由文本>`（**用选项文案**，`new_feature_no` 这种机器 id 不进正文） |
| 出处 | 这条答案自己的 E 编号 |
| 来源 | `origin=user`（用户自己说的话，卡片上默认勾选） |

**三种不落地**（各自在草案卡的 `gaps` 里留一句话，绝不静默）：
① 题的 `target` 是**未授权的新功能 slug**——落下去等于凭空建功能子树，直接撞硬约束
（这一条的用户决策已经被 `authorize_new_feature` / "不新建"两条结构动作消费掉）；
② 题来自 **s11 未决条目**（`carried_sources` 命中）——答完已有机械 `remove`（§11.0.10），再 ADD 会当场对冲；
③ 答案已经被引用（整合者干完了活）。**空答**不落也不留噪声；**去处不合法**（如功能字段表里没有这个名字）
只跳过 + 留一句话——这段跑在事务里，不许打崩整轮。

**验收**：`tests/application/test_answer_landing.py`（7 条）、`test_integrate_answers.py` 的两条
（没引用 ⇒ 落地；引用过 ⇒ 不落地）。

### 11.0.18 未决队列的两端：题序、同去处收口、消化配额（2026-09-29 作者拍板，P12）

**题序**（报告 F12：用户明确提的需求被模型自出的题挤掉配额）：`assemble` 的顺序是
`carried` → **feature 决策题**（结构门：要不要新建子树，它决定整棵树建不建）→

背后的席位意见会变成新的 unaccounted 留痕。

**消化配额**：每批从 s11 挑回的老未决项 2 → **3**（一轮两批 ⇒ 最多 6 条）。**不设"必须清零"的

产生大于消化是算术事实。未决清单是**随交付物一起给用户的东西**（阻塞项同时进就绪度），
不是假装能清零的东西。

### 11.0.20 矛盾的机械通道：analyzer 报对子、装配层盖章（2026-09-29 作者拍板，P12）

**为什么**：`kind` 必填（§11.0.17）只是把"能不能标出来"交给模型；P10 真跑 54 道题
`conflict` **0 道**、`edge-contradiction` 15 题 8 题没写 `kind`。指望模型记得标不成立。

**判断做一次，做在读用户原话的那一步**：

1. **analyzer 报对子**：claims 报文新增 `contradictions: [{claim_a, claim_b, why}]`，默认空数组。
   里面写的是**序号**（第几条主张，从 1 开始）——`c1/c2` 是我们按 claims 数组下标发的，
   提示词里从没出现过，让模型写 id 等于让它猜。序号 → `c{i}` 的映射只有
   `contradictions_from_packet` 一处。判据只有一条：**两侧立场互斥**（"记录不许改" vs
   "点错了要能改"）；"只是还没定"不算（那是缺信息，走 `gap`）。写歪的（序号越界、指向自己、
   领域校验不过）丢**那一条** + 留痕，不判死整轮。
2. **落库**：`Round.contradictions`（payload 键 `contradictions`；老行没有 → 空，不编对子）；
   `attach_contradictions` 在 `attach_claims` 之后调（要核对主张确实在这一轮里）。
3. **整合者看得见**：`$contradictions` 槽位渲染**主张原文**（不是 id），并要求出一道让用户
   拍板的题、`kind` 写 `conflict`。
4. **装配层盖章**：`assemble(..., contradictions=contradiction_pairs(round_))`；题目的
   `evidence_refs` **同时覆盖**某一对的两个 E ⇒ 该题 `kind` 强制为 `conflict`，模型写什么不算
   （只改 `kind`，`blocking` 仍按 `01` §7 的章节规则算）。

**边界**：这条通道只管"**本轮输入内部**的主张互斥"。跨轮冲突（新主张 vs 文档既有结论）
与"席位意见 vs 主张"仍走原来的通道（整合者/席位写 `kind`）。

### 11.0.21 续跑口径：整步重试 + 席位调用级续跑 + 重试带上次报错（2026-09-29 作者拍板，P13）

**核验（对 09-28 报告的修正）**：报告 F2 那句"重试是整轮重来、会重跑 4 个席位"**已经不成立**——
`RunSeatRound` 只跑 `Round.pending_seats`（`domain/round/round.py`），已交回的意见不重跑，
`test_run_seat_round_only_refills_seats_that_have_not_reported` 与 P13 新增的**走真图**用例
（`test_retry_after_a_failed_integration_does_not_re_run_the_seats`）各钉一遍。

**口径一：`retry_hint`——失败原因留到重试的第一次尝试。**
报文类失败（`PacketParseError` / 领域校验错）时 `Round.fail(reason, hint=repair_note)`；
重试后第一次尝试的 `validation_error` 就是它——**不再盲调**（一次整合 20–90 秒）。
**网关类失败（超时 / 5xx）不留**：那种错对模型没有信息量，递进去只是把提示词喂脏。

**口径二：`retry_hint` 一次性。** `take_retry_hint()` 取走即清——不清的话陈年错误会被后面
每个动作当成校验错误递进去，比不递更糟。取用点在动作开头；**没有 hint 就不开事务**
（寻常路径的事务数被既有用例钉着：不许为只读开事务）。

**口径三：两条信息分开放。** `failure.reason` 是**给我们看的**（"整合两次都过不了校验：…"）；
`retry_hint` 是**给模型看的**（"上一次的报文没通过校验：…该怎么改"）。

**口径四：失败点在投影里可见。** `RoundView.failure_at_step` + `retry_from`
（对着 `graph.RESUME_ROUTES` 写：`started` / `claims_ready` / `seats_running` 三句人话，
认不出的 step → `None`，不猜）。

### 11.0.28 材料信息包：工具层的地基（2026-09-30 作者拍板，P17 C-2a）

**底层形态是信息包，不是一段纯文本。** `MaterialPacket = {material_id, project_id, parsed, created_at,
schema_version}`，其中 `ParsedMaterial = {origin, title, source_ref, media_type, bytes_len,
chunks[], parser_id, parser_version, truncated, warnings}`，块 `MaterialChunk = {chunk_id, ordinal,
text, heading_path, anchor}`（锚点是人话："第 3 页" / "第 12–40 行"）。
提示词里那段文字只是**渲染结果**（`context.render_materials`），不是底层事实。

**三个可替换点（换 docling / 换检索实现时只动组装点一行）**：
`MaterialParser`（v1 `LocalMaterialParser`：UTF-8 / pdfminer / bs4+lxml）、
`MaterialRetriever`（v1 用 SQLite `LIKE`；升级位 `fts5(trigram)`，本机 3.51 实测可用）、
`WebSearchGateway`（v1 Tavily REST）。端口在 `application/ports.py`，实现在 `infrastructure/tools/`。

**只给"带进提示词的块"发号（本批最重要的口径）**：`parse → chunks（全量入库，不编号）
→ context.select_chunks（唯一决策点）→ 只给选中的块记 `external` 出处 → Round.materials`。
所以**每一个编号都有消费者**（模型能引、界面能点、导出能列），账本与轮次 payload 不膨胀；
没带进去的块仍然在 `material_chunks` 里（F6 搜得到、材料卡列得到），只是没有编号。

**预算（先说清，别悄悄截断）**：材料合计 4000 字、检索结果合计 2000 字、单条检索截 300 字、
单块目标 500 字；超了在渲染文本里写「（材料较长，只带了 N 块 / 共 M 块）」。
（为什么这么小：integration 提示词已经 ~20k 字符、实测最慢单次 201.2s。）

**存储**：`materials`（**含原始字节 BLOB** —— 换解析器时要能重解析，用户不重传）+
`material_chunks`；同项目按 `(project_id, sha256)` 去重；列表接口**只回摘要**
（50 份 × 400 块不能塞进一个响应）。**原始字节永不进任何投影**：`as_json` 没有 bytes 分支，
进去就是 500（写成不变量 + 测试）。

**端点白名单 22 → 23**：`/projects/{id}/attachments`（`POST` 上传 multipart、`GET` 列表——
**同一路径模板只占一条**）。上限：单份 20MB（在读 body 之前用 `UploadFile.size` 判）、
每项目 50 份。

**提示词**：三份提示词各加一节 `$external_material`（**三处一起改**：`.md` 的槽、agent 的
`PROMPT_SLOTS`、render 调用；`tests/infrastructure/test_llm.py:65` 会机械比对前两者）。
没有材料时写「（这一轮没有外部材料）」——**不留空节**（空节会让模型以为材料被省略了）。

**坏文件要报"读不了"**：类型不支持、抽不出文字（扫描件）、半截/加密 PDF → `UnsupportedMaterial`（HTTP 422）。
真跑踩到过：半截 PDF 会把 pdfminer 的 `PSEOF` 直接顶到 HTTP 层变成 500，所以 PDF/HTML 两条路径
都要包一层把第三方异常转成 `UnsupportedMaterial`。

**材料不算权威（不用改代码）**：只引材料的提案仍会被装配层降级成 `proposed`、被
`_assert_traceable` 拦在 `E4`——见 §11.0.3 与 `05-DDD架构.md`，本批只加测试钉住。

```
4 事务外：select_chunks(budget=WEB_BUDGET, cost=web_block_cost) ← 唯一决定发哪些号
5 一个事务：应用复述卡 + 记勾选 + 逐块记 external 出处（external_ref = URL）+ Round.materials
6 事务外：发布事件；图接着走 seat_round → integrate
```

为什么先查后写：先写（把轮次推到 `seats_running`）再查的话，进程崩在查的中间时重试会按
`RESUME_ROUTES` 直接进席位轮——**用户授权的检索被静默跳过**。先查后写最坏只是"材料表里多一份
没人引用的包"，用户重进还停在复述卡上，能重来。

**同一把尺子（本批最重要的一条）**：联网结果在选块时用的成本必须**不小于**渲染时的成本
（`web_block_cost` = 标题 + URL + 摘要 + `WEB_EID_RESERVE`），否则"编号 == 带进提示词的块"
立刻漏——账本里会出现一个模型永远看不到的编号。选块仍然只有一个决策点（`select_chunks`，
成本函数可注入），`render_web_results` 保留预算当安全网，并照实写"只带了前 N 条 / 共 M 条"。

**工具这一趟的留痕（`DropSource.TOOL`，留痕的第三支）**：三种情况各写一条，
`seat_id` 恒为 `None`（它不是席位的事），闭环区**单列一段**"工具这一趟（联网检索）"：
① 检索失败（超时 / 401 / 504 / 非 JSON）→ "检索失败：…"，**不判死整轮**；
② 某条查询搜到 0 条 → "没有搜到结果"；
③ 搜到的没全带进去（预算）→ "预算只带得下 N 条，还有 M 条没带进去（材料表里留着，搜得到）"。

**材料仍然不算权威**：检索结果与上传材料同一条路——`external` 不在 `TERMINAL_KINDS` 里，
只引它的提案被装配层降级 `proposed`、被 `E4` 拦（本批**一行既有业务代码没改**，只加测试）。

### 11.0.30 材料检索：块级命中 + `score` 的消费者（2026-10-01，P18 C-2c-1）

**为什么要它**：材料是这批新增的最大一块数据（上传 + 联网都落进 `materials`），但在这之前
**除了"本轮带进去的那几块"，用户没有任何办法再找到它**——`/attachments` 只回摘要（没有块正文），
F6 只搜文档/功能/编号/发言。于是"存下来了"和"用得上"之间差一条路。

**端口**：`MaterialRetriever.search(*, project_id, query, limit)` → `tuple[MaterialHit, ...]`，
块级返回（`{material_id, chunk_id, score, excerpt, anchor, source_ref, title}`）。
v1 实现 `SqliteLikeRetriever`（`infrastructure/sqlite/materials.py`）：

```
WHERE m.project_id = ? AND c.text LIKE '%<转义后的查询>%' ESCAPE '\'
排序：命中次数 ↓ → 命中位置靠前 → 块更短（并列按 chunk_id 稳定）
excerpt：命中词前后各 40 字（列表里一行放不下整块）
```

**五条口径**：① **块级**（材料卡、编号、锚点都是块级的，命中"一份材料"说不清是哪一句）；
② 空查询**回空**（连检索器都不问，省一次扫表）；③ `%` / `_` / `\` 按**字面**匹配（`ESCAPE '\'`，
否则用户搜 "100%" 会命中一片）；④ **只在本项目里找**（串味会让用户看到别家的材料）；
⑤ `score` 与顺序**同向**，消费者是 F6 的展示顺序——`search_hits` 拿到后**不重排**。

**接进 F6**：`SearchProject` 注入 `MaterialRetriever`（仍然只有只读端口，结构上不可能开事务）；
`search_hits` 多一个 `materials=` 参数、多一类 `kind="material"` 命中，
`label = "标题：片段"`、`where = "材料 · 锚点"`、**`ref = chunk_id`**（点得动的落点）。
**不加端点、不建表、不加索引**（单用户规模，现查现算）。

**点得动与点不动**：命中的块在本轮材料里 → 前端滚到材料卡那一块并闪一下（`data-chunk` 落点）；
**不在**任何一轮里（那份材料还没被带进过某一轮，所以没有编号）→ **说实话**，
不许假装能跳、也不许掉进"这条内容现在不在文档里"的兜底。

**升级位**：`FTS5(trigram)` / 向量都在**同一个端口**后面，换实现只改 `bootstrap/container.py`
一行（调用方一行不改）。什么时候升：真跑量出"整句子串命中率不够"时——
`MaterialHit.score` 与 `excerpt` 就是量它的抓手。

### 11.0.31 材料的删除与重解析：**编号发出即冻结**（2026-10-01，P19 C-2c-2）

**一句话口径**：一份材料里只要有**一块**被带进过某一轮（发了 `external` 编号 `E7`、`E12`…），
这份材料就**冻结**——不能删、不能就地重解析。因为编号指向的正是它里面的块：
删了 `E7` 指向空气，就地改形状让 `E7` 改指别的内容。**两条都破证据链，一律不许。**

**判据（唯一）**：`WorkspaceIndex.material_references(project_id) -> {material_id: (E7, E12)}`，
扫 `rounds.payload.materials[]`（`material_id` + `eid`），**不限轮数**、坏行跳过。
**不能用账本反查**：`external_ref` 是 `attachment:<标题>#cNN`（按标题拼，两份同名文件会撞）。
投影到界面上就是 `MaterialSummaryView.eids`（空 = 没被用过 = 可以删、可以就地重解析）。

**四条推论**：

| 动作 | 没被引用过 | 被引用过 |
|---|---|---|
| **删**（`DELETE /projects/{id}/attachments/{id}`） | 删材料行 + 块 + 原始字节（不可恢复） | **409 `material_frozen`**，消息里列出编号 |
| **重解析**（`POST …/attachments/{id}/reparse`） | **就地重读**：同一个 `material_id`、同一个去重键、原始字节不动，只换块与解析器身份（`replace_chunks`） | **不就地改**：用变体键 `sha256("reparse:{旧id}\|{parser}@{version}")` **另出一份**，旧的留着当冻结记录 |
| **联网来的材料**（`origin="web_search"`） | 不重解析（它是**当时的网页快照**，不是文件）→ 422，"要新的就重新搜" | 同左 |
| **命中不存在的 id** | 404 `unknown_material`（资源不在，不是形状错） | 同左 |

**为什么被引用的那条必须"另出一份"**：否则"已引用 + 解析器升级"是**死锁**——
就地改会改指编号；删又不许删；而"重新上传同一份文件"会被 `UNIQUE (project_id, sha256)`
挡回**旧的那份**。变体键同时给了**幂等**（连点两次重解析不会生出第三份）。

**两个动作都返回"刷新后的材料列表"**：界面就地在列表上操作，一次拿到真相，不做乐观更新。
**端点 23 → 25**（删一条、重解析一条）。界面的三件事分得很清：
`带进这一轮`（只改本轮选择，不动库）/ `重解析` / `删掉`（冻结的按钮是灰的，旁边写着原因）。

### 11.0.32 主张超限不判死 + 非猜测带假设：脱字段不丢主张（2026-10-01，P21 F16）

**背景**：真跑审计（`.codex/runs/2026-10-01/报告.md` F16）里，一份"把前面几章补齐"的长输入
**起轮就 502**，而且是**唯一一条没有 `/retry` 可点**的失败路（轮次都还没建出来）。
两条留样各死一次：`model_calls` id=33（第 6 条主张带 `assumption` 但标签是 `constraint`）、
id=34（**17 条主张 > 12 条上限**）。同一份输入拆成两半，两次都一次通过。

**口径一（条数）**：`claims` 上限 **12 → 20**；分析者改走 `parse_packet_trimmed`——
**只有 `too_long` 才截断**，保留模型自己排的前 N 条，溢出一条写一条留痕
（`主张 #21 起（共 N 条）`）。这与席位（P6）、整合（P7）**同一条口径**：
条数是可修复的错，不该让整轮重跑。

**口径二（字段）**：`claims_from_packet` 返回 `(claims, dropped)`。非 `guess` 标签带了
`assumption` 时，**把假设摘掉、主张本体留下**，并留痕"只有猜测才带假设：这条主张标的是 X"。
**不许丢主张**：`c{i}` 的序号被互斥对子按"第几条"指认着，丢一条会让后面整体错位；
而字段写歪只是笔误。仍然判死的两类：`raw_span` 在输入里找不到（编造）、
主张本体过不了领域校验（空文本 / 猜测不带假设 / 决定不给拍板人）。

### 11.0.35 容器里的非对象元素：丢掉那一条，不丢整轮（2026-10-01，P22 F17）

**来历**（审计 `.codex/runs/2026-10-01/报告.md` F17）：L2 第 3 轮 `POST /opening` → 502，
`details.purpose=seat_review`——模型在 `opinions[1]` 里写了一个**占位符字符串**
`"O2_placeholder"`。pydantic 报 `model_type`，而 `parse_packet_trimmed` 只容忍 `too_long`
（§11.0.7）→ 该席位重装一次、第二次仍错 → **整轮判死**。用户有点 `/retry` 可点（比 F16 好），
但代价是整轮停在 `failed`、还要再等一次模型调用。

**口径**：`list[BaseModel]` 容器里的**非对象元素**与"超限"是同一类**形状错**，不是内容错
（那一"条"根本没有内容可判）。处置照 §11.0.7 的三步走：

1. **先重装一次**：纠错话术说清"`opinions` 里第 2 条不是对象、该是什么形状"，
   **不回喂模型写的那串占位符**（learnings L20）；
2. 第二次仍错 → **丢掉那一条 + 留痕**（`handle = seat.export_import:opinions[2]`，
   `source=assembly`，`pass_index` 照记），整轮继续；
3. **一条都不许默默丢**——所以摘除**一定**上报（`Discarded` 列表），
   由用例层写成 `Round.dropped`（`source` 区分来源）。

   **2026-10-04 更正**：这一段写的是"摘除只开给有留痕出口的调用方"，并说整合者
   当时还没有留痕出口、只能走截断档。后来 P23 给整合者开了出口（`Round.dropped` +
   `Draft.gaps`），整合者改用宽松档——于是**严格档与截断档在生产上从来没有调用者**，
   已连同它们的四个入口一起删除（`tests/architecture/test_parse_entry_points.py`
   现在守着"解析入口恰好三个，且每个在 `src/` 里至少有一个调用者"）。
   三档是引擎曾经的能力，不是产品的选择。

**三条不许松的边界**：

① **只摘非对象**：元素是对象、字段写错（`claim: null` / `form: null`）照旧抛，
   不许被"丢那一条"掩盖（`test_dropping_a_placeholder_does_not_mask_a_real_field_error`）；
② **摘空之后的校验照旧生效**：主张一条都不剩 ⇒ `min_length=1` 拦下、整轮判死
   ——主张是一轮的地基（GB1），"空着往下跑"比失败更糟；
③ 席位的 L2 约束照旧：全摘空且 `basis` 也空 ⇒ 仍是 `PacketParseError`
   （空返回不等于没意见）。

**主张这一包要格外小心一件事：序号会前移。** 互斥对子写的是"第几条"（§11.0.20），
而我们发 `c{i}` 是按**落下来的**数组下标。丢一条会让后面整体前移，所以用一张
`ClaimPositions`（原始序号 → 落下来的第几条）换算：指到被摘掉那条的互斥对子
**丢那一条 + 留痕**（"指到的主张没切进来"），其余按换算后的位置取。这一条有独立用例
（`test_a_contradiction_ordinal_is_remapped_after_a_dropped_claim`）。

**留痕长什么样**：`RoundView.dropped` 多出一种 reason——"这一条不是对象（模型写了占位符），
没有内容可收"。前端一个字没改（`document/dropped.ts` 本来就是按 `(seat_id, pass_index)`
把留痕挂到席位包下面的）。

**2026-10-01 补（P23）：这条口子现在也开给整合者了。** 原先它只开给席位与主张，
因为"摘掉一条"必须有人记账；整合那一包当时还没有出口。现在整合也有了
（`Round.dropped` 记 `提案 #2（不是对象）`，草案卡 `gaps` 加一行"本轮有 N 条内容因为报文
形状不对没进卡片"），所以 `Integrator.integrate()` 一并改用 `parse_packet_lenient`，
`IntegrationOutcome.discarded` 把它交回用例层。**一条额外的守卫**：摘完之后若整包
什么都不剩（无题、无清单项、无提案、无申报），判成 `PacketParseError` 而不是放过
——否则它会走到 `draft_of(...) is None` → `ShapeError` → **HTTP 409**，
用户看到的是一句莫名其妙的错；走报错才能进既有的"重装 → 降级成 s11"出口。

### 11.0.37 归因补交代：用小调用问去向（2026-10-01，P23 起 · P24 定型）

**要解决的问题**：§11.0.35 末段的真跑结论是"补提示词没把 `unaccounted` 降下来"
（同车道 316 条意见 34 条 → 97 条意见 34 条）。模型不会**自愿**逐条交代。

**试错（P23，走了一次弯路，留证）**：第一版是"点名**重装整包**"——要求模型把整份报文
重写一遍，把点名的去向补上。真跑：它**确实照办**（点名 3/4/3 条补了 2/4/3 条），
但重写出来的报文又漏了**别的**意见，两轮 34 → 18 条、整合调用 6 → 12 次，**没解决**。

**定型（P24）**：补交代改成**小调用**——只问"我点名的这几条里，哪些是你没采用的"，
把它交回的 `dropped_opinions` **并回原报文**，**绝不重写**题目与提案。
模型没有机会"补一批、又漏一批"。

```
整包调用（唯一一次，含校验重装 ≤2）
  → assemble → 算 unaccounted
     ├─ 不为空 & 有进展 & 额度未用 → 小调用：只问点名的几条去向
     │      → 并回原报文（只加 dropped_opinions）→ 重新 assemble（纯函数，不花模型调用）
     └─ 为空 / 没进展 / 额度用完 → 往下走，剩下的照旧写进 Round.dropped（unaccounted）
```

**六条边界**：

1. **两本账分开**：`MAX_INTEGRATION_ATTEMPTS = 2`（报文过不了校验，**整包**重装）
   与 `MAX_ACCOUNTING_REPAIRS = 2`（报文没错、只是没交代，**小调用**）各算各的；
2. **小调用只回答"没采用的"**（`schemas.DispositionsPacket` 只有一个字段）。
   **不让它回"我用了"**：那样等于让模型自己把这条指标清零（`04` C5 否掉过"赌模型老实"）。
   **它没列的就仍算没交代**——沉默还是沉默；
3. **只认点过名的 handle**：小调用问的就是那几条，答案里多出来的地址不并入
   （那不是"哪条意见没进卡片"，并进来只会给留痕添噪音）；
4. **同一把尺子**：小调用看到的东西只有两样——点名的那几条意见
   （`render_selected_opinions`）与**核算真正读过的东西**
   （`render_citations`：题目归因过的席位条目地址 + 题/提案引用过的编号）。
   判据读什么，提示词就只给什么；给多了，模型就会拿"我写过类似的话"当"我用过了"；
5. **判定与写库共用一份实现**（`_accounted` / `_unaccounted_for`）：两处口径不同的话，
   会出现"为不存在的问题多花一次模型调用"或"该报的没报"。为什么判定时用
   `assembled.proposals`、写库时用加上机械提案的全量也对得上——机械提案
   （s11 落地 / 答案机械落地 / 撤下未决 / 降级）引用的只有 `system_default` 与
   `card_answer` 的编号，**从不引用席位判断自己的编号**；
6. **两条都要在事务外**：模型调用不许进 `with uow`（`tests/architecture` 守着），
   所以两段都在 `_integrate_with_repair` 里；`_dropped_items_for` 只负责最后把账写下来。

**护栏与兜底**：

- **没进展就不再花**：上一次点名之后 `unaccounted` 的条数没降 → 直接收手
  （真跑里出现的正是"重写换一批漏"，那种情况点数不降）；

### 11.0.38 主要输入口：按网址抓网页 + Word / Excel（2026-10-02 作者拍板，P27 C-2c-4）

**切在哪（"主要"先做，其余不铺开）**：`.docx`（`python-docx`）、`.xlsx`（`openpyxl`）、
**按网址抓网页**（`WebFetcher`）。不做 docling（重依赖 + 首次下模型；端口留着，换实现只改组装点
一行）、不做 pptx / 老 `.doc` / rtf / epub、不做 OCR（抽不出就明说）、不做表格结构化
（`MaterialTable` 至今没有消费者，docx 表格**按行渲染**成文本块）、不做自动 / 批量抓取
（与"没勾就不联网"同一条纪律）。其余类型照旧 422，消息里指路：
"先把内容另存成 .md / .txt / .pdf / .docx / .xlsx（老 .doc / .xls 也请另存）"。

**抓来的网页走"材料"那一支**（`origin="web_fetch"`）：块级全文、进 4000 字那个池子，
**不是**检索结果支（300 字摘要 / 2000 字池）。理由：它是**用户点名的材料**，不是搜出来的线索；
`external_material_text` 按 `origin == "web_search"` 分流，天然落材料那一支。
提示词里这类材料的头一行多写"来源：URL"（上传材料的 `attachment:标题` 与标题重复，不占预算）。

**原始字节 = 抓回来的 HTML**，进 `materials.content`：所以抓来的网页**可以"重解析"**。
与联网搜回来的"快照"刻意不同——那份的字节是摘要拼的，重解析还是 422（"要新的就重新搜"）。

**同一个网址再抓 = 刷新**（照 §11.0.31 的两条路）：没被引用过（没发过编号）→
`MaterialStore.refresh` **就地换原始字节与块**，`material_id` / 去重键 / `created_at` 都不动
（界面"这一轮选了哪几份"是按 id 记的）；被引用过 → **另出一份**
（变体键 `sha256("fetch:{网址}|{新字节 sha256 前 12 位}")`），旧的冻结留着——那些块挂着编号。
去重键 `sha256("fetch:{网址}")` 与检索那条路的 `web:{网址}` **分开算**：一条是"我抓的整页"，
一条是"搜回来的线索"，两者同时存在是对的。抓不到就往上抛，**库里一行都不留**。

**抓取护栏**（`HttpxWebFetcher`）：只收 `http` / `https`（URL 不许带账号密码）；**拒绝内网 /
环回 / 链路本地地址，且每一跳都重新判**（`ipaddress.is_global`）；重定向自己跟、≤3 跳；
15 秒；5 MB **边下边数**；`Content-Type` 必须是 `text/html` / `application/xhtml+xml` /
`text/plain`。理由：这套 API 没有鉴权，任何页面都能诱导本机后端去抓内网地址（CSRF 型 SSRF）。

**两种失败分开报**：**"你给的地址不能用"**（不是 http(s) / 带凭据 / 内网 / 不是网页 / 太大）=
`fetch_refused` → **422**；**"抓的时候出了问题"**（超时 / 非 2xx / 解析不了域名 / 跳转太多）=
`tool_call_failed` → **502**。界面两种情况都只显示后端那句 message。

**两个解析器身份**（`identities()`）：`python-docx` / `openpyxl`；抓来的网页**复用 `bs4-html`**
（与上传 `.html` 共用同一条抽取 `extract.html_text`）——所以抓来的网页不会被 `needs_reparse`
判成"旧解析器读的"。锚点都是人话：`第 3–7 段` / `表格 2（表头：角色、能否导出）` /
`工作表「排期」第 1–3 行` / `第 5–9 行`。

**没新增 DTO 字段、没新增提示词槽、没新增事件**——这是"换实现不是改架构"的验收点：
三个新输入口走的是既有材料链（`ParsedMaterial → MaterialStore.put → select_chunks →
只给选中的块发号 → render_materials → 账本 external`）。端点 25 → **26**：
`POST /projects/{id}/attachments/fetch`（body `{url}`，返回材料摘要，与上传同形）。

### 11.0.42 输出侧口径：**一次整合**最多 60 条 + 解释进 rationale（2026-10-03 作者拍板，P37）

**来历**：`LIMITS_TEXT` 原来写"内容候选（proposals）**一轮**最多 60 条"，而执行是**按次**算的——
一轮会整合 2–3 次，M4 的两轮真跑里一轮累计过 **93–103 条**。措辞与执行对不上。

**量出来的**（201–204 次成功整合调用，跨 P30/P35/P36 的库；脚本
`.codex/runs/2026-10-03/P37调研/measure_output.py`）：提案条数中位 **31** / p90 65 / 最大 90；
回包中位 **17,923 字符**（p90 29,028、最大 37,905）；耗时中位 **44.2s**（最长 545.3s）；
**17% 的调用写了 >60 条** → 先重装一次（59% 修好），其余**真截断**——留痕里 12 条
"超出单轮上限 60 条，被截断未进卡片"，最多一次**丢掉 16 条提案**（有留痕，但用户拿不到）。

**口径三条**：

- 60 条 **不动**：抬到 90 会让单次回包压到 16,384 的输出上限（`04` G10 F34 的截断）；
  降到 40 会把溢出面从 17% 推到 ~40%（p90=65），更多内容被丢；
- 措辞改准：**一次整合最多 60 条**（这一轮可能整合好几次，每次都要守）+ 写清后果
  （先让你精简一次、再截断丢掉多余的）；
- **正文只写文档里要出现的那句话**：依据说明 / 为什么这么定 / 上下文复述，写 `rationale`
  （草案卡上单列"它为什么这么判断：…"）——正文越长，这一趟越慢，也越容易撞输出截断。

**触发条件**：溢出率 **> 30%** 或单次截断丢 **≥ 20 条**，再谈"抬上限 + 同时抬 `max_tokens`"。

### 11.0.44 跨轮记忆：存"确认过的那一块"（2026-10-03 作者拍板，M6）

### 11.1 留痕：一条通道，四个来源

```
本轮席位意见（current_reviews）
  ├─ 模型申报        → dropped_opinions[{handle, reason}]  ─┐
  ├─ 归因对不上号    → 装配层（from_opinions 指向不存在的条目）─┤→ Round.dropped[]
  └─ 没人交代过      → 装配层核查（unaccounted）              ─┤   （累加，跨趟保留）
工具这一趟（C-2b，source=tool，seat_id 恒为 None）             ─┘   └→ rounds.payload.dropped
  ├─ 检索失败：…（不判死整轮）                                            └→ RoundView.dropped[]
  ├─ 没有搜到结果                                                              └→ 闭环区
  └─ 预算只带得下 N 条，还有 M 条没带进去（材料表里留着，搜得到）
```

界面侧：`source=tool` 的那几笔**单列一段**"工具这一趟（联网检索）"，
不许混进"去处写错的 / 更早那趟的 / 地址对不上号的"那一句里（`06-前端.md`）。

**"算交代过"的三条**（任一条成立就不报 `unaccounted`，这是把假阳性压到最低的边界）：
① 地址出现在某道题的 `from_opinions` 里；② 它自己的出处编号（只有判断有）出现在某条提案或
某道题的引用里；③ 模型在 `dropped_opinions` 里申报过。**结构性豁免**：整合失败走降级出口时，
这一趟的疑问会被原样落进 s11，所以算交代过；没落地的判断照报。

形状：`DroppedItem{handle, reason, source, seat_id, pass_index, packet_id?}`。`handle` 的形状**故意不校验**
（模型写歪的地址正是要留痕的东西）。

`packet_id`（2026-10-04 加，**可选**）：这一条来自哪一包（§4.4 信封的 `packet_id`）。
- **有值**：席位 / 分析者来源——那一趟的 `envelope.packet_id` 就在手边，在**通道口**填
  （`use_cases` 的 4 个留痕 builder + `analyzer.analyze()` 出口一处 `replace()` 覆盖 9 条）。
- **`None`**：assembly 归因对不上号、tool 失败——它们**没有 agent 包**，`None` 的含义是
  "不来自模型回包"，不是"没填"。
- 前端 `dropsFor`：**两侧都有 id 才按 id 精确匹配**，否则回退 `(seat_id, pass_index)`。
  回退不是妥协——`pass_index` 只在同一轮内区分趟次，而 `Round.dropped` 跨轮累积，
  纯启发式会把两轮同 `pass_index` 的留痕混在一起。
- 老行兼容：payload 里没有这个键 → 读回 `None`（`_dropped_from_payload` 用 `.get()`）。
