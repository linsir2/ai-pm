### 2.1 手改文档（F17）

文档区里每条内容都能自己动手，不用绕 AI：

| 动作 | 入口 | 后端 |
|---|---|---|
| 改一条 | 条目上 hover / 聚焦出现的「改」→ 编辑框 → 保存 | `POST /projects/{id}/edits` `op=replace` |
| 删一条 | 「删」→ 变「确认删」→ 再点一次 | `op=remove` |
| 加一条 | 块末尾「+ 加一条」；章节级块是「+ 新开一段」 | `op=add` + `block_id` |
| 在这一章写第一条 | 空章节里的「+ 在这一章写第一条」 | `op=add` + `block_id=s2`（章节 id） |
| 加进偏好区 | 偏好区里的「+ 加一条」 | `op=add` + `block_id=preference-area` |

三条规矩：

1. **一次改动一版**（`trigger=manual`），旧版本留在快照里，可回退；
2. **手改内容有自己的出处编号**（第七类 `manual`），所以文档里每条内容依然查得到"谁说的"；
3. **改过的块 AI 之后动不了**（后端 D5）：下一轮草案要改写或删除它会被拒——这就是
   "卡片改的与文档改的谁优先"的答案。人自己不受这条限制，可以接着改、接着删。

这两处限制都已解决（`04-未决.md` F8）：给功能**补一个还不存在的字段块**已做（`F8-①`：手改给
`{feature_slug, field}`，块不存在由 domain 建，功能本身仍不许凭空造）；章节级"加一条"改为
**先找同章节同类型非手改块 append，找不到才新建**（`F8 残留`），不再每次新开一段。

### 2.4 B 轮优化：导航身份 / 三栏显隐 / 左树表达 / 模板 about（2026-10-15 设计，未实现）

起因有二：① 用户实测——点"最近项目"和点"模板库"看着是同一个界面，没有任何反应区别；
② 模板只有 2+N 个、无视觉外观，卡片墙是负信息（外部调研：GitHub chooser 同构；Miro 式
hover 预览不适用——差异在章节清单不在外观）。

**§1 导航修复**：`ProjectList` 左导航只保留页内真实段（新建项目 / 最近项目）+ scrollspy
高亮当前段（IntersectionObserver，只管高亮不管跳转）；「模板库」从死锚点改成按钮，
进真正的 templates view（与 TopBar 模板按钮同一个 `setView("templates")`）。
三视图标题各表身份（你的项目 / 模板库 / 工作区面包屑）；TopBar 模板按钮在 templates
视图下加 active 态（`aria-current` + 视觉）。`NewProjectForm` 上的 `id="home-templates"`

**§2 模板收敛**：选择留在新建处（tpl-card radiogroup 已有），加 about 行——纯函数组装

### 2.2 就绪度、导出与版本历史（2026-09-24 定，P5）

**就绪度：一个数 + 一份清单，出现在四处**

| 位置 | 长什么样 |
|---|---|
| 左栏就绪度卡 | 环形图（**无阻塞章节占比**，s13 不参与）+「已确认 N 条 · 阻塞 M 项」 |
| 文档区版本条 `VersionBar` | `vN · [版本历史] · [就绪度 N%] · 记忆 N`；就绪度 chip 点击开清单抽屉 |
| 章节头 | 该章有缺口 → 内联列出（`.chapter__gaps`，阻塞 / 提示各一行），不折叠 |
| 清单抽屉 | 点「就绪度 N%」打开：按章分组，每条是 `title` + `detail` + 阻塞/提示标签 |

就绪度百分比与环形图用**同一个纯函数**（`document/readiness.ts` 的 `readinessPercent`；
比例的分母是 `workspace.document.sections` 的章数，不是硬编码的 13）：
无阻塞章节 / 参与判定章节（s13 不参与）。

判"有内容"按**非空条目**算，不按 `blocks.length > 0`——s8 有六个固定子块以后，
空子块会被误算成"有内容"（后端 `ReadinessChecker` 用同一条规则）。

**导出**：顶栏右侧「导出」按钮 → 浏览器直接下载 `<项目名>-v7.md`。
不做预览页（预览会变成第二套渲染，迟早跟导出的不一致）。

**版本历史**：文档区版本条的「版本历史」按钮点开一个抽屉（`01` §5 草图里本来就画了"版本历史 ▸ v0.4 …"）：

- 左列版本列表（`v7 · 手工改一条 · 12:31`，带 `trigger` 与摘要）；
- 选两个版本 → 中间显示 diff（按章节/字段分组：新增 / 删除 / 改写，改写显示前后两行）；
- 「回到这一版」→ 二次确认 → `POST …/rollback` → 文档刷新、多出一版（`trigger=rollback`）。

**跨轮编号跳转**：胶囊在**本轮**仍然走本地索引（`api/evidence.ts`，快）；
本地查不到就调 `GET /projects/{id}/evidence/{eid}`：拿 `round_id` 就切到那一轮，
拿 `used_by` 就滚到引用它的那条内容并闪一下。查不到才说"查不到"（现在就是这个话术）。

**落地补充（2026-09-28，P5b）**：

- 条目锚点：`EntryList` 的每条内容带上 `id="entry-<entry_id>"`——没有它，"滚到那条内容"没地方落。
- 历史轮是**只读**：切过去时闭环区顶部出横幅"正在看历史轮次 r-xxxx（只读）·[回到最新一轮]"，
  抽屉与开场卡都不出（`mode` 传 `null`）。输入框仍然可用：一发新输入就回到当前轮。
- 留痕一行：每个席位包底部"它说的 N 条里，M 条没进卡片"+ 逐条地址与原因；
  挂不到本趟席位包上的（更早那趟 / 地址对不上）在闭环区末尾单列一行。

**意见留痕**：每个席位包底部一行灰字——"它说的 4 条里，2 条没进卡片（原因：…）"，
点条目地址跳到那条意见。这是"信任"最便宜的一半。

**放弃这一轮（2026-09-28，P5c）**：席位在跑时，状态行旁边多一个「放弃这一轮」按钮
（`POST /rounds/{id}/abandon`）。按下去这一轮变成 `abandoned`（终点）：状态行显示
"已放弃：<原因>"，输入框解锁（可以马上写下一轮），文档一个字节都不改。
在途的那条请求会被后端取消，前端用 `abandoning` 标志位吞掉它注定会失败的网络报错——
用户不该看到"连不上后端"。

**缩编提示（2026-09-28，P5c）**：席位节点标题下面一行——
"第 2 / 3 轮 · 这一趟只请了 2 个（缩编：只请与本次答案相关的面）"，
只在 `active_seats` 比用户编制少的时候出现；问卷里 `asked_by` 为空的题标"整合者提的"。

### 2.3 模板管理：列表 + 编辑器（2026-10-15 设计，未实现）

> 列表态的章节预览、导航归属与窄屏复位见 §2.2a。

**两屏，`view` 三态**（`workspace` / `projects` / `templates`——原 `listing: boolean` 改成枚举，
两个 boolean 表达互斥视图迟早会出四态）。入口两处：首页（`Onboarding`）与项目列表顶栏——
"从零建"这条路径必须处处可达，不能被模板库吞掉。

**A 屏 · 模板库**：一行一条 `标题 · N 章 · 内置/我的`，自建的带 `[编辑][删除]`，内置的不带删除按钮。
**不做卡片墙、不做分类树、不做搜索、不做展开预览**——只有 2 个内置模板时这些控件全在处理"空结果"
（Storybook 有 19 种框架模板时把选择器整个砍掉了，改成自动探测 + `--type` 逃生口）。
预览也不另做一屏：编辑器本身就是预览。

**B 屏 · 编辑器**：单栏，每章一块，**元数据行内编辑**（6–13 项时"选中→切右侧面板→改→切回"的往返
成本高于收益；json-editor 的三栏退化记录是实测依据）。每章暴露：标题 / **这一章是干什么的**
（`purpose`，必填且直接进提示词的章节说明，不暴露用户就没法改章节说明）/ 角色 / 条数判据（至少 N 条，
可指定只数哪种块）/ 覆盖度 / 槽位列表（name + title + kind，**kind 必填**——API 层就是必填）。
顶部是复制源下拉 + 模板标题 + 保存。

**校验一律用界面结构表达，不报错红字**（结构性约束在整个编辑过程中天然被违反，红字会一直亮着）：
锚点章的删除按钮置灰且悬停说明；锚点章的**角色下拉整个锁住**（2026-10-15 验收 F5：
此前只防"重复占用"，没防"把唯一的锚点改成别的 role"——UI 必须不许制造后端必然拒绝的状态。
改那一章的叫法只改标题，不改 role）；非锚点章的下拉里已被占用的锚点 role 置灰；
锚点章**不显示**判据输入（后端本来就拒）；数字输入 `min=1`。
**不加 dry-run 校验端点**——加了就是两条真相源。
**三个锚点是谁由后端 `/schema.template_anchor_roles` 说了算**（2026-10-15 验收 F2/F3：
前端曾自抄一份三锚点枚举，后端加第四个锚点时置灰会静默失效；`pickedRoles`/`isAnchor`
改问 schema 的那份。`template_roles` 是全部 8 个，锚点是其中 3 个的两张表）。

**章节 id 只读**：`s{当前最大 + 1}`，**不填补空缺**（`light` 的 `s1,s2,s4,s5,s11,s13` 跳号是刻意的，
空缺 = "standard 的这一章此处不需要"）。id 是提示词里给用户看的稳定符号（"你的回答写到 s5"），
跟位置无关；重排也不改 id。

**内置模板既不能改也不能删**（409 `template_builtin_protected`）——改了就回不到出厂状态。
界面上的表达是**不给出编辑/删除按钮**（不是点了报错）：内置那两条只留 `[用这个建项目]`。

**"从零建"是复制源下拉里的一项**，选它得到一份**预置三个锚点章**的空模板（功能需求 /
风险与开放问题 / 版本历史，role 各就各位，`purpose` 给默认文案）。不是空白列表——空白列表的用户
必须先手动补齐三个锚点才能过校验，而"哪个 role 是必须留的"是产品硬规则，不该让用户去猜。

**章节重排用上移/下移按钮，不做拖拽**——本仓零第三方 UI 依赖（只有 react/react-dom），
拖拽要自己写且不可访问。

**删除用内联二次确认**（按钮变"确认删除？"再点一次才发）——本仓没有确认弹窗的既有模式，不为它造一个。


### 2.4a 管理后台（2026-10-16 重做）

第一版（Task 8）是两张平铺的列表（审批队列 + 用户列表）+ 满屏空白，而且**同一批用户出现两次**
（pending 既在审批队列、又带着一个「封禁」出现在用户列表里）。

**这一屏现在只打 `/auth/stats` 一个端点**。原先打 `/auth/users` + `/auth/usage` 两个再在前端
join——那既是"两个真相源"（一次动作之后两边时点可能对不上），口径也不够用。
`/auth/users`、`/auth/usage` **保留不动**：它们是既有窄口径契约（`06` §5 那本账钉着），
新端点不是替代而是补充。`/auth/stats` 装不下它们的名字，所以是新路径而不是把
`usage` 撑成什么都往里塞。

**分区而不是平铺**（`ADMIN_SECTIONS`）：管理员打开这一屏的第一个问题是"有没有人在等我批"，
第二个是"现在谁在用"。核心两区（待审批 / 已生效）**永远显示**——空的时候看得见
"没有待批的"本身就是答案；异常两区（已拒绝 / 封禁中）**空了就隐藏**。

**每行动作是状态机的刻意子集，不是镜像**（`actionsFor`）：

| 行 | 给什么 | 为什么不给别的 |
|---|---|---|
| `admin` | **一个都不给**（渲染成 `—`） | 后端 `admin_protected` 硬拦，给一个点了必然报错的按钮只会让人以为坏了 |
| `pending` | 批准 / 拒绝 | 封禁一个还没生效的人没有意义 |
| `active` | 封禁 | |
| `rejected` / `banned` | 恢复（复用 `approve`） | 误操作不必不可逆 |

**为什么调用数不是主角**：`failed`（`ok = 0`）、`avg_duration_ms`、`total_tokens` 才是管理员
先看的。真跑一次的数据：183 次调用里 **16 次超时失败（8.7%）**、平均 **66.7 秒**、
149 万 token——光看"用量 183"这三件事一件都看不见。

**口径上的坑**：轮次 / 模型调用 / 会话三张表挂在同一个 owner 上，一次 join 会把行数乘起来
（183 条调用配 19 个 round 就是 3477 行）。读模型一律用**相关子查询**，
`test_stats_counts_failures_and_tokens` 钉死这件事。

**版面**：`.doc__inner.admin` 不受 `52em` 限宽约束——那是给正文阅读的行长上限，
这一屏是数据表，八个列挤在阅读宽度里只能横向滚动。表头底色用 `app-bg`，
数字列一律等宽 + `tabular-nums`，失败数用语义色（0 时不出现，不画 0）。

**没做的**：不做搜索 / 分页 / 角色编辑 / 审计日志。当前 2 个账号，这些控件全在处理空结果；
真要多起来，得先有"账号多到需要检索"这个事实。

### 2.5 登录 / 注册屏（2026-10-16 定稿，M17 多用户之后的第二版）

第一版（Task 7）几乎没样式：`.input` 这个类在样式表里**根本不存在**，表单又没套白卡片，
于是全是浏览器原生外观。第二版按 `DESIGN.md` 的禁令重做，立场是
**不描述产品，摊开产品的一块**（`selective truth`：形容词会撒谎，截图不会）。

- **分栏**：左栏是中性灰底上一张"窗"（`--proof-bg` + `.proof`），窗里摆真实产出——摘自真实项目
  「真跑验证-20261005-A-订单导出」的**非功能要求**与**未决**，出处编号是真的（`E94` / `E97` / `E169`）。
  右栏是 420px 的表单列，卡片 360px、白底、**圆角 8px 不带阴影**。
- **左栏直接复用 App 自己的类名**（`topbar` / `doc__inner` / `doc__crumb` / `chapter__title-row` /
  `chapter__body` / `.block` / `entries-wrap` / `entries > entry` / `chip` / `dot` / `vbar`），
  新增的 `.proof__*` 只有窗框、顶栏高度、左栏底色、脚注，**外加一处覆盖**：
  真实 `.doc__inner` 有 `min-height: 100%`（工作台里要铺满一屏），裁切里必须压成 0。
  这么做的理由：这块东西的全部说服力来自"它是真的"。另画一套像文档的样式，
  迟早和真实渲染走样——**缺一层包裹就不生效**这条已经踩过：描边规则是
  `.chapter__body .block .entries > .entry`，少了 `.block` 卡片就没了。
- **窗框 820px ≈ 真实文档区的 52em（832px）**：让裁切是**真实比例**而不是缩小版。
  窄了出处列会被挤到 min-content、胶囊折行——CSS 注释其实接受折行（"装不下就在自己的列里换行"），
  但每条都折不好看。实测真实工作台在此宽度下 entry 宽 634px、出处列 32px，与裁切一致。
- **章节之间贴得紧是真的**：`.chapter` 与 `.chapter__head` **没有任何 CSS 规则**，
  所以工作台里章节本来就贴着。裁切**不偷偷加间距**——加了就不是真裁切了。
  想改章节间距是 App 层面的事，不能只在登录屏改。
- **三条硬约束**：无渐变、无阴影堆叠、无「居中大标题 + 三列图标卡」。
  左栏刻意是**无彩色底**——纯品牌色墙是登录屏最响的 AI 味信号。
  强调色**只**出现在提交按钮和链接上（`UI Craft` 的眯眼测试）。
- **出处胶囊的悬停摘要**：裁切里的胶囊用 `<span class="chip" title="…">`，**不是** `<button>`——
  真实 App 里的胶囊是可点的（`EvidenceChip` → `onJump` 回原话），而这里是静态裁切**点不了**；
  做成按下去没反应的按钮，是拿假交互换真实感。摘要沿用 `EvidenceChip` 的 `title` 约定
  （`出处 E94：<原文摘要>\n<来源>`），内容全部取自真实出处账本：问卷题 / 席位判断。
- **跨轮来源走 `.chip--remote`（虚线边）**：E169/E170/E172 的 `kind` 是 `system_default`
  且来自另一轮（`r-14d70eb4`），在真实 App 里这类编号本地查不到，本来就是虚线——照抄。
- **注册态在窗外补一句注解**：`.proof__aside`，「上面这一章是它会问你的问题。问出来先落在草案里，
  你勾了才写进文档」。放**窗外**而不是窗内——窗内必须保持产品原样，注解是我们的话。
- **脚注不许声称裁切里能点**：胶囊点不了，所以脚注写"在应用里点编号能顺着回溯到原话"，
  不写"点它能回溯"（这是踩过的坑：文案在它所处的上下文里撒谎）。
- **审批账本**：把「提交注册 → 管理员审批 → 进入工作台」画成三步（`.ledger`），
  用的是证据胶囊那套等宽语言。注册态高亮第 1 步。
  解决的是**别的登录屏都不讲的事**：注册完到底会发生什么。
- **响应式**：`≤1040` 整块左栏撤掉、表单独立存活（`UI Craft` 的 320px 硬要求）。
  因此**副标题不许提「左边」**——1040 以下它会变成撒谎（这是踩过的坑）。
- **左栏内容是静态快照，不是活数据**：多用户之后所有端点都要身份，未登录拿不到任何东西，
  而为一个展示屏开公开端点会把未认证面变大。需要更新时改 `LoginView.tsx` 里的 `ProofPanel`。
- **暗色**：主题 state 在 `Workspace` 里，而它登录后才渲染——所以加 `ThemeGate`
  在 `App` 里把存量主题先铺到 `<html>`，否则用暗色的人登出后看到一片亮屏。

### 3.2 三条硬规矩（写代码时不许破）

1. **事件只做两件事**：推进"这一轮走到哪"（`step` / `waiting_on` / `seat_round_count`），
   以及打一个"该重读了"的信号（`doc.changed` → 重读文档；`generation.failed` → 重读这一轮）。
   事件**不拼数据**：文档与轮次的真身一律从后端读回来（`state/workspace.ts` 的注释与测试钉住这条）。
2. **弹什么卡由最近一次拿到的投影决定**，不由事件决定。所以会出现"事件说该答题了、但题目还没取回来"
   的中间态：这时底部条显示在跑，不弹空问卷（`awaitingMode` 会判成 `loading`）。
3. **组件不做业务判断**：能不能提交、该显示什么、默认勾什么，全部来自 `payload.ts` /
   `status.ts` / `progress.ts` 这些纯函数，它们只读后端投影。

**P3a 联网申请的界面口径（2026-10-26）**：

- **申请卡是非阻塞的**：`web_requests` 只在线程流里多一段卡，不新增 `waiting_on`、不加 SSE 事件；
  `round.updated` 仍只置 stale。批准即执行时按钮显示"处理中…"，客户端超时/失败后主动
  `GET /rounds/{id}` refetch（非工具异常不补发事件）。
- **`allow_web` 默认关**：开关旁必须写第三方披露——打开后席位/整合者的检索词会发给外部搜索
  服务（`RoundView.web_search_network_access`）；没有联网工具时开关禁用并说明。
  开关常驻开场卡，即使这一轮还没有任何提案（可以先授权后续席位）。
- **decision 可见**：只有 `proposed` 出「批准 / 拒绝」；拒绝不占执行名额，名额满只挡批准；
  历史轮只读、轮忙/轮终态禁用；失败必须显示 `state=failed` + `result_note`，不吞。
- **名额来自后端**：`/schema.limits.max_web_executions`（生效值，可能小于 3），
  执行数按 `RoundView.web_requests` 里 `approved/done/failed` 计；前端不硬编码 3。
  上限未读到时不猜：禁用批准并说明"还没读到本轮联网名额上限"。
- **旧轮 fallback**：有 analyzer 新申请时只渲染新卡；没有新申请时回退旧 `web_queries`
  列表（两套同时存在也不重复渲染）。`allow_web` 开关按 R22 仍常驻。

## 6. 视觉怎么落地

`DESIGN.md` 是唯一真相源，`src/styles/tokens.css` 是它唯一的实现：

- **色**：一个主色 + 四个状态色（缺口 / 矛盾 / 开放问题 / 空）+ 一个成功色（就绪度环形图与 chip），其余中性；暗色重做表面不反相。
- **字**：UI 无衬线（**中文走系统字体，不引 webfont**——全量中文 webfont 几 MB，与「零加载成本」冲突）；拉丁的 JetBrains Mono 与 Instrument Serif 走 `@fontsource` **自托管 latin 子集**（各约 21KB，不引 CDN，见 `§2.5`）；文档标题与章节名用衬线；编号、版本、id 用等宽 + 等宽数字（`.chip` 也带 `tabular-nums`，别只 `.mono` 带）。
- **纸**：文档区在应用底色上是一张有细边与圆角的纸，正文限宽 `60em`、行高 `1.75`、段距 `0.75em`。
- **动效**：只有三种时长（80 / 160 / 240ms），只有"卡片出现""抽屉滑入""写入后的高亮"，
  并且 `prefers-reduced-motion` 下一律关掉。
- **不做**：渐变、发光、玻璃、阴影堆叠（浮层除外）、满屏动画。

## 7. 无障碍与响应式

- 全部交互元素是原生 `button` / `input` / `select` / `textarea`；出处胶囊是 `button`（不是可点的 `span`）。
- 闭环区的三个页签（本轮 / 灵感箱 / 讨论）是 `role=tablist` + `role=tab` + `aria-selected`；
  左栏章节状态点是 `role=img` + `aria-label`（状态文字，读屏拿得到）。
- 抽屉是 `role=dialog` + `aria-modal="false"`：它只盖住闭环栏，文档必须保持可读，
  所以**不做焦点陷阱**，但"收起"是显式按钮（Esc 不吞、不丢这一轮）。
- 统一 `:focus-visible` 焦点环；跳过某题是 `aria-pressed` 的开关。
- 断点：`≥1240` 标准三栏；`980–1240` 左栏收窄到 176、闭环栏到 340；`<980` 单列堆叠
  （左栏变横向滚动条、闭环区掉到文档区下面、底部条两段上下叠）。
- **顶栏在窄屏的收纳**：`≤1240` 把推送状态的**文字**视觉隐藏（`.sr-only` 那套，**仍在无障碍树里**
  ——读屏照旧听得到）；`≤980` 再把品牌名「PM Studio」同样隐藏、并给搜索框一个下限宽度
  （`min-width: 120px`），免得被挤成一个字。按钮一律 `white-space: nowrap`：中文两字按钮被 flex
  压到 39px 宽会变成"一列一个字"（`导出` / `暗色`）。
