# 06 · 前端界面（长什么样、数据从哪来）

> 这份回答三件事：**界面分成哪几块**、**每块的数据从后端哪个字段来**、
> **哪些东西后端没有所以界面不做**。
> 视觉规范唯一真相源是 `DESIGN.md`；接口真相源是 `02-编排与数据.md` §5 与
> `backend/src/pmstudio/application/dto.py` 的投影。两者冲突时以代码为准，并回来改这份。

---

## 1. 范围

**做**（就是主闭环的界面）：建项目 → 输入 → 复述 → 席位 → 问卷 → 草案 → 确认 →
文档多一版；三个面（文档区 / 闭环区 / 抽屉）与实时推送；**手改文档**（F17，2026-09-24 起）。

**不做**（这一版后端也真没有，界面不造）：

| 不做的东西 | 为什么 | 什么时候能加 |
|---|---|---|
| 版本历史列表与差异对比 | 没有列版本的端点；`Document.versions` 只在聚合里 | 加 `GET /projects/{id}/versions` 之后（P3） |
| 全局搜索 | 索引层没建（作者明确：先打通主闭环） | 索引层之后 |
| 章节说明 / "已完成 3/12" 这种完整度 | 合格标准只在 `01-规格.md` §4 与后端 `sections.py`，没有端点 | 加 `GET /document/schema` 或把标准做成代码之后 |
| 讨论区输入框 | 讨论区本身是 v1 之后的整块能力 | P4+ |
| 展示模型的思维链 | 设计明令禁止（`01-规格.md` §5） | 永远不做 |
| 卡片里改内容 | 卡片只有要 / 不要；改文本归文档（文档里现在能直接改了） | 永远不做（这是分工，不是排期） |
| 附件、联网、检索图标 | 工具层没实现 | 工具层之后 |

三栏宽度（`200 / 1fr / 380`）来自 `DESIGN.md`，与 `01-规格.md` §5 的"70% / 30%"是同一件事。

**一处对 `01-规格.md` §5 的调整**：那张图把输入区画成横跨文档区与闭环区的底部条，
这里照做；但它同时把"状态：等你回答"画在输入条上——现在状态在闭环区的状态行里，
因为状态是"这一轮走到哪"的事，和闭环区同列才不会让人跨屏找。

**换章只有一条路**：左栏那棵树。早先文档区顶上还有一排章节按钮，和左栏重复，已删——
同一件事给两个入口，人会不知道该看哪个。

### 2.1 手改文档（F17）

文档区里每条内容都能自己动手，不用绕 AI：

| 动作 | 入口 | 后端 |
|---|---|---|
| 改一条 | 条目上 hover / 聚焦出现的「改」→ 编辑框 → 保存 | `POST /projects/{id}/edits` `op=replace` |
| 删一条 | 「删」→ 变「确认删」→ 再点一次 | `op=remove` |
| 加一条 | 块末尾「+ 加一条」；章节级块是「+ 新开一段」 | `op=add` + `block_id` |
| 在这一章写第一条 | 空章节里的「+ 在这一章写第一条」 | `op=add` + `block_id=s2`（章节 id） |
| 加进偏好区 | 偏好区里的「+ 加一条」 | `op=add` + `block_id=preference-area` |

三条规矩：

1. **一次改动一版**（`trigger=manual`），旧版本留在快照里，可回退；
2. **手改内容有自己的出处编号**（第七类 `manual`），所以文档里每条内容依然查得到"谁说的"；
3. **改过的块 AI 之后动不了**（后端 D5）：下一轮草案要改写或删除它会被拒——这就是
   "卡片改的与文档改的谁优先"的答案。人自己不受这条限制，可以接着改、接着删。

当前的两处限制（记在 `04-未决.md` F8）：给功能**补一个还不存在的字段块**要等复述卡的功能字段选择器；
在章节级块上"加一条"每次新开一段（domain 的 target 只能落到章节/功能/字段，落不到"这一块"）。

### 3.1 一次完整迭代

| 你做什么 | HTTP | 后端发生什么 | 界面怎么变 |
|---|---|---|---|
| 建项目 | `POST /projects` | 造 13 章空骨架 + v1 | 文档区出现 13 章，全"空" |
| 输入 + 开始这一轮 | `POST /projects/{id}/rounds` | Analyzer 切分主张、定性、归位、发编号 | 闭环区出现**复述卡**（占满闭环栏） |
| 在复述卡上改标签/去处、选席位、确认 | `POST /rounds/{id}/opening` | 逐个席位跑（每席位一个事务）→ 汇合点发号 → 整合 | 时间线 ③ 逐条长出信息包（`packet.emitted`），随后 ④ 出现题/候选 |
| 交卷（可部分作答、可跳过） | `POST /rounds/{id}/answers` | 答案回灌 → 重跑席位轮 → 再整合 | 抽屉收起，时间线重跑一遍；出草案或再出问卷 |
| 在草案卡上勾要哪些 | `POST /rounds/{id}/confirm` | 唯一写入口写文档 → 多一版 | 文档插入内容并高亮这一版写的块；版本条 +1 |
| 失败 / 关页面后回来 | `POST /rounds/{id}/retry` | 只补没交回的席位，编号不重发 | 状态行变回"席位在跑"，已交回的席位不重跑 |

### 3.2 三条硬规矩（写代码时不许破）

1. **事件只做两件事**：推进"这一轮走到哪"（`step` / `waiting_on` / `seat_round_count`），
   以及打一个"该重读了"的信号（`doc.changed` → 重读文档；`generation.failed` → 重读这一轮）。
   事件**不拼数据**：文档与轮次的真身一律从后端读回来（`state/workspace.ts` 的注释与测试钉住这条）。
2. **弹什么卡由最近一次拿到的投影决定**，不由事件决定。所以会出现"事件说该答题了、但题目还没取回来"
   的中间态：这时底部条显示在跑，不弹空问卷（`awaitingMode` 会判成 `loading`）。
3. **组件不做业务判断**：能不能提交、该显示什么、默认勾什么，全部来自 `payload.ts` /
   `status.ts` / `progress.ts` 这些纯函数，它们只读后端投影。

## 4. 纯函数层（测得着的那一层）

界面里唯一被单测钉住的是**纯函数**（计划 §3.9：组件级测试留 P4）。六份，共 69 条：

| 文件 | 它决定什么 |
|---|---|
| `state/workspace.ts` | 事件怎么归约：`packet.emitted` 把席位从待启动变已完成、`doc.changed` 只置"该重读"、别的项目的事件不理会、重复序号不重放 |
| `document/status.ts` | 章节状态优先级 `conflict > open > gap > filled > empty`（矛盾 > 开放问题 > 本轮有提案 > 有内容 > 空） |
| `document/structure.ts` | 功能子树一览、字段分"整段文字/步骤"与"清单/验收标准"两组、页内锚点 |
| `api/payload.ts` | 交卷载荷（没答的按跳过）、草案默认勾选（**它提议的默认不勾**）、复述卡只交改过的纠正、`awaitingMode` |
| `state/progress.ts` | 本轮执行进度七格、标签分布、"改判几条" |
| `api/evidence.ts` | 出处索引（本轮主张 + 已发号判断），查不到的编号就显示查不到 |

## 5. 与后端逐项核对（这一节是"不要无中生有"的账）

| 界面上的东西 | 后端有没有 | 界面的处理 |
|---|---|---|
| 证据编号 `E12` 跳回原话 | 本轮有（`claims[].eid`、`opinions[].eid`） | 点胶囊滚动 + 闪一下；**跨轮编号后端查不到**，胶囊变虚并写"不在这一轮里"（P4 补查询端点） |
| 复述卡改标签 | 部分有 | 后端 `Claim` 规定"标签决定分区"，且猜测必须带假设、决策必须带拍板人。所以界面**锁定**：当前是猜测就只能保持猜测，任何时候都改不到猜测/决策（否则会 422） |
| 复述卡改去处 | 有 | 去处跟着标签走：改成偏好就落到偏好区（`zone` 由界面按标签定，不让后端拒） |
| 复述卡改到功能字段 | 没有 | 只能改到章节一级；功能字段级要等复述卡的功能选择器（P4） |
| 问卷"已答 4/5" | 没有 | `RoundView` 不含答案，界面不显示答题进度，只说"未答的 N 题按跳过提交" |
| 历史轮次的席位发言 | 没有 | `seat_packets` 只给**当前**那一轮的意见；时间线上只显示"第 N 轮" |
| 上一轮的主张 | 没有 | 主张也是当前轮的；跨轮要等索引层 |
| 章节"已完成 3/12" | 没有 | 只显示五个状态；完整度等后端把合格标准做成可判据 |
| 版本差异 | 没有 | 只显示当前版本号与"n 章有内容" |
| 席位"进行中" | 半有 | 只有 `completed` / `pending`；"正在交回"是界面按"有请求在跑"推断的视觉状态 |
| 草案 "1 条改判" | 有 | `proposal.op` 不是 `add` 的条数 |
| 推送连接状态 | 有 | 首帧要等后端 15 秒心跳才到，所以头 15 秒显示"推送连接中"，不是"断了" |
| 席位交回空意见（"判断 0 · 疑问 0"） | 有（后端允许） | 这是**合法状态**：席位没什么要补时会交空 opinions + 一段 basis。界面改成说人话——basis 当正文，"这个席位这一轮没有要补的（交回空意见）"，不再甩两个 0 出来。同时把席位提示词收紧：先尽力找一条该问的疑问，空意见是例外 |

**两处有意保留的重复**（都是"界面要知道、后端没给"的小常量，改后端时要一起改）：

1. `labels.ts` 的 `FIELD_TITLES`（12 个功能字段的中文名）——真相源是后端
   `domain/authoring/schema.py` 的 `FEATURE_FIELDS`。更好的做法是后端把字段表作为
   schema 端点暴露出来（记进 `04-未决.md` F2）。
2. `state/progress.ts` 的 `MAX_SEAT_ROUNDS = 3` —— 真相源是 `domain/round/step.py`。
   它只用于进度条的"2 / 3 轮"显示。

## 6. 视觉怎么落地

`DESIGN.md` 是唯一真相源，`src/styles/tokens.css` 是它唯一的实现：

- **色**：一个主色 + 四个状态色（缺口 / 矛盾 / 开放问题 / 空），其余中性；暗色重做表面不反相。
- **字**：UI 无衬线（系统字体优先，不引 webfont）；文档标题与章节名用衬线；编号、版本、id 用等宽 + 等宽数字。
- **纸**：文档区在应用底色上是一张有细边与圆角的纸，正文限宽 `34em`、行高 `1.75`、段距 `0.75em`。
- **动效**：只有三种时长（80 / 160 / 240ms），只有"卡片出现""抽屉滑入""写入后的高亮"，
  并且 `prefers-reduced-motion` 下一律关掉。
- **不做**：渐变、发光、玻璃、卡片阴影堆叠、满屏动画、全圆角气泡。

## 7. 无障碍与响应式

- 全部交互元素是原生 `button` / `input` / `select` / `textarea`；出处胶囊是 `button`（不是可点的 `span`）。
- 章节标签条是 `role=tablist` + `role=tab` + `aria-selected`；状态点是 `role=img` + `aria-label`。
- 抽屉是 `role=dialog` + `aria-modal="false"`：它只盖住闭环栏，文档必须保持可读，
  所以**不做焦点陷阱**，但"收起"是显式按钮（Esc 不吞、不丢这一轮）。
- 统一 `:focus-visible` 焦点环；跳过某题是 `aria-pressed` 的开关。
- 断点：`≥1240` 标准三栏；`980–1240` 左栏收窄到 176、闭环栏到 340；`<980` 单列堆叠
  （左栏变横向滚动条、闭环区掉到文档区下面、底部条两段上下叠）。

## 8. 怎么跑、怎么验

```bash
# 前端
cd frontend
npm install                 # 需要一次网络
npm run dev                 # 5173，/api 代理到 8000
npx tsc --noEmit            # 类型
npx vitest run              # 纯函数单测

# 后端（真模型；缺 key 或模型名必须起不来）
cd backend
PMSTUDIO_MODEL=... PMSTUDIO_API_KEY=... PMSTUDIO_API_BASE=... \
PYTHONPATH=src python3 -m uvicorn pmstudio.bootstrap.container:build_app --factory --port 8000
```

后端起在别的端口时，前端用 `PMSTUDIO_API_TARGET=http://127.0.0.1:8010 npm run dev` 覆盖代理目标即可。

手测清单（照做即可覆盖全部退出条件）：建项目 → 输入一段"混三类东西"的话 →
改一条标签再确认 → 看席位逐条交回 → 答一半跳过一题 → 确认草案 → 文档多一版 →
刷新页面（断点续传）→ 再跑一轮"信息明确"的输入，应当整段跳过问卷直接出草案。
