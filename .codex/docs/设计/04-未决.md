## C. 编排细节

**C1 内置哪些领域席位？** **已定（2026-09-24）**，而且提名方式也改了：

- 常驻组 5 个（`always_on=true`）：业务规则 / 数据规模与性能 / 前端交互 / 权限与角色 / 技术方案；
- 触发组 5 个（关键词命中）：导出与导入 / 通知与触达 / **状态机与流转** / **第三方集成** /
  **合规与数据安全**（后三个 2026-09-24 补齐）。
- 目录一共 10 个，落在 `infrastructure/seats/definitions/*.toml`。
- **谁来挑**：Analyzer 在同一次调用里挑（见 `02-编排与数据.md` §4 ②），目录只当候选人名单。
  补目录因此不会让每轮多跑席位——以前"常驻 + 命中"全部要跑，现在是模型裁。
- 范围守卫与陌生人读者仍然标"以后"。

**C2 席位一次推导多少条？** **已定，但与当初的建议不同**：提示词写"本席位最多 5 条判断"、
报文 `SeatPacket.opinions` 上限 8；**超了整轮失败**，不是"把多出来的降级成清单项"。
理由：静默截断会让人以为席位只说了这么多，失败更诚实（可重试）。

**C3 清单项的默认值由谁定？** **已定**：默认值必须来自席位推导（带理由）。
实现里唯一的硬编码默认是"跳过的题按题面后果落成 s11 开放问题"（`_system_defaults`），属结构类。

**C4 "它提议的"默认不勾，用户从不勾怎么办？** **做了一半**：
默认不勾 ✓；「本批全接受（N 条）」与「全不勾」按钮 ✓（2026-09-24 补，全接受含提议组）。
**还差**"连续三轮全不勾就提示关闭席位提议"——那要跨轮记账（`Round` 之外的地方存历史）。
**已做（2026-09-29，P14）**：确认那一刻由 `ProposalCommitter` 数出"给了几条 / 收了几条"落进
`Round`；出草案时用 `WorkspaceIndex.recent_rounds`（只读投影）+ 纯函数
`proposal_ignore_streak` 算连续轮数，到 3 就在草案卡上说一句（只提示，不动默认值）。
详见 `02` §11.0.24。

**C5 Integrator 丢弃 finding 要不要留痕？** **已定 + 全部做完（2026-09-28）**：

- 第一半（P4）：归因解析不上的席位条目进 `Questionnaire.dropped`，问卷卡上显示"哪几条没算数"。
- 第二半（P5b **已做**）：整合报文加 `dropped_opinions: [{handle, reason}]`（模型自己写丢弃理由），
  装配层与第一半**合并成一条通道** `Round.dropped[]`，落库、进 DTO；
  闭环区每个席位包下面显示"它说的 N 条里，M 条没进卡片（原因：…）"。
  **比当初的设计多了第三个来源**：`unaccounted`——装配层自己核"既没被引用、也没被申报"
  的意见（`source ∈ {integrator, assembly, unaccounted}`）。理由：只有前两个来源，等于赌模型会
  老实交代；真跑证明它不会。落地时还发现 `Questionnaire.dropped`（第一半）只在**出问卷**那条路上
  被写进轮次，走草案那条路全丢——现在两条路都写，`Questionnaire.dropped` 已退休（旧库兼容读）。

为什么必须落库而不是只在当轮内存里：用户过两天回来查"这条为什么没写进文档"，答案得还在。

**C6 答案轮的终止条件**：**已定 + 已实现（2026-09-24）**：默认最多两批问卷。
`MAX_QUESTIONNAIRES = 2`，到顶不再问，剩余题目降级成 s11 开放问题
（`_stop_asking_reason`：问卷闸门优先，席位轮上限兜底）。
**还差**"用户可主动继续深挖"这个入口。**2026-09-29 核验**：要新端点（白名单 19 → 20）
**已做（2026-09-29，P14）**：`Round.dig()` + `POST /rounds/{id}/dig` + 草案卡按钮。
口径：dig **不新开**席位轮（复用已交回的意见，只花一次整合调用），但同步放宽"批后那一趟"
席位轮额度；轮内队列不再被清空，于是那些没问上的题会被 carried 真的问出来。详见 `02` §11.0.25。

**C7 一轮最多几次席位轮？** **已定 + 已实现**：上限 3 次（`MAX_SEAT_ROUNDS`）；

**C8 答案回来后缩编席位？** **已定（2026-09-24）**，实现见 `02` §7.1：
席位 TOML 补 `sections`/`fields`（顺带把 `01` F16 的"负责章节/能产出什么"补上），

**已实现（2026-09-28，P5c）**：命中路径与兜底见 `02` §7.1 的"落地口径"；
`narrow_seats()` 是纯函数（有离线测试 + 用例级测试：答完一批只跑名单里的席位）。

**C9 引用词表混用导致整轮失败（真跑踩到，2026-09-24 已修）**

现象：作者真跑 `p-edc2b350` 的一轮，界面报「整合两次都过不了校验：题目的依据编号不存在：O1」，
点"继续/重试"又撞同一堵墙（日志里那个 502），那一轮永久卡死；同时第 2 次席位轮交回的
9 条疑问一条也没法回答。

原因（三条叠在一起）：

1. 席位意见渲染成 `[判断] [O1] …`，而整合器提示词的小标题写着"（带编号；编号就是这条判断的
   出处）"，同一份提示词另一处又要求"evidence_refs 只能引用清单里的编号"。模型没有合法写法
   可引（疑问**不进**账本，所以疑问根本没有编号），于是自己拼地址——重放抓到的原文是
   `seat.business_rules:O1`、`seat.tech_approach:O1`（4 次重放里 1 次泄漏）。
2. 校验很严：引用不存在的编号 → 整轮失败；重试重跑同一句提示词 → 同一个坑。
3. `Round.fail()` 用"当时的 step"当 `at_step`，并发（双击重试）时第二次记成
   `at_step=failed`，`resume()` 恢复成非法状态、路由表 KeyError → 这一轮再也恢复不了。

修法（三条都实现了，见 `docs/plans/2026-09-24-P4-引用通道与失败出口.md`）：

1. **词表分离**：渲染改成 `（席位条目 seat.x:O2 · 出处编号 E7）`，疑问写"没有出处编号"；
   提示词两处都说明"席位条目不是编号"。判断自己的 E 编号也显示出来（以前没有，模型因此
   无法引用某条判断本身）。
2. **归因通道**：题目新增 `from_opinions`（非证据字段）→ 装配层算 `asked_by`
   （依据编号所属席位 ∪ 条目地址解析出的席位），解析不上的进 `dropped` 留痕。
   **账本语义不动**：疑问不是证据，不进账本。
3. **失败出口**：整合两次仍失败 → 席位疑问原样落 s11 + 出草案卡（缺口行写原因）；
   `fail()` 幂等、坏 `at_step` 明确报错、`RESUME_ROUTES` 补 `failed` 兜底、
   一个 round 同时只允许一个动作（`round_busy` → 409）。

## D. 数据与一致性

**D1 用户手改 content 的排期？** **已定（2026-09-24）**：手改做进 v1。
落地方式：`POST /projects/{id}/edits`（`op = add / replace / remove`）→ `EditEntry` 用例
→ `ProposalCommitter.apply_manual`（与 AI 写入共用同一个 `DocumentWriter`，仍是唯一写路径）。
手改内容自动生成一条 `manual` 来源的编号（第七类 kind，且算可追溯链的终点）；
指令带 `manual=True`，落到的块打上 `manually_edited`。
**D5 的边界也一并澄清了**：`manually_edited` 拦的是"AI 静默覆盖"，人自己可以继续改、继续删。

**D2 偏好区存在哪？** **已定 + 已实现**：`Document.preference_entries`，随文档版本化
（进 `Snapshot`），不进 13 章、不进交付物；界面在 13 章之后单列一节。

**D3 block id 生成规则？** **已定，按实现口径改写了当初的建议**：
块 id 用**确定性语义 id**（`s2.b1` 章节内容块 / `feat-<slug>` 功能根 / `<功能块>.<字段>` 字段块），
条目 id 用短的 `entry-<8 位随机>`。比"短随机 + 语义前缀"更好读，也天然满足"永久稳定 id"
（同一份内容重放不会换 id）；`_free_id` 负责撞名时加 `~2`。

**D4 版本快照存整棵树还是增量？** **已定 + 已实现**：v1 存整棵树（`Snapshot(blocks=...)`），
diff 展示时再算；diff 界面本身还没做（P3，见 F1）。

**D5 出处账本会被导出吗？** **已定 + 2026-09-24 生效（P5a 已实现）**：导出只带
`编号 + kind + 一句话摘要`（附录 A），原话（`raw_span`）留在系统内——界面上点编号能看，
导出文件里没有。导出本身在 P5a 落地（`01` §7.3）。
**2026-10-02 收窄（P31）**：附录 A **只列本文引用过的编号**（含偏好区），
账本里没进正文的不进交付物、只用一行说明条数——理由是账本跨轮只增，
里面一大半是读者在正文里根本没有落点的编号（真跑 59 份导出：附录占全文 51%，63% 未被引用）。
同批修掉一处导出漏渲染：**功能名称的编号以前被吞了**（界面一直挂着，导出没有）。
