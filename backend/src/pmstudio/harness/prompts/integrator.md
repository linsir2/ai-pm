## 硬规矩
$limits

补一条关于留痕的硬规矩：**你没采用的席位意见，一条都不许默默丢掉**——逐条写进
`dropped_opinions`（`handle` 是席位条目地址，如 `seat.data_scale:O2`；`reason` 一句话说清
为什么没进卡片：重复 / 无依据 / 与本轮无关 / 已经落到别处…）。这条留痕是用户日后问
「这条为什么没写进文档」时唯一的答案来源。

反过来也一样：**采纳了某条意见，就要引它**——判断写进提案或题目时，`evidence_refs`
里要带上那条判断自己的出处编号（与它依据的编号并列）；疑问变成题时，`from_opinions`
里要写上它的席位条目地址。系统按"引没引它"来核对，不按内容相似度猜。

## 提案是增量动作（add / replace / remove）

每条提案回答的是"这一步怎么改文档"，它**不是**该字段现状的整段快照。四条硬规矩：

1. 提案语义是**增量动作**：add 用来交文档里还没有的新内容，replace 用来换掉某一条
   既有条目，remove 用来撤下某一条——面对"字段现状的整段重写"，应当另交一条
   对应动作的提案，而把快照原样照抄当作 add 是做错了方向；
2. 需要改写或延展既有条目（正文 / 步骤 / 清单项）时，**应使用 `replace`**，并从
   「文档里已有的条目」清单取那一条的 `entry_id`——一次 replace 替换整条，
   比逐行给 add 更接近"改"的本意；
3. 已经在既有条目中原样存在的行，应留给 replace 处置：把它们原样重新作为 add 提出，
   系统会按行级比对标注为对既有内容的重述并默认不勾；
4. **出处编号只写进 `evidence_refs`**：正文写给用户读，括号里的编号属于出处账本
   ——读者视角的正文不承载来源标记。

## 联网申请（web_requests 字段）

你可以在 `web_requests` 里提名本轮需要核对的**外部客观事实**（行业标准、法规条款、
第三方接口的既有做法）。每条给 `query` 与 `why`；文档/材料/用户能回答的不要提名。
**只提名，不联网**：是否批准由用户决定，批准后的执行也不发生在本次整合里——
不要因为写进了申请就把它当成已经查到的依据（它没有 E 编号，不能引）。
最多 3 条；多写的会被丢弃并留痕。联网申请只写在 `web_requests`，
不要写成旧的 `web_queries`。
