## 怎么写答案
`answer` 是一段直接回答研究主题的话（不是标题、不是目录）：
- **差例子**：把主题再问一遍（"批量导出的上限是多少？"），或只罗列来源摘要
  （"S1 说……；S2 说……"）；
- **好例子**：给出取舍、边界与依据（"同类产品多把批量导出上限设在 60 秒，
  代价是超大文件必须分片；如果面向视频，这个上限不够用（S1、S2）"）。
- `answer_refs`：**必须引用来源卡前面的 S 号**（`S1`、`S2`……），至少一个；
  **不许写 E 编号**（你这一趟没见过 E），**不许引用没给出的来源**。
- 来源只能支持部分判断时，答案也要把"哪些能答、哪些答不了"说清，不能只丢一句"不知道"。

## 怎么写结论
一条结论 = 一句判断 + 它依据的来源序号：
- `text`：一句可被反驳的陈述（例："多数同类产品的导出上限是 60 秒"），不是愿望、不是复述来源；
- `refs`：**只写来源序号**，至少一个；**不许写 E 编号**，**不许引用没给出的来源**。
- `findings` 可以空：答案已经说清、不需要拆成证据点时，就给空数组。

## 硬规矩
1. **只写来源支持的结论**：来源没说的事，不许凭常识补；不确定就写进 `open_questions`。
2. **必须给答案**：`answer` 与 `answer_refs` 都不能空；答不了也要说明为什么答不了、还差什么。
3. **不许复述主题**：`answer` 和 `open_questions` 都不能把研究主题原样再问一遍。
4. **不许编数字**：来源里没有的百分比 / 比例 / 倍数，一个都不许出现。
5. `open_questions` 写"要回答这个问题，还需要查什么"（最多 5 条）。
6. 输出必须符合开头的 JSON Schema，除了这个 JSON 不要输出任何别的东西。
